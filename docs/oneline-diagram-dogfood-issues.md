## 一、挡路的缺陷

### O-1　多选之后无法批量改属性　【严重】

**复现**：框选或 `Shift` 点选任意两个以上曲线 → 看属性面板。

**看到**：整个面板塌成一句话——

```
同时选中了多个组件；只选中一个才能编辑属性
文字样式 / 不跟随
提取与写回以单条为对象，先只选中一条
```

线条颜色、线条粗细、文字颜色、字号全部不可达。

**期望**：同类属性可批量写入（至少「线条颜色」「线条粗细」这两条）。

**代价**：这是本次任务里**最大的一笔开销**。一条支路 36 条曲线要分三种颜色，母线层级 19 条
线要分三档线宽，全图一共做了 **75 次**「点空白 → 点中对象 → 开取色器 → 填 HEX → 回车 →
Escape」的六步循环。八条支路靠组件实例复用才没有乘以八；换成一张不能组件化的图（每条支路
真的都不一样），这条就是**做不下去**。

**判据**：一个实施工程师照着接线图画，第一件事就是「把这一圈线都改成红的」。今天他只能
一根一根改。

**已修**（`add-multi-selection-property-edit`）：选区里带**同一种 Renderer** 时，多选面板渲染
那个物料自己的 Inspector——字段、编辑器与分组与单选逐字相同，写入作用于整批，只占一步撤销。
取值不同的字段标成「多个值」；锁定的成员不写入并把条数说出来。混合类型仍退回空态：文字的
`color` 与曲线的 `stroke` 不是一件事，按名字取交集会让用户读不出自己在改谁。

一处**顺手就会写错**的地方写在明处：patch 合到**每个目标各自**的 props 上，而不是拿其中一条
的整份 props 去覆盖全部——两条线一条线宽 2、一条线宽 5 时，后者改个颜色会顺手把线宽也改成 2，
而这个错误在屏幕上看不见。端到端用例的判别性断言因此钉在线宽上，不在颜色上。

### O-2　`CIRCLE` 的「指定半径」不接受半径数值　【中】

**复现**：命令行敲 `C` → 回车 → 敲 `500,100` → 回车（提示变成 `指定半径或 [直径(D)]:`）
→ 敲 `14` → 回车。

**看到**：命令行回 `需要一个点`，圆不落地。

**期望**：提示写着「指定半径」，那就该收一个半径数值。AGENTS.md 里两条都指向它该成立——
「裸数字 = 当前活动字段的值（直接距离输入）」，以及「命令行是动态输入唯一的输入端，
光标旁的框只渲染」。既然输入端只有命令行这一个，直接距离输入就不该在这里落空。

**绕过**：把半径换算成圆周上的一个绝对点（圆心 `500,100` 半径 14 → 敲 `514,100`）。
全图 27 个圆全部这么画的。

**判据**：键盘用户按提示照做会直接卡住，而屏幕上写着的那句话是对的行为的反面。

**已修**（`update-point-input-reachability`）：根因不在命令，在动态输入——裸数字要拿**指针
此刻的位置**当方向，而命令由命令行或工具栏按钮启动时指针从未进过图面，那份位置是空的。
**单字段参数化那一档不需要它**：`radius` / `diameter` 的另一个分量是角度，而角度对结果没有
任何影响（那正是它被做成单字段的理由），落点由参考点与这个数完全确定。两个数值字段的参数化
不照此办理：那里方向是真的由指针给的，垫一个默认方向等于替用户猜一个他没说过的角度。

### O-3　吸附把半径点吸回圆心，圆被判退化——**且没说是吸附干的**　【中】

> 初稿把这条写成「完全静默、命令行不提示」，**那是错的**，已按复验结果改写。

**复现**：网格吸附开着（绘图工作区默认 10），鼠标画圆，圆心点落在一条已有线段的端点上，
半径点离圆心 6px。

**看到**：圆不落地，命令行提示 **`这个形状是退化的`**。

**对照实验**（同一次会话内）：

| 圆心位置 | 半径 | 取点方式 | 结果 |
|---|---|---|---|
| 落在已有线段端点上 | 6px | 鼠标 | ✗ `这个形状是退化的` |
| 空白处（不挨任何几何） | 6px | 鼠标 | ✓ 落地 |
| 空白处 | 20px | 鼠标 | ✓ 落地 |
| 落在已有线段端点上 | 3px | **命令行键入坐标** | ✓ 落地（量到 6×6） |

**结论**：不存在「最小半径」限制；是**端点吸附把半径点吸回了圆心**，圆退化成一个点。

**期望**：提示要说清是吸附造成的（比如「半径点吸附到了圆心」），而不是只说结果。
今天这句话让用户去怀疑自己的半径太小——而真正该做的是临时关掉对象捕捉或改用键入坐标。

**代价**：第一轮画支路时 4 个圆（r=3/3/10/14）连着丢掉，我是数实体个数才发现的——
提示在图面底部命令行里，画一串图元时眼睛不在那儿。

**已修**（`update-point-input-reachability`）：命令取点时，会话已经上报的 `reference` 被排除
出特征点捕捉，与几何编辑「拖夹点时排除被拖那个顶点的原位置」是同一条判断的第二次应用——落点
被吸回参考点，对每一条画几何的命令都只能产出退化几何，那个结果一定会被当场拒掉，因此这处
排除不拿走任何用户够得着的结果。排除**按位置**而不按 Entity 身份：把落点拽回去的正是**那条线
的端点**，按身份排除挡不住它。

### O-5　「全屏预览」不重新取景　【轻】

**复现**：打开预览（此时缩放 59%）→ 点「全屏预览」。

**看到**：进了全屏，缩放**仍是 59%**，画板缩在左上角，右侧和下方是一大片空白。
手动再点一次「适应窗口」才正常（点完 100%）。

**期望**：AGENTS.md 明写「适应窗口是**动作不是档位**，只在打开、换目标、从下拉换屏三处
触发」，全屏不在其中——所以这是**设计缺口而不是实现走样**。但进全屏是一次幅度极大的取景
变化，理由与「从下拉换屏」同类（可视区整个换了），建议把它加进触发点。

**复验补上了另一半**：**退出**全屏同样不重新取景，而那一半更难受——画板比对话框还大。
实测三个数：

| 时刻 | 视图缩放 | 这一档「适应窗口」该是多少 |
| --- | --- | --- |
| 模态形态 | 95% | 95% |
| 进全屏之后 | **95%** | 100% |
| 退出全屏之后 | **100%** | 95% |

**已修**（`update-preview-refit-on-fullscreen`）：进出浏览器全屏各重新取景一次，触发读的是
`fullscreenchange` 而不是那颗按钮——用户可以用 `Esc` 或浏览器自己的方式离开。

一处**顺手就会写错**的地方写在明处：**不能在收到事件的那一帧取景**。`fullscreenchange` 早于
ResizeObserver 把新台面量出来，当帧取景会按**旧**尺寸算出同一个比例，缺陷原样留着，而模态
形态此后不为窗口变化再取景，因此没有第二次机会。正确做法是记下「下一次台面尺寸变化时取一次
景」。组件用例就钉这一条：先手动放大一档，再触发 `fullscreenchange`，比例必须**不动**
（当帧取景会把手动缩放冲掉）。

### O-6　属性面板上两个字段都叫「圆角」　【轻】

**复现**：选中一个 `RECTANGLE` 画出来的矩形，看属性面板。

**看到**：两处同名「圆角」：

| 分组 | `data-property-path` | 作用 |
| --- | --- | --- |
| 外观 | `borderRadius` | 宿主盒的圆角（对空心曲线看不见） |
| 几何 | `cornerRadius` | 多段线的角圆角（真正改形状的那个） |

**期望**：屏幕上要能分清。今天只能靠「试一个、看形状变没变」来区分，而空心矩形改
`borderRadius` 是**完全没有可见效果**的——用户会以为圆角这个功能坏了。

**已修**（`update-palette-and-radius-legibility`）：外观那一个改叫**「边框圆角」**——它坐在
边框颜色与边框宽度旁边，也与字段名对得上；几何那一个保留「圆角」，那是用户想改形状时要找的
那一个。两处各加了一句说明自己作用在什么上。

## 三、可发现性问题

### O-8　符号库面板的分类计数具有误导性　【轻】

**复现**：切到绘图工作区，看左下「符号库」面板。

**看到**：`Symbols (0)`、`dianciganying (0)`、`kaiguan-baohu (0)` …… 每个分类都是 `(0)`，
展开之后也不列出任何东西。

**实际**：这些文件夹里各有 2～18 个 `.svg`（`dianciganying` 有 11 个）。

**证据**（复验）：把 `dianciganying/变压器1.svg` 导入为组件之后，计数变成
`Symbols (1)`、`dianciganying (1)`、`项目组件 (2)`——确认这个数字数的是**已导入的项目组件**，
不是文件数。

**期望**：从产品定义上这个面板是「货架」不是文件浏览器，`(0)` 本身没算错。但一个名字叫
**符号库**、列着一排符号目录名、每个都写着 `(0)` 的面板，第一次看就是「符号库是空的」。
我据此认定这条路不通，绕到底部「资源」面板才找到那些 SVG。至少需要一句「去资源里导入」
的空态引导。

**已修**（`update-palette-and-radius-legibility`）：整块货架的文件夹段一个组件都没有时，面板
上出一句「这些文件夹里的符号还没有导入成组件。在「资源」里右键一个 .svg，选「导入为组件」。」
**只在整块都空时说，且只说一次**——某一段是 0 而别的有货时，机制已经在屏幕上演示过了，那个 0
自己说得清楚；九个段各写一遍是同一句话说九遍。搜索期间不说：那时的 0 是「没搜到」，与「还没
导入」的下一步完全不同。

## 四、做对了的地方（值得保住）

- **命令行键入坐标是这张图能画出来的前提**。「键入的坐标不被任何吸附改写」这条不变量
  实测严格成立：要 `300,100` 落地就是 `300,100`，w=1、h=100，一个像素不差。全图 100 多个
  图元的几何精度全靠它。
- **组件提取 → 实例复用**这条链路很顺：框选 45 个实体 → `GROUP` → 拖进资源目录 → 命名 →
  原地变成实例，再从组件库按钮点 7 下就出 7 条支路，位置用属性面板逐个写死即可。
  这一步把 8×45 = 360 次绘制压成了 45 次。
- **复制粘贴正常**（复验见下）：选中实例 `Ctrl+C` / `Ctrl+V`，实体数 89 → 90，粘贴落在指针处。
- **SVG 导入会报降级**：导入 `变压器1.svg` 时右下角提示「部分内容未能完整导入: mask ×1,
  rect ×1」——与「不能表达的属性降级，元素永不丢弃，各自出诊断」这条约定一致。
- **属性面板的 `data-property-path` 让自动化可寻址**（`cornerRadius`、`strokeWidth`、
  `fontSize`），比按 label 文本找稳得多。
- **多段线圆角是几何级的**：电池外框写一个 `cornerRadius=8` 就圆了，形状本身变了而不是
  盒子变了，缩放下不失真。

## 五、撤回：初稿里三条**不是**（或不是那个）产品缺陷

记在这里而不是删掉，因为它们是「自动化驱动的假象」的典型样本，下一个人容易再踩一次。
三条的共同形状是一样的：**我读面板的时候，我以为已经发生的那件事其实还没发生。**

### ~~Ctrl+V 粘贴无效，且后续属性编辑会静默作用到原对象~~　**撤回**

初稿说粘贴是 no-op。**复验推翻**：给浏览器上下文授予
`clipboard-read` / `clipboard-write` 权限之后，选中实例 `Ctrl+C` → 移动指针 → `Ctrl+V`，
实体数 **89 → 90**，粘贴正常。

初稿观察到的现象，根因是我的 Playwright 上下文没有剪贴板权限；「粘贴什么都没发生，
所以选区停在原对象上，于是接下来 7 次改位置都作用在同一个对象上」是这个前提下的**正确**
行为。产品无责。

### ~~资源浏览器双击文件夹跳过一层~~　**撤回**

初稿说网格里双击 `Symbols` 直接落进了 `Symbols/daoti-lianjieti/`。**复验不复现**：
从 `Demo Assets` 根双击 `Symbols` 瓦片，grid 的 `aria-label` 从 `Demo Assets` 变成
`Symbols`，正好进一层。

初稿那次之前，我先在左侧另一个面板点过同名的 `Symbols` 项，多半是那次点击改了当前目录。
是操作污染，不是缺陷。

### ~~删掉组件资源后，组件库分组计数不刷新~~　**撤回**

初稿说删掉 `变压器1.component.json` 之后瓦片没了、分组计数还停在 `(1)`，等 2.5 秒与切换面板
都不刷新。**复验不复现**，两条路径都走了一遍：

| 步骤 | 根目录的 `Disconnector.svg` | 嵌套的 `Symbols/dianciganying/变压器1.svg` |
| --- | --- | --- |
| 导入为组件 | `项目组件 (1)` | `Symbols (1)` / `dianciganying (1)` / `项目组件 (1)` |
| 删除组件资源并**确认** | `项目组件 (0)`，瓦片同时消失 | 三处全部回到 `(0)`，瓦片同时消失 |

根因是我自己：删除会弹一个 `role="alertdialog"` 的确认框，而我当初用 `[role="dialog"] button`
去找按钮、拿到空数组，就以为没有确认框、删除已经发生了——**此后读到的面板是删除之前的面板**。
这一次的探针把它抓了出来（`overlay open? 2`，按钮是 `["取消","删除"]`）。

代码上也对得上：`resolveComponentShelf` 里段的 `count` 与它的瓦片列表读的是**同一份**
`catalog.components`，两者在构造上不可能分叉。一条「计数与列表不一致」的缺陷在这里没有容身处。

### ~~文字工具落点被网格吸附，等距排版做不出来~~　**撤回**

观察是准确的（点 200/218/236/254/272，落位 200/214/236/250/272，行距 14/22/14/22），
**归因是错的**，而且这条能力本来就有。

**成因不是网格吸附，是对齐吸附。**证据三条：

1. 文字盒高**恰好 14**。落位里那两个被挪走的正好落在前一条文字的**底边**上
   （200 + 14 = 214、236 + 14 = 250），而没被挪的那三条离前一条的底边都超过 8 像素。
2. 网格步长只有 4 / 8 / 16 / 32 四档，**没有一档能把 218 挪到 214** 而同时让 200 / 236 / 272
   原地不动。
3. 关掉工具栏那个「吸附」开关重做同一组点击，落位是 518 / 536 / 554 / 572——**一个像素不差**。

而「对齐吸附在绘图工作区里开着」本身也不是疏漏：它是**文档**字段，工作区只能给新建文档做种子，
AGENTS.md 把这条代价写在明处——「打开一份已有页面再切到绘图，对齐吸附仍然开着，要关只能按那个
按钮」。我正是打开默认首页再切过去的。

**而且「等距的数值列」根本不用一个一个摆**：`DISTRIBUTEY`（别名 `DY`）一条命令就做完了。
实测把那五条 200/214/236/250/272 选中敲 `DY`，当场变成 200/218/236/254/272。它也不是藏起来的
——命令行里敲一个 `D` 就列在第二条（`DISTRIBUTEY(DY)垂直等距`）。我当初手工改的那 5 次 Y
是白做的，原因只是我没去看命令行的补全。
