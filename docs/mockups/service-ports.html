架构 · 端口设计

后端的两个端口

后端还不存在。先把它的形状定成浏览器这一侧看见的两个端口，服务端照着实现； 在它出现之前由本地实现顶在同一个位置。拆的是接口不是部署—— 两个端口背后完全可以是同一个进程、同一张表。

01全景

虚线是可替换的那一条缝。缝之上是产品代码，缝之下今天有三种实现：接 HTTP 的、 接本地目录的，以及用资源端口去顶库端口的那一个——它是「现在没有后端」这句话的落点。

编辑器那一列一行不改。它今天就在用 ComposeAssetProvider，换的只是背后接的是谁。

判据
一个端口答不了两边。ComposeAssetProvider 是一棵文件树，首页要的每一件事 它都答不了——「PCS 有 64 个」要遍历整棵树读每个文件的标签，而协议里没有标签； 「回收站」要软删，而协议里 delete 就是删；「用过多少次」是业务计数。反过来，页面库也答不了 编辑器要的事：用户往资源里放 SVG 符号、DXF 与脚本，那是目录与字节。
今天的做法为什么撑不住
首页那份目录现在是 listComposePageDescriptors 走遍整棵树拿到的（BFS， 每个文件夹一次 list）。本地目录上这是对的；换成 HTTP 之后它就是 打开首页要几十个来回，而且拿回来的东西里没有一样是首页真正要的。 它不会被删——它降为 Provider 实现的内部细节。

02身份：一个 key，两个视图

两个端口之间只有一个连接点。库里一条记录的 pageKey，就是资源服务上那份 .page.json 的 assetKey。

pageKey  ===  assetKey

库记录

ComposeLibraryRecord · 数据库

  • kind项目 / 模板
  • categories场景类型标签，空即未分类
  • deletedAt非空即在回收站
  • useCount被用作底稿的次数
  • thumbnailUrl可为空

资源记录

ComposeAssetEntry · 数据库

  • name / parentId目录结构住这儿
  • mediaType页面的身份判据
  • revision就是 ETag
  • size / modifiedAt存储层给的
对象存储 assets/{assetKey} 扁平，不带路径 · 改名与移动只动表，零字节搬运
判据
assetKey 必须是服务端签发的不透明 id，不能是存储路径。协议已经写着它 「在 rename/move 后保持不变」，而对象存储的 key 是路径——把路径当 assetKey 的话， 用户在资源浏览器里改一下文件夹名，图上每一个引用它的实例同时断掉， 而这个错误只在改名之后才出现，屏幕上没有任何东西解释它。
推论
两条记录一对一挂在同一个 key 上，实现上可以就是同一张表的几个业务列。因此 modifiedAt 与 revision 不需要在两边同步——它们本来就是同一行。 若把库做成独立服务、自己存一份 modifiedAt，那么每一次保存都要有人去通知它， 而漏掉那条通知的症状是「图改了但首页上的排序没动」，用户会以为保存没成功。

03写有三条路，判据是有没有乐观锁要守

读只有一条（query 出目录、resolveUrl 出内容）。写要分开， 因为这三件事的失败方式完全不同。

缩略图
库端口
putThumbnail
保存成功之后异步上传，失败不阻断保存，记录上可以一直没有图。 缺一张图用户看得见，而让保存因为一张缩略图失败是不可接受的。
为什么保存不也走直传
直传要多一次回执握手才拿得到新的 revision，而页面文件本来就只有几十到几百 KB。 为一条不省带宽的路径加一次握手，换来的是保存路径上多一处可失败的地方。

04「就用这个」是一次调用

首页上最要紧的那个动作：客户指中一张模板，以它为底开始改。 前端只发一次请求，复制、建记录与计数加一在服务端的同一个事务里。

第 3 步不经过浏览器——一张大接线图好几 MB，而在对象存储里复制是一次服务端操作。 第 7 步之后编辑器回到它今天的老路：writeFile 加 expectedRevision。

判据
「用过多少次」只能由这一步加。端口上没有任何可以单独调的自增——那样打开一次 就能刷，而这个数存在的全部理由是回答「哪个画法是大家在用的」。 这也是整份设计里唯一要求服务端写业务数据的地方，别处它只管存取文件。

契约是这些 TypeScript 端口本身，线上怎么走由实现方定。 端口上没有鉴权参数——那是 HTTP 适配器的事，放进端口会让本地实现凭空多出一个它答不了的参数。

代价
预签名 URL 会过期，而一张图可能开着好几个小时。返回值必须带 expiresAt，消费方在过期前重取——不带它的症状是 图在某一刻集体变成裂图。这条复用 subscribe 那条既有的重解路径， 不另造一套。
