Figma 的布尔节点既是容器又有几何，而 Curve MUST NOT 与 Hierarchy 组合。

Figma 做的是什么

截图上那五项，语义上是两类东西。

四条布尔运算（Union / Subtract / Intersect / Exclude）在 Figma 里产出一个活的布尔节点： 子级原样留着、双击可以进去改，运算本身随时能换成另一条。Flatten 则是破坏性的， 把选中的东西拍成一条可编辑的矢量路径——把一个圆角矩形变成能拖控制手柄的 path， 正是 Figma 用户用 Flatten 的主要理由。Subtract 是「上面的减最下面的」，Exclude 就是异或。

值得抄的是这五个词与它们的几何语义：它们是矢量编辑的通行词汇， AutoCAD 的 UNION / SUBTRACT / INTERSECT （别名 UNI / SU / IN）说的是同一件事，两边的用户各带一半肌肉记忆过来。 不值得抄的是那个活节点，理由在下面第 01 条。

仓库里已经有什么

这一节是整份可行性的地基，每一行都指向真实文件。

HATCH（油漆桶求面）与布尔运算是同一份数学的两种用法： 那边从落点射一条射线、绕出围住它的那一块面；这边要把全部的面都绕出来， 再按「在哪几个操作数里面」决定留不留。绕面这件事——两两求交切子边、节点按容差合并、 叠在一起的边收成一条、半边图上取最右转向、退化时换射线方向重试—— curve-region.ts 已经写完并且上线了。

算法：面分类法

四步，其中两步是现成的。

为什么不是边裁剪

另一条通行路线（Greiner–Hormann 那一类）是把「进 / 出」标在每个交点上，沿边走。 它的账在退化情形上：共线重叠边、顶点恰好落在对方边身上、两条弧相切——每一种都要一条特判。 而这些正是本产品最常出现的情形：网格吸附让两个矩形共享一条边，是画柜体轮廓时的常态。

面分类把退化交给已经处理过它们的那一层：buildGraph 的叠边去重 （两条画在一起的边界线在图上就是一条边界）与 castRay 的六方向重试。 判据是：仓库已经为求面付过这笔账，布尔不该再付第二遍。

为什么不做活的布尔节点

这是整份设计里唯一一处对 Figma 的重大偏离，值得单独画一张图。

还有一条产品判据，与协议无关。仓库里反复用的那句话是—— 用户画完之后想对它做什么。在这个产品里，布尔运算的典型用途是柜体轮廓开一个口、 母线搭接处去一块、给符号底板挖一个孔，而下一步全是拖那个新形状的顶点。 活节点恰恰做不到这件事：要改轮廓得先进到子级里去改原来那两个形状。

Figma 自己也承认这一点——它提供 Flatten，用途正是把活节点拍掉。

语义决策

写成可以直接搬进 OpenSpec 的形式：每条一句判据，代价写在明处。

破坏性，不做活节点

五条命令都产出一个新的普通 Curve Entity，操作数在同一个事务里删掉，撤销一步全回去。判据是上面那两条：协议互斥 + 用户下一步要拖顶点。代价：改主意要撤销重来，而不是像 Figma 那样换个运算。

结果的外观、名字与父级取同一个来源

取层序最靠后（画在最下面）那个操作数的 Appearance、Renderer props、名称与父级，新 Entity 插在它原来的位置。判据是：取不同来源会让场景树上那一行与画布上那块颜色指向两个不同的对象。这与 Figma 取最底层的样式一致，也与 HATCH 把填充插在最靠后的边界之下同一条。

旋转烘进几何，因此旋转过的操作数是支持的

投影走世界空间，结果落成一条 rotation 为 0 的新曲线，与 SVG 导入「变换在导入期烘进几何」同一条。这与 HATCH 跟随拒绝旋转边界不冲突——那条限制的理由是每帧重求要读盒快照，而布尔是一次性的、事后不再跟随。跨父级同理支持：世界投影已经把层级差吃掉了。

取能表达结果的最窄 kind

没有岛且全是直边 → 闭合 polyline（顶点可拖、圆角可调）；否则 path；有岛时写 fillRule: 'evenodd'。一律落 path 的症状是「这条线看起来一样却拖不动顶点」——resolveComposeCurveRegion 尾段已经是这么做的，照用。

结果为空时拒绝，不产出一个看不见的 Entity

两个不相交的形状取交集，Figma 给一个空的布尔节点。那是静默的错；把静默的错变成可见的错，是这条的全部价值。命令行说「这两个形状没有重叠」，文档一个字节不动。

锁定的、被导线绑着的操作数拒绝并说明

「你锁了它」和「我把它删了」是两件事，后者会让锁形同虚设。导线绑着它时删掉会让绑定悬空，而悬空引用不让文档非法——这个错屏幕上只在 Inspector 里现形，因此必须在事前拦住。带动画轨道的操作数照做，但出一句说明。

直线拒绝，未闭合折线放行

判据是有没有面积而不是闭没闭合：isPointInsideComposeCurve 对开放几何按隐式闭合处理，因此一条未闭合折线是有面积的，与 SVG 填充开放路径的规则一致；而 line kind 连这一步都没有。按「闭合」判会拒掉用户明明看得见一块面的那些图形。

Flatten 不求交

它只把每条几何转成子路径、拼成一个 path，fillRule 缺席（即 nonzero）。因此它是布尔失败时用户唯一还能走的那条路，也是把一个圆角矩形变成能拖控制手柄的路径的入口——那正是 Figma 用户用 Flatten 的主要理由。单选一个对象也成立。

五条命令，别名照抄 AutoCAD

UNION / SUBTRACT / INTERSECT / EXCLUDE / FLATTEN，别名 UNI / SU / IN / XOR / FLAT。EX 留给将来的 EXTEND，因此异或用 XOR。快捷键照抄 Figma 的 ⌥⇧U/S/I/E/F——alt 这个修饰符在 DEFAULT_STAGE_SHORTCUTS 里一个都没用过，不撞车。

split button 的面固定是 Union，不记忆

不做「按钮面显示上次用的那个」。仓库对看不见的状态的既有判据是「那个值有没有被印出来」，而一个只有认得图标的人才读得出来的按钮面不算印出来。代价写在明处：第二常用的 Subtract 要多点一下 ▾。

v1 不做

贝塞尔操作数、活节点与嵌套布尔、描边转轮廓（Outline Stroke）、布尔结果的「重新生成」（它没有边界清单可跟随——那是 Hatch 的事）。

八种拒绝，互相可分

「敲了没反应」与敲错字在屏幕上无法区分，因此每一种都要有自己的一句话。

情形命令行说明（示意）
选择集不足两个布尔运算至少需要两个形状；只选了 1 个。
选中了不带几何的对象「机柜底板」是容器，布尔运算只作用于曲线。
操作数含贝塞尔路径这一版还不支持带曲线段的路径参与布尔运算。
操作数含直线直线没有可运算的面积。
操作数锁定「外框」锁着，先解锁再运算。
操作数上接着导线「端子排」上接着 3 条导线，布尔运算会删掉它。
结果为空这两个形状没有重叠，交集是空的。
求解退化（六个射线方向全部读不出朝向）这几个形状的相交情况算不出来；把它们稍微错开一点再试。

P4贝塞尔进平面图（可选）收益是两份

cubic 进 ComposeOutlinePiece、补 cubic×cubic 求交（Bézier clipping）。这一步同时解锁 HATCH 用贝塞尔边界——那是仓库里已经写明的另一处 v1 缺口。

三个要你拍板的问题

一、破坏性 vs 活节点

我推荐破坏性，理由是协议互斥加上「用户下一步要拖顶点」。但如果目标用户会反复调整同一个符号的形状，活节点要另开一次协议讨论——它是一个新的 Entity 类型，不是一个新 Component。

推荐：破坏性。

二、P4 做不做

贝塞尔操作数在接线图里几乎用不到（符号是直线加弧），在大屏底板里可能要（SVG 导进来的装饰形状就是 path）。它的收益是两份——同时解锁 HATCH 的贝塞尔边界。

推荐：P3 先上线，P4 看真实图纸里 path 的占比再定。

三、快捷键给不给

七个裸字母已被绘图命令占满，⌥⇧ 这一组在 DEFAULT_STAGE_SHORTCUTS 里完全空着。照抄 Figma 的 ⌥⇧U/S/I/E/F 零成本、零冲突，而且从 Figma 过来的用户直接会用。

推荐：照抄。
