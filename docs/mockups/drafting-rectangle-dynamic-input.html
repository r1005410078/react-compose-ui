画矩形的动态输入

与画线共用同一条规则，只是标注从一条变成两条正交的。画布片段按 Stage 的真实 token 1:1 绘制，图上每一段几何都与框里的数值对得上。

宽摆在哪里
上边外侧标注线的中点
两条延伸线从上边的两个角点向外引 48 px，标注线平行于所量的那条边，在框后断开。
高摆在哪里
右边外侧标注线的中点
同一条规则的第二次应用。两条标注互相正交，因此不会挤在一起。
角度呢
没有角度
矩形是轴对齐的，角度恒为 0°。画一条永远指向 0° 的弧是噪音。
与画线是同一条规则：框落在自己那条标注的中点上，标注在框后面断开

画线时那条规则管一条长度标注和一段角度弧；画矩形时它管两条正交的边长标注。 规则一个字没变，因此用户在两条命令之间不需要重新学任何东西——这正是把「框摆在哪里」 收敛成一句话的价值。

五个状态

从按下 R 到画完一个矩形。编号是实际顺序。

01 按 R，还没取第一个角点

与画线完全一样：第一个点没有「上一点」，量不出宽高，因此这一档是绝对坐标。X 是活动字段，直接打数字就进去了。

02 拖出矩形，宽是活动字段

两条标注跟着光标实时重画，数值取的是解算之后的落点——与预览矩形的角、捕捉标记、十字光标是同一个值。标注摆在靠近光标的那两条边外侧：从左下往右上拖就是上边和右边，反向拖就换到下边和左边，视线始终不用离开光标。

03 Tab：焦点换到高，宽被锁住

Tab 在换焦点的同时锁住它离开的那个字段（AutoCAD 的行为）。这让「拖个大概的宽度 → Tab → 打一个精确的高度」变成两步。想解锁就再 Tab 回去重打。

04 打了 300 回车，光标继续往外走

锁定之后光标可以跑到锁死的那条边之外，矩形不跟过去——这是「宽已经定了、高还在跟鼠标」唯一说得清楚的画法，与画线锁定长度时画那个半径圆是同一条处理。

05 按住 Shift：约束成正方形

Shift 是临时约束，松开即恢复。两个框仍然各自可编辑——打一个数字进去，另一个跟着变成同一个值。

拒绝的三种画法

长度 + 角度（沿对角线量）

AutoCAD 的动态输入全程只有「长度/角度」一套字段，画矩形时给的是对角线长度和一个 37°。用户想知道这个框多宽，还得自己开根号。我们的字段由命令 声明，没有必要跟着受这个限制。

把宽高写进一个框，440 × 180

看起来更省地方，但两个数就没法分别锁定，Tab 也没有去处。而「锁住宽、 只改高」正是画元器件外框时最常做的事。

标注永远摆在上边和右边

实现最简单，但从右上往左下拖的时候标注会跑到图形的另一头，用户的视线要在光标和标注 之间来回跳。跟着光标那两条边走，代价只是一次符号判断。
