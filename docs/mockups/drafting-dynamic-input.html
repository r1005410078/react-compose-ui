画线的动态输入

取点过程中长度和角度长什么样、摆在哪里、写什么字。画布片段按 Stage 的真实 token 1:1 绘制，图上每一段几何都与框里的数值对得上。

长度摆在哪里
一条与线平行的标注线的中点上
标注线从起点和终点各引一条短延伸线，垂直偏移 40 px。它明确说出「量的是这一段」。
角度摆在哪里
角度弧的中点上
弧从水平 0° 射线扫到线，半径等于当前长度；框落在扫掠一半的那个位置， 与长度框是同一条规则。
框里写什么
只有数，没有文字标签
300 和 45°。位置已经说清了各自量的是什么。 第一个点例外，用 X / Y 前缀。
一条规则管住两个框：框落在自己那条标注的中点上，标注在框后面断开

长度框在标注线的中点，角度框在弧的中点。两条标注都不从框底下穿过去——断开的缺口本身 就在说「这个数说的是这条标注」。角度弧的半径必须等于当前长度：固定的小半径 在小角度下退化成几个像素，等于没画；半径跟着长度走之后，弧长与角度成正比，再小的角也有 一段读得出来的弧。

五个状态

从按下 L 到画完第二段。编号是画线的实际顺序。

01 按 L，还没取第一点

第一个点没有「上一点」，量不出长度和角度，因此这一档是绝对坐标，两个框贴着光标。 X 是活动字段，直接打数字就进去了。

02 光标压到端子上

捕捉命中时坐标框读出的是端子的精确坐标，不是光标的裸坐标——框和落点始终是同一个值。 命中的种类写在命令行，不占光标旁的位置。

03 取了第一点，正在找第二点

两条标注都跟着光标实时重画。数值取的是解算之后的落点——跟预览线终点、 捕捉标记、十字光标是同一个值；读裸指针的话，开着栅格吸附时框里的数字会跟线的终点对不上。

04 打了 260，Tab

长度锁死之后预览线不再跟到光标——它停在半径 260 的那个圆上，只跟着光标转，因此线的终点 和光标之间有一段可见的空隙。虚线圆是这个锁的示意，只在有字段被锁时出现； 角度弧的半径也跟着变成 260。

05 第一段落地，画第二段

标注的基点跟着换成上一段的终点：角度永远是从这一段的起点量起，不是从整条折线的 起点。已落地的段回到普通几何色，只有正在画的那一段是 accent。关键字做成可点的 chip。

否掉的三个做法

两个框并排贴着光标

好处是 Tab 切换时视线不用跳。但它把「这个数量的是什么」交给了一个图标， 而标注线和弧本来就能把这件事画出来。省下的那次视线跳动不值得换掉这个。

角度框贴在弧的 0° 端

这是上一版的做法。0° 端就在起点附近，而长度标注的延伸线也从起点引出——两个框会挤在 同一小块地方，反而看不清各自属于哪条标注。放到弧的中点之后，两个框各自落在自己那条 标注的正中，规则也收敛成一句话。

把命令提示也搬到光标旁

AutoCAD 的动态提示会在光标边上写「指定下一点或 [放弃(U)]」。我们的命令行是常驻的， 同一句话再抄一份会让光标旁堆到三行——而画图时视线在落点上，需要的是数字不是句子。
