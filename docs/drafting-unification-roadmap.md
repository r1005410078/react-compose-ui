# 绘图统一路线图：CAD 融入页面世界

## 文档定位

本文是「把 CAD 能力融入页面编辑器」的**纲领性路线图**，用于串联多个 OpenSpec 变更，不代表
当前已经稳定的公共 API。每一步都是一个独立可发布、可回退的 OpenSpec 提案；**路线图是方向，
提案才是权威**——每刀的提案只在轮到它时写，吸收前面各刀实现时发现的事实；本文在每刀完成
后回填实测结果与被推翻的预判。

本文**接替** `cad-document-roadmap.md` 的后续方向：那条路线（独立 CAD 文档类型，步骤 1–9）
已经走完并交付了全部图元数学、捕捉、命令行与 DXF 解析——这些原样存活；被本路线替换的是
「独立文档类型 + 独立编辑外壳」这个壳。

## 产品意图（2026-08-22 修订）

用户场景把方向定死了：实施工程师画一张主接线图，图上每个刀闸是一个**有状态的对象**——
分/合是位置与角度的动画片段，由页面脚本按遥信驱动。这是 SCADA/HMI 组态，不是绘图。

因此分工是：**CAD 借的是画法，对象世界归页面。**

- **身份模型学 Figma**：画出来的东西是普通页面 Entity——进场景树、有属性面板、能打关键帧、
  能做成组件、被页面脚本控制。画的方式特殊，画出来的东西不特殊。
- **手感学 AutoCAD**：命令行驱动、对象捕捉、正交、十字线、左窗口右交叉框选。用户拿到的
  原图是 DXF，肌肉记忆是 CAD 的。
- **切换发生在模式层，不发生在文档层**：绘图模式是 Stage 的会话状态（参照 Figma 的
  Design/Draw 切换），换工具栏、换手势语义、加命令行；文档、场景树、属性面板、动画面板
  在两个模式下是同一套。

## 已定的决策

| # | 决策 | 后果 |
| --- | --- | --- |
| 1 | **没有第二个世界**：删除 CadDocument/.cad.json/CAD 标签页（路线末刀） | 曲线成为页面词汇；cad 数学存活、外壳消亡 |
| 2 | **曲线保留盒**：`LayoutItem` + 盒局部几何（Figma vector node 模型） | 移动/动画/树/预览零改动可用；不需要 v8 |
| 3 | **命中判据从「每画布一个常量」变成「每 Entity 一个 capability」** | 盒物料按矩形，曲线按点到几何距离；canvas-kit 边界不变 |
| 4 | **刀闸=Component Asset**：端口挂组件定义、片段挂组件定义、状态挂实例 | 一次声明全部实例都有；50 个刀闸不是 50 份手工动画 |
| 5 | **无限图纸消亡**：图画在场景（Frame）里 | 交付物本来就是固定尺寸大屏；DXF 按内容包围盒开场景 |
| 6 | **不写迁移器**：无线上 `.cad.json` 资产 | 与删 Page Slot 同一条判断，为零份文档写迁移是负债 |

决策 2 是读代码后的修正：位置的事实来源本来就在 `LayoutItem.offset`（动画位置轨道路径就是
`['LayoutItem','offset']`，move 插件写的也是它，`Transform` 只有 `rotation`），去掉盒等于把
每条既有轨道 fork 一遍。口头阶段的「v8 + 无盒 Entity」方案在此作废，记下以免重提。

## 路线

每刀门槛一致：五道（`lint` / `typecheck` / `test` / `build` / `test:e2e`）+ 该刀自己的
端到端纵向用例；判别性断言先验红再实现。

### 步骤 1 · 曲线 Entity — `add-curve-entities` ✅

让「一条线」成为合法页面 Entity：core 可选 `Curve` Component（盒局部几何，`kind` union
留位）、几何写入漏斗（端点 → Curve + 紧包围盒同一事务）、stage-engine 距离窄相位命中、
`curve` 物料、工具栏点击添加。协议版本不变。

这一刀是整个论题的最小验证：线进场景树、能点选（点盒空角不选中）、能移动、能撤销、能预览、
能打位置与旋转关键帧——**旋转关键帧就是刀闸分/合的原语**。如果曲线在这条路上接不顺，损失
止于一刀。

刻意不做：弧/多段线/文字、绘图模式、CAD 框选语义、盒 resize 手势、端点几何关键帧。

**门槛**：五道 + 曲线纵向 e2e（添加 → 场景树 → 按距离命中 → 改端点 → 拖动 → 撤销 → 预览）
与关键帧 e2e。✅ 全绿，e2e 122 → 124。

**提案里最重要的一处判断被实测确认**：保留盒之后，场景树、属性面板、位置/旋转关键帧、
预览、撤销**没有写一行曲线专用代码**就可用——两条 e2e 正是为了钉住这一点。

**一处提案级修正（读代码才发现）**：以为 Stage 点选走 `StageSceneIndex.entityAtPoint`，
实际上 Stage 的点选是 **DOM 驱动**的（Entity 节点上挂 `onPointerDown`），`entityAtPoint`
只服务取色采样。因此「按距离而不是按盒」落在**两处**：DOM/CSS 那条（`.is-segment` +
物料的透明加宽 stroke，机制仓库里已有，line/arrow 就在用）与 `entityAtPoint` 那条。
线状判定改成按 `Curve` Component 而不是 Renderer 类型枚举。详见 change 的 design D4。

**创建入口定在 Palette 而不是 Stage 工具栏**：工具栏上的 line/arrow/circle 是拖拽绘制工具，
而本刀只做点击添加，Palette 的 `external.add` 恰好就是这条既有路径，零新代码。

**顺带修掉一处测试脆弱性**：`pointerDrop` 用 `boundingBox()` 作为按下点，而 Palette 可滚动
——新增一个 Preset 就把靠后的物料挤出视口，`boundingBox()` 仍返回坐标而按下位置已在面板之外
（ECharts 用例因此挂掉）。helper 补 `scrollIntoViewIfNeeded()`。

### 步骤 2 · 绘图模式 — `add-drafting-mode` ✅（模式外壳 + 画线）

Stage 的模式切换（会话状态，不进文档）：工具栏换成绘图工具、底部出命令行、十字线 + 捕捉
标记、CAD 选择语义（点中累加、Shift 移出、左窗口右交叉）。两点画线是第一个真手势——起点
终点各吸一次捕捉，非 100% 缩放验证。

捕捉候选从页面既有 `snapCandidates`（盒的六条参考线）扩展出**几何特征点**（端点、中点，
圆心/象限点随弧一起来）。命令行会话机、点输入解析从 `cad` 包搬运——它们不认识文档协议，
搬运成本低。

**门槛**：五道 + 绘图纵向 e2e（进模式 → `L↵` → 点两下 → 第二条起点捕捉到第一条端点 →
切回设计模式，线在场景树里、能撤销）与「命令进行中仍可平移」。✅ 全绿，e2e 124 → 126。

**命令引擎一行没搬**：`@compose-ui/commands` 本来就对 `TContext`/`TEffect` 泛型、连 `core`
都不依赖，Stage 只声明自己的两个类型。当初把它立成零依赖包的回报在这里兑现——若当时让它
认识 `CadDocument`，今天就要么改它的类型、要么写第二份。

**路线图这里写错了一处**：说「捕捉候选从既有 `snapCandidates` 扩展」。读代码后改口——
`snapCandidates` 返回 `{ axis, value }` 的参考**线**（Figma 式对齐），CAD 捕捉要的是一个二维
**点**。形状不同，是姐妹查询而不是扩展。v1 的候选因此只出曲线的端点与中点，**不出盒的角点**：
那正是对齐吸附覆盖的语义，两套同时生效会在同一次取点里互相拉扯。

**框选是白拿的**：`ComposeStageMarqueeMode` 已有 `directional`（左→右窗口、右→左交叉），
绘图模式切个默认值即可，零代码。

**一处对 CAD 优先级表的有意偏离**：CAD 里「命令取点」最高，Stage 把它排在 `pan` **之下**
——`pan` 是按住空格/中键的临时覆盖，命令进行中仍要能平移画布去看远处那个点。有一条 e2e 钉住它。

**顺带下沉两块共享物**：点输入管线与坐标语法从 `cad` 移进 `core`（两个消费者、无文档知识），
命令行组件从 `cad-canvas` 上移到 `components`（正好满足 AGENTS 的「两个第一方消费者」门槛）。
`ComposeGridSettings` 借此改成两轴独立——页面网格本就允许 X≠Y，单一步长会把一个轴吸错。
CAD 的 87 项既有用例不改一行即全绿，是这两次搬运没有改变行为的证据。

### 步骤 2b · 编辑命令与选择语义 — `add-drafting-editing-commands` ✅

`MOVE`/`COPY`/`ERASE` 与 CAD 选择语义一刀落地。两者是同一个用户故事的两半：选择语义单独
落地没有消费者，而 `MOVE` 的第一步就是「选择对象」——替换语义下点第二个对象会丢掉第一个，
三条命令全部退化成单选。

**门槛**：五道 + 选择语义 e2e（点中累加 → Shift 移出 → Esc 清空 → 切回设计模式恢复替换）
与编辑纵向 e2e（命令中选两条 → 基点 → `@60,0` → 一起走 → 一步撤销 → `E↵` 当场删 → `CO`
连续放两份）。✅ 全绿，e2e 126 → 128。

**选择语义是 Context 上的一个标记，不是第二套插件**：`StageInteractionContext.selectionMode`
（`'replace'` 默认 / `'accumulate'` 绘图），点选与框选读**同一张表**（`selection-mode.ts`）。
写成两套插件会把「命中一个 Entity 之后该做什么」复制两份，而那条路径里还有双击进文字编辑、
锁定判定、拖动接管、幽灵 ID 过滤四件与选择语义无关的事。分开写还会让「点着累加、框着替换」
这种没人设计过的组合悄悄出现。

**这一刀刻意不下沉**：`cad` 有形状一样的 `applyCadSelection`，但插件这边要的是四行分支，
而那个函数的契约里还有「内容不变时原样返回入参」——那是 `ComposeCadCanvas` 为了按引用判断
重绘加的。步骤 2 搬点输入管线是因为搬的是一整条求解；这里搬的是一个 `if`，够不着门槛。
共享的门槛是**行为会不会漂移**，不是「两处都有」。

**选择集归宿主，会话只是镜像**：CAD 的命令会话自己攒 `picked`（`selection` 输入是并入）。
Stage 不能照抄——选择集在这里已经存在（选中框、属性面板、场景树联动、Esc 清空）。会话攒第二
份，Shift 移出就只改宿主那份，用户看着两个对象被移出而命令仍作用在三个上。因此 Stage 的
`selection` 输入语义是**替换**，宿主在选择集变化时喂进当前完整选择集。这是对 CAD 会话的
有意偏离，理由是两边的选择集所有权不同。

**`MOVE` 与拖动共用的是提交漏斗，不是拖动预览**：`planMovePreview` 里的三样都是拖动特有的
——激活阈值区分「点一下」与「拖一下」（命令没有这个歧义，沿用会让小位移静默失败）、平移吸附
在命令路径上**违规**（基点与位移点已经各自过了点输入管线，再吸一次会改写键入的坐标）、落点
解析会把纯平移变成跨父级重挂载。共用点因此定在 `planTransformCommit`，产出**一条**
`entity.transform.set`，多选移动是一步撤销。

**一处实现中才发现的缺口**：累加语义下点空白**不清空**选择集（那是一次没框住东西的框选），
于是「怎么清空」在绘图模式里没有入口。补成 AutoCAD 的答案——没有命令在跑时 Esc 清空选择集。
提案里没写这一条，是把两套语义的差异只想到了「怎么加」而没想到「怎么减」。

**`createDuplicateCommand` 的 `+10` 让出成可选参数**：那个常量的语义是「复制一份别正好盖住
原件」，而 `COPY` 有真实位移，叠加固定偏移会让每个副本都偏出一个常量——在图上看着像手抖。

### 步骤 3 · 弧、多段线、文字 — 词汇扩展（一到两刀）

`kind` union 扩到 arc/polyline，文字沿用页面既有 Text 物料（页面世界有真字体度量，CAD 包
「等宽字体 + 固定比例」的近似不再需要——这是统一白拿的一笔）。矩形仍是闭合多段线，整圆
仍是 ±360 扫掠弧——两条判断原样平移。窄相位与捕捉逐 kind 扩展，数学从 `cad` 包搬运。

### 步骤 4 · 符号组件：端口与导线 — `add-symbol-components`

端口从块定义搬到 Component Asset（组件局部坐标，一次声明全部实例都有）；导线是曲线 Entity，
端点是 `free | port` 引用，几何**求解不存储**（移动、复制、撤销、导入自动正确的那条论证
原样成立）。端口捕捉排在端点之前——像素级正确但没有绑定的导线在屏幕上不可见。
删除被绑定实体时端点冻结成自由端点。

开放问题（轮到时答）：导线求解读布局快照还是读文档几何——实例在场景里是绝对定位，但求解
时机要与布局求解的帧序对齐。

### 步骤 5 · 组件片段与实例状态 — `add-component-clips`

刀闸的分/合：**命名片段住组件定义，状态住实例**。脚本 API 是状态机语义
（`qs1.setState('open')`）而不是时间轴寻址。这一步同时回答老路线图挂起的「变体切换能不能
表达成轨道」——可能不需要 step 轨道，片段 + 状态就是它要的形状。

开放问题（轮到时答）：旋转基点——刀片绕铰点转，而盒旋转绕盒中心；要么 `Transform` 加基点，
要么片段用几何轨道表达。这是本刀最大的设计风险，提案阶段必须先答。

### 步骤 6 · DXF 入页面、拆除旧世界 — `add-dxf-to-scene`

DXF 导入产出场景 + 组件（BLOCK → Component Asset），按内容包围盒开场景。解析器与诊断
聚合原样复用，映射层重写目标。然后**删除** CadDocument、CAD 标签页、`cad-canvas`；`cad`
包中仍被引用的纯数学下沉或随消费者搬家；AGENTS.md 与 README 的 CAD 段落重写。

## 未定的决策

- **图层的归属**：CAD 图层的 visible/locked 与场景树既有的显隐/锁定重叠，但 DXF 的图层
  语义（byLayer 颜色继承）页面世界没有对应物。候选：图层退化成 Group、或成为标签式的
  命名选择集。定夺推到步骤 6（DXF 映射时必须答）。
- **AutoCAD GROUP（命名选择集）**：一个对象可同时属于多个组，树表达不了。等场景树里的
  实际使用暴露需求再立项。
- **端点夹点编辑与盒 resize 的关系**：盒缩放该不该等比缩放几何点，与夹点手势一起答
  （步骤 2 或 3）。
- **几何关键帧下的编辑语义**：「渲染用采样、命中用原件」在几何会动时产生可感分歧，
  老路线的这条警告仍然成立；步骤 5 的片段若用几何轨道表达旋转，必须先答。

## 关于步骤顺序

1 是一切的地基且风险最集中，必须最先。2 与 3 可以对调（先扩词汇再做模式也通），但先有
模式能让弧/多段线一落地就有真实绘制入口，测试更接近用户路径。4 依赖 3（导线是多段线级
词汇）。5 依赖 4（片段动的是符号内部）。6 收尾拆除，依赖 3（词汇齐了 DXF 才有映射目标），
与 4、5 可并行。
