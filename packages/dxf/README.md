# @compose-ui/dxf

无 React、无 DOM 的 DXF 导入包，只依赖 `@compose-ui/core`。

三层纯函数：**分词**（组码/值成对）→ **记录**（按 `0` 分组）→ **映射**。前两层认识的是 DXF
的文件结构，与产出什么文档毫无关系；换目标时只重写第三层。

页面 Entity 需要 Preset 与 Renderer，而那些住在物料与 Registry 里——一个格式包不该认识它们，
因此 seed 由**调用方注入**。

产出的是**导入计划**而不是文档：一次导入落两类资源（一份 `.page.json` 与若干
`.component.json`），它们分属不同的 Store，而组件实例需要资源引用与 revision——那些要等组件
文件写完才存在。因此计划里不含实例 Entity，宿主写完文件、建好实例之后交给
`assembleDxfDocument`。

**导入能导的，报告导不了的**：整份拒绝不合理——一个 `DIMENSION` 不该让 95% 可用的图导不进来；
静默丢弃同样不行——用户拿结果与原图一对，发现少了东西却没有解释，只会认为工具不可靠。诊断带
稳定机器码并按类型聚合计数。
