## Requirements
### Requirement: CadDocument v1 协议

系统 MUST 提供独立于 ComposeDocument 的 `CadDocument` v1 文档协议。该协议 MUST 复用
`ComposeEntity` 的 ECS 结构，使 Patch 代数、事务运行时、Undo/Redo 与序列化全部共用，
差异只体现在校验器与 Component 词汇上。

文档 MUST 声明 `schemaVersion` 为 1 且单位固定为 `px`，MUST NOT 携带任何画布或图纸尺寸——
CAD 是无限图纸，没有输出边界。

文档 MUST 至少包含一个图层，每个图层 MUST 有文档内唯一的 id。空文档 MUST 带有默认图层。

校验 MUST 返回与 ComposeDocument 校验同形的结果：合法时给出规范化后的文档，非法时给出
带稳定机器码的问题列表。校验器 MUST 可直接注入通用事务运行时。

#### Scenario: 空文档合法且带默认图层

- **WHEN** 创建一份新的空 CAD 文档
- **THEN** 校验通过
- **AND** 文档含有恰好一个图层，没有 Entity

#### Scenario: 缺少图层被拒绝

- **WHEN** 校验一份图层列表为空的文档
- **THEN** 校验失败并给出对应的机器码
- **AND** 图层 id 重复时同样失败

#### Scenario: 结构完整性

- **WHEN** `rootIds` 指向不存在的 Entity，或 `entities` 的 key 与 Entity 自身 id 不一致
- **THEN** 校验失败
- **AND** 未被任何根引用且不是任何 Entity 子级的孤儿同样被拒绝

#### Scenario: 接入通用事务运行时

- **WHEN** 用 CAD 校验器创建事务运行时并派发命令
- **THEN** dispatch、Undo、Redo 与历史导航按既有语义工作
- **AND** 运行时不注册 ComposeDocument 的内建命令

### Requirement: CAD 文件协议与 Store

CAD 文档 MUST 以 `.cad.json` 为文件后缀持久化，并具有独立的媒体类型。系统 MUST 提供绑定
Asset Provider 的 CAD Store，支持列举、读取、新建与带 revision 校验的保存。

Store 在写入前 MUST 校验文档，MUST NOT 把非法内容落盘。列举时单个文件损坏 MUST NOT 阻断
其余文件。

#### Scenario: 新建后可读回

- **WHEN** 通过 Store 新建一份 CAD 文件并随后读取
- **THEN** 读到的文档与写入的一致
- **AND** 返回的 revision 可用于后续保存的乐观并发校验

#### Scenario: 拒绝写入非法文档

- **WHEN** 保存一份校验不通过的文档
- **THEN** 写入被拒绝并抛出说明原因的错误
- **AND** Provider 上的既有文件不被改动

#### Scenario: 损坏文件不阻断列举

- **WHEN** 目录中存在一个无法解析的 `.cad.json`
- **THEN** 列举仍返回其余可用的 CAD 文档
- **AND** 损坏项以问题列表形式单独报告

### Requirement: CAD 直线图元

CAD 文档 MUST 支持由两个点定义的直线图元。图元 MUST 声明所属图层，且该图层 MUST 存在于
文档中；校验 MUST 拒绝指向不存在图层的图元。

图元 MUST NOT 自带颜色：颜色继承所属图层（DXF 的 ByLayer）。显式颜色覆盖不在本能力范围内。

#### Scenario: 直线通过校验并可持久化

- **WHEN** 文档中加入一条两点直线并保存后重新读取
- **THEN** 校验通过且两个端点与图层归属与保存前一致

#### Scenario: 拒绝不存在的图层

- **WHEN** 图元声明的图层 id 不在文档的图层表中
- **THEN** 校验失败并给出对应机器码

#### Scenario: 端点必须是有限数值

- **WHEN** 端点坐标缺失或不是有限数
- **THEN** 校验失败

### Requirement: CAD 直线命令

系统 MUST 提供 `LINE` 命令：先取第一点，随后循环取下一点，每取得一点即产出一条连接前一点的
直线。命令 MUST 支持放弃上一个顶点与结束命令两种流程控制。

一次 `LINE` 执行产生的多条直线 MUST 作为**一个事务**提交，使一次撤销回到命令开始之前，
而不是逐段撤销。

#### Scenario: 两点画出一条直线

- **WHEN** 用户启动 LINE 并依次给出两个点后结束
- **THEN** 文档中新增一条以这两点为端点的直线
- **AND** 一次撤销即回到命令开始之前

#### Scenario: 连续取点产生折线

- **WHEN** 用户给出三个点后结束
- **THEN** 文档中新增两条首尾相接的直线
- **AND** 它们属于同一个事务

#### Scenario: 放弃上一个顶点

- **WHEN** 用户在取得若干点后选择放弃
- **THEN** 最近一个顶点被丢弃，提示回到取上一点的状态
- **AND** 在只有第一点时放弃等同于取消命令

#### Scenario: 取消不写入文档

- **WHEN** 用户在命令进行中取消
- **THEN** 文档不发生任何变化
- **AND** 预览被清除

### Requirement: CAD 点输入管线

系统 MUST 把「用户指定的一个点」的求解建成一条**有序管线**，每一级要么产出精确点、要么把
候选点向某个约束靠拢。管线 MUST 允许在不改动调用方的前提下插入新的一级。

管线 MUST 遵守以下优先级：**显式键入的坐标 > 正交约束 > 网格吸附**。显式键入的坐标 MUST NOT
被任何吸附改写——用户键入 `100,50` 却落在网格点上是一类极难排查的缺陷。

#### Scenario: 键入坐标不被吸附改写

- **WHEN** 网格吸附开启且用户键入一个不落在网格上的绝对坐标
- **THEN** 结果就是键入的坐标
- **AND** 正交开启时同样不改写它

#### Scenario: 指针取点依次经过正交与网格

- **WHEN** 用户用指针取点且正交与网格都开启
- **THEN** 点先被钳到相对上一点的轴向，再按网格步长取整
- **AND** 两者都关闭时结果就是原始点

### Requirement: CAD 坐标语法

系统 MUST 支持三种键入坐标：绝对 `x,y`、相对上一点 `@dx,dy`、极坐标 `距离<角度`。
角度 MUST 以度为单位、逆时针为正；由于屏幕 Y 轴向下，实现 MUST 对 y 分量取负，使
`100<90` 指向屏幕上方。

相对与极坐标 MUST 在没有上一点时被拒绝；非法写法 MUST 被拒绝而不是求出一个近似点。

#### Scenario: 三种写法

- **WHEN** 用户依次键入 `100,50`、`@10,20`、`100<45`
- **THEN** 第一种得到绝对点，第二种相对上一点偏移，第三种按距离与角度求解
- **AND** `100<90` 指向屏幕上方而不是下方

#### Scenario: 缺少上一点时拒绝相对写法

- **WHEN** 命令的第一步键入 `@10,20` 或 `100<45`
- **THEN** 输入被拒绝并给出说明
- **AND** 会话停在原提示

#### Scenario: 非法写法被拒绝

- **WHEN** 键入的文本不是任何一种坐标写法
- **THEN** 解析失败，宿主转而按关键字处理
- **AND** 不产生任何近似点

### Requirement: 正交模式

系统 MUST 提供可切换的正交模式：开启时，相对上一点的取点 MUST 被钳到水平或竖直方向，
取位移绝对值较大的那个轴。没有上一点时正交 MUST 不生效。

#### Scenario: 钳到位移较大的轴

- **WHEN** 正交开启且指针相对上一点的水平位移大于竖直位移
- **THEN** 结果与上一点等高，横坐标取指针位置
- **AND** 竖直位移较大时结果与上一点同列

#### Scenario: 没有上一点时不生效

- **WHEN** 正交开启但命令尚未取得任何点
- **THEN** 结果就是原始点

### Requirement: CAD 对象捕捉

系统 MUST 支持在指定点时捕捉到既有几何的特征点：端口、端点、中点、圆心、象限点、插入点与
交点。捕捉半径 MUST 以**屏幕像素**表达，由宿主换算为世界单位——视图缩小时同样的屏幕半径覆盖
更大的世界范围。

候选 MUST 先按模式优先级排序（端口 > 端点 > 中点 > 圆心 > 象限点 > 插入点 > 交点），同级再按
到目标点的距离。半径内没有候选时 MUST 返回空，而不是给出最近的任意点。

捕捉 MUST 是点求解管线中**优先级最高**的一级：命中时结果就是特征点，MUST NOT 再被正交或
网格改写。

#### Scenario: 端点优先于中点

- **WHEN** 捕捉半径内同时存在某条线的端点与另一条线的中点
- **THEN** 结果是端点
- **AND** 同为端点时取更近的那个

#### Scenario: 捕捉到两条线的交点

- **WHEN** 捕捉半径内存在两条相交直线的交点且没有更高优先级的候选
- **THEN** 结果是该交点
- **AND** 平行或不在线段范围内相交时不产生交点候选

#### Scenario: 半径外不捕捉

- **WHEN** 目标点与任何特征点的距离都超过捕捉半径
- **THEN** 不返回候选
- **AND** 点按原有管线（正交、网格）求解

#### Scenario: 捕捉压过正交与网格

- **WHEN** 捕捉命中且正交与网格都开启
- **THEN** 结果是特征点本身，不被钳到轴向也不被网格取整

#### Scenario: 隐藏图层不参与捕捉

- **WHEN** 某条线所在图层不可见
- **THEN** 它的端点、中点与交点都不作为候选

### Requirement: CAD 捕捉标记

命令等待取点时，系统 MUST 在当前捕捉到的特征点上渲染标记，并按模式区分形状：端口菱形、
端点方框、中点三角、圆心圆圈、象限点棱形框、插入点双方框、交点叉号。没有命中时 MUST 不渲染
任何标记。

对象捕捉 MUST 可切换；关闭时 MUST 不产生候选也不渲染标记。

#### Scenario: 标记随指针移动更新

- **WHEN** 指针在既有直线的端点附近移动
- **THEN** 端点上出现方框标记
- **AND** 指针移开捕捉半径后标记消失

#### Scenario: 关闭对象捕捉

- **WHEN** 用户关闭对象捕捉
- **THEN** 不再出现任何捕捉标记
- **AND** 取点按正交与网格求解

### Requirement: CAD 图元命中

系统 MUST 按**点到几何的距离**判定命中，MUST NOT 按包围盒判定。直线没有盒模型：一条对角线
的包围盒里绝大部分是空的，按矩形判定会让两条交叉线互相遮挡对方的命中区。

容差 MUST 以**屏幕像素**表达，由宿主换算为世界单位。多个图元同时落在容差内时 MUST 取
`rootIds` 中更靠后的那个——后画的在视觉上更靠上。隐藏图层上的图元 MUST NOT 参与命中。

#### Scenario: 命中按距离而不是包围盒

- **WHEN** 目标点落在某条对角线的包围盒内但离线段本身超过容差
- **THEN** 不命中该线
- **AND** 落在另一条穿过同一区域的线的容差内时命中那一条

#### Scenario: 重叠时取后画的

- **WHEN** 两条线都落在容差内
- **THEN** 命中 `rootIds` 中更靠后的那条

#### Scenario: 隐藏图层不参与命中

- **WHEN** 某条线所在图层不可见
- **THEN** 点在它上面也不命中

### Requirement: CAD 框选的窗口与交叉模式

框选 MUST 按拖动方向区分两种判定：**左→右是窗口**，只选完全落在框内的图元；**右→左是交叉**，
选与框相交或完全落在框内的图元。两种模式 MUST 在视觉上可区分（实线框与虚线框）。

拖动方向 MUST 由起点与终点的水平关系决定，MUST NOT 由框的最终归一化坐标决定——归一化之后
方向信息就丢了。隐藏图层上的图元 MUST NOT 被框选。

#### Scenario: 窗口模式只选完全包含的

- **WHEN** 用户从左向右拉出选框，一条线只有一部分落在框内
- **THEN** 该线不被选中
- **AND** 完全落在框内的线被选中

#### Scenario: 交叉模式选相交的

- **WHEN** 用户从右向左拉出选框，一条线穿过框的边界
- **THEN** 该线被选中

#### Scenario: 选框的视觉区分

- **WHEN** 拖动方向为左→右或右→左
- **THEN** 选框分别渲染为实线与虚线

### Requirement: CAD 选择集语义

系统 MUST 维护一个选择集，其语义 MUST 遵循 AutoCAD 而不是页面编辑器：

- 点中图元 MUST **加入**选择集，不需要按下修饰键；
- Shift + 点中图元 MUST 把该图元**移出**选择集；
- 框选结果 MUST 加入选择集；
- 在空白处按下且没有拉出选框 MUST **清空**选择集；
- Escape MUST 在有活动命令时取消命令，否则清空选择集。

被选中的图元 MUST 在图面上有可区分的呈现。

#### Scenario: 点选累积

- **WHEN** 用户依次点中两条线
- **THEN** 两条都在选择集中

#### Scenario: Shift 点选移出

- **WHEN** 用户 Shift 点中一条已在选择集中的线
- **THEN** 该线被移出，其余保持不变

#### Scenario: 单击空白清空

- **WHEN** 用户在空白处按下并原地松开
- **THEN** 选择集被清空
- **AND** 不产生任何文档命令

#### Scenario: Escape 的两级语义

- **WHEN** 有活动命令时按 Escape
- **THEN** 命令被取消，选择集保持不变
- **AND** 没有活动命令时按 Escape 清空选择集

### Requirement: CAD 指针手势仲裁

同一次左键按下在 CAD 中有三种互斥含义，其归属 MUST 由**声明的优先级**决定而不是实现里的
判定顺序：活动命令正等待取点时交给命令（最高），命中图元时更新选择集，空白处按下时开始
框选（最低）。

仲裁 MUST 复用 `@compose-ui/interaction-kernel`，MUST NOT 另写一套。插件 MUST 是纯状态机：
不认识命令会话，只发出效果由宿主执行；点的捕捉、正交与网格求解 MUST 留在宿主，插件只决定
指针归谁。

图面上的指针拥有者 MUST 只有一个：所有按下先经仲裁器判定，仲裁器拒绝后才可以走宿主自己的
兜底（中键平移）。

#### Scenario: 命令取点压过点选

- **WHEN** 活动命令正等待取点，用户在一条既有线上按下
- **THEN** 该点交给命令，选择集不变
- **AND** 没有活动命令时同一次按下选中该线

#### Scenario: 空白处按下开始框选

- **WHEN** 用户在没有图元的位置按下并拖动
- **THEN** 出现跟随指针的选框
- **AND** 松手时按拖动方向的判定模式更新选择集

#### Scenario: 中键平移走兜底路径

- **WHEN** 用户按下中键
- **THEN** 仲裁器不接管，宿主的平移分支生效
- **AND** 框选进行中按下中键不会同时产生平移

### Requirement: CAD ERASE 命令与先选后执行

系统 MUST 提供 `ERASE`（别名 `E`）命令，并 MUST 同时支持两种次序：启动时选择集非空则直接
提交删除，不再提示；选择集为空则提示选择对象，此后的点选与框选结果喂给命令，确认时提交。

删除 MUST 作为**一个** batch 提交：一次 ERASE 删除的多个图元属于同一次操作，逐个撤销会让
用户按 N 次撤销才回到命令之前。提交后选择集 MUST 被清空——被删掉的 id 留在选择集里会指向
不存在的 Entity。

#### Scenario: 先选后执行

- **WHEN** 用户先选中两条线再输入 `E` 并确认
- **THEN** 两条线在一次事务中被删除
- **AND** 一次撤销即可全部恢复

#### Scenario: 先执行后选

- **WHEN** 用户先输入 `E` 并确认，再点选两条线并确认
- **THEN** 两条线在一次事务中被删除

#### Scenario: 没有选中任何对象时取消

- **WHEN** 用户输入 `E` 并确认后直接再次确认
- **THEN** 命令结束且不产生任何文档命令

### Requirement: CAD 块定义表

`CadDocument` MUST 提供与 `entities` 平级的**块表**：每个块定义有稳定 id、面向用户的名字，
以及一份自己的平坦图元集合。块内图元 MUST 以**块局部坐标**表达，其原点即插入基点。

块表 MUST 与 DXF 的 BLOCK 表同构，使 DXF 导入不必再做一次结构翻译。块内图元 MUST NOT 出现
在文档顶层的 `rootIds` 中——它们不是图纸上的对象，只有被插入时才可见。

块 MUST NOT 嵌套：块内图元携带 `CadInsert` 时 MUST 判为非法并给出可定位的错误。嵌套在示意图
里极少用，显式拒绝好过让后来者以为它碰巧能用。

文档没有块表字段时 MUST 按空块表读入，`schemaVersion` MUST NOT 因此改变。

#### Scenario: 块内图元不出现在图纸顶层

- **WHEN** 文档含一个块定义
- **THEN** 块内图元不在 `rootIds` 中，也不被直接渲染
- **AND** 顶层的可达性判定不把块内图元算作孤儿

#### Scenario: 拒绝嵌套块

- **WHEN** 某个块定义内部的图元带有 `CadInsert`
- **THEN** 文档校验失败，错误路径指向该图元

#### Scenario: 旧文档按空块表读入

- **WHEN** 读入一份没有块表字段的 `.cad.json`
- **THEN** 得到一份块表为空的合法文档

### Requirement: CAD 块实例

系统 MUST 提供 `CadInsert` Component 表达一次块插入：引用的块 id、插入点、旋转角与
**两轴比例**。比例 MUST 分轴给出而不是单个数——接线图需要镜像符号，负比例是常规用法。

引用不存在的块 id MUST 判为非法。

实例几何 MUST 由块定义**求解**而不是复制：块局部坐标依次经比例、旋转、平移得到世界坐标。
修改块定义 MUST 使其全部实例随之改变——这正是块存在的理由。

#### Scenario: 实例按插入参数变换块几何

- **WHEN** 一个块被以某个插入点、旋转角与比例插入
- **THEN** 实例在图纸上的几何是块局部几何依次经比例、旋转、平移的结果

#### Scenario: 负比例镜像符号

- **WHEN** 插入比例的某一轴为负
- **THEN** 实例几何沿该轴镜像

#### Scenario: 改块定义，全部实例跟着变

- **WHEN** 同一个块被插入多次，随后块定义中的几何被修改
- **THEN** 全部实例的呈现同步改变，无需逐个更新实例

#### Scenario: 悬空块引用被拒绝

- **WHEN** 某个 `CadInsert` 引用的块 id 不在块表中
- **THEN** 文档校验失败，错误路径指向该实例

### Requirement: 块实例参与命中、框选与捕捉

命中、框选与对象捕捉 MUST 看见块实例**展开后**的世界几何，MUST NOT 把实例当作不可分的图片。
插入一个符号之后必须能从它的接线端点起笔画线，否则块只是一张贴图。

命中与框选的结果 MUST 是**实例本身**而不是块内图元：块内图元不是图纸上的独立对象，选中它们
会让「删除」等操作失去明确目标。

#### Scenario: 捕捉到块实例的端点

- **WHEN** 指针移动到某个块实例内一条线段的端点附近
- **THEN** 出现端点捕捉标记，取点落在该端点的精确世界坐标上

#### Scenario: 点选块实例得到实例

- **WHEN** 用户点中块实例内某条线段
- **THEN** 选中的是该实例，不是块内的那条线段

#### Scenario: 框选按展开几何判定

- **WHEN** 选框以窗口模式完整框住某个实例展开后的全部几何
- **THEN** 该实例被选中
- **AND** 只框住其中一部分时，窗口模式不选中它而交叉模式选中

### Requirement: CAD BLOCK 与 INSERT 命令

系统 MUST 提供 `BLOCK`（别名 `B`）把当前选择集变成一个块定义，并把被选图元原地替换为该块的
一个实例。基点 MUST 可指定；被选图元 MUST 按基点换算为块局部坐标。整个操作 MUST 是一个事务。

系统 MUST 提供 `INSERT`（别名 `I`）按块名插入实例，插入点 MUST 走既有的点求解管线（对象捕捉
优先于正交与网格）。

`BLOCK` 在选择集为空时 MUST 提示选择对象，与 `ERASE` 的两条次序一致。

#### Scenario: 先选后执行建块

- **WHEN** 用户选中两条线后执行 `BLOCK` 并给出名字与基点
- **THEN** 一个事务内产生块定义，两条线被一个实例取代
- **AND** 一次撤销即回到建块之前

#### Scenario: 插入点捕捉到既有几何

- **WHEN** 执行 `INSERT` 且插入点落在既有线段端点的捕捉半径内
- **THEN** 实例的插入点是该端点的精确坐标，不被网格取整

#### Scenario: 未知块名被拒绝

- **WHEN** `INSERT` 收到的名字不在块表中
- **THEN** 命令给出提示且不产生任何文档写入，会话不结束

### Requirement: CAD 指针反馈

画布 MUST 在指针移动时把「这一下按下会发生什么」显示出来，而不是只在按下之后才给出结果。
用户 MUST 能在按下之前看出落点位置与生效的约束。

命令正等待取点且已有参照点时，画布 MUST 渲染一条从参照点到当前指针解算点的橡皮筋，并与已经
放置的预览段在视觉上可区分。橡皮筋的终点 MUST 由与真实按下**同一条**点求解管线给出，因此
正交、网格吸附与对象捕捉 MUST 在按下之前就体现在橡皮筋上。

画布 MUST 高亮**这一下按下会选中**的图元。命令正在消费点输入时按下不产生选择，此时
MUST NOT 高亮任何图元。高亮的命中判据 MUST 与选择使用同一个容差。

画布 MUST 显示指针的世界坐标；指针离开图面时 MUST 隐藏读数。

#### Scenario: 橡皮筋跟随指针

- **WHEN** 用户启动 LINE 并取得第一点后移动指针
- **THEN** 图面出现一条从该点到指针解算点的橡皮筋
- **AND** 它与已放置的预览段可区分

#### Scenario: 约束在按下之前可见

- **WHEN** 正交开启且用户在取得第一点后斜向移动指针
- **THEN** 橡皮筋是水平或垂直的，与按下后得到的落点一致

#### Scenario: 命令结束后橡皮筋消失

- **WHEN** 用户结束或取消命令
- **THEN** 橡皮筋不再渲染

#### Scenario: 悬停高亮指示可选中

- **WHEN** 没有命令在消费点输入，用户把指针移到容差内的图元上
- **THEN** 该图元高亮
- **AND** 指针移开后高亮消失

#### Scenario: 命令取点时不高亮

- **WHEN** 命令正等待取点，用户把指针移到图元上
- **THEN** 不出现高亮

#### Scenario: 坐标读数

- **WHEN** 用户在图面上移动指针
- **THEN** 命令行显示该位置的世界坐标
- **AND** 指针离开图面后读数隐藏

### Requirement: CAD 指示点

画布 MUST 把「当前被指示的点」建成一个具名的会话状态，MUST NOT 把它当作指针事件的渲染——
吸附的含义正是解算落点与指针裸坐标不同。十字光标、橡皮筋终点、坐标读数与捕捉标记 MUST 全部
消费同一个指示点，MUST NOT 各自重新解算。

指示点 MUST 存储指针的**屏幕位置**并在读取时解算为世界落点。存世界坐标会在不以光标为锚点的
视口变化后失效，使指示与真实光标分离。

指示点 MUST NOT 由任何指针手势会话拥有：框选、平移与命令取点是互斥手势，而指示 MUST 在三者
进行期间都继续更新。

#### Scenario: 四个指示器读同一个点

- **WHEN** 对象捕捉命中一个特征点
- **THEN** 十字光标、橡皮筋终点与坐标读数落在同一位置

#### Scenario: 手势期间指示继续更新

- **WHEN** 用户正在拖拽框选
- **THEN** 指示点仍随指针更新

#### Scenario: 平移中世界落点不变

- **WHEN** 用户按住中键平移视图
- **THEN** 光标下的世界落点保持不变

### Requirement: CAD 十字光标

画布 MUST 在图面上隐藏系统指针并绘制十字光标，且 MUST 按**当前等待的输入类型**切换形态，
使用户不必读命令行就能看出这一下按下会发生什么。

形态 MUST 遵守以下对应关系：没有活动命令时同时绘制十字线与拾取框；命令等待取点时只绘制
十字线；命令等待选择对象时只绘制拾取框。命令等待的既不是点也不是选择时 MUST NOT 绘制十字
光标，并交还系统指针。

拾取框的半边长 MUST 等于点选命中容差，且 MUST 随缩放保持屏幕尺寸不变——命中判据本身是屏幕
概念，框与容差可以分头变化就会出现「框压住了却点不中」。

同时绘制十字线与拾取框时，十字线 MUST 在拾取框处断开，框内 MUST NOT 有线穿过：框覆盖的正是
用户要看清的靶区，线穿过去等于用光标盖住自己正对准的东西。

拾取框 MUST NOT 表达「当前是否命中图元」。它在空闲时恒常显示，说明的是靶区位置；命中与否
由图元自身的悬停高亮回答——高亮更靠近视线焦点，且能回答「命中的是哪一条」这个拾取框答不了
的问题。

十字光标 MUST 钉在与橡皮筋终点、坐标读数相同的解算后落点上。十字线长度 MUST 可按视口百分比
配置。指针离开图面时 MUST NOT 残留光标。

画布 MUST 只对 mouse 与 pen 指针绘制十字光标并隐藏系统光标；touch 指针 MUST NOT 绘制，也
MUST NOT 隐藏系统光标。

宿主 MUST 能关闭十字光标。隐藏系统光标会一并丢掉操作系统的光标辅助设置（放大光标、高对比
光标），而这一需求无法被探测，因此必须留一个出口。关闭时 MUST NOT 隐藏系统光标。

#### Scenario: 空闲时十字线与拾取框同时出现

- **WHEN** 没有活动命令，指针在图面上
- **THEN** 图面同时绘制十字线与拾取框
- **AND** 系统指针不可见

#### Scenario: 取点时只有十字线

- **WHEN** 命令正等待取点
- **THEN** 只绘制十字线，拾取框消失

#### Scenario: 选择对象时只有拾取框

- **WHEN** 命令正等待选择对象
- **THEN** 只绘制拾取框，十字线消失

#### Scenario: 十字线在拾取框处断开

- **WHEN** 同时绘制十字线与拾取框
- **THEN** 拾取框内部没有十字线穿过

#### Scenario: 拾取框不随命中改变

- **WHEN** 指针从空处移到图元上
- **THEN** 拾取框外观不变
- **AND** 该图元出现悬停高亮

#### Scenario: 拾取框大小等于命中容差

- **WHEN** 在任意缩放下把拾取框边缘压在图元上并按下
- **THEN** 该图元被选中
- **AND** 拾取框的屏幕尺寸不随缩放改变

#### Scenario: 触摸指针不绘制十字光标

- **WHEN** 用户用触摸在图面上操作
- **THEN** 不绘制十字光标
- **AND** 系统光标不被隐藏

#### Scenario: 宿主关闭十字光标

- **WHEN** 宿主关闭十字光标
- **THEN** 图面不绘制十字光标
- **AND** 系统光标可见

#### Scenario: 指针离开图面

- **WHEN** 指针移出图面
- **THEN** 十字光标不再绘制且不残留最后位置

### Requirement: CAD 画布网格与标尺

CAD 画布 MUST 与页面画布共用同一个视口模型、同一个点阵求解与同一套设备像素取整规则，使同一
世界坐标在两个画布上落到相同像素。网格 MUST 绘制主线与细线两级。

网格投影间距不足以逐条显示时，画布 MUST 抽稀为原网格的子集，MUST NOT 整片隐藏网格——缩小
正是画总图时最常用的区间，此时失去网格等于失去全部空间参照。

CAD 画布 MUST 提供上边与左侧标尺以及原点角。标尺 MUST 显示跟随**指示点**的游标标记，并在
存在选择集时显示其包围盒在该轴上的区间与尺寸。宿主 MUST 能关闭标尺。

网格设置 MUST 是会话级视图状态，MUST NOT 写入 `CadDocument`——CAD 是无限图纸，不带任何画布
设置。

#### Scenario: 缩小后网格抽稀而不是消失

- **WHEN** 用户把视图缩小到网格投影间距不足以逐条显示
- **THEN** 画布仍显示网格，只是隐藏了部分格线
- **AND** 图元仍然吸附到原始配置的步长

#### Scenario: 刻度与网格线落在同一位置

- **WHEN** 在任意缩放与设备像素比下渲染
- **THEN** 同一世界坐标的标尺刻度线与画布网格线覆盖同一条 1 CSS px 带

#### Scenario: 标尺游标跟随指示点

- **WHEN** 指针在图面上移动
- **THEN** 两条标尺各显示一个对应当前指示点的游标标记
- **AND** 指针离开图面后游标消失

#### Scenario: 网格设置不进文档

- **WHEN** 用户改变网格显示或步长后保存
- **THEN** `.cad.json` 的内容不因此改变

### Requirement: CAD 几何位移

系统 MUST 提供移动与复制既有几何的能力。位移 MUST 按 Entity 的 Component 分派：直线的两个
端点各加位移，块实例只改插入点——**块定义 MUST NOT 因移动实例而改变**，否则移动一个实例会把
所有实例一起搬走。

一次移动 MUST 作为**一个事务**提交，使一次撤销回到操作之前，而不是逐个图元撤销。

位移的落点 MUST 走与取点相同的求解管线，因此对象捕捉、正交与网格吸附 MUST 同样生效。

#### Scenario: 移动多个图元

- **WHEN** 用户选中若干图元并执行移动，给出基点与第二点
- **THEN** 所有选中图元按同一位移平移
- **AND** 一次撤销即回到移动之前

#### Scenario: 移动块实例不改块定义

- **WHEN** 用户移动一个块实例
- **THEN** 只有该实例的插入点改变
- **AND** 同一个块的其他实例不动

#### Scenario: 位移接受吸附

- **WHEN** 对象捕捉命中一个特征点时提交第二点
- **THEN** 位移按捕捉到的特征点求得，而不是指针裸坐标

### Requirement: CAD COPY 连续放置

`COPY` 命令 MUST 在放下一个副本之后继续等待下一个落点，直到用户显式结束。每个副本 MUST 在
放下时即成为一次独立的文档变更。

连续放置不是打磨：把同一个符号摆一排是高频动作，每放一个都要重敲一次命令会让用户放弃使用它。

#### Scenario: 连续放置多个副本

- **WHEN** 用户执行复制并依次给出多个落点
- **THEN** 每个落点各产生一个副本
- **AND** 命令在用户结束之前保持活动

### Requirement: CAD 拖动移动

用户 MUST 能通过拖动**已选中**的图元来移动它。拖动 MUST 与移动命令派发相同的命令，使两条
路径的撤销回到同一个状态——它是第二个入口，MUST NOT 成为第二份事实来源。

按下点命中的图元**不在**选择集中时 MUST NOT 开始拖动移动，而是照常执行选择；否则第一次点击
会变成一次零位移的移动，用户再也选不中东西。命令正在消费点输入时 MUST NOT 开始拖动移动。

#### Scenario: 拖动已选中的图元

- **WHEN** 用户按下并拖动一个已在选择集中的图元
- **THEN** 选择集中的图元按拖动位移移动
- **AND** 一次撤销回到拖动之前

#### Scenario: 拖动未选中的图元只是选中它

- **WHEN** 用户按下一个不在选择集中的图元
- **THEN** 该图元被选中，文档不发生变化

#### Scenario: 命令取点期间不触发拖动

- **WHEN** 命令正等待取点，用户按下一个已选中的图元
- **THEN** 该次按下成为命令的一个点，不产生移动

### Requirement: CAD 块端口

块定义 MUST 能声明一组端口，每个端口 MUST 有块内唯一且稳定的 id，位置 MUST 以**块局部坐标**
表达。端口 MUST 跟随实例变换，与块内几何走同一条比例 → 旋转 → 平移。

端口 MUST 是块**定义**的一部分而不是实例的：同一个块的全部实例 MUST 拥有同一组端口 id。

旧文档没有端口字段时 MUST 读作空列表，`schemaVersion` MUST NOT 因此改变。

端口 id 在块内重复时 MUST 校验失败并给出稳定机器码。

#### Scenario: 端口跟随实例变换

- **WHEN** 一个块声明了局部坐标下的端口，并以某个位置、旋转与比例插入
- **THEN** 该端口的世界坐标等于局部坐标经比例、旋转、平移后的结果
- **AND** 同一个块的另一个实例按自己的插入参数解出自己的端口位置

#### Scenario: 旧文档按空端口读入

- **WHEN** 读入一份块定义不含端口字段的既有文档
- **THEN** 校验通过，该块的端口为空列表

#### Scenario: 端口 id 重复被拒绝

- **WHEN** 校验一份块内存在两个相同端口 id 的文档
- **THEN** 校验失败并给出对应的机器码

### Requirement: CAD 导线

系统 MUST 提供 `CadWire` 图元，其两个端点各自 MUST 是**自由点**（世界坐标）或**端口引用**
（`{ entityId, portId }`）。

导线的世界几何 MUST 由端点求解而不是存储：端口端点的坐标 MUST 在读取时由被引用实例当刻的
插入参数解出。因此移动、复制、撤销或任何其他改变实例位置的路径 MUST NOT 需要额外的重解步骤。

导线 MUST 参与既有的可见性遍历，因此 MUST 同样可被命中、框选、捕捉与渲染。

平移一条导线时 MUST 只移动它的自由端点；端口端点 MUST 保持绑定。两端都绑定的导线因此
MUST NOT 因平移而改变。

#### Scenario: 移动符号，导线跟着走

- **WHEN** 一条导线的一端绑定到某个块实例的端口，用户移动该实例
- **THEN** 导线的该端点跟随到新的端口位置
- **AND** 文档中导线自身未被写入任何坐标

#### Scenario: 平移只动自由端点

- **WHEN** 用户平移一条一端绑定、一端自由的导线
- **THEN** 自由端点按位移移动，绑定端点仍在端口上
- **AND** 两端都绑定的导线平移后几何不变

#### Scenario: 导线参与命中与捕捉

- **WHEN** 指针落在一条导线上
- **THEN** 该导线可被点选命中
- **AND** 它的端点与中点同样是捕捉候选

### Requirement: CAD 导线端点引用完整性

文档校验 MUST 拒绝不完整的导线端点引用，并对每种情形给出可区分的稳定机器码：引用的 Entity
不存在、引用的 Entity 不是块实例、该实例的块未声明这个端口 id。

这条 MUST 由**校验器**承担而不是由某条命令承担：改变实例所引用块定义的路径不止一条（命令、
外部写入、导入），命令级检查只能挡住写过检查的那一条。

块定义内部 MUST NOT 包含导线，并在校验时给出稳定机器码——块内容是块局部且自包含的，而导线
端点引用顶层 Entity id。

#### Scenario: 悬空端点被拒绝

- **WHEN** 校验一份导线端点引用了不存在 Entity 的文档
- **THEN** 校验失败并给出对应的机器码
- **AND** 引用的 Entity 不是块实例时给出另一个机器码

#### Scenario: 切换块定义丢失端口被拒绝

- **WHEN** 把一个被导线绑定的实例改为引用另一份未声明该端口 id 的块定义
- **THEN** 校验失败并给出端口未知的机器码

#### Scenario: 块内导线被拒绝

- **WHEN** 校验一份块定义内含有导线图元的文档
- **THEN** 校验失败并给出对应的机器码

### Requirement: CAD WIRE 命令

系统 MUST 提供 `WIRE`（别名 `W`）命令，依次取两个点画出一条导线。落在端口上的点 MUST 绑定
该端口，落在别处的点 MUST 成为自由端点。

绑定 MUST 在命令 handler 中依据当刻文档完成，而不是由命令会话完成——会话是不认识文档的纯
状态机，且 handler 必须是纯函数，使撤销后重做产出同一批绑定。

两个端点解析到同一个端口，或两点重合时，MUST 拒绝而不是写入一条退化的导线。

#### Scenario: 两端绑定端口

- **WHEN** 用户执行 `WIRE` 并依次点在两个不同实例的端口上
- **THEN** 新导线的两个端点分别绑定到对应的 `{ entityId, portId }`
- **AND** 一次撤销即回到画线之前

#### Scenario: 空处取点成为自由端点

- **WHEN** 第二点落在任何端口之外
- **THEN** 该端点是自由点，坐标为求解后的落点

#### Scenario: 退化导线被拒绝

- **WHEN** 两个点解析到同一个端口
- **THEN** 命令被拒绝，文档不发生变化

### Requirement: CAD PORT 命令

系统 MUST 提供 `PORT`（别名 `PO`）命令，为一个块**定义**增加端口：选定一个块实例，指定一个
世界坐标点，该点 MUST 被换算为块局部坐标后写入块定义。

换算 MUST 在 handler 中完成——它需要读取实例的插入参数。实例任一轴比例为 0 时变换不可逆，
MUST 拒绝并给出可定位的错误。

选定目标不是块实例时 MUST 拒绝。

#### Scenario: 加端口对全部实例生效

- **WHEN** 用户在某个块实例上指定一点执行 `PORT`
- **THEN** 该块定义获得一个新端口
- **AND** 同一个块的其他实例在各自变换下同样解出这个端口

#### Scenario: 比例为零的实例被拒绝

- **WHEN** 目标实例某一轴的比例为 0
- **THEN** 命令被拒绝，块定义不变

### Requirement: CAD 端口捕捉

端口 MUST 是一种捕捉模式，且 MUST 排在端点之前——端口通常正好画在符号线段的端点上，端点若
在同等距离下胜出，用户会得到一条**看起来正确但没有绑定**的导线，而这个错误在屏幕上不可见。

端口捕捉标记 MUST 与其他模式形状不同（菱形），沿用「用形状而不是颜色区分」的既有约定。

系统 MUST 在图面上渲染每个实例的端口位置，使用户在开始画线之前就能看到可以连到哪里。

#### Scenario: 端口压过端点

- **WHEN** 捕捉半径内同时存在一个端口与一条线的端点
- **THEN** 结果是端口，即使端点更近

#### Scenario: 隐藏图层上的实例不产生端口候选

- **WHEN** 某个块实例所在图层不可见
- **THEN** 它的端口既不渲染也不作为捕捉候选

### Requirement: CAD 删除绑定目标时冻结导线端点

删除一个被导线端点引用的 Entity 时，系统 MUST 把这些端点冻结为**删除前最后解算位置**上的
自由端点，MUST NOT 连带删除导线，也 MUST NOT 留下悬空引用。

用户没有选中的东西不应消失，而文档必须保持合法；冻结后图面上导线原地不动、末端悬空，一次
撤销完全恢复。

#### Scenario: 删除设备，导线留在原处

- **WHEN** 用户删除一个有导线绑定的块实例
- **THEN** 导线仍然存在，被绑定的端点变成自由点且位置不变
- **AND** 一次撤销同时恢复实例与绑定

#### Scenario: 同批删除导线自身

- **WHEN** 用户同时选中一个实例与绑在它上面的导线并删除
- **THEN** 两者都被删除，不产生冻结后的残留

### Requirement: CAD 拖动预览与提交同源

拖动移动的预览 MUST 由对预览文档施加与提交**完全相同**的平移后重跑可见性遍历得到，
MUST NOT 通过对已渲染线段施加屏幕位移得到。

理由是导线：拖动一台设备时它的导线并未被选中，屏幕位移的预览里不动，而提交后会动。同样，
两端绑定的导线平移是 no-op，屏幕位移的预览会让它跟着走然后在松手时弹回。

#### Scenario: 预览里导线跟着设备走

- **WHEN** 用户拖动一个有导线绑定的块实例
- **THEN** 拖动过程中导线的绑定端点跟随设备
- **AND** 松手后的结果与拖动过程中所见一致

### Requirement: CAD 圆弧图元

系统 MUST 提供 `CadArc` 图元，由圆心、半径、起始角与**扫掠角**定义。整圆 MUST 表达为
`sweep` 为 ±360 的圆弧，系统 MUST NOT 为整圆另立一种图元——命中、框选、捕捉、平移、块变换与
校验因此各只有一份实现。

角度 MUST 以度为单位，正值 MUST 表示屏幕上的顺时针，与块插入的旋转及极坐标输入取同一约定。

协议 MUST 用带符号的扫掠角而不是终止角：单给终止角分不出 10° 的短弧与 350° 的长弧，而这个
歧义只在特定角度组合下现形。

半径为非正数、任一字段不是有限数值时 MUST 校验失败并给出稳定机器码。

`schemaVersion` MUST NOT 因本图元而改变：既有文档不含该 Component，一律仍然合法。

#### Scenario: 整圆是扫掠 360 的弧

- **WHEN** 创建一个 `sweep` 为 360 的圆弧
- **THEN** 它是一个完整的圆
- **AND** 命中、捕捉与平移走的是与部分弧完全相同的代码路径

#### Scenario: 非法几何被拒绝

- **WHEN** 校验一份圆弧半径为 0 或为负、或角度不是有限数值的文档
- **THEN** 校验失败并给出对应的机器码

### Requirement: CAD 可见几何遍历

命中、框选、对象捕捉与渲染 MUST 共用同一条可见性遍历，其返回值 MUST 是**几何联合**
（线段、圆弧或文字），MUST NOT 把圆弧在遍历中拍扁成线段。

拍扁会迫使渲染二选一：跟着画出可见的多边形，或绕开这条遍历单独画圆而与命中分叉——后者正是
「看得见却点不中」。拍扁还会让**圆心与象限点不存在**，而它们不是任何线段的特征点。

#### Scenario: 四个消费者看到同一份几何

- **WHEN** 图纸上存在一个圆弧
- **THEN** 命中、框选、捕捉与渲染都从同一条遍历取得该圆弧本身
- **AND** 遍历结果中它不是若干线段

### Requirement: CAD 圆弧的命中与框选

圆弧的命中 MUST 用点到圆弧距离的闭式解：目标点的角度落在扫掠范围内时取 `|到圆心距离 − 半径|`，
落在范围外时取到两个端点距离的较小者。

窗口框选 MUST 用圆弧的**紧包围盒**判定，MUST NOT 用整圆的包围盒——一段 90° 的弧，整圆盒是四倍
面积，明明框住了的弧会被判成没框住。紧包围盒 MUST 判断四个轴向极值角是否落在扫掠内。

交叉框选 MAY 按弦高误差拍扁后判定：框选本身是像素级粗粒度的手势，而精确的弧–矩形求交开销与
收益不相称。

#### Scenario: 命中按到弧的距离

- **WHEN** 目标点落在圆弧的包围盒内但离弧线本身超过容差（例如圆心附近）
- **THEN** 不命中该弧

#### Scenario: 扫掠范围外按端点距离

- **WHEN** 目标点的角度不在扫掠范围内
- **THEN** 距离按到两个端点的较小者计算

#### Scenario: 窗口框选用紧包围盒

- **WHEN** 选框恰好框住一段 90° 的弧，但没有框住它所在整圆的包围盒
- **THEN** 窗口模式下该弧被选中

### Requirement: CAD 圆心与象限点捕捉

系统 MUST 支持捕捉圆弧的圆心与象限点（0°、90°、180°、270° 四个方向上的点）。象限点 MUST 只在
落于扫掠范围内时成为候选。圆弧的端点与中点（半扫掠处）MUST 同样是候选。

优先级 MUST 为 `端口 > 端点 > 中点 > 圆心 > 象限点 > 交点`，与 AutoCAD 的惯例一致。

捕捉标记 MUST 按模式区分形状，圆心与象限点各有自己的形状。

#### Scenario: 圆心可捕捉

- **WHEN** 指针移到圆弧圆心的捕捉半径内
- **THEN** 出现圆心捕捉标记，取点落在精确圆心上

#### Scenario: 扫掠外的象限点不是候选

- **WHEN** 某个轴向方位不在圆弧的扫掠范围内
- **THEN** 该方向上不产生象限点候选

#### Scenario: 端点压过圆心

- **WHEN** 捕捉半径内同时存在弧的端点与圆心
- **THEN** 结果是端点

### Requirement: CAD 块内圆弧的缩放

块实例展开时，圆弧 MUST 按实例比例是否**等比**分流：等比（含负值镜像）MUST 仍然产出精确圆弧，
非等比 MUST 拍扁成线段。

镜像 MUST 同时翻转起始角与扫掠方向，否则镜像后的符号轮廓看着对而弧的走向是反的。

系统 MUST NOT 在非等比时按某一轴的比例硬算成圆——那会画出一个用户从未画过的形状，且没有任何
提示。

#### Scenario: 等比缩放仍是精确弧

- **WHEN** 一个含圆弧的块以等比缩放插入
- **THEN** 展开结果仍是圆弧，半径按该比例缩放
- **AND** 圆心与象限点仍可捕捉

#### Scenario: 镜像翻转弧的走向

- **WHEN** 一个含圆弧的块以负比例镜像插入
- **THEN** 弧鼓起的方向随之镜像

#### Scenario: 非等比缩放降级为线段

- **WHEN** 一个含圆弧的块以两轴不等的比例插入
- **THEN** 展开结果是线段而不是圆弧
- **AND** 图面上的形状仍与椭圆一致

### Requirement: CAD CIRCLE 与 ARC 命令

系统 MUST 提供 `CIRCLE`（别名 `C`）命令：先取圆心，再取一点定半径。

系统 MUST 提供 `ARC`（别名 `A`）命令：按起点、弧上一点、终点**三点定弧**，与 AutoCAD 的默认
次序一致。三点共线时 MUST 拒绝并停在原提示继续等待，MUST NOT 结束命令——沿一条既有直线连点
三下在实际操作里很常见。

弧鼓起的方向 MUST 由中间那点落在起点→终点的哪一侧决定。

两条命令的取点 MUST 走既有点求解管线，因此对象捕捉、正交与网格吸附同样生效。

#### Scenario: 两点画圆

- **WHEN** 用户执行 `CIRCLE`，取圆心后再取一点
- **THEN** 得到一个以两点距离为半径的整圆
- **AND** 一次撤销回到画圆之前

#### Scenario: 三点画弧

- **WHEN** 用户执行 `ARC` 并依次给出三个不共线的点
- **THEN** 得到一段经过这三点的圆弧
- **AND** 中间点落在另一侧时弧向另一侧鼓起

#### Scenario: 共线三点被拒绝且命令继续

- **WHEN** 第三点与前两点共线
- **THEN** 命令给出拒绝提示且仍在等待第三点
- **AND** 文档不发生变化

### Requirement: CAD 文字图元

系统 MUST 提供 `CadText` 图元，由插入点、内容、字高、旋转与水平对齐定义。插入点 MUST 是
**基线上的对齐锚点**，与 DXF 的 TEXT 同构。

`height` MUST 表示**字号（em 尺寸）**而不是大写字高：大写字高与字号的比例随字体而变，写进
协议等于把同一个字体相关的猜测钉进渲染与命中两处，然后看它们各自漂移。DXF 导入时做一次
显式换算。

内容为空、字高非正、旋转不是有限数值、对齐不是受支持的取值时，MUST 校验失败并给出稳定
机器码。空文字 MUST NOT 被接受——它在屏幕上不存在却仍参与命中与捕捉，成为一个点不中也
删不掉的幽灵。

`schemaVersion` MUST NOT 因本图元而改变：既有文档不含该 Component，一律仍然合法。

#### Scenario: 文字按对齐锚点定位

- **WHEN** 同一个插入点上分别以左、中、右对齐放置同一段文字
- **THEN** 三者的包围盒相对插入点分别向右、居中、向左展开

#### Scenario: 空文字与非正字高被拒绝

- **WHEN** 校验一份内容为空字符串或字高为 0 的文档
- **THEN** 校验失败并给出对应的机器码

### Requirement: CAD 可见几何是一把伞

可见性遍历的返回类型 MUST 是 `CadGeometry`（曲线或文字），而曲线类型 `CadCurve`
MUST 继续只表示线段与圆弧。

系统 MUST NOT 把文字并进 `CadCurve`：线段与圆弧共享端点、中点、到点距离与拍扁一整套运算，
而文字与它们没有任何共同运算。把文字塞进去会让「曲线」退化成「凡是画得出来的东西」的别名。

#### Scenario: 遍历同时给出曲线与文字

- **WHEN** 图纸上同时存在直线、圆弧与文字
- **THEN** 同一条遍历返回三者，且文字带有可区分的类别标记

### Requirement: CAD 文字按包围盒命中

文字的命中判据 MUST 是**点是否落在它的文字框内**：框内距离为 0，框外取到框边的距离。

这 MUST NOT 被理解为对「按距离而不是包围盒」的破例。那条规则的理由是「一条对角线的包围盒
里绝大部分是空的」，而文字**占满**自己的盒子——盒子就是用户看见的那块墨。

文字框 MUST 随旋转一起旋转；框选的窗口与交叉判定 MUST 使用旋转后的四角。

#### Scenario: 点在文字上即选中

- **WHEN** 用户点在文字笔画之间的空隙上
- **THEN** 该文字被选中

#### Scenario: 框随旋转一起转

- **WHEN** 一段文字带有非零旋转
- **THEN** 命中判定使用旋转后的框，而不是未旋转的框

#### Scenario: 窗口框选要求整块文字在框内

- **WHEN** 选框只盖住文字的一部分
- **THEN** 窗口模式不选中它，交叉模式选中它

### Requirement: CAD 文字命中框与字形对齐

图面 MUST 用等宽字体渲染文字，包内 MUST 用文档化的「前进宽度 / 字号」比例计算命中框宽度，
垂直方向同样由文档化的上/下伸比例给出。

字体栈与这几个比例 MUST 被当作一对不变量维护：换掉字体而不换比例，命中框会从字形上漂开，
而这种偏差在短标签上看不出来，要等到有人写一串长文字才暴露。

#### Scenario: 长文字的命中框覆盖整串

- **WHEN** 一段较长的文字被放置在图纸上
- **THEN** 点在这串文字末尾字符处仍然命中它

### Requirement: CAD 插入点捕捉

系统 MUST 支持捕捉插入点，覆盖**文字的对齐锚点与块实例的插入点**——两者都回答「这个对象是
从哪个点放下去的」，AutoCAD 的 `INS` 同样同时管这两个。

优先级 MUST 排在象限点之后、交点之前。

#### Scenario: 捕捉到文字锚点

- **WHEN** 指针移到某段文字插入点的捕捉半径内且没有更高优先级的候选
- **THEN** 出现插入点捕捉标记，取点落在精确锚点上

#### Scenario: 捕捉到块实例插入点

- **WHEN** 指针移到某个块实例插入点附近
- **THEN** 该点是插入点候选

### Requirement: CAD TEXT 命令

系统 MUST 提供 `TEXT`（别名 `T`）命令，依次提示插入点、字高与内容。

字高一步 MUST 同时接受三种输入：直接回车采用默认值、键入数字、或在图上指一点并取它到插入点
的距离。默认值 MUST 在一次命令会话内记住。

内容为空时 MUST 拒绝且不写入文档。

#### Scenario: 三步写出一段文字

- **WHEN** 用户执行 `TEXT`，给出插入点、回车接受默认字高、键入内容
- **THEN** 文字出现在该插入点上
- **AND** 一次撤销回到写字之前

#### Scenario: 指点取字高

- **WHEN** 用户在字高一步在图上指一点
- **THEN** 字高等于该点到插入点的距离

#### Scenario: 空内容被拒绝

- **WHEN** 用户在内容一步直接回车
- **THEN** 命令拒绝，文档不发生变化

### Requirement: CAD 多段线图元

系统 MUST 提供 `CadPolyline` 图元，由一串顶点与一个 `closed` 标志定义。矩形 MUST 表达为四个
顶点的闭合多段线，系统 MUST NOT 另立矩形图元——命中、框选、捕捉、平移、块变换与校验因此各
只有一份实现。

闭合 MUST 由布尔标志表示，MUST NOT 靠「首尾顶点重复」表达：重复表示法里 `[A,B,C,A]` 是闭合
三角形还是回到起点的开放折线无法区分，而两者在框选与捕捉上给出不同的候选。

顶点少于两个、任一坐标不是有限数值，或全部顶点重合（包围盒跨度为零）时 MUST 校验失败并给出
稳定机器码。全部顶点重合的多段线在屏幕上不存在却仍参与命中与捕捉，是一个点不中也删不掉的
幽灵。

`schemaVersion` MUST NOT 因本图元而改变：既有文档不含该 Component，一律仍然合法。

#### Scenario: 闭合多段线比开放的多一段

- **WHEN** 同一串顶点分别以开放与闭合表达
- **THEN** 闭合的比开放的多出一段（末点回到首点）

#### Scenario: 退化的多段线被拒绝

- **WHEN** 校验一份只有一个顶点、或全部顶点重合的多段线文档
- **THEN** 校验失败并给出对应的机器码

### Requirement: CAD 多段线在遍历中展开为线段

可见性遍历 MUST 把多段线展开成它的各条线段，且全部线段 MUST 共用同一个 `ownerId`。

这 MUST NOT 与「不把圆弧拍扁」相混淆。判据是**展开会不会丢东西**：圆弧拍扁后形状变成可见的
多边形、圆心与象限点消失；而多段线本来就是一串线段，顶点仍是各段端点、各段仍有中点，形状
逐像素相同——展开是恒等变换而不是近似。

因此命中、框选、对象捕捉与渲染 MUST 不为多段线新增任何分支：按 owner 聚合的框选判定已经
适用，窗口模式要求**每一段**都在框内，正是「整个矩形被框住」所需的语义。

#### Scenario: 多段线是一个对象

- **WHEN** 用户点中一条多段线的任意一段
- **THEN** 选中的是整条多段线，而不是其中一段

#### Scenario: 窗口框选要求整条在框内

- **WHEN** 选框只盖住矩形的一部分
- **THEN** 窗口模式不选中它，交叉模式选中它

#### Scenario: 顶点与各段中点都可捕捉

- **WHEN** 指针移到多段线某个顶点或某段中点附近
- **THEN** 分别出现端点与中点捕捉标记

### Requirement: CAD PLINE 与 RECTANG 命令

系统 MUST 提供 `PLINE`（别名 `PL`）命令：与 `LINE` 同样的连点手感，但整条折线 MUST 产出
**一个** Entity。命令 MUST 支持闭合、放弃上一点与结束三个关键字。

系统 MUST 提供 `RECTANG`（别名 `REC`）命令：取两个对角点，产出四顶点的闭合多段线。两点重合
或退化成一条线时 MUST 拒绝。

`LINE` MUST 保持产出互相独立的直线：画临时辅助线时要的恰恰是互不相干的线段，两条命令在
AutoCAD 里同样并存。

两条命令的取点 MUST 走既有点求解管线，因此对象捕捉、正交与网格吸附同样生效。

#### Scenario: 一条多段线是一个 Entity

- **WHEN** 用户执行 `PLINE` 连点四次后结束
- **THEN** 文档里新增**一个** Entity
- **AND** 一次撤销回到画之前

#### Scenario: 闭合关键字接回首点

- **WHEN** 用户在 `PLINE` 进行中键入闭合关键字
- **THEN** 多段线闭合并提交

#### Scenario: 只放了一个点就结束

- **WHEN** 用户在 `PLINE` 只取了一个点就结束命令
- **THEN** 不写入任何 Entity

#### Scenario: 两点画矩形

- **WHEN** 用户执行 `RECTANG` 并给出两个对角点
- **THEN** 得到一个四顶点的闭合多段线
- **AND** 两个对角点重合或共线时命令被拒绝

### Requirement: DXF 导入器

系统 MUST 提供无 React、无 DOM 的 `importDxfDocument(text)`，把一段 ASCII DXF 映射为
`CadDocument` 与一份诊断清单。它 MUST 是纯函数：喂字符串、断言结果，不依赖交互内核与资源
系统。

MUST 支持的实体：`LINE`、`CIRCLE`、`ARC`、`LWPOLYLINE`、`TEXT`、`INSERT`；MUST 支持 `LAYER`
表与 `BLOCKS` 段。

解析 MUST 保留同一条记录内**重复出现的组码**，MUST NOT 把记录收成「组码 → 单值」的映射——
`LWPOLYLINE` 的顶点正是重复出现的 `10`/`20`，收成映射会只剩最后一个顶点。

产出的文档 MUST 通过既有的 CAD 文档校验。

#### Scenario: 基本实体各自映射到对应图元

- **WHEN** 导入含 `LINE`、`CIRCLE`、`ARC`、`LWPOLYLINE`、`TEXT` 的 DXF
- **THEN** 得到对应的直线、整圆、圆弧、多段线与文字图元
- **AND** 文档通过校验

#### Scenario: 长折线的顶点不被折叠

- **WHEN** 导入一条含五个顶点的 `LWPOLYLINE`
- **THEN** 多段线有五个顶点，而不是一个

#### Scenario: 闭合标志被读出

- **WHEN** `LWPOLYLINE` 的 `70` 组码带闭合位
- **THEN** 多段线是闭合的

### Requirement: DXF 导入的坐标翻转

DXF 的 Y 轴朝上而屏幕的 Y 轴朝下，导入 MUST 翻转 Y。翻转 MUST 同时取反**角度**：圆弧的起始
角与扫掠、文字旋转、块实例旋转。块实例的**比例 MUST 保持不变**。

这三条 MUST 一起成立：它们是同一个矩阵恒等式的三个推论（`F R(θ) F = R(−θ)`、`F S F = S`）。
只翻位置不翻角度的症状是「图看起来像镜像的」，很容易被误当成源文件本身的问题。

#### Scenario: 位置翻转

- **WHEN** 导入一条 DXF 坐标为 `(10, 20)` 到 `(30, 40)` 的直线
- **THEN** 结果的端点是 `(10, -20)` 与 `(30, -40)`

#### Scenario: 不对称圆弧的角度取反

- **WHEN** 导入一段起角 30°、终角 100° 的 DXF 圆弧
- **THEN** 结果的起始角是 −30°，扫掠是 −70°
- **AND** 弧上的采样点与「先按 DXF 求点再翻转 Y」的结果一致

#### Scenario: 块实例的旋转取反而比例不变

- **WHEN** 导入一个旋转 30°、x/y 比例为 2 与 3 的 `INSERT`
- **THEN** 实例旋转为 −30°，比例仍是 2 与 3

### Requirement: DXF 导入诊断

导入 MUST 返回诊断清单，说明哪些内容没有被完整表达。每条诊断 MUST 带**稳定机器码**，同类
问题 MUST 按类型聚合计数而不是逐条报告。

系统 MUST NOT 静默丢弃不支持的内容——用户拿导入结果与原图一对，发现少了东西却没有解释，
只会认为工具不可靠。系统同样 MUST NOT 因为存在不支持的实体而拒绝整份文件：一个
`DIMENSION` 不该让 95% 可用的图导不进来。

带 `bulge` 的多段线段 MUST 按**弦**导入并给出诊断，MUST NOT 静默变成直线。

#### Scenario: 不支持的实体被跳过并报告

- **WHEN** 导入含三个 `SPLINE` 与一个 `HATCH` 的 DXF
- **THEN** 这些实体不进文档
- **AND** 诊断里有一条 `SPLINE` 计数为 3、一条 `HATCH` 计数为 1

#### Scenario: bulge 按弦导入并报告

- **WHEN** `LWPOLYLINE` 的某个顶点带非零 `bulge`
- **THEN** 该段按弦导入
- **AND** 诊断里有对应机器码

### Requirement: DXF 图层与块的映射

图层 MUST 以 DXF 的图层名作为 id。图层 `0` MUST 始终存在，文件未提供时补一个。实体引用了
表里没有的图层时 MUST 落回 `0` 并给出诊断，MUST NOT 拒绝整份文件。

`BLOCK` MUST 映射为块定义，块内几何 MUST 以**基点**为原点换算为块局部坐标。名字以 `*` 开头
的布局块 MUST 跳过。块内出现 `INSERT` 时 MUST 跳过该实体并给出诊断——本仓拒绝嵌套块，硬导会
让整份文档不合法。

#### Scenario: 块与实例成对导入

- **WHEN** 导入一份含 `BLOCK` 定义与引用它的 `INSERT` 的 DXF
- **THEN** 得到块定义与块实例
- **AND** 块内几何按基点换算为块局部坐标

#### Scenario: 未知图层落回 0

- **WHEN** 某个实体引用了 `LAYER` 表里没有的图层名
- **THEN** 它落在图层 `0` 上并产生一条诊断

#### Scenario: 布局块与嵌套块

- **WHEN** DXF 含 `*Model_Space` 块，或某个块内含 `INSERT`
- **THEN** 前者被跳过，后者跳过该实体并产生诊断

### Requirement: CAD 画布打开时按内容取景

CAD 画布首次量到真实图面尺寸后，若文档含可见几何，MUST 把视口取到该几何的包围盒上。文档为
空时 MUST NOT 改动视口。

真实图纸的坐标动辄几千、几十万，按默认视口打开会是一片空白，而用户会认为导入失败了。

取景 MUST 是**会话状态**而不是文档状态，且宿主 MUST 能关闭它。

#### Scenario: 打开有内容的图纸即可见

- **WHEN** 打开一份几何远离原点的 CAD 文档
- **THEN** 图面上看得见这些几何

#### Scenario: 空文档不改动视口

- **WHEN** 打开一份空的 CAD 文档
- **THEN** 视口保持默认，新建流程的手感不变

### Requirement: CAD 图元外观覆盖

系统 MUST 提供可选的 `CadStroke` Component，含 `color`、`width` 与 `dashPattern` 三个**各自
可选**的字段。缺省 MUST 表示回退：颜色回退到所属图层，线宽回退到默认值，线型回退到实线。

清除某一项 MUST 表现为**删掉那个键**，MUST NOT 写入哨兵值——否则「显式设成无」与「跟随图层」
会变成两个都要处理的状态。三项全被清除时整个 Component MUST 一并删除。

系统 MUST 提供唯一的解析入口，返回已经落实的颜色、线宽与虚线；渲染 MUST 只消费解析结果。

`schemaVersion` MUST NOT 因此改变，且不含 `CadStroke` 的既有文档的解析结果 MUST 与引入本能力
之前逐字相同。

#### Scenario: 缺省逐项回退

- **WHEN** 一个图元只覆盖了颜色
- **THEN** 它按覆盖的颜色画，线宽与线型仍取默认
- **AND** 修改所属图层的颜色不再影响它

#### Scenario: 既有文档表现不变

- **WHEN** 解析一个不含 `CadStroke` 的图元
- **THEN** 颜色等于图层颜色，线宽等于默认值，线型为实线

#### Scenario: 非法外观被拒绝

- **WHEN** 校验一份线宽非正、颜色不是字符串或虚线段含非正数的文档
- **THEN** 校验失败并给出稳定机器码

### Requirement: CAD 线宽与虚线的单位

线宽 MUST 以**屏幕像素**表达，MUST NOT 随缩放变化——它是显示宽度，与 AutoCAD 的 lineweight
一致；放大图纸时一根粗线会变成色带，而用户放大恰恰是为了看清结构。

虚线间隔 MUST 以**世界单位**表达，MUST 随缩放变化——它是图上的实际长度，与 AutoCAD 的
linetype 一致；写成屏幕像素会让虚线密度在任何缩放下都一样，那条线因此不再携带长度信息。

#### Scenario: 缩放时线宽不变而虚线变密

- **WHEN** 视图放大一倍
- **THEN** 线宽的屏幕像素数不变
- **AND** 虚线段的屏幕长度随之加倍

### Requirement: CAD 块实例的外观由实例决定

块内图元自身的 `CadStroke` MUST NOT 参与解析，整个实例 MUST 按实例自己的外观呈现。

这沿用图层的既有判断：让块内图元各自决定外观，同一个块在不同插入处会呈现不同，那就不是块。

#### Scenario: 实例的外观覆盖整个符号

- **WHEN** 给一个块实例设置颜色
- **THEN** 该实例展开出的全部几何都按这个颜色画
- **AND** 同一个块的其他实例不受影响

### Requirement: CAD COLOR、LWEIGHT 与 LTYPE 命令

系统 MUST 提供 `COLOR`（别名 `COL`）、`LWEIGHT`（别名 `LW`）与 `LTYPE`（别名 `LT`）三条命令，
流程一致：取选择集（启动时已有选择则直接使用），再收一个值。

三条 MUST 接受 `BYLAYER`（大小写不敏感）表示清除该项覆盖；`LTYPE` MUST 额外接受
`CONTINUOUS`。颜色 MUST 接受十六进制与九个标准色名，线宽 MUST 是正数，线型 MUST 是一串正数。

值解析失败时 MUST 拒绝且**不结束命令**——打错一个值就要重新选一遍对象，在 CAD 里是不可接受
的手感。

一次修改 MUST 作为一个事务提交，使一次撤销回到修改之前。

#### Scenario: 先选后执行改颜色

- **WHEN** 用户选中若干图元并执行 `COLOR`，键入一个颜色
- **THEN** 这些图元按该颜色画
- **AND** 一次撤销回到修改之前

#### Scenario: BYLAYER 清除覆盖

- **WHEN** 用户对已有颜色覆盖的图元执行 `COLOR` 并键入 `BYLAYER`
- **THEN** 该图元回到图层颜色
- **AND** 三项都被清除后文档里不再留下空的外观 Component

#### Scenario: 值不合法时命令继续

- **WHEN** 用户在 `LWEIGHT` 键入 0 或一个非数字
- **THEN** 命令拒绝并停在原提示
- **AND** 换一个合法值仍能完成
