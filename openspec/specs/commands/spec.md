## Requirements
### Requirement: 无 React 无 DOM 的命令与键位包

`@compose-ui/commands` MUST 是无 React、无 DOM 的独立包，MUST NOT 依赖 `core`、任何 UI
Context 或任何领域包——动作只是 `run(ctx)`，本包 MUST NOT 认识任何文档协议。

本包 MUST 同时承载键位的类型、归一化、序列化、事件匹配与平台格式化五项能力。这五项属于
同一件事，分散在不同包时任何一个包都无法独立完成「一次按键命中了哪个动作」或「两个动作
是否撞键」的判定。

事件匹配 MUST 接受结构化的事件形状而非 DOM 事件类型；平台格式化 MUST 把平台作为必填参数
接收，MUST NOT 在包内读取 `navigator`。

#### Scenario: 包边界

- **WHEN** 检查 `@compose-ui/commands` 的依赖与源码
- **THEN** 不存在对 React、DOM 全局或任何 `@compose-ui/*` 包的依赖
- **AND** 该约束由依赖边界测试守住

#### Scenario: 五项能力同处一包

- **WHEN** 一个消费者要判定某次按键命中了哪个动作
- **THEN** 归一化、匹配与动作查表都来自本包，无需再依赖第二个包
- **AND** 检测两个动作是否撞键同样只依赖本包

#### Scenario: 格式化不读取平台全局

- **WHEN** 在没有 `navigator` 的环境中格式化键位
- **THEN** 调用方传入平台字符串即可得到确定结果
- **AND** 包内不出现对 `navigator` 的读取

### Requirement: 单一权威的键位定义

`ComposeKeybinding` MUST 只在 `@compose-ui/commands` 中定义一次。其他包对外暴露的键位类型
MUST 是该定义的别名或转导，MUST NOT 各自重新声明结构相同的类型。

归一化 MUST 拒绝空 code，MUST 拒绝同时要求 `primary` 与显式 `control`，并 MUST 剔除取值为
假的修饰键字段，使序列化结果可用于相等判定。

#### Scenario: 别名而非重复定义

- **WHEN** 检查 `components`、`stage` 与 `editor` 暴露的键位类型
- **THEN** 三者都解析到同一个定义
- **AND** 既有的公共类型名称与消费者代码保持不变

#### Scenario: 归一化拒绝非法组合

- **WHEN** 归一化一个同时要求平台主修饰键与显式 Control 的键位
- **THEN** 抛出配置错误
- **AND** 空 code 同样被拒绝

### Requirement: 动作到键位的共享映射

动作 id 到键位列表的映射 MUST 由本包提供泛型容器与操作，使不同的动作 id 集合共用同一套
归一化、去重、冲突检测与命中解析。

同一份默认键位 MUST NOT 在两个包中各写一遍。当一个包的动作集合是另一个包的超集时，
超集一方 MUST 由子集一方的表展开得到，只补充自己独有的条目。

#### Scenario: 默认键位不重复维护

- **WHEN** 修改一个同时属于 Stage 与 Editor 的动作的默认键位
- **THEN** 只需改一处
- **AND** 两个包读到的默认值必然一致，而不依赖人工同步

#### Scenario: 冲突检测

- **WHEN** 在同一作用域内为两个动作配置了相同键位
- **THEN** 冲突检测报告出另一个动作
- **AND** 判定基于归一化后的序列化结果，修饰键书写顺序不影响判定

### Requirement: 多步提示命令会话

系统 MUST 提供由**键盘启动**、按提示逐步取得输入的命令会话协议。会话 MUST 由命令定义创建，
而不是由指针事件触发——命令驱动的编辑范式里，交互从输入命令名开始，取点是命令进行中的一步。

每一步 MUST 声明它接受哪些输入种类（点、文本、关键字），并可携带关键字选项与默认值。会话
推进 MUST 返回四态之一：给出下一步提示、提交一个效果、被取消、或拒绝本次输入并停在原提示。

拒绝 MUST NOT 结束会话：非法输入在 CAD 里是常态（点错、打错关键字），结束命令会让用户重来。

效果类型 MUST 对消费者泛型；本包 MUST NOT 认识任何文档协议。

#### Scenario: 命令由文本启动并按别名解析

- **WHEN** 用户输入命令别名并确认
- **THEN** 对应命令的会话被创建并给出第一步提示
- **AND** 别名匹配不区分大小写，未知输入不创建会话

#### Scenario: 多步取点直到提交

- **WHEN** 会话依次收到满足各步要求的输入
- **THEN** 每一步返回下一步的提示
- **AND** 命令完成时返回一个待提交的效果

#### Scenario: 关键字改变后续流程

- **WHEN** 某一步提供了关键字选项而用户输入其中一个
- **THEN** 会话按该关键字的语义推进
- **AND** 未列出的关键字被拒绝且会话停在原提示

#### Scenario: 非法输入不结束会话

- **WHEN** 某一步收到它不接受的输入种类
- **THEN** 会话返回拒绝并附带说明
- **AND** 下一次输入仍按原提示判定

#### Scenario: 取消结束整条命令

- **WHEN** 会话在任意一步收到取消
- **THEN** 会话结束且不提交任何效果
- **AND** 已经收集的中间输入被丢弃

### Requirement: 命令消费选择集

命令会话 MUST 能把**一批对象标识**作为一步输入接收，使「先选后执行」与「先执行后选」共用
同一条状态机。标识对本包 MUST 是不透明字符串——本包不认识任何文档协议，也 MUST NOT 解释
标识的含义。

命令启动上下文 MUST 能携带启动当刻已有的选择，使命令在已有选择时直接进入下一步而不再提示。

#### Scenario: 启动时已有选择则不再提示

- **WHEN** 命令在启动上下文中收到非空选择
- **THEN** 会话跳过选择步骤
- **AND** 直接给出后续提示或提交效果

#### Scenario: 启动时没有选择则提示选择

- **WHEN** 命令在启动上下文中收到空选择
- **THEN** 第一步提示接受选择输入
- **AND** 收到选择输入后累积，确认时按累积结果提交

#### Scenario: 不接受选择的步骤拒绝选择输入

- **WHEN** 当前提示不接受选择输入而会话收到一次选择
- **THEN** 会话返回拒绝并停在原提示
