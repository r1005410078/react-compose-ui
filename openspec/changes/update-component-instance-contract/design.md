## 上下文

`add-instance-structural-overrides` 让实例内部可投影、可选中、可结构编辑之后，暴露属性、强制 Group
根与固定 Hug 几何这三条早期约束都失去了原有理由，并各自制造出可见的使用问题。本变更收敛契约，
不引入新的覆盖机制。

## 目标/非目标

- 目标：删除暴露属性、放宽组件根、实例暴露根容器属性、组件源保存后有条件自动同步。
- 非目标：Detach、跨 Provider Variant、稳定参数契约的替代方案、ComposeDocument v7、放宽八层上限。

## 决策

### 删除暴露属性

暴露属性按 property ID 锚定，直接字段覆盖按内部实体 ID + 字段路径锚定，前者能在组件重构后存活，
后者不能。删除是有代价的：组件作者失去“声明一组不随重构失效的参数”的能力。

仍然删除，因为当前实现只是个半成品表单，收益不足以抵消两套并行覆盖机制的复杂度：解析要维护四段
顺序、冲突判定要分两类、Apply 要分别处理。需要稳定参数契约时应以单独提案重新设计，而不是保留
这个形态。

删除后解析顺序从四段收敛为两段：Base → Variant 链 → 实例结构操作。旧文件的每条暴露属性覆盖由
显式纯迁移转换为指向同一 target 的 `set-field` 操作，渲染输出逐字节不变。

### 组件根放宽为任意单根

`applyComposeComponentOverrides` 与 Parser 当前硬性要求单个 first-class Group 根。放宽为“单根”，
根可以是 Group、Container 或任意 Entity。

单根约束保留：diff 与操作应用都依赖“父子两份文档共享同一根 ID”，多根会让锚点失去参照。根仍然
不可删除、不可 reparent。

提取器规则变为：选区是单个未锁定顶层节点时直接复用它作为组件根；多选或需要归零坐标时才创建
Group 包装。这样单选容器不再产生 `Container > Container`。

### 实例几何跟随组件根

实例不再固定 Hug 且 `resize: 'none'`。实例的 `LayoutItem` 与 `GeometryConstraints` 从组件根的
对应 Component 派生，Resize 与外观、裁剪、Auto Layout 的编辑写入实例覆盖的结构操作，作用目标是
组件根本身。

这与“根不可删除、不可 reparent”不冲突：那两条限制的是结构位置，不是字段值。

### 有条件自动同步

组件源保存成功后，Store 通知依赖实例。实例先按既有冲突检测逐条试应用自身覆盖：

- 全部兼容：直接以一次事务刷新 lineage 与 resolvedSnapshot，不打断用户。
- 存在失效覆盖：不自动提交，实例进入 `pending-update` 并保留旧快照，由用户确认丢弃后再提交。

自动路径与手动路径共用同一套冲突判定和同一次事务写入，避免出现两条行为不同的更新通路。跨会话的
外部 revision 变化同样走这条逻辑，因为判定依据是覆盖是否失效，与变更来源无关。

## 风险/权衡

- 失去稳定参数契约：换取单一覆盖机制与更低的作者门槛；需要时以单独提案重新设计。
- 放宽根类型扩大了组件文档的形态空间：单根、根不可删/移的不变量保留，diff 与 Applier 的前提不变。
- 自动同步会在用户无操作时改变文档：仅限无冲突路径，且与手动路径共用同一次事务，Undo 可回退。
- 实例可 Resize 后与组件源尺寸产生分歧：分歧本身就是实例覆盖，Revert 即可回到源尺寸。

## 迁移计划

ComposeDocument 保持 v6。Component Asset 仍是 `schemaVersion: 1`：含 `properties` 的 Base 与含
`properties` 分区的实例覆盖只经显式纯迁移读取，Parser 不静默接受。既有以 Group 为根的组件文件
无需改动，放宽后的根约束向后兼容。
