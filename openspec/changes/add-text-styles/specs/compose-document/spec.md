## ADDED Requirements

### Requirement: 可选文字样式表

`ComposeDocument` MUST 支持一个可选的 `styles` 字段：一张 id 到文字样式的表，每条样式有稳定 id、用户可读名称与一组排版属性值。**缺席即没有样式**，因此既有文档逐字节不变，本字段 MUST NOT 需要迁移，协议版本 MUST NOT 变。

Entity MUST 支持一个可选的 `Style` Component 承载「这个 Entity 跟随哪条样式」。缺席即不跟随任何样式。它 MUST 是 Entity 的能力而不是某个 Renderer 的字段——与 `Interaction`、`Ports`、`Wire` 同一条判断，将来加别的样式种类时 Renderer 协议一个字节不改。

指向不存在的样式 MUST NOT 让文档非法：它只是解析失败，该 Entity MUST 保留作者写下的值。「还没配」「配错了」「配的东西没了」三者必须可区分，而做成非法会让删掉一条样式就阻断保存。

#### Scenario: 没有样式的文档一个字节不变

- **WHEN** 一份既有文档不含 `styles` 与任何 `Style` Component
- **THEN** 它保持合法，渲染结果逐像素不变

#### Scenario: 悬空引用只是解析失败

- **WHEN** 一个 Entity 的 `Style` 指向已被删除的样式 id
- **THEN** 文档仍然合法
- **AND** 该 Entity 按作者写下的值渲染

### Requirement: 样式值垫底，作者写下的值覆盖

文字样式的解析 MUST 是「样式的值垫底、Entity 上作者写下的 props 覆盖」。因此**跟随样式的字段在文档里缺席**，而文档里出现那个字段就表示它被这一处覆盖了。

「应用样式」MUST 在写入引用的同一个事务里**删掉该样式管辖的那几个 props**，MUST NOT 只写引用：不删的话样式加上去什么都不会变，而屏幕上没有任何东西解释为什么。

「脱离样式」MUST 把解析出来的值写成作者值并删掉引用，呈现 MUST 逐像素不变。

#### Scenario: 应用样式当场生效

- **WHEN** 用户把一条文字样式应用到一条已经手填过字号的文字
- **THEN** 该文字按样式的字号渲染
- **AND** 它的 `Renderer.props` 里不再有被样式管辖的那几个字段

#### Scenario: 局部覆盖仍然可能

- **WHEN** 一条跟随样式的文字被单独改了字号
- **THEN** 只有这一条用新字号，其余跟随者不变

#### Scenario: 改样式，跟随者一起变

- **WHEN** 用户改动一条样式的字号
- **THEN** 所有跟随它且未覆盖该字段的文字一起变

#### Scenario: 脱离样式不改变呈现

- **WHEN** 用户让一条文字脱离样式
- **THEN** 它的 `Renderer.props` 得到脱离前解析出来的值
- **AND** 画面逐像素不变

### Requirement: 样式操作的作用对象是选区，单选是它的退化情形

应用、脱离、重命名与删除 MUST 按**一组** Entity 规划，单选 MUST 是这一组恰好一个成员的退化情形——与时间线的关键帧选区是同一条判断。多选下这四件事 MUST 逐字成立。

「提取为样式」与「把这一条写回样式」MUST 只在恰好选中一条时提供：两者都要从**这一条**的当前值取排版，而多选没有「这一条」。少掉的入口 MUST 说明理由，MUST NOT 静默消失。

选区里各自跟着不同样式时，MUST 与「整批都不跟随」**分别呈现**：后者是一条能派发的命令（脱离），把混合也画成那个空选项会让用户读成「这一批已经都不跟随了」。

删除一条样式 MUST NOT 追着去解除跟随者的引用——那会把一次删除变成一次波及全文档的写入，而撤销还得把它们一条条放回去。跟随者因此回到 Renderer 的默认排版，这是一次**看得见**的外观改动，删除前 MUST 把跟随者数量说出来。

#### Scenario: 多选批量应用是一个事务

- **WHEN** 用户选中多条文字并挑一条样式
- **THEN** 全部目标在**一条** batch 命令里被应用
- **AND** 撤销一步全部回去

#### Scenario: 混合与「不跟随」可区分

- **WHEN** 选中的多条文字各自跟着不同的样式
- **THEN** 样式选择器呈现「多种样式」而不是空值
- **AND** 「不跟随」仍是一个可选中的项，选中它即整批脱离

#### Scenario: 删除前说出跟随者数量

- **WHEN** 用户删除一条正被若干对象跟随的样式
- **THEN** 确认框写出跟随者的数量与「它们会回到默认排版」
- **AND** 确认之后只有样式表那一条被删除，跟随者的引用变成悬空
