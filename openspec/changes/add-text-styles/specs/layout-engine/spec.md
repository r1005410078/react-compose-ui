## ADDED Requirements

### Requirement: 样式解析住在布局 Runtime

文字样式的解析 MUST 由布局 Runtime 在拿到新文档时跑一遍纯函数完成，并与快照**成对**产出已解算文档，使下游的 Stage 渲染、Preview 渲染、文字测量与 Inspector **一行不改**。各路径自己解析一遍 MUST NOT 发生——那正是仓库为导线几何明令禁止的逐条路径回写，而漏掉任何一条的症状是「这处文字没跟着样式变」。

样式解析 MUST 排在布局求解**之前**，MUST NOT 排在其中：它不依赖几何（导线与填充依赖），而文字测量要用到排版值，排在其中会造出一个循环。

解析 MUST 是纯函数：同一份文档解析多少次都是同一个答案，且 MUST NOT 修改输入文档。

#### Scenario: 下游不需要认识样式

- **WHEN** 文档里有文字样式且有 Entity 跟随它
- **THEN** Runtime 交出的已解算文档里，那些 Entity 的排版 props 已经是解析后的值
- **AND** 渲染与测量按既有路径读到它们，不需要额外的样式入参

#### Scenario: 测量用的是解析后的排版值

- **WHEN** 一条 Hug 文字跟随一条指定了更大字号的样式
- **THEN** 它的测量尺寸按样式的字号得出
