# 设计：几何编辑模式

## 1. 复用既有的可编辑路径机制，不造第二套

`StageEditablePath` 那条链是为运动路径写的，但它一开始就没有动画语义：顶点 id 对引擎是不透明
字符串，几何是世界坐标，手势结果原样回传。复用它，这一刀白拿四样已经写好并且已经有用例守着的
东西：

| 已经有的 | 这一刀因此不用做 |
| --- | --- |
| `path` 插件优先级 1400 > 点选 700 | 「顶点必须是热的、且优先级显式排在点选之上」 |
| 三阶段（move/end/cancel）加并发中止、目标切换中止 | 拖拽的生命周期 |
| 覆盖层排在变换手柄**之上** | 顶点与角点重合时拖不动的那个坑 |
| 切线手柄命中优先于顶点 | 曲线没有切线，这一条自动退化 |

派生曲线顶点的那个函数与 `curveFeaturePoints` 挨着放，**共用同一个 `projectComposeCurveToBox`
投影**，但**不合并**：特征点是**捕捉目标**（含象限点与各段中点，多段线的中点也在里面），夹点是
**可拖的把手**。合并的症状是象限点变成能拖的东西，而弧的象限点根本不是自由度。

## 2. 会话住在 Stage，与文字编辑同构

```
双击曲线 → 插件发 geometry-editing.enter → Stage 记下 { entityId }
Escape / 点空白 / 换工具 / 选中别的对象 → geometry-editing.exit
```

逐条对着文字编辑抄：插件里多一个分支（`context.isGeometryEditable?.(id)`），效果多两个成员，
Stage 多一个 Hook 状态，变换手柄多一条抑制。**判定由宿主注入**而不是引擎自己读 `Curve`——引擎
不认识文档协议，这与 `isTextEditable` 是同一条边界。

一次双击只能进一个：文字可编辑的目标进文字编辑，否则才看几何。两者不会同时成立（曲线不是文字）。

## 3. 谁写文档：宿主传入的那条不写，Stage 自己那条写

规范今天写着「Stage MUST NOT 因为路径编辑派发任何编辑命令，路径几何的事实来源始终在宿主」。
这条**对运动路径成立**，理由是它的事实是关键帧——一个顶点对应一个关键帧的时间与值，Stage
不认识那套协议。

曲线几何不一样：**它就是文档本身**。Stage 已经为 resize、move、绘制派发命令，顶点拖动没有任何
理由绕道宿主再绕回来，绕一圈只会让编辑器去实现一份它不该知道的曲线数学。

因此规范收窄成「宿主传入的路径由宿主负责」，而不是「一切顶点都由宿主负责」。**这两句话今天读
起来一样，明天就不一样了**——留着原话，下一个人会以为几何编辑违反了规范。

## 4. 弧的四个夹点各干什么

弧是「圆心 + 半径 + 起始角 + 带符号扫掠角」。四个夹点各自只动一个自由度，**另一端一动不动**是
判据：

| 夹点 | 改什么 | 不动的是 |
| --- | --- | --- |
| 圆心 | 平移整条弧 | 半径与两个角 |
| 起点 | `startAngle`，同时调 `sweep` 让终止角不变 | 半径、终点 |
| 终点 | `sweep` | 半径、圆心、起点 |
| 中点 | 半径 | 圆心与两个角 |

「起点动而终点跟着跑」是最容易写出来也最难用的版本：用户拖的是这一端，另一端凭什么动。

`sweep` 的符号保持不变，差角归一化到同号的 `(0, 360]`；**恰好归一化到 0 时取 360**——用户把终点
拖回起点，看得见的结果是整圆，而空弧什么都画不出来。

**整圆（`|sweep|` 为 360）只出圆心与中点。**起点与终点落在同一个像素上，两个含义不同的夹点叠在
一起，用户拖到哪个全凭渲染顺序；而对整圆来说「改起始角」在屏幕上根本看不见。

## 5. 落点解算与写入

拖动的世界坐标先过**绘图命令那条同一个 resolver**（特征点捕捉 > 正交 > 网格，键入坐标不适用），
再经实体矩阵的逆换算进盒局部，改掉被拖的那一个夹点，最后加上 `LayoutItem.offset` 得到 parent
局部几何交给 `entity.curve.set`。

- **解算复用而不是重写**：分叉的症状是「画线时吸端点、拖顶点时不吸」，而用户无法判断哪个是对的。
- **拖到盒外不钳制**：`entity.curve.set` 会按新几何的紧包围盒重新归一化盒与几何，这正是它作为
  唯一漏斗的价值。移动阶段只更新本地预览，松手才写一条事务——撤销一步回到原几何。
- **已知限制**：旋转过的曲线上拖顶点，盒重新归一化会让盒原点移动，而旋转基点缺席时是盒中心，
  因此图形会绕新中心重新摆一次。这是盒模型固有的，不在这一刀里解决，写进路线图。

## 6. 画完即进几何编辑

`draw-text` 画完直接进文字编辑，这条规则今天就在。曲线绘制手势结束后进几何编辑是**同一条规则的
第二个实例**，不是新规则。

**命令产出的对象不自动进。**`LINE` 逐段落地、`PLINE` 结束时提交，而命令自己还握着光标与提示；
两个「正在取点」的东西叠在一起，`Escape` 的含义会变得说不清——退命令还是退几何编辑。命令跑完
之后用户双击一下就进去了，代价是一次双击。

## 7. 至多一条路径，宿主传入的优先

运动路径只在动画模式且选中单个 Entity 时出现，几何编辑由双击进入，两者能同时成立。覆盖层
渲染两条路径会画出两套顶点，而它们指向不同的事实。

规则取最保守的那个：**宿主传入的优先**，此时不进几何编辑。理由是运动路径是宿主明确要求画的，
Stage 不该把它顶掉；反过来 Stage 自己进入的会话，用户可以退出。
