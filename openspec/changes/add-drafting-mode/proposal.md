# 绘图模式：Stage 的第三种编辑模式

## Why

统一路线第二刀。上一刀证明了「曲线是普通页面 Entity」——它进场景树、有属性面板、能打
关键帧。但**画一条线的方式还是「点一下 Palette，得到一条默认斜线」**，那不是实施工程师
画单线图的方式。

这一刀补上手感：进入绘图模式，工具栏换成绘图工具、底部出命令行、光标变十字线，敲 `L↵`
点两下画出一条线，第二条线的起点**捕捉**到第一条的端点。切回设计模式，画出来的线仍然是
普通 Entity——**画的方式特殊，画出来的东西不特殊**，这正是 Figma Design/Draw 的模型。

读代码之后结论比路线图乐观：**命令引擎一行都不用搬**。`@compose-ui/commands` 本来就对
`TContext` / `TEffect` 泛型，连 `core` 都不依赖；命令注册、别名解析、四态推进
（`prompt` / `commit` / `cancelled` / `rejected`）与「`prompt` 携带 `commit` 连续放置」全部
现成。Stage 只需声明自己的 context 与 effect 类型。

## What Changes

### 模式是编辑器的第三段，不是新工具

`ComposeEditorMode` 从 `design | animation` 扩到三段，加 `drafting`。它**不是**
`StageInteractionTool` 的新成员：工具是「现在这一下要干什么」，模式是「整块画布按哪套规矩
工作」——绘图模式要同时换掉工具集、光标、框选判定与底部 chrome，塞进工具枚举会让每处消费
工具的地方都要再判断一次模式。模式是会话状态，不进文档，与视口、网格同一条规矩。

模式切换器当前把「两个选项」写死在方向键逻辑里，本刀一并泛化。

### 命令行由 Stage 自己渲染

绘图模式下 Stage 底部出现命令行，会话状态住在 Stage——预览几何、捕捉标记与提示文本是同一
份状态的三种呈现，拆到编辑器去会立刻需要一个新的跨包协议来回传。`ComposeCadCanvas` 已经
是这个形状。

命令行组件从 `cad-canvas` **上移到 `components`**：它只消费 `ComposeCommandPrompt` 与一组
文案，没有任何文档语义，而现在正好有两个第一方消费者——这是 AGENTS.md 给出的上移门槛。

### 点输入管线下沉到 core

坐标解析（`x,y` / `@dx,dy` / `距离<角度`）与点求解管线（键入坐标 > 捕捉 > 正交 > 网格）是
两段**纯函数**，不认识任何文档协议。当前住在 `cad`，本刀移进 `core`（去掉 `Cad` 前缀），
`cad` 改为消费共享实现。`core` 已经承载视口代数、轴点阵与几何精度，这一段属于同一类。

### 特征点捕捉是新查询，不是扩展既有的对齐吸附

路线图写的是「从既有 `snapCandidates` 扩展」，**读代码后要改口**：`snapCandidates` 返回的是
`StageGuide`（`{ axis, value }` 的参考**线**），服务 Figma 式对齐；CAD 捕捉要的是一个具体的
二维**点**。形状不同，是姐妹查询而不是扩展。

v1 只出**端点与中点**，且只来自带 `Curve` 的 Entity：盒的角点属于「对齐」语义，页面既有的
guide 吸附已经覆盖，两套同时生效会在同一次拖动里互相打架。

### `LINE` 与取点插件

`LINE` / `L`：连续画线，`prompt` 携带 `commit` 逐段落地（与 `COPY` 连续放置同一个机制），
Esc 结束。取点由一个新的 kernel 插件承担，优先级排在 **`pan` 之下**——命令进行中仍然要能
按住空格平移画布，AutoCAD 同样如此。

### 框选语义是白拿的

Stage 已有 `ComposeStageMarqueeMode`，其中 `directional` 就是「左→右窗口、右→左交叉」。
绘图模式把默认值切到它即可，不需要新代码。

## Impact

- `@compose-ui/core`：新增点输入管线（从 `cad` 移入）。
- `@compose-ui/cad`：改为消费 core 的管线，删除本地副本；行为不变。
- `@compose-ui/stage-engine`：特征点捕捉查询、绘图命令 context/effect、`LINE` 定义、取点
  插件；新增对 `@compose-ui/commands` 的依赖（零依赖 Layer 1 包，方向合法）。
- `@compose-ui/components`：命令行 Pattern（从 `cad-canvas` 上移）。
- `@compose-ui/cad-canvas`：改为消费 `components` 的命令行。
- `@compose-ui/stage`：绘图模式的十字线、捕捉标记、橡皮筋预览与命令行挂载。
- `@compose-ui/editor`：第三种模式、绘图工具栏、模式切换器泛化。
- 文档协议**不变**：绘图模式只产出既有的曲线 Entity。

## 本步刻意不做

- **`MOVE` / `COPY` / `ERASE` 与 CAD 选择语义**（点中累加、Shift 移出）：它们是同一个用户
  故事的两半——「选对象再操作它」。选择语义单独落地没有消费者，跟着编辑命令一起做才验证得了。
  下一刀。
- **弧、多段线、文字命令**：词汇本身还没有，属于步骤 3。
- **极轴追踪、捕捉模式的开关面板**：正交（F8）与端点/中点捕捉先跑通一条纵向流程，追踪与
  可配置捕捉集等有人真正画图之后再谈。
- **端点夹点编辑**：拖动已有线的端点仍未开放，它与「盒缩放要不要等比缩放几何」是同一个
  待决问题。
- **绘图模式下的 Palette 与场景树**：不做任何隐藏或改造——对象世界归页面，这正是本路线的
  前提，绘图模式只换输入方式。
