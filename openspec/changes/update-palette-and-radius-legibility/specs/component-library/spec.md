## ADDED Requirements

### Requirement: 货架整块为空时说明原因

组件库面板 MUST 在**整块货架的文件夹段一个组件都没有**时给出一句空态说明：这些文件夹里的
文件还没有被导入成组件，以及下一步去哪儿做。

分类计数数的是**已导入的组件**而不是文件数，这没有算错——这个面板是货架不是文件浏览器。
但一个列着一排符号目录名、每个都写着 `(0)` 的面板，第一次看就是「这里是空的」，用户据此认定
这条路不通。

说明 MUST 只在整块都空时出现，且 MUST 只出现一次：某一个文件夹是 0 而别的有货时，机制已经在
屏幕上演示过了，那个 0 自己说得清楚；逐段各写一遍是同一句话说很多遍。

**文件夹段不止一个时才 MUST 出现。**一行写着 `(0)` 说的是「这一格还没有东西」，用户读得懂；
而一列文件夹名全写着 `(0)` 说的是「这个面板是空的」，那句话是错的——文件就在那些文件夹里。
造成误读的是这块**看起来像目录树**的东西处处报零，不是零本身。这条同时挡住一处说错话：只有
一个「项目组件」段的货架里，下一步不是去资源里导入文件，而是在画布上提取组件。

搜索期间 MUST NOT 出现：那时的 0 是「没搜到」，与「还没导入」的下一步完全不同。

#### Scenario: 一个组件都没导入时给出引导

- **WHEN** 货架列着若干文件夹段，且每一段的计数都是 0
- **THEN** 面板上出现一句说明「还没有导入」并指出去哪儿导入
- **AND** 这句话只出现一次

#### Scenario: 有一段有货时不出现

- **WHEN** 其中一段有 1 个组件、其余段是 0
- **THEN** 不出现那句说明

#### Scenario: 只有一个文件夹段时不出现

- **WHEN** 货架只有一个文件夹段，计数是 0
- **THEN** 不出现那句说明

#### Scenario: 搜索期间不出现

- **WHEN** 用户输入了搜索词且没有命中
- **THEN** 不出现那句说明
