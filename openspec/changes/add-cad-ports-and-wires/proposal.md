# 端口与导线

## Why

全仓搜索 `connector` / `port` / `anchor` / `ConnectionPoint` 零命中。这是画示意图的硬缺口，
也是**画图工具与示意图工具的分水岭**：

> 拖动一台交换机，连着它的网线必须跟着走。

今天做不到。步骤 7 让符号可以复用（块与实例），步骤 8.5 让符号可以移动（MOVE / COPY / 拖动），
但两条线画在符号旁边只是**碰巧重合**——移动符号，线原地不动，图立刻错。用户唯一的补救办法是
把线一起框选着搬，而那在拓扑图上意味着每次调整都要手工维护几十条线的关系。

网络拓扑、一次接线与电路原理图这三类目标场景，全部以「谁连着谁」为主要信息。连接关系不在
文档里，图纸就只是一张画；它在文档里，图纸才是可查询、可校验、可自动布线的**图**。

## What Changes

### 端口住在块定义上

- `CadBlockDefinition` 增加 `ports`：一组 `{ id, position }`，`position` 是**块局部坐标**。
- 端口因此**跟随实例变换**（比例 → 旋转 → 平移，与块内几何同一条变换），并且一次声明、
  全部实例都有——这正是块存在的理由。
- `PORT` / `PO` 命令：选中一个块实例，指一个点，给该块**定义**加一个端口。

### 导线端点存引用而不是坐标

- 新增 `CadWire` Component：两个端点各自是 `{ kind: 'free', point }` 或
  `{ kind: 'port', entityId, portId }`。
- 导线几何**求解不存储**，与块实例几何同一条原则。移动符号时导线跟着走，因此**不需要任何
  「重解」代码**——没有存下来的东西就没有会过期的东西。
- `WIRE` / `W` 命令：两点画一条导线。落在端口上就绑定，落在空处就是自由端点。

### 端口捕捉压过一切

- 新增 `port` 捕捉模式，排在 `endpoint` 之前。端口通常**正好落在符号几何的端点上**，若不给
  它最高优先级，用户点上去会捕到端点、画出一条**看起来完全正确但没有绑定**的导线——这是本
  能力最危险的失败模式，因为它在屏幕上不可见。

### 不变量立在校验器里

- 导线端点引用不存在的 Entity、引用的 Entity 不是块实例、或其块未声明该端口，一律**校验
  失败**并给出稳定机器码。
- 「变体切换要求端口 id 稳定」因此不再是约定：变体在本仓就是另一份块定义，切换实例的
  `blockId` 若丢掉了被引用的端口 id，事务会被校验器直接打回。

### 删除设备不连带删线

- 删除一个被导线绑定的 Entity 时，那些端点**冻结在最后解算位置上变成自由端点**，而不是把
  导线一并删掉。用户没选中的东西不该消失，而文档必须保持合法。

### 拖动预览改为「解算预览文档」

- 拖动预览今天是把选中图元的线段整体平移若干屏幕像素。有了导线之后这条路必然分叉：拖动一台
  设备，**它的导线并没有被选中**，预览里不动，松手却会动。
- 改为对预览文档跑一次与提交完全相同的 `translateCadEntity`，再走同一条可见性遍历。预览与
  提交因此共用同一段代码，不可能分叉。

## Impact

- `@compose-ui/cad`：文档类型与校验、端口解算、导线解算、捕捉、`WIRE` 与 `PORT` 命令、
  两条新 handler、平移预览。
- `@compose-ui/cad-canvas`：端口标记、端口捕捉标记、拖动预览改为文档解算。
- 协议：`schemaVersion` **不变**。`ports` 缺省读作空数组，既有 `.cad.json` 一律仍然合法。

## 本步刻意不做

- **正交走线（曼哈顿路由）、避障、线段合并**：路由是打磨层，且需要先有连接关系才谈得上。
- **多段导线**：一条导线只有两个端点。折线导线要先定「中间拐点属于谁」，而拐点的价值全部
  来自自动路由，两件事应当一起做。
- **端口方向与电气类型**（输入/输出、电压等级）：没有消费者。加一个没有人读的字段，只会在
  真正需要时挡路。
- **切换实例块定义的命令**：变体切换在本仓没有任何入口。为一个不存在的入口写命令是投机；
  它要保证的那条不变量已经由校验器承担，任何将来的实现路径都绕不过去。
