# 变更：内建「页面」与「绘图」工作区

## 原因

`add-custom-workspaces` 立了机制，内建只有一个 `page`。本变更加上第二个：**绘图**——把工具的
耗材铺开（符号库拉高、十字光标贯穿图面、底部让位给图面），页面工作区则把基础组件与它们的
面板铺开（场景图、属性、资源）。两者工具栏逐字相同，差别全在面板与库。

绘图工作区里分量最重的一块是**符号库**：`app/symbols/` 里 58 个储能一次接线图元件分在 8 个
文件夹，今天的物料面板只会把它们平铺成一列。符号就是项目组件（SVG 导入成 Component Asset v2、
根 Frame 上声明 Ports，这条链已经通了），分类就是文件夹（资源浏览器已经有这棵树）。因此
物料面板要按**货架**（`sections`）渲染：一段 = 一个来源，Registry 的基础组件或资源里的一个
文件夹（按子文件夹分组或平铺），带标题与搜索。**选文件夹不选文件**——往 `Symbols / 变电站` 里
再导十个符号，它们自动出现。

设计稿第 1、2、3、10、11 节：
https://claude.ai/code/artifact/bb4abedb-212a-4a4e-abc8-6eb6c2c19047

**以 `add-custom-workspaces` 落地后的规范为基线。不考虑兼容性。**

## 变更内容

### 新增

- **内建 `drawing`（绘图）**：preset 摆出同一套四区结构，但工具组标题「符号库」、活动、分栏
  拉高，底部边缘组折叠；`session` 的十字光标臂长 100（页面是 5，AutoCAD `CURSORSIZE` 默认值）；
  `seeds` 的网格步长 10 / 10（页面 8 / 8），**对齐吸附关**（页面开）。
- **工作区定义加两个字段**：`palette`（`title`、`search`、`sections` 货架）与 `seeds`（新建
  文档的网格步长、网格吸附与对齐吸附）。切换时应用货架；种子只在新建时落地。
- **物料面板按货架渲染**：`sections` 每段是 `presets`（按单项 `include` 勾选，`paletteHidden`
  的勾不出来）或 `folder`（资源文件夹路径，`groupBy: 'flat' | 'subfolder'`），每段可默认折叠；
  面板接受 `title` 与 `search`（跨段按名称过滤）。文件夹不存在时那一段渲染成一行「找不到」
  并可去掉，不报错。页面默认货架 = 基础组件 + `components` 平铺，无搜索；绘图默认货架 =
  `Symbols` 按子文件夹分组 + `components` + 基础组件折叠，标题「符号库」，带搜索。
- `ComposeComponentDescriptor` 加 `folderPath`，由 Store 从资源条目的 `parentId` 链推出。
- **新建种子**：在某个工作区里新建页面时 `document.canvas.grid` 与 `document.canvas.smartSnap`
  取该工作区 `seeds` 的值。
- 两张工作区黄金图（页面 / 绘图）。

### 修改

- 「工作区定义与注入」：加 `palette` 与 `seeds`。
- 「内建工作区」：恰好两个，`page` / `drawing`。
- 「工作区切换」：切换也应用物料货架。
- 「工作区管理」：另存为也复制货架。
- 「混合组件目录」：按货架渲染、文件夹来源、子文件夹分组、搜索、标题、`folderPath`。

### 不做

- 物料面板的自定义对话框与瓦片右键：`add-shelf-customization`。
- 瓦片的密排样式：沿用今天的两列大瓦片，58 个符号靠分组折叠与搜索找，不靠把瓦片缩小。
- 给 Component Asset 加 `category` 字段：分类就是文件夹，沿用「没有消费者的字段不进协议」。
- 图纸单位与比例（路线图决策 5：像素就是它的单位）。
- 绘图工作区默认收起属性面板：先不收，等「只看画布」上了再看用户按不按。

## 已定的取舍

| 事项 | 取值 | 理由 |
| --- | --- | --- |
| 名字 | 页面 / 绘图，id `page` / `drawing`，不本地化 | 「图纸」排除了网络拓扑图 |
| 绘图的底部组默认 | 折叠 | 命令行常驻在图面里；资源浏览器第一次用展开一下，工作区记住 |
| 绘图的属性面板默认 | 不收 | 等「只看画布」上了再看 |
| 绘图的网格种子 | 10 / 10，网格吸附开 | AutoCAD `SNAPUNIT` 默认值。任务 0.1 量过 `app/symbols/` 的 88 个端子：**没有模数**，因此这份数据决定不了 8 还是 10，见下 |
| 绘图的对齐吸附种子 | 关（页面开） | 它与特征点捕捉是姐妹查询，同时开着会在同一次取点里互相拉扯，见下 |
| 十字光标臂长 | 页面 5 / 绘图 100 | 前者是 `CURSORSIZE` 默认值，后者贯穿图面用于跨图对齐 |
| 其余会话开关 | 两边同值 | 会话开关本来就按工作区各记一份，默认值再分叉会让「我上次关的」与「它本来就是关的」分不开，见下 |
| 工具栏 | **不由本变更回答** | 它需要 `toolbar` 字段，而那是 `add-shelf-customization` 的内容 |

### 对齐吸附为什么在绘图里默认关

工具栏那个「吸附」按钮是**两样东西的合并开关**，拆开看结论相反：

| 层 | 住在哪 | 绘图要不要 |
| --- | --- | --- |
| 对象捕捉（端点 / 中点 / 圆心 / 端口） | 取点管线，恒开，工具栏上没有它 | **要**，接线全靠它 |
| 网格吸附 `grid.snapEnabled` | 文档，已有种子 | 要，徒手画的外框与分区框靠它 |
| 对齐吸附 `smartSnap.nodes/guides`（Figma 式参考线） | 文档，本变更给它加种子 | **不要** |

第三层与第一层是**姐妹查询**：`snapCandidates` 返回 `{axis, value}` 的参考线，
`findStageFeaturePoint` 返回落在端点上的二维点，而特征点候选**刻意不出盒的角点**，正是为了
避开对齐吸附的语义——两套同时生效会在同一次取点里给出互相拉扯的答案。接线图上每一次落笔都在
找端子，因此绘图这一档默认关掉。

它只能是**种子**不能是会话开关：`toggleSnap` 派发的是 `configureCanvas` 事务，写的是文档，而
工作区的第三条硬边界正是「不写文档」。代价写在明处——**打开一份已有页面再切到绘图，对齐吸附
仍然开着**，要关只能按那个按钮，而那本来就是一次进撤销历史的文档编辑。

### 其余会话开关为什么两边同值

盘完账，`angleConstraint`、`polarIncrement`、`gridVisible` 与 `transformGizmo` 四个都没有分叉
的理由：

- **变换指示器**：它确实与绘图冲突——代码里 `transformGizmo` 是「不画曲线几何轮廓」的直接
  条件，开着时一条导线会退回盒加八个手柄。但两边默认都是关的，而会话开关本来就按工作区各记
  一份、切回时恢复，冲突**已经由既有机制挡住**。把页面默认翻成开是另一个产品决定，不该作为
  工作区拆分的副作用发生。
- **角度约束**：极轴默认开这条决定的理由是「它不挡任何画法」，对页面同样成立；页面偶尔跑一次
  `LINE` 画分隔线时，极轴把它吸到正 0° 反而是帮忙。
- **网格可见**：两边都开是观感问题，没有可援引的判据，不在提案里替用户定。

### 端口模数（任务 0.1 的结论）

`app/symbols/README.md` 记着源库为 48 个元件声明的 88 个端子坐标。量下来**它们不落在任何
模数上**：两轴同时整除 8 的只有 13/88、整除 10 的 0/88；两端子元件的端子间距（38 个）分布在
14 到 125 之间，整除 8 的 4 个、整除 10 的 6 个、整除 4 的 13 个。x 坐标 69/88 是 64——那不是
模数，是 128×128 取景框的中线。

因此这份数据**决定不了**步长，两条候选都得不到支持，取舍回到默认值 10。它也不构成缺陷：
落点管线是「键入 > 捕捉 > 网格 > 角度约束」，**捕捉命中即短路**——接到端子上靠端口捕捉，
网格从来不需要够着端子。网格种子的实际服务对象是用户徒手画的那些东西（外框、分区框、导线的
自由端），那里没有任何来自符号库的约束。
