# 变更：组件实例的内容缩放

## 原因

拖一个组件实例的角手柄，今天发生的是**盒变大、图没变大**：实例 resize 把尺寸写进嵌套根
Frame，Auto Layout 的 `fill` 子级会跟着重排，而绝对定位的子级原地不动。对一张卡片式组件这
正确，对一个**图形符号**完全错误——刀闸、断路器、电机要在同一张图上摆好几种大小，而它们的
子级全是绝对定位的几何。

这还是一次**能力倒退**：今天的 `svg` 物料靠 `fit`（`preserveAspectRatio`）做得到整体缩放，
一旦把 SVG 转成 Entity 树反而做不到了。SVG 导入不补这条就等于导进来的符号只有一个尺寸。

## 变更内容

- 组件实例新增 Renderer prop `contentFit`：`'layout'`（默认，今天的行为）与 `'scale'`
  （内容按盒与组件根尺寸的比值整体缩放，嵌套文档尺寸不变）。
- **零协议变更**：它是 Renderer prop，因此白拿 Inspector、数据绑定与外观轨道；默认值让既有
  文档**逐像素不变**。
- `'scale'` 下 resize MUST NOT 改写嵌套根 Frame 的尺寸——那是 `'layout'` 那一支的机制，两支
  同时改一份数据会让「实例多大」有两个答案。
- 非等比拖动时内容 MUST 按两轴各自的比值缩放（与 `viewBox` 跟随盒同一条语义），MUST NOT 强行
  等比后留白：曲线已经是这么跟随它自己的盒的。
- 实例内部下钻的选中框与命中沿用既有的 DOM 测量，因此缩放对它们是透明的。

## 影响

- 受影响的规范：`basic-materials`
- 受影响的代码：`packages/materials/src/component-instance`
- 后续：`add-svg-import` 落地的实例应声明 `contentFit: 'scale'`——图形符号要的是整体缩放
- 不在本变更内：同文档里 Group / 容器的缩放传播（没有嵌套运行时，只能把缩放烘进子级几何，
  是另一套机制）；Figma 式的每子级锚点约束（表达力更强，但是一整套新协议字段与求解改动）
