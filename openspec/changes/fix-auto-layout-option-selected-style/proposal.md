# 变更：Auto Layout 选项默认值的选中态改用统一强调色

## Why

Auto Layout 面板里，方向、换行、主轴、交叉轴四个字段的**默认值选项**看起来点不中——用户点击后感觉
没有反应。

点击其实完全生效：`aria-checked` 正确翻转、命令正确派发。问题出在配色。
`packages/materials/src/flex-layout/styles.css` 给选中态分了两套样式，选中项是默认值时用一套接近未
选中态的中性灰，只有非默认值才用强调蓝。四个字段的默认值恰好是 `row`、`nowrap`、`flex-start`、
`stretch`，正对应用户反馈中点不动的那四个。

这与前述的拉伸继承问题性质不同：那是未记录的实现细节，这是 `basic-materials/spec.md`「紧凑 Auto
Layout Inspector」里已有场景明文要求的行为——「显式默认项使用中性弱选中样式，非默认选择才使用强调
蓝色」。当初的设计意图是让用户能区分"这是我特意选的"和"这本来就是默认值"，意图本身合理，但落地后的
对比度太低，牺牲了"看得出选中"这个更基本的可用性要求。因此这是一次对既有规范的 MODIFIED，而不是修
一个未记录的 bug。

## What Changes

- MODIFIED `basic-materials/spec.md`「紧凑 Auto Layout Inspector」的"再次点击已选 Flex 选项恢复默认"
  场景：把「显式默认项使用中性弱选中样式，非默认选择才使用强调蓝色」改为「默认项与非默认项的选中态
  使用同一强调色，不做视觉区分」。
- 只改 CSS 选中态配色，**不改任何底层行为**：`data-initial-value` 标记继续保留（"再次点击已选默认值
  选项保持幂等"的底层逻辑不变），`component-inspectors.test.tsx` 中断言该属性存在的既有测试不需要
  改动。

## 首期边界

- 不引入新的"这是默认值"视觉指示（小圆点、副标记等）来替代弱选中色。用户反馈的问题是"看不出选中"，
  新增指示符解决的是另一个问题（"看不出这是不是默认值"），后者没有人提出过诉求，不做这个范围外的
  设计。
- 不调整未选中态、hover 态与 focus 环的配色。
