# 设计说明

## 为什么是撤销既有设计，而不是调参

当初给默认值选项单独配一套弱化色，意图是：如果默认值也用强调蓝高亮，用户分不清"这是我特意选的"还是
"这本来就是默认值，没人碰过"。这个意图合理。

问题出在落地时选的对比度太保守：弱选中态（`#292b2c` 纯色背景）和完全未选中态
（`linear-gradient(180deg, #242525, #191a1a)`）在这套深色主题里视觉差异太小，用户的真实反馈是"选了
跟没选一样"。也就是说，"区分默认值"这个次要目标，代价是牺牲了"看得出选中"这个更基本的可用性要求，
两者的优先级排反了。

修法选择"直接统一成强调蓝"而不是"把弱选中态的对比度调高"，是因为：一旦弱选中态调到能被清楚看出"已
选中"的程度，它和强调蓝在视觉上也不会有本质区别了，那还不如省掉这套配色分支，少一处需要维护的样式
规则。默认值这个信息本身并没有丢——`data-initial-value` 属性保留，"再点一次恢复默认"的交互逻辑不变，
只是不再用颜色去表达它。
