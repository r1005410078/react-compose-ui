平移复现用例（0.735 档、来回平移 140 帧后停下）：p50 13.5 / p95 23.2 / 最长 40.5ms；停下之后
**5ms** 内补全。`useDeferredValue` 那一版停下后要等数秒——那是用户报的「图延迟很久才出来」。
决策 6 之前（同步换窗）同一条路径 p95 是 86 / 200 / 145 / 65 / 22ms，换窗那一帧最长 79ms。

四处实测推翻或补上了提案里的取值，都记在 design.md 决策 2 与决策 6 里：

1. **外扩一屏 = 一个都不裁**。窗口九倍视口面积，而这张图整体只有三四倍视口大。降到四分之一屏。
2. **窗口按真实可视区取尺寸 = 每帧换窗口**。一次四十帧滚轮缩放产生 17880 次 DOM 增删，p50 从
   92ms 涨到 111–154ms——**比不裁剪还慢**。改成只认缩放档位（一个八度四档）。
3. **两条边各自吸各自的 = 平移每格换两次窗口**。格数在 7 与 8 之间跳。改成格数由档位定死。
4. **换窗那一帧落在平移帧上 = 时不时卡一下**。提案只算了稳态节点数，没算换窗那一帧的重建
   （两千节点上 80ms）。先试的 `useDeferredValue` 让图延迟数秒才出来，推翻；现在是元素缓存 +
   场景层内分批 + 文档顺序分桶 + 接近全集不裁，见决策 6。

## 4.5 的答复：这一刀不够，但不够的地方与预想的不同

放大之后（zoom ≥ 0.5）缩放已落到 p50 8–11ms，平移全程 p50 8–10ms、p95 11–13ms，**这一档
解决了**。

**缩放到整张图都在可视区的那一档（适配后的 0.119）裁剪帮不上忙**：可见集按定义就是全集，
缩放仍是 p50 93ms。这不是调参问题——没有任何窗口取值能在「所有东西都得画出来」的前提下少画。
要动的就是 `--compose-canvas-zoom` 那条已写明的不变量（「线宽反向除掉画布缩放」），而那是一次
产品取舍（手势期延迟写入会让线宽在捏合时先「呼吸」一下再回正），不该混进一次纯性能改动。
建议单独立项。

## 打开图纸（用户报：双击 DXF 整页冻住、十几秒才出图）

剖析（有头 Chromium、CDP Profiler、双击到节点数稳定）：一个 **11.5 秒**的长任务，其中 10 秒在
`invalidateMeasurements → calculateAndPublish` 这条链上；场景在 1.4 秒时就已经进了 DOM，之后
的十秒是页面冻住。根因不在解析（纯计划层 40ms）也不在渲染：

1. **每个文字的测量器各自在 `document.fonts.ready.then` 上挂失效**，字体早已就绪，1941 个
   `.then` 回调连成一串微任务，每一次都让布局运行时**当场整趟重解**（~5ms × 1941）。
2. 布局运行时的 `invalidateMeasurements` 收一次失效就重解一次，没有合并。
3. 导入时每个实体都过一次 `registry.createSeed`，5381 次 Preset 校验约 280ms。

三处各修一刀：`fonts.ready` 只在订阅那一刻字体**仍在加载**时才响应（`materials`）；失效同步
记账、重解合并进一个微任务（`layout-engine`，`solve()` 作废挂起的那一次）；seed 按 Preset 记住
（`editor`）。判别性单测：三次失效各自到达只发布一次；字体早已就绪时订阅不产生失效（对修改前
的代码红）。

| | 标签出现 | 节点数稳定 | 最长任务 |
| --- | --- | --- | --- |
| 修前 | 12.2s | 12.5s | 11482ms |
| 修后 | 1.1s | 1.4s | 659ms |

剩下的 659ms 是打开页面那一趟：首次 Yoga 求解（约 280ms，含 1941 次文字 DOM 测量）与 5381 个
节点的首次 React 提交。这一档要再降只能把首次求解切片或按视口延后测量，眼下不做。
