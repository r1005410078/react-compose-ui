# 设计说明

## 四个被问过的取舍，本变更取的值

设计稿末尾列了四件要定的事。这里记下取值与理由，方便日后回看时知道当初是怎么想的；
取值都可以被推翻，但推翻要连理由一起换掉。

### 1. 属性面板标签跟着选区变

**取：跟着变**（`属性 · 矩形`）。

不跟着变的话，主体标题那 52px 只能靠删搜索条省下 36px，119px 里最大的那一块留着。
Dockview 的标签一般是稳定的（它是「哪块面板」的名字），跟着选区变会让用户第一眼以为面板
被换掉了——缓解办法是**标签左侧常驻属性面板的图标**：变的是文字，不变的是图标与位置。
Figma 的右栏就是这么做的。

### 2. 三颗布局开关，不是四颗

第四颗会是「只看画布」，而它在工作区管理菜单里**已经有入口**。本变更的规则是「一个动作
只给一个入口」——正因为这条才删掉了 8px 把手，不能同一份变更里又违反它一次。

### 3. 工作区切换器不按数量折叠

宽度无界是真问题（每「另存为」一次多一段），但折成下拉要改「MUST 是 `radiogroup`，方向键
按索引循环」这条已写下的 MUST，而它与本变更要解决的密度问题正交。留作后续。

### 4. 工具栏行取 36px 不取 40px

30 + 3 + 3。取 40 只让出 9px 而不是 13px，而 3px 的上下留白在 30px 按钮上已经够——按钮
自己有 4px 圆角，视觉上不会贴住行边。

## 模式切换器为什么不做成图标 toggle

这一条中途改过一次，两版的推理都记下来。

**第二版（已推翻）**：工具栏那一行的既有语汇是二态开关（正交、极轴、网格、吸附、变换指示
器全是），模式也是二态，所以做成一颗 30px 的菱形 toggle，成本 34px，绘图工作区放得下。

**推翻它的**：那条推理把「形状相同」当成了「含义相同」。这个仓库自己写着——两个东西长得
一样、按下去做的事不同，是最难自己发现的一类缺陷（夹点的方块 / 条形 / 菱形就是照这条分
的）。模式与开关有四处不同，其中最后一条是决定性的：

| | 开关（吸附 / 网格 / 正交…） | 模式（设计 / 动画） |
| --- | --- | --- |
| 改的是 | 落点被怎么修正 | 拖动的结果**写到哪里** |
| 同时成立 | 可以同时开五个 | 互斥，恒在其中一个里 |
| 不知道自己在哪一档时 | 多吸一下、少吸一下 | 每一次拖动都在写你没打算写的东西 |
| 可否从货架移除 | 可以，能力还在命令面板里 | **不可以**——移掉之后没有任何东西说你在动画模式 |

因此它钉在行尾、不属于货架，也就**不存在「要不要钉成不可移除」这个问题**——它根本不进
货架。形状与顶栏那颗保持一致：它就是同一个控件换了地方，搬家已经够用户重新找一次了。

## 按下态：为什么是「内缩」而不是「加间距」

拥挤有三个成因，按贡献排序：两种按下态同形、组内间距 1px、底 30×30 而图标 20px。

最容易想到的一刀是把组内间距从 1px 调到 3px，但它**付不起**：绘图货架 15 格、组内 11 处
间距，一共 22px；而绘图工作区在放进模式切换器（76px）之后余量已经是负的。

内缩 2px 不花任何宽度：格子仍是 30px、**命中区一个像素不变**，相邻两块之间从 1px 变成
5px（1 + 2 + 2）。这也是为什么不能改图标——20px 幅面与 1.5 描边是一对（1 单位 = 1 设备
像素，笔画正好落在像素格上），缩幅面等于重画整套图标。

## 开关按下只改颜色，因此颜色必须同时是明度

开关的按下态没有底、没有记号，状态**只剩颜色这一个通道**。因此点亮色不能取
`--compose-accent`（`#3687ff`）——它与静息灰几乎一样暗，只有色相差，色觉障碍的用户会读成
同一枚图标。取更亮的一档，同时把静息态从 `text-subtle` 压到 `text-muted`，让开与关既是
色相差**也是明度差**。

这与「端口记号和捕捉标记 MUST NOT 只靠颜色区分」不冲突：那条说的是**两个不同的东西**
（所以形状先分开），这里是**同一个控件的两个状态**，而它已经有 `aria-pressed` 这条与颜色
无关的通道。

## 删按钮之前先补动作，是同一条规则的第四、五次应用

「收走一个入口可以，收到只剩一个不可以」——`add-shelf-customization` 立下这条时它就逼出了
`stage.canvasSettings` 与 `stage.toggleTransformGizmo` 两条动作。本变更又逼出两条：

- `document.save`：删按钮之后 `Cmd/Ctrl+S` 是硬接在按键处理里的，用户改不了那个键。
- `document.toggleAnimationMode`：模式切换器不上货架，因此**不是**被那条规则逼出来的；
  理由更普通——一个改变拖动语义的开关只有一个鼠标入口，键盘用户够不着。

两者的区别值得记一笔：前者是规则的直接后果，后者是一次独立判断。

## 落地时挖出来的一处既有缺陷：无层规则压过分层规则

把开关的按下态改成「只改图标颜色」之后它完全不显形。量下来的原因与本变更无关——示例应用里
有一条**没有分层**的裸规则：

```css
button { color: inherit; }
```

而编辑器包的样式住在 `@layer components` 里。**无层的规则压过任何有层的规则，与选择器权重
无关**，因此工具栏图标的颜色一直由继承决定：`text-subtle`（静息）与按下态的 `text-strong`
**从来没生效过**。此前看不出来，是因为按下态还有一块底在说话；一旦颜色成了唯一的通道，这条
缺陷就变成「按下去什么都没发生」。

修法是把那条 reset 收到示例应用自己的按钮上。**判别性用例只能是端到端**：jsdom 不跑层叠，
组件测试断不了；黄金图会变但读不出原因。因此 `toolbar-shelf.spec.ts` 里那条「按下态分两种」
断的是**计算后的颜色**，并且验过它在修复前是红的。

推论：这一层的样式改动，凡是靠层叠取胜的，都要有一条端到端量计算值——否则下一条无层规则
出现时，没有任何东西会红。
