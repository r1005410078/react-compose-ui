# Stage 规范增量

## MODIFIED Requirements

### Requirement: 受控工具模式与专属选区反馈

Stage MUST 接受受控的 `tool` 值并按它改变手势语义。工具集 MUST 只包含**没有其他入口**的
动作：`select`、`scale`、`rotate` 与各 `draw-*` 绘制工具。

以下四个工具值 MUST NOT 存在，因为各自都有严格不弱的既有入口：`marquee`（`select` 在空白处
拖拽即框选）、`move`（`MOVE` 命令能键入精确位移）、`pan`（空格与中键是随时可用的临时覆盖，
不占用工具状态）、`draw-line`（`LINE` 命令产出 `Curve` Entity）。

`select` 工具在空白处拖拽 MUST 框选，判定由拖拽方向归约得出（见 stage-engine 的框选判定
Requirement）。MUST NOT 存在任何可以覆盖方向的模式参数或宿主开关。

Stage MUST 为当前工具提供专属选区反馈：`scale` 显示缩放手柄，`rotate` 显示旋转手柄，
绘制工具显示落点预览。

**单选一条带 `Curve` 的 Entity 且工具是 `select` 时，选区 MUST 画它的几何轮廓，MUST NOT 画
选区矩形、Resize 手柄或边缘命中带。**判据是**盒是不是这个对象的轮廓**：矩形、图片、容器的盒
就是它们的轮廓，文字占满自己的盒，而一条对角线的包围盒里绝大部分是空的——那个矩形宣称了对象
并不占据的面积，且比线本身显眼得多。线越接近 45 度它越大，拖端点时还一直在变。

这条判据 MUST NOT 被读成「给曲线开特例」：同一句话在矩形上的答案就是画盒，在文字编辑态上的
答案是画盒但去掉填充。它也 MUST NOT 扩大到非曲线 Entity。

轮廓 MUST 与几何编辑会话画的是**同一条几何**（同一个派生入口），MUST NOT 另写一份——两份
实现的分叉症状是「双击前后线的轮廓差半个像素」，而那种偏移只在特定缩放下现形。几何编辑态下
它 MUST 由可编辑路径层绘制，选区层 MUST 让位：两层各画一条会重叠出一条更粗的线。覆盖层
MUST 保持不认识文档：世界折线由宿主派生后传入。

**`scale` 与 `rotate` 工具下 MUST 照旧画盒**与各自的手柄。盒不是错的，它只是不是轮廓；用户
明确在做盒操作时，盒就是他正在操作的那个东西。曲线的整体缩放能力因此没有消失，只是从「随时
都在」变成「进那个工具」，而两个工具都已存在。

**多选 MUST 照旧画整体包围盒**，MUST NOT 逐对象改画轮廓。多选框回答的是「这一堆的范围」，
那是一个用户接下来真的会操作的矩形，它不宣称任何单个对象的轮廓。

几何编辑会话 MUST 在轮廓之外**再加**夹点与十字光标，两态因此可区分；轮廓本身在两态都画，
进出会话时对象的呈现只**增减夹点**，不整体换一套。AutoCAD 把选中与夹点
合成一态是因为它没有单独的顶点模式；本产品有，而「能不能拖出一个新形状」必须一眼可辨。

#### Scenario: select 在空白处拖拽即框选

- **WHEN** 当前工具是 `select`，用户从空白处拖出一个矩形
- **THEN** 按拖拽方向归约出的判定选中命中的节点

#### Scenario: 专属选区反馈

- **WHEN** 当前工具是 `rotate`
- **THEN** 选区显示旋转手柄而不是缩放手柄

#### Scenario: 选中曲线不画包围盒

- **WHEN** `select` 工具下单选一条斜线曲线
- **THEN** 图面不绘制选区矩形，也不绘制 Resize 手柄

#### Scenario: 轮廓沿几何而不是沿盒

- **WHEN** `select` 工具下单选一条斜线曲线
- **THEN** 绘制的轮廓落在线身上；包围盒四角处没有轮廓

#### Scenario: scale 工具下盒与手柄回来

- **WHEN** 选中同一条曲线并切到 `scale` 工具
- **THEN** 图面绘制选区矩形与缩放手柄

#### Scenario: 非曲线 Entity 不受影响

- **WHEN** `select` 工具下单选一个矩形 Entity
- **THEN** 图面照旧绘制选区矩形与 Resize 手柄

#### Scenario: 多选仍画整体包围盒

- **WHEN** 同时选中一条曲线与一个矩形 Entity
- **THEN** 图面绘制覆盖两者的整体包围盒，而不是逐对象的轮廓

### Requirement: 曲线几何编辑会话

`ComposeStage` MUST 提供曲线的几何编辑会话：select 工具下双击一个带 `Curve` 的未锁定 Entity
MUST 进入该会话，`Escape`、在空白处按下、切换工具或选中集不再**恰好只有该 Entity** MUST
退出。会话状态 MUST 住在 Stage 自己这里，与画布内文字编辑同构；宿主 MUST NOT 需要为进入或
退出接线。

某个夹点被点亮时，`Escape` MUST 先熄灭它而 MUST NOT 退出几何编辑会话；再按一次才退出。
两级与 AutoCAD 的热夹点 → 温夹点 → 取消选择同构。

进入会话时 MUST 清掉命令行上残留的 notice。用户此刻站在一个会取点的状态里，而残留的那句
（例如上一条命令被取消时留下的「已取消」）在说一件已经过去的事。

会话 MUST 是**单对象作用域**：Shift 累加选中另一个 Entity MUST 退出会话。会话的全部呈现
（夹点、轮廓、十字光标、被排除出捕捉的那一个 Entity）都只描述一个对象，而会话又抑制了选区
包围盒与手柄；把它按在多选状态上会让第二个被选中的对象在图面上完全隐身。

会话期间 MUST 显示该 Entity 的夹点，并 MUST 复用既有的可编辑路径覆盖层与路径手势通道，
MUST NOT 另写一套顶点渲染或拖拽。

指针停留在某个夹点的命中区上时，该夹点 MUST 改变呈现。夹点的可见图形比它的命中区小，没有
悬停反馈时用户唯一能确认「按下去会抓到它」的办法是按下去试。该反馈 MUST NOT 引入每帧
`pointermove` 都要写一次的 React 状态——它是纯视觉的，可由样式派生。

会话期间 MUST NOT 为该 Entity 显示任何 Resize 或旋转手柄。盒的角手柄与角顶点几乎压在同一个
像素上，两个含义叠在一起谁也点不准。该抑制与文字编辑那条是同构的两条独立规则。

退出会话 MUST 回到该曲线在 `select` 下的普通选中呈现，那是**几何轮廓**而不是盒（见「受控工具
模式与专属选区反馈」）。轮廓在两态都画是有意的连续性：进出会话时对象的呈现只**增减夹点**，
不整体换一套。

会话期间 MUST NOT 绘制选区包围盒。三条理由，任何一条单独成立：

1. **盒不是曲线的轮廓。**一条对角线的包围盒里绝大部分是空的——这正是命中判据不按包围盒的
   那条理由，视觉上同样成立：那个矩形宣称了对象并不占据的面积，而且比线本身显眼得多。
2. **拖夹点时它是过期的。**选区盒由手势的预览变换推出，而夹点拖动不产生预览变换（它走本地
   几何预览），因此整个拖动过程中盒停在拖动**之前**的位置。它不只是多余，它在说谎。
3. **它要表达的信息已经有人表达了。**可编辑路径覆盖层沿**真实几何**画出轮廓，夹点也落在
   对象上——「选中的是谁」比一个矩形说得更准。

文字编辑态只去掉填充而保留边框，因为文字盒**就是**那个对象的轮廓；曲线不是，因此整个矩形
都不画。两者是同一条判断在不同形状上的两个结论。

会话期间 MUST 绘制十字光标并收走系统光标，判定 MUST 与绘图命令取点期间共用同一个解析结果。
拾取框 MUST 只在**既没有点亮任何夹点、也没有拖动**时绘制，其余时候 MUST 只绘制十字线。
没点亮也没拖动的会话正是「等着抓点什么」的状态，框表达可抓的靶区；一旦抓住——不论是按住
拖着还是点亮了等着——那件事已经发生，框只会挡住落点。

**捕捉标记 MUST NOT 在没有夹点被会话作用着的那一档绘制。**拾取框与捕捉标记回答的是两个
不同的问题：框说「这一块是靶区」，在「等着抓点什么」的那一档有意义；标记说「落点吸上了
什么」，而那一档**没有落点**——命令行提示就是「命令：」，与 AutoCAD 一致（对象捕捉标记只在
命令正在请求一个点时出现）。在别的对象的端点上亮起标记，会让用户以为那些对象也能改形状。

判据 MUST 是**同一份事实**：拾取框已经在读「有没有夹点被作用着」来决定画不画，捕捉标记
MUST 读同一份，MUST NOT 各判一次。

**拖动期与点亮期照旧绘制**：那两档正在放置一个点，而「把这个角对到那个角上」正是几何编辑
最常做的事，一起收走会毁掉这条能力。

该拾取框的半边长 MUST 由夹点的命中半径派生，MUST NOT 复用点选那一档的配置值。顶点模式是
Stage 里唯一一处存在**统一命中容差**的地方——可抓目标只有夹点，而每个夹点的命中区都一样大，
因此这里的框可以真的表达「压住了就抓得到」。派生 MUST 取命中圆的**内切**关系而不是外接：
框内一律抓得到，宁可少说不可多说。两个值分开写死会让下一个改命中半径的人漏掉框。

拖动夹点 MUST 先经与绘图命令**同一条**落点解算（特征点捕捉、正交、网格），移动阶段 MUST 只
更新本地预览，结束阶段 MUST 派发一条 `entity.curve.set`。落点越出当前盒时 MUST NOT 钳制——
盒与几何由该命令重新归一化，撤销一步 MUST 回到原几何。

拖动某个夹点期间，**只有那个顶点自己的原位置** MUST NOT 参与特征点捕捉：它就在指针底下，
不排除的话夹点会被吸回原处，用户要把指针拖出容差半径才动得了。

排除 MUST 是**点级**的，MUST NOT 把整个 Entity 收走。理由只对被拖的那一个点成立，而同一个
对象的其他顶点与各段中点正是用户最常要对齐的目标——「把这个角对到那个角上」。做成 Entity 级
时它在屏幕上的样子有欺骗性：用户看到「只有一个顶点会变色，其他都不变」（变色的那个在别的
对象上），以及「顶点不在网格上就永远落不上去」（捕捉够不着，网格接管，而顶点不在格点上），
两句话是同一个原因。

排除 MUST 只在**有夹点被会话作用着**时成立——没有夹点被作用时既不解算落点也不绘制标记，
排除与否没有任何可观察后果。这一条曾经写成「未拖动时不排除任何东西」并以空闲档的捕捉标记
观察，而那个标记本身就是上面禁止的那个。

捕捉标记与落点解算 MUST 读同一份排除，否则会出现「标记在这里、点落在那里」。

曲线绘制手势结束后 MUST 直接进入该 Entity 的几何编辑会话。绘图**命令**产出的 Entity
MUST NOT 自动进入：命令仍握着光标与提示，两个正在取点的东西叠在一起会让 `Escape` 的含义
说不清。

宿主传入 `editablePath` 时 MUST NOT 进入几何编辑会话：覆盖层至多渲染一条路径，而两条路径
指向不同的事实。

#### Scenario: 双击曲线进入并显示夹点

- **WHEN** select 工具下双击一条未锁定的直线曲线
- **THEN** 图面显示它的三个夹点
- **AND** 该 Entity 的 Resize 手柄、旋转手柄与选区包围盒都不显示

#### Scenario: 只有既没点亮也没拖动时才画框

- **WHEN** 会话已开始而指针尚未按下
- **THEN** 图面同时绘制十字线与拾取框
- **AND** 按住某个夹点拖动期间只绘制十字线，且十字线全程跟随指针
- **AND** 原地单击点亮一个夹点之后同样只绘制十字线

#### Scenario: 悬停在夹点上改变它的呈现

- **WHEN** 指针停留在某个夹点的命中区上
- **THEN** 该夹点的呈现与未悬停时不同
- **AND** 指针移开后恢复

#### Scenario: Shift 累加退出会话

- **WHEN** 一条曲线正在几何编辑会话中，用户 Shift 点选另一个 Entity
- **THEN** 会话退出，夹点消失
- **AND** 两个 Entity 按多选的既有规则显示选中呈现

#### Scenario: 拖端点把轴对齐的线掰成斜的

- **WHEN** 在非 100% 缩放下双击一条水平直线，把它的一个端点拖到另一个高度并松手
- **THEN** 文档里该曲线的两个端点不再等高
- **AND** 只产生一条可撤销记录，撤销后回到水平

#### Scenario: 拖中点整条线搬走并按中点捕捉

- **WHEN** 在非 100% 缩放下拖一条直线的中点夹点到另一条曲线的端点附近并松手
- **THEN** 该直线的中点精确落在那个端点上，而不是指针的裸坐标
- **AND** 线的长度与方向不变

#### Scenario: 拖夹点时不被自己吸住

- **WHEN** 拖动一个夹点，指针仍在该夹点的捕捉容差之内
- **THEN** 落点跟着指针走，不被该曲线自己的端点吸回原处

#### Scenario: 同一个形状的其他顶点仍可捕捉

- **WHEN** 一条多段线正在几何编辑会话中，把它的一个顶点拖到**同一条多段线**的另一个顶点附近
- **THEN** 落点精确落在那个顶点上，图面显示捕捉标记
- **AND** 同一条多段线各段的中点同样可以命中

#### Scenario: 空闲档不画捕捉标记

- **WHEN** 会话已开始、没有任何夹点被点亮或拖动，指针靠近**另一个** Entity 的端点
- **THEN** 图面不绘制捕捉标记
- **AND** 十字线与拾取框照常绘制

#### Scenario: 点亮之后不排除自己的其他点

- **WHEN** 点亮一条多段线的某个顶点，指针靠近**同一条多段线**自己的另一个顶点
- **THEN** 图面显示该顶点的捕捉标记，落点精确落在它上面

#### Scenario: 退出会话回到普通选中呈现

- **WHEN** 几何编辑会话中按下 `Escape`
- **THEN** 夹点消失，该曲线回到 `select` 下的普通选中呈现——几何轮廓
- **AND** 既不出现选区包围盒也不出现 Resize 手柄

#### Scenario: 画完曲线停在几何编辑里

- **WHEN** 用曲线绘制工具拖出一条新曲线并松手
- **THEN** 新 Entity 被选中并处于几何编辑会话，图面显示它的夹点

#### Scenario: 宿主运动路径优先

- **WHEN** 宿主已传入 `editablePath`，用户双击一条曲线
- **THEN** 不进入几何编辑会话，图面仍只渲染宿主那条路径
