# 设计说明

## 容差是屏幕量，改的只是量级

`world = (屏幕 − 视口) / zoom`。容差表达的是**鼠标能瞄多准**，那是屏幕上的事，不随缩放变——
这一条不动。把它做成世界量的症状是「缩小时点不中、放大时抢走旁边的东西」，那是另一个缺陷。

因此这一刀不碰 `calc(px / var(--compose-canvas-zoom, 1))` 那条反向除法，只改被除的那个数。

## 为什么照抄 AutoCAD 的 3，而不是自己推一个

前车之鉴就在同一个仓库里：十字线臂长曾经试过按「臂长与拾取框的比例」推一个数，理由听起来很
硬（拾取框在两边都是固定的十几个 CSS 像素，比图面百分比更可比），推出来的值在实机上仍然明显
偏长——比例是从截图上目测的，而长度是观感问题。最后照抄了 `CURSORSIZE` 的默认值。

拾取容差是同一类量：它的对错只能在实机上、在真实密度的图纸上判断，而 AutoCAD 的默认值是几十年
密集图纸用出来的。**3 是抄来的，不是推来的**，这一句本身就是这个数的理由。

## 为什么 `butt` 而不是留着 `round`

`round` 让命中区从两端各伸出半个带宽。它在**任何**尺寸上都是错的，只是小尺寸上才看得见：

- 它让命中区成为包围盒的**超集**，而这个功能的整条理由是「盒里绝大部分是空的」。
- 端点是接线图上密度最高的地方（`LINE` 逐段落地，每段一个 Entity，它们共享端点）。越过端点
  意味着相邻段互相偷点击。
- AutoCAD 的拾取从不越过端点。

**多段线的拐角不受影响**：拐角由 `stroke-linejoin` 承担（默认 miter），`butt` 只作用于两个
自由端。这也是为什么不能顺手把 join 一起改掉。

## 为什么拾取框跟着变小

Stage 的拾取框只在**命令等待选择对象**时绘制，而那一档用户选的就是曲线。框画成 12×12、真实
容差却是 ±3，等于教用户瞄错。

这与「默认 6 是为了与顶点模式那一档（11.3px）对齐」的旧理由冲突，冲突按**诚实优先**解决：
顶点模式那个框是诚实的（由夹点命中半径派生），点选这个框此前不是。两档的框从此各自表达自己
那一档真实抓得到的范围，而不是互相凑成一样大。夹点本来就是比发丝线更大的目标，框不一样大是
**对的**。

## 为什么常量住 `core`

`stage` 与 `materials` 之间没有依赖关系，而这个数要被两边读。同样的判断已经在
`COMPOSE_SCENE_SIZE_PRESETS` 上做过一次：各写一份必然漂移，而漂移的症状（框和真实容差不一致）
恰恰就是这一刀在修的东西。

规范里那句「Stage 的拾取框 MUST NOT 参与任何命中判定」**保留**——它说的是「框不是判定的输入」，
这一条仍然成立：判定由物料的 stroke 完成，框只是把同一个数画出来。改掉的只是后半句「没有全局
的那个数」，因为现在有了。

## 判别性

改这个数**不会**让既有的两条空角用例变红——它们用的是大尺寸曲线，±6 和 ±3 都够不着那个角。
因此新增两条：

1. **小尺寸曲线的空角**：一条 36px 见方的曲线，点它包围盒里离线身最远的角。这一条在改之前
   必红。
2. **端点外侧**：沿线身方向越过端点 4px。`round` 时命中、`butt` 时不命中，与容差的量级无关，
   因此它单独钉住 cap 那一半。

两条各钉一个原因，缺任一条另一半都能悄悄回退。

## 框选：为什么窗口没暴露问题，而窗交暴露了

`contain` 要求 AABB 完全落在框内。对**未旋转**的曲线，节点 AABB 就是几何的紧包围盒，因此
「盒进框」与「几何进框」等价——窗口判定一直是对的，只是碰巧。

`intersect` 则不然：框与盒有交集就算命中，而盒里绝大部分是空的。斜线的空角是最极端的情形，
一个从不碰线身的框照样选中它。

推论：这一刀改的主要是 `intersect`，但两者都改走几何，因为一旦旋转起来 `contain` 的等价关系
也不成立了，而曲线的世界几何本来就要算出来。

## 框选判定怎么算

复用点选与特征点已经在走的那条链：`projectComposeCurveToBox` 把几何投到盒里，再用
`index.getWorldMatrix` 把点送到世界。分三步：

1. 曲线拆成线段：`line` 一段，`polyline` 走 `composePolylineSegments`，`arc` 走既有的
   `flattenComposeArc`。
2. 端点变换到世界，得到世界空间的折线。
3. 与框（世界轴对齐矩形）判定：任一端点在框内，或任一线段与框的四条边相交。

**弧拍扁的误差是有意接受的**：同一个仓库已经为非等比缩放做过同样的选择（等比仍是精确弧，
非等比拍扁成多段线）。框选是一个「选中或不选中」的布尔判断，不是渲染，弦高误差不会以任何
方式呈现给用户。

**填充是例外**：填色区域是用户看见的墨，因此框落在填充内部也算命中，判断走
`isPointInsideComposeCurve` 与 `getComposeCurveFill`——与点选路径读的是同一对函数。空心时
不做这一步，那正是「盒里绝大部分是空的」覆盖的情形。

## 为什么变换的是几何，不是框

把框逆变换进几何空间会更省事，但非等比缩放会把矩形变成平行四边形，四条边不再轴对齐，判定
反而更复杂；旋转时同理。这与点选那条既有判断同源——「判定留在世界空间，把**几何**变换过去，
不要把光标点变换进几何空间」。

## 为什么不顺手把旋转盒也修了

改的是同一行，但需要「矩形对凸四边形」的判定（SAT 或分离轴），那是另一套机器，且它会把
`resolveMarqueeSelection` 从「读 AABB」变成「读世界矩阵」，波及所有 Entity 而不只是曲线。

两处报障、可见症状与判别性用例都在曲线上。欠账**留在原处**（注释与规范各一句），不因为顺手
就扩大这一刀的爆炸半径，也不因为改了一半就把话删掉。

## 判别性

四条新用例，各钉一个原因，缺任一条对应的那一半都能悄悄回退：

| 用例 | 钉住的东西 | 改前 |
| --- | --- | --- |
| 离线身 5px 处点不中 | 容差量级 | 必红 |
| 沿线身越过端点 4px 点不中 | 命中层的 cap | 必红 |
| 空角里的窗交框不选中斜线 | 框选按几何 | 必红 |
| 穿过线身的窗交框仍选中 | 上一条没有矫枉过正 | 改前绿，防回归 |
| 双击进入后十字线就在双击点上 | 播种 | 必红 |
| 命令行启动且不动鼠标时不画十字线 | 清除 | 必红 |
| 几何编辑空闲档悬停别的线不出标记 | 标记读 `gripTarget` | 必红 |
| 点亮之后同曲线其他顶点仍可捕捉 | 排除仍是点级 | 改前绿，防回归 |

既有的两条空角用例**改不改都绿**——它们用的是大尺寸曲线，±6 和 ±3 都够不着那个角。容差的
判别性因此 MUST 落在「离线身 5px」这种恰好夹在新旧容差之间的位置上，而不是空角：空角在两个
容差下都点不中，拿它当用例会得到一条永远绿的假判别。

## 十字光标的位置：为什么是「清 + 播种」两件事一起做

只清不播种：双击进入几何编辑后，十字线要等用户动一下鼠标才出现——而那一下双击本来就带着
坐标，白白丢掉。

只播种不清：漏掉任何一条进入路径，就又画在旧位置上，而这个缺陷**只在特定顺序下出现**（要先
跑过一次会话），最容易活下来。

两件一起做之后，不变量可以写成一句：**十字光标只画在本次跟踪开始之后观测到的位置上。**没有
这样的位置就不画。命令行敲入的那一档因此不画，直到第一次 `pointermove`——浏览器不提供查询
指针位置的接口，先不画是唯一诚实的答案。

## 捕捉标记：为什么这次是删规则而不是加规则

规范里那条 Scenario 明写空闲档要显示捕捉标记，用它观察「未拖动时不排除任何点」。它是个**用
错了观察点**的用例：被观察的规则是「排除」，而用来观察的是「标记」，于是标记本身的对错从来
没被审视过。

一旦空闲档不解算落点，「排不排除」就没有任何可观察后果——那条规则收敛进已经写下的「排除的是
被会话作用着的那个夹点」。删掉的是一句在新语义下**恒真**的话，不是一条约束。

替换的观察点落在点亮之后：点亮一个顶点，同一条曲线的**其他**顶点仍要能捕捉。这条钉住的还是
原来那件事（排除是点级不是 Entity 级），而且落在一个真的会解算落点的档上。

## 四条为什么走一起

前两条共用 `core` 的曲线几何；后两条共用 `stage` 的同一份会话状态（`pointerScreen` 与
`gripTarget`），而且**用户双击进入几何编辑时一次就同时撞上**。分四次排队意味着「进入几何
编辑」这条端到端路径要被验证四遍，而每一遍都要重新画线、重新双击。
