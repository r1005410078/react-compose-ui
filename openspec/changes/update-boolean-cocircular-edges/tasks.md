## 1. 支撑归一与它的三件配套（core）

- [ ] 1.1 `curve-arrangement.ts`：片段 → 支撑（线段给规范式 `(nx, ny, c)`，弧给 `(cx, cy, r)`），
      规范式的法向定向到上半平面——共线的两条因此得到同一组数
- [ ] 1.2 `curve-arrangement.ts`：按**轨迹**分组（取样点到对方支撑的偏差 ≤ 一个量化步长），
      组内按支撑数值取字典序最小的那一条当规范支撑，成员全部重算到它上面
- [ ] 1.3 `buildGraph`：同一支撑组内的两条片段不求交，改为按对方端点切开
- [ ] 1.4 `buildGraph`：节点合并容差取「相对量」与「一个量化步长」的较大者；零长子边一律丢弃
      （不再只丢线段）
- [ ] 1.5 单测（判别性）：
      - 两条圆心差三个量化步长、轨迹只差半个步长的弧归到同一条支撑；
      - 轨迹差一个量级的两条弧**不**归一；
      - 同一组片段换输入顺序，归一之后逐位相同；
      - **只补容差不做归一**时那条并集仍然求不出来（钉住「这一条单独不成立」）；
      - 零长的弧子边不进图

      > Red result: 5 failed | 3 passed (8)，失败全是断言（支撑不相等 / 重复没收掉 / 零长边还在）
      > Red reason: `weldComposeOutlineSupports` 与 `composeOutlineSupport` 先落了桩（原样返回、
      >   线段支撑恒为零），因此 Red 由**断言**产生而不是 `TypeError`——后者属于「依赖缺失」，
      >   按 project.md 不算有效 Red。

      > 桩上有一条**假绿**：线段支撑恒返回同一个常量时「方向相反的两条共线线段归到同一条支撑」
      > 自动成立。补了一条反向用例（差半个量级的两条平行线不归一）之后它才真的判别。
      > 另一处：法向定向要把 `-0` 归正——`-0` 与 `0` 在比较里相等，却让同一条支撑在逐位比较下
      > 读成两条。
