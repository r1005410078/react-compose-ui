## 上下文

本变更是三个动画提案中的第三个，依赖 `add-animation-asset-runtime` 已经提供的 Asset v1、Animation
能力、确定性 Runtime 与 Store。这里只做**创作路径**：时间轴、Auto-keyframe、关键帧 Inspector、
编辑会话与 Stage 受控预览。

底部动画面板、时间轴、播放控制区与右侧关键帧 Inspector 的视觉与交互基准是 `design/animation.png`。
出现分歧时以本文的文字决策为准，并回填更新设计稿或在此说明偏离原因。设计稿确认的细节：

- 底部标签栏固定顺序为 资源、动画、命令、日志，当前活动为「动画」。
- 左侧场景图列出容器后代的可动画节点（如 Fault、Alarm），选中节点在时间轴中高亮为一条独立轨道行。
- 播放控制区从左到右为：播放/暂停、Auto-keyframe（菱形图标）、当前时间输入框、总时长输入框、
  时间单位（ms）、重新生成/刷新，以及带红点强调的「自动记录属性」开关。
- 时间轴刻度以 100ms 为主分度；节点行下方展开属性轨道（如「背景填充」），轨道上以菱形标记关键帧，
  播放头为竖直贯穿线，选中关键帧的菱形带外圈高亮，轨道末尾以对应颜色色块提示该属性的最终取值。
- 右侧关键帧 Inspector 标题格式为 `节点 / 属性`（如 `Fault / 背景填充`），并显示帧序号（如 `3/4`）、
  时间、属性名、值（含色板）与插值方式；插值为 Bezier/Spring 时下方以「曲线」「弹簧」两个 Tab
  展开可视化编辑器，Linear 场景下曲线 Tab 显示对角直线并标注 “Linear”。

**设计稿是人工评审参照，不是像素基准。** Playwright 黄金图必须从实现截取；定稿前逐项人工比对
标签顺序、播放控制区图标排布、关键帧菱形/播放头与 Curve/Spring Inspector 布局。

## 目标/非目标

- 目标：容器范围时间轴；自动属性轨道；关键帧与区间编辑；独立可撤销的草稿与显式保存；Stage 与
  Runtime 使用同一 FrameSnapshot。
- 非目标：布局动画、组件实例内部目标、动画变量库、多播放器混合编排、时间轴上的曲线批量编辑。

## 决策

### 播放头使用资源本地时间

时间轴按容器聚合，但每个节点有自己的 `delayMs`、`speed` 与 `durationMs`。播放头统一表示**活动
资源的本地时间**（0 到 `durationMs`），关键帧寻址、Inspector 帧序号与 Auto-keyframe 写入时间全部
使用这个时间。

`delayMs` 与 `speed` 只影响节点区间在时间轴上的可视化呈现（起始偏移与区间长度），不参与关键帧
寻址。理由：关键帧存的是资源本地时间，如果播放头是"容器全局时间"，则同一个播放头位置在不同
speed 的节点上对应不同的帧，用户在切换活动资源时会看到帧选择跳变，而且 `speed=2` 时会出现无法
表达的半毫秒时间点。代价是聚合预览在 delay/speed 不同的节点间不是严格同步的时间轴——这可以接受，
因为容器播放头本来就只用于编辑预览，Preview 里每个节点仍有独立时钟。

### Auto-keyframe 拦截可动画属性命令

Auto-keyframe 是编辑会话状态，进入动画编辑时默认开启且可关闭。开启时 Editor 的 recording adapter
检查正式命令：可动画字段被转换为动画草稿操作，非动画字段继续派发文档事务。材料与 Stage 不识别
动画包，只使用注入的 dispatch/recording port。

新轨道在播放头大于 0 时自动以当前 authored/布局值创建 0ms 基础帧，并在当前时间写新帧；0ms 修改
只写一个帧。已有同时间帧直接更新。连续拖动或颜色编辑合并为一个动画会话历史项。

**Auto Layout 子节点的位置不录制。** Flow 容器的子节点位置由 Yoga 决定，拖拽产生的是 reorder 命令
而不是 LayoutItem 位置变更，把 reorder 解释成位置关键帧会产生与布局求解冲突的结果。这类拖拽保持
原有 reorder 语义，并发布一条说明性诊断；该节点的位置通道只能通过时间轴上的数值编辑写入 offset。

### 窄口径「添加轨道」只对 scale 开放

界面默认不提供"添加属性"，轨道由 Auto-keyframe 产生——这是设计稿的意图，也避免了一份没有语义的
空轨道列表。

但 scale 通道在 ComposeDocument 里没有 authored 对应字段（`ComposeTransform` 只有 `rotation`），
不存在可拦截的命令，纯 Auto-keyframe 会让它永远不可达。因此提供一个窄口径的「添加轨道」入口，
**只列出没有 authored 对应字段的通道**（v1 仅 scale）。位置、旋转、透明度、背景不出现在这个菜单里，
它们仍然只能由 Auto-keyframe 产生。这是对设计稿的一处有意偏离。

### 撤销栈路由由面板可见性与焦点决定

动画草稿的 Undo/Redo 独立于页面文档历史，两者共享同一组快捷键，因此必须有确定的路由规则：

动画面板可见**且**焦点位于动画面板内（时间轴或关键帧 Inspector）时，撤销作用于动画会话草稿；
否则作用于页面文档历史。切换路由时不跨栈撤销，也不合并两个栈的历史项。`@compose-ui/history`
面板只呈现页面文档历史，不显示动画草稿历史——草稿是未保存的会话状态，混进会话快照会让"回到某个
快照"的语义无法定义。

### 容器时间轴聚合、单资源编辑

时间轴范围按选区确定：选中 Hierarchy Entity 时使用自身；选中叶子时使用最近 Hierarchy 祖先；顶层
叶子使用隐式 Canvas。时间轴显示范围内全部后代 Animation，每个节点一条持续区间，下方显示自动识别
的属性轨道。当前只有一个动画资源处于可编辑状态，点击其他节点轨道可切换活动资源。

聚合预览范围取每个动画首个有效周期结束时间的最大值；loop 只展示一个正向周期，ping-pong 展示一个
往返周期。

底部动画面板使用现有 bottom Edge Group，横跨左侧、Canvas 与右侧区域；标签顺序固定为资源、动画、
命令、日志。

### 草稿与显式保存

时间轴编辑只修改带 Undo/Redo 的会话草稿；保存或 Ctrl+S 才按 expected revision 写 Provider。冲突
提供重新加载或显式覆盖，Preview 继续使用最后成功保存的 revision。

自动创建的槽位与当前节点映射先留在草稿；资源保存成功后再提交映射事务。理由与
`add-animation-asset-runtime` 的创建顺序一致：文档不得引用尚不存在的资源内容。

## 风险/权衡

- 命令拦截改变了编辑器最核心的写入路径 → recording adapter 是纯函数式的命令分类器，关闭录制时
  必须逐命令断言完全透传；这是本变更回归风险最高的部分。
- 两套撤销栈 → 路由规则显式化并单独测试，避免"看起来撤销了但撤的是另一个栈"。
- Spring 与 rAF 的非确定性 → E2E 使用受控播放头、禁用实时动画并在固定帧截图。
- 对设计稿的偏离（scale 添加轨道入口）→ 在此记录，并在实现后回填设计稿。
