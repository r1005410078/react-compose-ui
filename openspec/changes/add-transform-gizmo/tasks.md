## 备注

- 1.1 原写「全部屏幕尺寸恒定」。端到端暴露这条是错的：环压在对象本体上会把**拖对象**的手势
  接走，而动画模式下指示器默认打开、那正是「拖对象打关键帧」最常做的地方。240×140 的矩形抓
  1/4 处离中心 69px，固定 72px 的环恰好吃掉它——`animation.spec.ts` 与 `scene-animation.spec.ts`
  各红一条。改成：轴与把手屏幕恒定，**环跟着选区大小走并恒在轮廓之外**，小对象用最小值兜底。
  规范已同步改写并加了一条判别性场景。
- 4.2 的角度读数需要一个单字段的 `angle` 参数化：`core` 的 `ComposePointFieldKind` 与
  `commands` 那份逐字相同的联合各加一个取值。理由与 `radius` 逐字相同——到中心的距离对旋转
  结果没有任何影响，一个永远不影响结果的只读字段比没有更差。
- `stage.rotateTool` 快捷键动作（`Shift+R`）连同工具一并删除，没有为指示器开关另配键位。
- 1.1 之后又改了两处，都由实机使用暴露：
  - **轴上的把手从「一个方块」拆成「箭头平移 + 方块缩放」**，因此四角手柄不再是缩放的唯一入口。
    同时把三段的定位从「到中心的绝对距离」改成「到环的偏移」——环跟着选区走，绝对距离会让大
    对象上的箭头整个缩进环里，屏幕上是「圆里面两根短线」。平移的命中区只覆盖环外那一段，否则
    整条轴线会在对象上划出两条走廊，走廊里拖对象会静默退化成沿轴平移。
  - **指示器中心改读预览几何**：原先读冻结索引，理由写的是「拖环时中心不该漂移」——那句话只
    对旋转成立（基点本来就是旋转的不动点），而平移时它让指示器整场拖动都钉在原处。
- 缩放方块需要 `claimStageResize` 带一个**按下当刻的边偏移**：方块不画在被拖的那条边上，按
  绝对落点解算会让第一帧就把那条边挪到光标底下。四角手柄不置位，既有行为逐像素不变。
- 1.1 第三次改写，这次是把「环跟着选区走」整个推翻（调研 Rive 之后与用户确认）：
  - **全部尺寸屏幕恒定，环半径 80 在内**（方块 52 / 环 80 / 箭头 112）。跟着选区走的代价是
    指示器随对象无限长大——220×150 的盒子就把环推到 149、箭头推到 199，转过 90° 之后箭头落到
    图面之外（`transform-gizmo.spec.ts` 里因此不得不把平移排到旋转之前）。Rive、Unity、
    Blender 都是屏幕恒定。
  - **代价是接受的**：大对象上环压在本体上，落在那条 20px 命中带上的拖动是旋转而不是移动。
    `animation.spec.ts` 与 `symbol-to-nested-component.spec.ts` 原来抓 1/4 处，恰好落在带上，
    改成从中心偏 40/24（距离 47）抓取并写明理由。
  - **环与四角手柄的重叠改由层序解决**：环单独一层排在缩放手柄之下，轴仍在其上。SVG 里绘制
    顺序就是命中顺序。上一版那条「留白必须大于命中带半宽」的不变量随之删掉——它只在环恰好
    擦过四角时起作用、平时无从验证，而它的代价是环不能有固定大小。
  - 箭头命中段起点由 `环半径 + 命中带半宽` 推出，不再另取常量。
- 上一条那个「命中段只覆盖环外」当天就被实机推翻：画出来 112px 的箭头只有最外面 22px 能抓、
  方块只有画出来的 10px，于是环（整圈 20px 宽的带）成了唯一抓得住的把手——用户报的是「x 轴
  不能移动、xy 轴缩放也不行」。**看得见的与抓得住的必须是同一段**：命中带改成覆盖整条轴线
  （最里面 24px 留给对象本体，两条轴在中心交叉，否则「按住对象中间拖」会变成受约束移动），
  方块加一个 22px 的透明靶区。端到端相应改成抓**用户会抓的地方**——轴线中段、方块中心偏 4px；
  点几何中心的用例对这一类缺陷永远绿。
