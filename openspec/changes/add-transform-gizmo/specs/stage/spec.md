## ADDED Requirements

### Requirement: Rive 式变换指示器

宿主打开时，Stage MUST 在选区上画出变换指示器。它 MUST 由三种**形状不同**的把手组成，
MUST NOT 只靠颜色区分语义：

- **轴上的方块**（两个）：沿该轴平移，只写位置
- **圆环**：只写角度
- **中心的圆点**：只显示，标明「绕这里转」，v1 MUST NOT 可拖

两个东西长得一样而按下去做的事不同，是最难自己发现的一类缺陷；这与夹点按角色分三种形状是同
一条规则。

**中心与轴按选区大小分流**：

- 单选时中心 MUST 是该 Entity 的**旋转基点**，MUST NOT 是包围盒中心。指示器的价值正是把
  `Transform.pivot` 从 Inspector 下拉框里的一个属性变成图面上看得见的东西——绕错点转在第一帧
  就该看得见。两条轴 MUST 跟着该 Entity 的 `rotation` 转。
- 多选时中心 MUST 是选区包围盒中心、轴 MUST 轴对齐：那时没有单一基点，也没有单一 `rotation`。

推论 MUST 写在实现旁边：**斜轴上拖动会同时改 `offset.x` 与 `offset.y`**，因此「一个把手对应
一条轨道」不成立——指示器分开的是**位置与角度这两个通道**，不是位置的两个分量。视口没有旋转，
因此世界角等于屏幕角。

轴色 MUST 沿用 3D 工具的通行约定（X 红、Y 绿）。它是**结构色**而不是状态色：永远成对出现、
永远带箭头、永远钉在中心上，靠位置与形状先分开、颜色只作二次编码。为避让既有配色而另发明一套
的代价更大——用户从别的工具带来的直觉会全部作废，而那份直觉正是它不需要说明书的原因。

把手尺寸 MUST 屏幕恒定，MUST NOT 跟画布缩放一起变粗变长。

拖环时的角度读数 MUST 走只读读数那一条通道（与缩放的宽高读数同一个纯函数与同一套呈现），
MUST NOT 自带第二套标签样式——同一个数在两处呈现里对不齐，是各画一套的必然结果。

开关是 **chrome 的可见性而不是模式**：关掉时既有手势 MUST 一个字节都不变。Stage MUST NOT
认识「动画模式」这个词，开关 MUST 由宿主经 prop 传入。

#### Scenario: 指示器画在基点上而不是盒中心

- **WHEN** 一个旋转基点设在左边中点的对象被单独选中，且指示器已打开
- **THEN** 中心圆点落在该对象盒的左边中点上

#### Scenario: 轴跟着对象的旋转

- **WHEN** 单选的对象已经转过 30°
- **THEN** 两条轴同样倾斜 30°，而不是保持水平与垂直

#### Scenario: 三种把手形状各不相同

- **WHEN** 指示器显示出来
- **THEN** 平移把手是方块、旋转把手是圆环、中心是圆点，三者形状互不相同

#### Scenario: 多选换成包围盒中心与轴对齐

- **WHEN** 同时选中两个对象
- **THEN** 中心落在选区包围盒中心，两条轴水平与垂直

#### Scenario: 关掉之后别处手势不变

- **WHEN** 指示器关闭
- **THEN** 图面上没有把手，拖动对象本体、盒手柄与空白框选的行为与打开前一致

## MODIFIED Requirements

### Requirement: 受控工具模式与专属选区反馈

Stage MUST 接受受控的 `tool` 值并按它改变手势语义。工具集 MUST 只包含**没有其他入口**的
动作：`select`、`scale`、`draw-container` 与 `draw-text`。

以下工具值 MUST NOT 存在，因为各自都有严格不弱的既有入口：`marquee`（`select` 在空白处
拖拽即框选）、`move`（`MOVE` 命令能键入精确位移）、`pan`（空格与中键是随时可用的临时覆盖，
不占用工具状态）、`draw-line`、`draw-rectangle`、`draw-circle`、`draw-arrow`（各有对应的
绘图命令，且命令那一套严格更强——能键入精确坐标、能捕捉、能正交、能中途放弃上一点）、
`rotate`（变换指示器的圆环即旋转入口）。

**`rotate` 的删除判据与上面几个略有不同，MUST 记在这里**：它不是「有一个更强的等价入口」，
而是「它是一个**模式**，而指示器不是」。切到 `rotate` 工具之后，画布上**每一次**拖动的含义
都变了；打开指示器之后，只有**把手上**的拖动有新含义，别处一个字节不变。这正是「模式必须是
对象作用域且有明确的进出」区分的两类东西。指示器 MUST 覆盖 `rotate` 原本的全部能力（含多选
绕包围盒中心转），否则删除会留下缺口。

**制图几何 MUST 只有命令一套入口。**留着绘制工具会让同一件事有两套机制，还会让一处已知的
仲裁器冲突**用鼠标就能触发**：取点插件（`drafting-point`，1650）高于绘制（`draw`，1000），
两者同时武装时 `pointerdown` 被前者吃掉，拖动永远起不来。

`draw-container` 与 `draw-text` MUST 保留：它们不是制图几何，没有命令等价物，也不与取点插件
争抢——它们本来就是拖一个盒出来。

`select` 工具在空白处拖拽 MUST 框选，判定由拖拽方向归约得出（见 stage-engine 的框选判定
Requirement）。MUST NOT 存在任何可以覆盖方向的模式参数或宿主开关。

Stage MUST 为当前工具提供专属选区反馈：`scale` 显示缩放手柄，绘制工具显示落点预览。

**单选一条带 `Curve` 的 Entity 且工具是 `select` 时，选区 MUST 画它的几何轮廓，MUST NOT 画
选区矩形、Resize 手柄或边缘命中带。**判据是**盒是不是这个对象的轮廓**：矩形、图片、容器的盒
就是它们的轮廓，文字占满自己的盒，而一条对角线的包围盒里绝大部分是空的——那个矩形宣称了对象
并不占据的面积，且比线本身显眼得多。线越接近 45 度它越大，拖端点时还一直在变。

这条判据 MUST NOT 被读成「给曲线开特例」：同一句话在矩形上的答案就是画盒，在文字编辑态上的
答案是画盒但去掉填充。它也 MUST NOT 扩大到非曲线 Entity。

轮廓 MUST 与几何编辑会话画的是**同一条几何**（同一个派生入口），MUST NOT 另写一份——两份
实现的分叉症状是「双击前后线的轮廓差半个像素」，而那种偏移只在特定缩放下现形。几何编辑态下
它 MUST 由可编辑路径层绘制，选区层 MUST 让位：两层各画一条会重叠出一条更粗的线。覆盖层
MUST 保持不认识文档：世界折线由宿主派生后传入。

**`scale` 工具下 MUST 照旧画盒**与缩放手柄。盒不是错的，它只是不是轮廓；用户明确在做盒操作
时，盒就是他正在操作的那个东西。曲线的整体缩放能力因此没有消失，只是从「随时都在」变成
「进那个工具」。

**多选 MUST 照旧画整体包围盒**，MUST NOT 逐对象改画轮廓。多选框回答的是「这一堆的范围」，
那是一个用户接下来真的会操作的矩形，它不宣称任何单个对象的轮廓。

几何编辑会话 MUST 在轮廓之外**再加**夹点与十字光标，两态因此可区分；轮廓本身在两态都画，
进出会话时对象的呈现只**增减夹点**，不整体换一套。AutoCAD 把选中与夹点
合成一态是因为它没有单独的顶点模式；本产品有，而「能不能拖出一个新形状」必须一眼可辨。

#### Scenario: select 在空白处拖拽即框选

- **WHEN** 当前工具是 `select`，用户从空白处拖出一个矩形
- **THEN** 按拖拽方向归约出的判定选中命中的节点

#### Scenario: 专属选区反馈

- **WHEN** 当前工具是 `scale`
- **THEN** 选区显示缩放手柄

#### Scenario: 选中曲线不画包围盒

- **WHEN** `select` 工具下单选一条斜线曲线
- **THEN** 图面不绘制选区矩形，也不绘制 Resize 手柄

#### Scenario: 轮廓沿几何而不是沿盒

- **WHEN** `select` 工具下单选一条斜线曲线
- **THEN** 绘制的轮廓落在线身上；包围盒四角处没有轮廓

#### Scenario: scale 工具下盒与手柄回来

- **WHEN** 选中同一条曲线并切到 `scale` 工具
- **THEN** 图面绘制选区矩形与缩放手柄

#### Scenario: 非曲线 Entity 不受影响

- **WHEN** `select` 工具下单选一个矩形 Entity
- **THEN** 图面照旧绘制选区矩形与 Resize 手柄

#### Scenario: 多选仍画整体包围盒

- **WHEN** 同时选中一条曲线与一个矩形 Entity
- **THEN** 图面绘制覆盖两者的整体包围盒，而不是逐对象的轮廓
