# 设计：动画模式的变换指示器

## 1. 它分开的是「位置与角度」，不是位置的两个分量

轴**跟着对象的 `rotation` 转**（Rive 的做法）。推论必须写清楚：斜着的轴上拖一下会**同时**改
`offset.x` 与 `offset.y`，因此「一个把手对应一条轨道」这句话**不成立**。

这不是妥协——用户提的问题是「没明确要改角度还是位置」，指示器分开的正是这两个**通道**。
位置的两个分量之间从来没有歧义：拖出来的就是一个二维位移，写两条轨道是它的正确表达。

轴跟着对象转还有一个理由：转过的对象上，「沿它自己的长边挪」是用户读得懂的操作，而「沿屏幕
水平挪」在一个 30° 的刀身上没有对应的语义。

视口没有旋转，因此**世界角等于屏幕角**——与夹点方向角是同一句话，将来给视口加了旋转，这两处
会一起静默错位。

## 2. 画在基点上，不是包围盒中心

这是本变更真正的价值：**把 `Transform.pivot` 从藏在 Inspector 下拉框里的一个属性，变成图面上
看得见的东西**。刀闸的铰点因此第一次可见。

刚修掉的两处缺陷都是「绕哪儿转」出的错，而它们能潜伏到用户报上来，正是因为屏幕上没有任何东西
在说这件事。指示器一画出来，绕错点转在第一帧就看得见。

## 3. 三种形状，不靠颜色区分语义

方块（平移）、圆环（旋转）、圆点（只是标记）。**形状必须各不相同**——两个东西长得一样而按下去
做的事不同，是最难自己发现的一类缺陷（夹点按角色分三种形状就是这条规则）。

颜色照抄 3D 工具的通行约定：**X 红、Y 绿**。这块画布的颜色确实已经被占了好几层（捕捉橙、
选中蓝、框选蓝/绿、导线红、失效琥珀），但轴色是**结构色**而不是状态色：它永远成对出现、永远
带箭头、永远钉在选中对象的基点上，靠**位置与形状先分开，颜色只是二次编码**——与「端口实心
小圆 / 捕捉空心方框」是同一条规则。

为了避让而另发明一套配色的代价更大：用户从 Rive、Blender、Unity、Godot 带来的直觉会全部作废，
而那份直觉正是这个指示器不需要说明书的原因。

## 4. 环复用既有 rotate 会话

`rotationCenter` 刚改成「单选取该 Entity 自己的基点」，因此环的拖动**就是**一次 rotate 会话，
只是不需要先切工具。**不另写一份旋转数学**——另写的那份必然在 Shift 吸附、`baseRotation`、
并发中止三处里漏掉一两处。

## 5. 仲裁优先级 1200

- 低于 `path`(1400) 与 `paint`(1300)：那些是**别的编辑会话**的把手，指示器不该把它们偷走。
- 高于 `entity-select-move`(700) 与 `resize`(600)：圆环会横穿盒手柄与圆角把手，排在它们之下
  等于环在四个角上按不动，而那正是环最容易被抓到的地方。
- 高于 `draw`(1000)：把手是小靶区，绘图工具开着时点中它显然是冲着把手去的。

## 6. 多选也出现，只是换一套中心与轴

单选：中心 = 该 Entity 的旋转基点，轴跟它的 `rotation`。
多选：中心 = 选区包围盒中心，轴轴对齐——那时没有单一基点（各有各的 `pivot`），也没有单一
`rotation`，而绕包围盒中心转正是 `rotate` 工具原本的行为。

这条让指示器**完整覆盖** `rotate` 工具的能力，删掉它才不留缺口。

## 7. 开关是 chrome 可见性，不是模式

`rotate` 是**工具**，也就是模式：切过去之后画布上**每一次**拖动的含义都变了。指示器打开之后，
只有**把手上**的拖动有新含义，别处一个字节不变——把手是屏幕上几十个像素的靶区，不是一层覆盖
全画布的语义。

这正是决策 10「模式必须是对象作用域且有明确的进出」区分的两类东西，因此**图标取代 `rotate`
按钮**而不是并排多一个：并排等于旋转有两个入口，是「工具集只保留没有别的入口的动作」禁止的
那一类。

进入动画模式自动打开：那里误拖的代价最高（往时间线塞一条没打算要的轨道，而用户得先发现它），
设计模式下拖错了就是挪了一下、撤销即可。自动打开之后用户仍可以手动关掉——它是视图状态。

Stage **不认识「动画模式」这个词**，宿主用一个布尔 prop 打开它——与 `lockGestureParent` 是同
一条既有边界。

## 8. 旧的那一层整层删掉

Godot 风格旋转拉线（拉杆 + 末端圆点 + 角度标签 + 中心枢轴环）与指示器回答同一个问题，留着就是
同一件事画两遍。它还带着一处刚暴露的不一致：空闲时中心取 `screenBounds`（包围盒），拖动中取
`rotationPreview.center`（已改成基点），两者对不上。

拖环时的角度读数改走**只读读数**那一条通道（与缩放的宽高读数同一个纯函数与同一套呈现），
因此不再需要它自带的那套标签样式——同一个数在两处呈现里对不齐，是各画一套的必然结果。
