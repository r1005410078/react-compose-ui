# 设计：符号导线

## 1. 求解不存储，因此「移动后重解」那段代码不存在

存坐标的方案要在每一条改变实例位置的路径上挂钩子：移动、方向键微调、Inspector 改位置、
撤销、粘贴、导入、组件刷新。**漏一条的症状是「线错位」，看起来像渲染 bug 而不是数据 bug**，
因此最难定位。这与 CAD 侧块实例几何是同一条判断。

代价是导线的 `Curve` 在作者文档里是一份**会过期的缓存**。这不要紧：读的人永远读解算后的那份，
而作者文档里的值只在两处被用到——导线自己被编辑时的起点，以及绑定失效后的回退几何。

## 2. 求解住在布局 Runtime

导线求解需要两样：绑定实例的**盒**（求端口的父级坐标要用盒尺寸算旋转基点）与它的 `offset`。
盒的事实来源是布局快照，不是文档——实例的 `LayoutItem` 是 Hug，`value` 只是测量缺席时的兜底。

而求解**会改导线自己的盒**。于是「文档」与「快照」必须成对产出，否则命中读到的盒与渲染画出的
几何差一帧。仓库里已经有这条经验，写在动画那条路径上：

> 画布必须拿到「同一次求解」的文档 + 快照一致对……直接配对会让 stage 的几何索引抛错并卸载
> 整个画布。

布局 Runtime 正是唯一产出这一对的地方，因此求解放在它的 `ready` 状态里：**先解布局、再解导线、
再把导线的盒补回快照**（导线是绝对定位，改它的盒不影响任何人，因此不需要二次求解）。
编辑器、预览与动画三条路径各自零改动。

**一处风险与它的退路**：编辑器今天把**作者文档**与 Runtime 的快照配在一起交给 Stage，改成
交 Runtime 那份文档之后，Stage 看到的文档会比作者文档晚一次求解。这在今天其实已经存在——
快照没就绪时 Stage 拿到的是 `undefined`，它本来就跟着 Runtime 的节奏。若实测出现可见延迟，
退路是把求解改成两个渲染入口（Stage 与 Preview）各自的 memo：仍然只有两处，代价是那两处
必须记得配对。

## 3. 自由端不存点

`CadFreeEndpoint` 存坐标，是因为 CAD 的导线没有盒——它的几何只有两个端点。这里导线是普通曲线
Entity，`Curve` 就是几何。再存一份自由端坐标等于给同一个端点造两个事实来源，而两者迟早分叉。

因此 `Wire` 只回答一个问题：**这一端绑到了哪个端口**。缺席即自由。

## 4. 绑定来自取点，不是坐标反查

取点时已经知道落点来自哪个端口（`StageFeaturePoint` 带上 `portId` 即可）。按坐标反查看起来
更简单，但它会让**一条恰好路过端口的普通线**莫名其妙地绑上——用户没有表达过那个意图，而这个
绑定在屏幕上不可见，要等到符号移动时才现形。

`LINE` 不绑定、`WIRE` 绑定，同样是这条判断：绑定改变对象此后的行为，意图必须显式。

## 5. 拖端点即改接线

步骤 10 的夹点拖动已经过点输入管线，而 11a 已经把端口放进了那条管线的最高优先级。因此
「拖到端口上就绑到它、拖到别处就解绑」几乎是白拿的，它同时消掉一个怪现象：拖动一个绑定端点
会写 `entity.curve.set`，然后被下一帧的求解覆盖回去，看起来像拖不动。

提交时把 `Wire` 与 `Curve` 写在**同一个事务**里：分两条会产生一个可观察的不一致中间态
（几何已经动了、绑定还指着旧端口），撤销也会变成两步。

## 6. 悬空引用不让文档非法

CAD 在删除被绑定实体时把端点**冻结**成自由端点，理由是「留悬空引用会让整批删除被校验打回」。
那条理由在这里不成立——本仓库对同类情形已有另一条判断，写在实例动画上：

> `animation` 指向不存在的 id 时保留原值并在 Inspector 标为失效——「还没配」与「配错了」
> 必须可区分。

照它办：**绑定不完整**（缺字段）是文档非法，**指向不存在的实体或端口**只是解算失败。求解遇到
失败的一端就用作者文档里的几何兜底，Inspector 标为失效。于是删除路径一行不用改，也不需要
在核心的删除命令里去拿一份它没有的布局快照。
