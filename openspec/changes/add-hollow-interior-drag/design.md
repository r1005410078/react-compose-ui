# 设计

## 决策 1：分界线是「选没选中」，不是「空心内部该不该可点」

- **不动的一半**：没选中时，空心曲线**不以包围盒拦截指针**。外框套在符号外面时让盒可点会抢走
  里面每一个符号的点击。
- **改的一半**：选中之后，那个盒是一句承诺。原来那条理由在这一档不成立——对象已经选中了，
  「点的是谁」这个问题已经有答案。
- **只对自己的选区**：别人的盒不拦你。这正是「盒是一句承诺」这条理由的作用范围——没画盒的
  地方没有承诺可违背。

## 决策 2：只接管拖，不接管点

- **内容**：接管在 `pointerdown`，但一步没动就在 `commit` 里还原成单击本来的含义
  （`cancel` + 清空选区，也就是框选兜底的结果）。
- **原因**：既有规则写着「本能力 MUST NOT 改变任何一次单击的含义」。真接管了单击，盒内部
  就再也点不到下面的符号，而那正是被否掉的那条过宽做法。
- **判据是指针有没有离开过按下点**，不是「收没收到 `pointer.move`」：浏览器在 `pointerup`
  之前会补发一次原地的 move，原地单击同样收得到。夹点「点亮」用的是同一条判据。

## 决策 3：优先级 825，夹在双击进几何编辑与框选之间

- 比 `geometry-edit-fallback`（850）**低**：盒内部的双击属于几何编辑。双击的第一下会被本插件
  接管，但它一步没动，因此还原成清空选区——与今天逐字相同，第二下照旧进几何编辑。
- 比 `marquee-converge`（800）**高**：要接管的正是那些本来会变成框选的按下。外框通常画在场景
  里，落在它内部的点首先命中的是场景本身，因此必须排在容器体收敛之上。

## 决策 4：Shift 不接管

Shift 的含义是「加进选区」，从来不是「移动」。而从一个大外框内部起手做加选式框选是正当用法，
这也顺带给「没法从框内起手框选」这个代价留了一个出口。

## 风险 / 权衡

- **选中一个大外框之后，没法从它内部起手框选**（不按 Shift 时）。接受：先按 Esc 即可，而
  「拖了一下东西跑了」没有任何补救。Figma 取的是同一侧。
- 锁定或不可移动的目标返回 `null` 而不是 `'consumed'`，这次拖动照旧变成框选——否则锁住一个
  外框会让它内部的框选也一起失效。
