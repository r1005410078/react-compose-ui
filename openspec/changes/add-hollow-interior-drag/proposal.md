# 选中的空心图形，盒内部起手的拖动即移动它

## 为什么

画一个空心矩形（或圆、多边形），点描边选中它——图面上出现包围盒与八个手柄。从盒的内部往外
拖，量出来的结果是：

```
拖动中：marquee = 1      ← 拉出了一个框选框
移动量：dx = 0, dy = 0   ← 对象没动
松手后：选区 = 0          ← 它把自己取消选中了
```

所以那一下**不是没反应，是做了另一件事**：拉框选、顺带丢掉选中。用户读到的是「我抓着这个
东西拖了一下，它跑了」。

「空心曲线不以包围盒拦截指针」这条规则本身是对的——外框套在符号外面时，让盒可点会抢走里面
每一个符号的点击。但那条理由**只对没选中的对象成立**：一旦选中，「点的是谁」这个问题已经有
答案，而我们画出来的那个盒是一句承诺——「你正在操作的是这块面积」。内部是死的、还会反过来
取消选中，屏幕上就是写着一件事、做着另一件事。

## 变更内容

- 新增 `hollow-move-fallback` 插件（优先级 825，排在双击进几何编辑之下、框选之上）：
  选中的恰好是一个空心曲线、按下点落在它盒内、且这一下**本来会变成框选**时，接管这次手势。
- **只接管拖，不接管点**：一步没动就把这次按下还原成它本来的含义（框选兜底 = 清空选区）。
  单击照旧穿过去，双击进几何编辑那条路一个字不用改。
- **按住 Shift 时不接管**：Shift 的含义是「加进选区」，从框内起手做一次加选式框选是正当用法。

## 影响

- 受影响 specs：`stage`（空心图形的指针语义）
- 受影响代码：`packages/stage-engine/src/interaction-kernel/`（新插件 + 优先级表 + 登记处）
- **代价**：选中一个大外框之后，没法从它内部起手框选了，得先 `Escape`。Figma 就是这么取舍
  的；这一侧的代价明显更小——从框内起手框选可以先按一下 Esc，而「拖了一下东西跑了」没有任何
  补救。
