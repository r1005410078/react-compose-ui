## ADDED Requirements

### Requirement: 导线在顶点模式里的 Delete

Stage MUST 按**此刻有没有夹点被会话作用着**把 `Delete` 与 `Backspace` 分流，判据读的是拾取框
画不画读的**同一份事实**：没有夹点被作用着时删整个 Entity，有夹点被作用着时按那个夹点的种类
决定。顶点模式里**没有**夹点被作用着时 MUST 仍然删掉整条导线——进了这个模式就删不掉它，是一个
没有出口的状态。

导线上这一档 MUST 分成四种落地，四种说明 MUST 各不相同——「按了没反应」与「按错了地方」在屏幕
上无法区分，而这四种情形的补救办法各不相同：

| 此刻 | `Delete` |
| --- | --- |
| 端点方块被点亮，该端自由 | 删掉那个顶点 |
| 端点方块被点亮，该端绑在端口上 | 拒绝，说明那一端绑着端口 |
| 段条形被点亮，那是中间的一段 | 剪断那一段 |
| 段条形被点亮，那是端段或唯一一段 | 拒绝，说明只有中间的段可以剪断 |

只剩两个顶点时的顶点下限拒绝照旧，说明与上面四种都不同。

Stage MUST 向引擎注入「这一端绑着什么」与「这是不是导线」两个判据：引擎不认识导线，与夹点求解
的轴对齐选项是同一条既有边界。判据 MUST 读既有的「是不是导线」谓词，与导线 Preset、端口捕捉、
夹点会话钉死正交读的是同一个答案——各判一次的症状是「这条线在顶点模式里是导线、在画的时候不是」。

**拒绝与落地 MUST 分开**：落地之后被作用的那个夹点不再存在，它的取点会话跟着结束；而拒绝时
几何一个字节没动、夹点还在，顺手结束会话会把刚说出来的那句理由用「已取消」冲掉——用户按了一个
键，屏幕上只剩一句与他的动作无关的话。因此这一档 MUST 交出三种结果而不是一个布尔：落地、拒绝、
以及「这里没有答案」（交回既有级联，删整个 Entity）。

剪断产出的两条 MUST 在同一条事务里写入，撤销一步 MUST 回到一条。

#### Scenario: 点亮中间段按 Delete 剪断

- **WHEN** 在非 100% 缩放下双击一条四顶点直角导线，原地单击点亮中间那一段的段夹点，按 `Delete`
- **THEN** 那一段从图上消失，文档里多出一条导线
- **AND** 一次撤销回到一条

#### Scenario: 点亮绑定端的顶点按 Delete 不动几何

- **WHEN** 双击一条起点绑在符号端口上的导线，点亮起点方块，按 `Delete`
- **THEN** 命令行说明那一端绑着端口
- **AND** 该导线的顶点数与两端绑定都不变

#### Scenario: 端段上的段夹点按 Delete 说明原因

- **WHEN** 点亮一条三顶点导线第一段的段夹点并按 `Delete`
- **THEN** 命令行说明只有中间的段可以剪断
- **AND** 该导线的几何不变

#### Scenario: 顶点模式里不点亮任何夹点仍删整条

- **WHEN** 双击一条导线进入顶点模式，不点亮任何夹点，按 `Delete`
- **THEN** 整条导线被删除

#### Scenario: 拒绝之后夹点还亮着

- **WHEN** 点亮一条导线绑定端的顶点并按 `Delete`
- **THEN** 命令行显示的是那句理由，而不是「已取消」
- **AND** 那个夹点仍被会话作用着

#### Scenario: 四种说明互不相同

- **WHEN** 依次触发绑定端拒绝、端段剪断拒绝、顶点下限拒绝与普通曲线的段夹点拒绝
- **THEN** 命令行给出四句互不相同的说明
