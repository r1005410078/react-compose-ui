# 设计：组件实例的播放头

## 1. 绑定住在宿主侧，不住在组件文档里

这是整个提案唯一真正的决定，其余都是它的推论。

组件文档里的 `Animations.bindings.currentTime` 指名一个**导出**。要让八个刀闸各走各的，
就得让八个实例各自指向不同的导出名——而清单是数组，覆盖「数组只作为字段整体写入，绝不生成
数组下标路径」，于是每个实例都攒一份完整的 `items` 副本，以后组件作者改时长要改八处。

换个位置就没有这个问题：

```
页面文档
└─ Entity「刀闸 3」            ← 实例本身就是一个 Entity
   ├─ Renderer(component-instance)
   │    props.animation      = 'switch'
   │    props.animationTime  = 0
   └─ Bindings                ← 逐 Entity，本来就是
        rendererProps.fields.animationTime → 'sw3Position'
```

`Bindings` 是宿主页面上那个实例 Entity 自己的 Component。八个实例是八个 Entity，天然八份
绑定；组件文档一个字节都不用改，作者改时长仍然只改一处。

**顺带解释了一个既有事实**：`ResolvedComponentContent` 渲染嵌套文档时不传 `scriptScope`
（去看那一行，参数表里就是没有）。嵌套文档没有作用域，因此组件文档里那份 `Animations.bindings`
在实例内**永远解析不出任何东西**。以前这看起来像个待补的洞，现在它是正确的：绑定该在宿主侧，
嵌套文档不需要作用域。

### 被否掉的两条

- **重新引入「暴露属性」声明**（组件声明哪些参数可被实例覆盖，实例只填那个参数）。这层声明
  在 `remove-component-property-definition` 里被删掉过，理由是 `set-field` 严格更强。为了
  一个用既有机制就能表达的需求把它请回来，是往回走。
- **接受 `items` 整份替换，靠 Apply/Revert chrome 兜底**。兜底能让用户**看见**遮盖，不能让
  遮盖不发生。八份副本仍然是八份副本。

## 2. v1 只有 seek，没有时钟

现行规范说宿主对嵌套 Frame 的动画能力是「play、pause、seek 与播放模式」。本提案只做 seek，
并把规范收窄到 seek。

理由不是省事，是**刀闸本来就是状态不是动作**——合闸与分闸是两个方向，一个 `playing` 布尔
表达不了；现场还要能表示「停在半开」。用时间轴表达状态，业务侧给一个数就够了。

而做了 play/pause 就得在物料里养一个时钟：每实例一个 rAF、一份播放模式状态机（loop /
pingpong / once）、一份挂载与卸载的生命周期。这正是「导航会话没有 `dispose`」那条坑的形状——
一个持有资源的会话对象放进 React，StrictMode 的挂载→清理→再挂载会让它在首次渲染后就失效，
而端到端跑的是生产构建，全绿也挡不住。

**没有时钟的物料是一个纯函数**：`(document, animationId, timeMs) → document`。没有生命周期
就没有生命周期缺陷。要自动播放的实例，页面脚本自己驱动那个数——脚本作用域本来就有 Signal。

`autoplay` 与 `playbackMode` 在实例里因此**被忽略**，不是被尊重也不是被报错。

## 3. 播放头是毫秒，不是归一化的 0–1

0–1 有一条真实的好处：组件作者改时长不会打断已经绑好的页面。但代价是仓库里凭空多出第二种
时间单位——`timeMs` 在关键帧、清单、采样器、动画面板与预览播放里出现了几十次，多一种就意味着
每个读代码的人都要先判断手上这个数是哪一种。

而那条好处大半被**钳制**吃掉了：`animationTime` 钳到 `[0, durationMs]`，作者把动画从 1000ms
缩短到 600ms 之后，原本绑着 1000 的实例落在 600——仍然是「完全打开」，语义没变。

## 4. 不回退到「第一条动画」，且「配错了」与「还没配」可判别

`animation` 缺席或为 `null` **不采样**，不回退到清单的第一条。项目里已经有过这条判断：
「任何新建路径都不得回退到 `rootIds[0]`」。位置性回退在只有一条的时候看起来永远是对的，
等到有第二条时才错，而那时没人记得这里有个回退。

两种非法状态必须可区分，这条抄 `Interaction.navigate.target`：

| `animation` 的值 | 含义 | 表现 |
| --- | --- | --- |
| 缺席 / `null` | 还没配 | 合法，不采样，Inspector 不报警 |
| 清单里不存在的 id | 配错了 | 不采样，Inspector 把该项标成失效并保留原值 |

保留原值而不是静默清空：清空会让「组件作者临时改错了动画 id」变成「页面上的配置被吃掉了」。

## 5. 采样排在覆盖之后，且只作用于渲染

顺序是 `快照 → 实例覆盖 → 采样 → 嵌套 Yoga`。

覆盖表达**作者意图**，采样表达**此刻的呈现**。反过来的话，覆盖会去改一份已经被时间改写过的
文档，同一份覆盖在不同时刻算出不同结果。

采样结果不回写任何地方——实例渲染器本来就不派发命令。这与 CAD 那条「采样只作用于渲染，命中与
捕捉继续读作者文档」是同一条原则；在这里更强一些，因为实例内部在宿主编辑期的命中走的是投影，
读的也是作者文档。

## 6. 编辑期也采样，这是后果不是决定

value 绑定在 `editor` 模式下照常解析（只有 method 绑定被换成 no-op）。因此 Stage 上的实例会
显示在绑定值对应的那一刻，与 Text 绑定了内容之后 Stage 上就显示那段内容完全一致。不需要为
动画新增一条模式判断。

宿主的 `layoutSnapshot` 不构成冲突：预览的播放 Hook 有「宿主自带 `layoutSnapshot` 时必须禁用
采样」这条约束，因为那份快照属于基础文档；而**嵌套 Runtime 是实例自己创建、自己持有的**，
采样后的文档喂给它，它自己重解，宿主那份快照根本不参与。

## 7. PERF：时间一变，嵌套布局重解一次

采样产生新的 document 对象 → `layoutDocument` 变 → layout effect 里 `runtime.updateDocument`。
时间每变一次，那个实例的 Yoga 树重解一次。

这与页面级动画的成本形状**完全一样**（`useComposeAnimationPlayback` 也是采样后重解），因此
不引入新的性能类别。刀闸这类状态驱动的场景一次业务事件才变一次，代价可以忽略；页面脚本若
用 rAF 驱动一个实例做 60fps 动画，成本等同于给那棵子树做 60fps 布局——记为 `PERF` 注释，
不在本刀解决。

`applyComposeAnimationAtTime` 在无命中时返回**原引用**，因此 `animation` 为 `null` 或该动画
没有任何轨道时，`useMemo` 之后 `layoutDocument` 引用不变，一次多余的重解都不会发生。

## 8. `materials` 直接依赖 `@compose-ui/animation`

只用一个函数：`applyComposeAnimationAtTime`。

依赖方向成立：`animation` 是第 1 层（无 React、无 DOM，只依赖 `core`），`materials` 是第 3 层。
`materials` 现有依赖里 `layout-engine` 是同一个形状——同为第 1 层的 headless 领域包，同样只
为组件实例的嵌套 Runtime 而依赖。

否掉的替代：**从宿主注入一个采样端口**。那要让 `ComposeRendererProps` 多一个字段，Stage、
Preview 与实例递归三条路径各自把它往下传一层，而所有调用方注入的都会是同一个函数。为了一条
本来就合法的依赖方向，造一个只有一种实现的端口，是负收益。

`AGENTS.md` 里 materials 那行允许依赖清单要一起更新，并写明「`animation` 只用于组件实例的
嵌套文档采样」——与 `layout-engine` 那句现有的限定语并列。

## 9. 判别性用例

**组件测试（`materials`）**：同一个实例，`animationTime` 从 0 改到轨道终点，断言嵌套 Entity
的呈现值发生对应变化。修复前这条是红的——采样根本不存在，值恒为作者值。

**判别性在于「两个实例，两个不同的时间」**：只测一个实例的话，把播放头写死成全局单值的错误
实现同样能过。因此纵向用例必须放**两个**同一组件的实例，绑到两个不同的导出，断言它们在同一
帧呈现两个不同的姿态——这正是「粒度」这个问题在屏幕上的样子。

**端到端**：矩形 → 建旋转动画 → 存成组件 → 页面上放两个实例 → 页面脚本导出两个数 → 各自绑
`animationTime` → 断言两个实例的旋转不同。

**不写的用例**：实例内 autoplay 的行为（本刀不做，写了等于给未来的实现钉死一个没设计过的
语义）。
