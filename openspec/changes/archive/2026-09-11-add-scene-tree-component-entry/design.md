## 上下文

场景树已经能把组件实例的内部层级投影成该实例节点的后代（复合地址 `实例ID/内部ID`），
内部编辑写回 `instanceOverrides`；组件资源也已经能以独立 TransactionRuntime 作为文档标签
打开。两条通路都在跑，但**从画面上那个实例走到它的定义**这条路不存在。

Unity 的 Prefab Mode 是这件事的既有解法，且与本仓库的三层语义（主组件 / 变体 / 实例）
已经明确对齐过。调研到的关键一条是**它不开新窗口也不开新标签**：进入方式有五条（Hierarchy 上
选中实例按 `P`、点实例右边的箭头、Inspector 的 Open；Project 窗口双击、Project 里选中后 Open），
进去之后是同一个 Hierarchy 与同一个 Scene view 换了内容，Hierarchy 顶部长出一栏写着当前 Prefab、
用头栏里的返回箭头回退一步，打开第二个 Prefab 是替换第一个。

我们这边有一个便利条件：**文档本来就不是 Dockview 面板**，标签条是自己画的，Stage 只有一份、
按活动文档在文档之间切表面。因此「就地换一层」缺的不是一套新机制，只是把呈现与身份分开。

## 目标/非目标

- 目标：实例行上一个进入入口；进入后树只剩该组件的节点；一条能返回并还原来路选区的路径。
- 目标：进入**不产生文档标签**，一个 assetKey 至多一份会话。
- 非目标：Unity 的 *in context* 呈现（画布上把页面其余内容画成锁定背景）。
  Unity 的 Hierarchy 在 in-context 与 in-isolation 两种模式下**显示的东西本来就一样**，
  本变更要的那一半已经拿到；把页面其余内容画成背景需要在页面世界里就地渲染组件文档的独立
  Runtime 并锁掉其余内容，是另一件事。
- 非目标：Auto Save。见下方决策。
- 非目标：给投影出来的**内部实例行**也加箭头。投影回答的是「这一个实例内部长什么样」；
  要改嵌套组件的定义，先进外层组件，它的实例行在那里就是一个普通行、自带箭头。
- 非目标：把组件目录与资源目录的「打开」也改成层。那条入口的意图就是打开一份文件。

## 决策

- **决策：箭头进的是定义，不是这一个实例。**
  判据：树上已经有一个「改这一个实例」的入口——左边的展开三角。两个入口做同一件事，
  用户没法从界面读出差别，而「我刚才改的是一个还是全部」这个错在屏幕上完全看不见。
  考虑过的替代：把这一个实例单独隔离出来编辑——那是 override 编辑的第二个入口，与展开三角重复。

- **决策：进入不产生文档标签，而是压成当前文档之上的一层。**
  判据是**用户表达的意图**，而不是被打开的对象是什么：从场景树的箭头进去是「看一眼这个实例
  的定义」——当前画布的一次导航；从组件目录或资源目录打开是「打开一份文件来编辑」。
  两种意图分流成两种呈现，同一个对象两种呈现是对的；反过来按对象分流（组件一律是标签）
  会让一次顺手的下钻留下一条要自己关、还得记得存的标签，那正是这条改动要修的。
  Unity 只有前一种，因为它根本没有多文档编辑器；后一种是我们自己的产品事实（组件就是资源里
  的一份文件），不该为了照抄而删掉。
  考虑过的替代：进入也开标签但**打上「临时」标记**、切走即关（编辑器界的 preview tab）——
  那仍然占着标签条的一格、仍然有关闭按钮，而返回箭头与关闭按钮是两个含义不同却长得一样的出口。

- **决策：一个 assetKey 至多一份会话，且至多一种呈现。**
  身份归 assetKey，呈现归最后一次表达的意图。两份 runtime 指着同一份组件资源就是两个事实
  来源——在其中一处改完存盘，另一处还显示着旧的，而 revision 冲突处理要到保存那一刻才发现。
  因此进入一个已经开着的组件复用那份会话，它在层存续期间从标签条让位；目标会话已经在来路栈里
  时截断到它所在那一段，而不是再压一层（Unity 的面包屑点回去就是这个）。

- **决策：返回时按「进入前就已存在，或有未保存修改」决定层的去留。**
  干净的层返回即丢弃，零摩擦——那是最常见的情形（进去看一眼）。脏的层升格成标签：
  **未保存的修改必须在屏幕上有一个家**。进入前就存在的会话原样回到标签条，因为进入只是
  临时借用了它的呈现，不该顺手把用户开着的文件关掉。
  考虑过的替代：照 Unity 弹「保存 / 丢弃 / 取消」。Unity 必须问，是因为它那儿一旦离开就没有
  别的地方能看见这份未保存的编辑；我们有标签条，升格既不丢数据也不拦路，而对话框是把一个
  选择推给一个此刻只想返回的人。
  考虑过的替代：返回时一律保留为标签——那就把「不产生标签」这条改动原样退回去了，只是把
  标签的出现时机从进入挪到返回。

- **决策：不做 Auto Save。**
  Unity 的 Auto Save 是它那条「离开就看不见了」的补偿。我们的保存是显式的、带 revision
  冲突处理，自动保存会绕过冲突处理，而冲突正是多人改同一个组件时唯一会暴露问题的地方。

- **决策：层存续期间活动标签仍是来路那条。**
  Unity 的 Scene 视图面包屑第一段就是**场景**——你还站在那份文档上，只是进了它内部的一层。
  实现上因此不必让 controller、画布与 Inspector 改读一份新的「当前层」状态：活动文档 id 照旧
  指向层，只有标签条的**条目列表**与**高亮**改读来路。少一份状态就少一处会漂移的事实来源。

- **决策：树的隔离由活动文档给出，不新造模式。**
  进入 = 让那份组件文档成为当前文档；树跟着整棵换，是既有行为。因此「树只显示组件的节点」
  不需要写任何隔离逻辑。
  考虑过的替代：在树里加一个「进入中」的作用域状态——那会造出第二份「当前在编辑谁」的事实来源。

- **决策：说明分三处，每处只答一个问题。**
  画布工具栏那行「主组件 · 名称」已经在回答**这份文档是什么**，它不动。场景树的来路出口行
  回答**我在哪一层、怎么回去**。第三处是画布内容区一圈**不依赖文字**的强调色内描边，它只回答
  一个是非问题：画布上这份是**借来的一层**，唯一的出口是返回。
  必须有第三处，是因为标签条不再说这件事了：同一个组件作为标签打开与作为层进入，工具栏那行
  逐字相同，而场景树面板可以被折叠——那时用户分不出眼前这份该按关闭还是该按返回，而在组件里
  改一笔影响的是**所有**实例。Unity 同样多处都说（Hierarchy 头栏 + Scene 视图面包屑），
  in-context 还把场景其余部分灰掉。
  它**不是**被否掉的那条导航条：不可点、不表达路径、不占纵向空间，与本仓库「形状先分开、
  颜色再分开」的既有规矩一致。

- **决策：双击实例行 = 进入（对 Unity 的有意偏离）。**
  Unity 的 Hierarchy 双击是在 Scene 视图取景，不进 Prefab Mode。这里偏离的理由是：树上的双击
  目前**什么都不做**（既有规范明写它不进重命名），而「往下看一层」在树上由左边的三角承担，
  双击因此空着；Stage 上没有三角，双击才被征用成下钻一层。同一个手势在两块表面上含义不同，
  是**表面不同**造成的，说得清；我们的取景是「适配选择」，本来就不在双击上。

- **决策：箭头常驻，不是悬停才显形。**
  省下的密度只在实例行上，而代价是这条能力不可发现。位置排在眼睛与锁**之后**、贴最右——
  那两个作用于树内，箭头离开这份文档。

- **决策：不占 `Escape`，不给裸字母快捷键。**
  树里的 `Escape` 已经是取消重命名与取消拖拽，第三个含义会让这颗键的效果取决于看不见的状态。
  Unity 用 `P`，而这里 `P` 已经归 `PLINE`；七个绘图裸字母键本来就是最容易撞的一类。

- **决策：协议里加的是 `canEnter` 而不是 `nodeKind: 'component-instance'`。**
  `scene-tree` 不认识资源、`assetKey` 或组件协议。`canEnter` 与 `enter` 是纯结构词，
  宿主决定它意味着什么。层与标签的分流同样一个字都不进树的协议——树只知道「有地方可回」。

- **决策：进入栈是会话状态。**
  不写文档、不进撤销历史、不进偏好。它回答「我这一刻在哪儿」，与工作区布局那种「我想怎么看」
  不是一回事，关掉编辑器就该没有。

- **决策：返回后的选区还原走「待还原 + 到位再应用」，不在切文档的同一拍里设选区。**
  切当前文档要经过宿主的 `onActiveSessionChange` 才换到目标 runtime，同一拍里设选区会被
  当前文档的选区校验丢掉。因此记下待还原项，等目标文档真的成为当前文档、且那些 id 确实
  存在时再应用。

## 风险/权衡

- 层没有关闭按钮，唯一出口是返回。这是有意的：返回箭头与关闭按钮长得一样却含义不同，
  两个都给等于让用户猜哪个会丢掉他的改动。
- 用户原本开着一条干净的组件标签，进入同一个组件再返回——标签回到原处（「进入前就已存在」）。
  这条规则的代价是要记一个「进入前在不在」的布尔，收益是不会顺手关掉用户开着的文件。
- 用户在栈中途关掉来路那条页面标签 → 栈截断到最长的一段仍然活着的前缀；不足两段即整条消失，
  根行不再是来路出口。
- 当前文档被切到栈外的标签 → 整条来路丢弃。来路必须描述当前屏幕上这棵树，否则根行会给出一个
  通往别处的返回控件。
- 画布的模式提示占一圈描边的视觉预算。它只在层存续期间出现，页面文档上一个像素不变。

## 迁移计划

无。新增字段与 props 全部可选，未声明 `canEnter` 的宿主行为不变；从组件目录与资源目录打开
组件文档的行为一个字节不变。

## 待解决问题

- 投影出来的内部实例行是否也该能进入：v1 不做，理由见非目标；若将来要做，`canEnter` 协议本身
  已经够用，只需宿主解析复合地址上的内层引用。
- 层里保存之后想留下继续编辑，眼下要从资源浏览器再打开一次（那条入口会把它升格成标签）。
  是否值得在层上给一个显式的「在标签中打开」，等有人真的抱怨再说——多一颗按钮就多一个
  与返回箭头争抢注意力的出口。
