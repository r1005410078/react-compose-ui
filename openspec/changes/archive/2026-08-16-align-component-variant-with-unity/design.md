## 上下文

数据层已具备 Unity 同构能力；产品层入口与图标让一般程序员难以区分主组件、变体、实例。
调研结论：

- **Unity**：拖资源进场景 = 实例；实例拖回 Project 选 Variant = 新建变体资源；Variant 图标蓝块+条纹。
- **Figma**：实心菱形 = Main，空心菱形 = Instance；拖 Assets = 实例；无 Unity 式「实例→继承变体」主路径。
- 团队决策：产品用语**保留「变体」**；模型**对齐 Unity**，不对齐 Figma 状态表。

## 目标 / 非目标

### 目标

1. 固定三层中文叙事与图标规则（主组件 / 变体 / 实例）。
2. 拖入与复制只产生实例；创建变体仅显式入口。
3. 从实例创建变体的闭环对齐 Unity（固化覆盖 + 默认改绑实例）。
4. 库、场景树、属性头信息一致，无需先懂 Unity/Figma 术语。
5. **修复缺陷**：实例本层覆盖可可靠 Apply 到直接父源（引用 Base 时即写回主组件），
   且场景快照与其他实例同步路径可用。

### 非目标

- Detach、跨 Provider、Figma Variants、换 base、ComposeDocument v7。
- 重写覆盖代数或删除 instanceOverrides。
- 完整复制 Unity Prefab Mode 全部 UI。

## 决策

### 1. 三层模型（程序员说法）

```text
主组件 = 模板（库）
变体   = 在模板上固定了一批改动的新模板（库，仍可跟着父更新）
实例   = 页面上用了某个主组件或变体的那一个（还可再本地改）
```

内部标识仍用 Base / Variant / component-instance。

### 2. 放置语义（对齐 Unity 默认）

| 用户动作 | 结果 |
|---|---|
| 库/资源拖入画布 | 仅 `component-instance` 实例 |
| 复制页面实例 | 新实例，同一 reference |
| 创建变体… | 新 Variant 资源；默认当前实例 reference → 新变体 |

禁止：拖入/复制自动 `createComponent` 新 Variant 文件。

### 3. 实例 → 变体（对齐 Unity 对话框）

```text
输入：页面实例 E，引用 R，本层 overrides O
输出：
  1. 新 Variant V：parent = R，overrides = O（结构操作）
  2. 默认：E.reference = V，E.overrides 清空（已固化进 V）
  3. 可选（二期）：仅创建 V，E 不变
```

创建对话框文案示例：

> 将把当前实例的本地改动另存为**变体**（组件库资源），并默认让本实例改用该变体。

### 4. 图标

- 全产品统一组件符号形（建议立方体或菱形，与场景树一致）。
- **主组件**：实心填充。
- **变体**：空心描边（实现简单）或实心+侧条纹（更 Unity）；提案默认 **空心 = 变体（库）与实例（页）共用空心，库内变体副标题「基于 xxx」区分实例**。
- 若空心同时用于「库变体」与「页实例」：靠**位置**（库 vs 页）+ 属性头「实例」文案区分——与 Figma「空心=实例」一致；库变体再加「基于」即可。

备选（更贴 Unity）：

- 库主：实心蓝块  
- 库变体：实心+条纹  
- 页实例：空心  

实现选一种写入 tasks，避免三套并存。

### 5. 文案

| 位置 | 文案 |
|---|---|
| 库列表主组件 | 名称 |
| 库列表变体 | 名称 + 副标题「基于 {父显示名}」 |
| 页实例属性头 | 「实例 · 与源同步」/「N 项本地覆盖」 |
| 打开主组件文档 | 「主组件」 |
| 打开变体文档 | 「变体 · 基于 {父}」 |
| 创建动作 | 「创建变体…」不变；说明用上表 |

### 6. 与 unify-component-instance-surface 关系

实例 chrome（头栏工具、statusSlot）继续用于**实例**；变体文档会话继续用变体覆盖面板，
文案改为「变体」叙事并显示父名。不强制两套面板像素级相同，但术语一致。

### 7. 缺陷：实例可改、无法写回主组件

**现象（用户报告）**：可编辑页面上其他实例的外观/结构，但无法把改动 Apply 回主组件。

**可能根因（实现排查方向，实现阶段验证）：**

1. **编辑未入 `instanceOverrides`**：根属性经 `instanceRootSelection` 应写覆盖；若误写宿主
   Entity 或未生成 ops，则 Apply 时 `operations.length === 0` 直接返回，父源不变。
2. **Apply 后场景事务失败**：`applyComposeInstanceOverrides` 已 `saveComponent`，但
   `setRendererProps` 未 committed → 用户见「事务未提交 / 来源已保存但实例未更新」，
   且无清晰重试；其他实例也不一定刷新。
3. **UI 禁用或文案**：无本层覆盖列表时 Apply 全部禁用，用户以为「不能写回」。
4. **引用不是 Base**：实例挂在变体上时 Apply 只进变体；用户期望「主组件」需二次 Apply 或
   打开变体再写父——产品需文案说明。

**修复要求：**

- Red：e2e/单测「引用 Base 的实例改根外观 → Apply → Base 文档含该外观 → 本层覆盖清空 →
  第二实例检查更新或自动同步可见」。
- 保证 instanceRoot / 结构编辑路径稳定写入 overrides。
- Apply 全链路：资源保存 + 场景提交；失败可区分「父未写 / 父已写场景未更」并支持重试更新实例。
- 写回主组件时 statusSlot 使用明确成功/失败文案（如「已写回主组件」）。

## 风险 / 权衡

| 风险 | 缓解 |
|---|---|
| 创建变体默认改绑改变现有用户预期 | 对话框说明；changelog；测试覆盖 |
| 空心图标既表示变体又表示实例 | 位置 +「实例」文案；或采用 Unity 条纹方案 |
| 一般程序员仍混淆 | README/帮助一条：「变体在库里，实例在页面上」 |

## 迁移

- 无 Asset schema 破坏。
- 既有变体/实例资源只读行为不变；仅新产品默认与 UI。
