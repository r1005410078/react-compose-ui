# 选中的空心图形，它的包围盒在容器里同样归它

## 为什么

「选中之后盒内部起手的拖动即移动它」这条能力**一进容器就失效**。同一个选中的空心矩形，只换
它画在哪里，单元测试量出来的结果是：

| 矩形画在哪 | 拖它的包围盒内部 |
|---|---|
| 场景空白上 | `entity.transform.set → hollow` ✅ 移动矩形 |
| **一个普通容器里** | `selection.change → ["box"]`，然后 `transform.set → box` ❌ **选中并拖走了容器** |

成因在守卫条件上。插件只接管**本来会变成框选**的那一下：

```
if (event.hit.kind !== 'surface' && !convergent) return null
```

而 `convergent` 要求命中目标是 `rootIds` 的**直接成员**，也就是场景
（`marquee-plugin.ts:181`）。普通容器不是场景，于是插件放弃，`entity-select-move` 接手，
选中并拖走了容器。

这不是一个边角情形：这个产品里的空心矩形是设备外框、柜体轮廓与分区框，它们**几乎总是画在
某个容器里**。那条能力因此在它最常出现的地方不成立，而立项时写下的症状原样回来了——用户
抓着一个东西拖了一下，动的是别的东西。

同一处还留着第二个洞：盒内部**原地单击**会清空选区，也就是说「点一下自己的盒」等于「取消
选中自己」。盒与八个手柄是一句承诺，而点在承诺的那块面积里把承诺撤销了。

## 变更内容

- 守卫多认一档：命中目标是这个空心图形的**祖先**时同样接管。祖先是 `surface` 与
  「会收敛成框选的顶层容器体」之外**第三个**独立理由，两条既有条件原样保留，因此不产生任何
  回归。
- 盒内部**原地单击**不再清空选区：它保持选中。一步没动时只取消会话，不再发任何选区效果。

## 影响

- 受影响 specs：`stage`（「选中的空心图形，盒内部起手的拖动即移动它」一条）
- 受影响代码：`packages/stage-engine/src/interaction-kernel/hollow-move-fallback-plugin.ts`
- **不影响未选中的对象**：未选中时照旧只有那一圈描边可点——「外框套在符号外面时让盒可点会
  抢走里面每一个符号的点击」那条理由一个字不动
- **不影响命中**：DOM 点选、场景索引与框选三条路径一行不改
- **归档次序**：本变更修改了 `add-hollow-interior-drag` ADDED 的那条 Requirement，归档 MUST
  排在它之后
