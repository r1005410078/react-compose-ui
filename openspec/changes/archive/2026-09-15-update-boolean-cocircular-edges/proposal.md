# 共用弧边界的两块面也能做布尔运算

## Why

两个对象**共用一段曲线边界**时，布尔运算报「求解退化」。这是用户报的那张图的最后一档：两个
相交的圆用油漆桶填出三块面，全选求并集——三块面两两都贴着同一条弧。

根因不是容差不够，是**同一段弧在图里存了两份，而这两份差得比浮点误差大得多**。每块填充
各自把它的边界写进文档：几何按 `COMPOSE_GEOMETRY_PRECISION` 舍到两位、盒尺寸也舍到两位，
读回来时再由三点定圆反解成弧。于是本该逐位相同的两条弧，**圆心差到 0.033、半径差到 0.039**
（量出来的，见 design）。

平面图把它们当成两条**几乎共圆但不重合**的边：
- 两两求交在这一档给出的是**无意义的交点**（量到一对near-coincident 圆报回了 `(100, 100)`
  这个圆心位置上的「交点」），子边因此在乱七八糟的参数上被切开；
- 「叠在一起的两条边收成一条」那条既有退化处理够不着——它要求两端节点相同，而这两条的端点
  差 0.007，节点合并容差只有 3.2e-5；
- 于是射线在几乎同一个距离上穿过两条边，每一个候选方向都退化，整块面求不出来。

上一个变更（`add-boolean-arc-path-operands`）里试过**只补节点合并容差**，当时的结论是「产出
一个几像素大的退化形状」，因此撤回并在 `curve-boolean.ts` 留了注释挡住。这一次在这个夹具上
重新量了一遍：**只补容差连报错都没改掉**，仍是 `degenerate`。归一才是主干，容差只是它的配套。

## What Changes

- **平面图建图之前先做支撑归一**（`core/curve-arrangement.ts`）：轨迹重合的片段归到同一条
  支撑（同一条直线 / 同一个圆）上，组内选一条**确定性的**规范支撑，成员全部重算到它上面。
  判据 MUST 是**轨迹**（取样点到对方支撑的偏差）而不是拟合参数——量到重合的两条弧圆心差
  0.033 而轨迹只差 0.0087，按参数判会把它们判成两条不同的边。
- **同一条支撑上的片段之间不求交，改为按对方端点切开**：它们之间没有横穿的交点，只有重叠。
  既有的叠边去重在切开之后自然收掉重复。
- **节点合并容差补上一个下限：这批片段所在空间里的一个坐标量化步长**。两份分别存进文档的同一
  个点本来就能差这么多。这一条**单独不成立**，必须与归一一起落地——这是上一次撤回的那条，
  这一次它的前提被补上了。
- **零长子边一律丢弃**，不再只丢线段：归一之后弧也会退化成零长。
- **量化步长由调用方给出**（`stage-engine`）：它等于文档精度的步长乘上「几何 → 盒」与
  「盒 → 世界」两段缩放，只有调用方知道这两段。缺省取文档精度的步长（盒与几何 1:1 时就是它）
  ——缺省偏小只会让归一够不着、退回今天那个**看得见**的失败，方向是安全的。
- 文案不变：真正认不出的自由曲线仍以 `bezier` 拒绝。
