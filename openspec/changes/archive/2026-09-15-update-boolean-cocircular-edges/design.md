# 设计：共用曲线边界的归一

## 量出来的数

夹具是用户那张图的最小形式：两个半径 60、圆心相距 60 的圆，油漆桶填出左月牙与透镜两块面，
各自走一遍**真实的往返**（求面 → `normalizeComposeCurveGeometry` → `projectComposeCurveToBox`
→ 回到世界 → `composePathAsOutline` 认回弧）。

两块面共用的那两段弧，按**拟合参数**比：

| | 圆心差 | 半径差 |
|---|---|---|
| 最好的一对 | 0 | 7.1e-15 |
| 最差的一对 | 3.3e-2 | 3.9e-2 |

按**轨迹**比（A 上 65 个取样点到 B 所在圆的径向偏差的最大值，只看角度范围重叠的那些）：

| 配对 | 角度覆盖 | 径向偏差 |
|---|---|---|
| 真正重合的一对 | 100% / 100% | 2.1e-14 |
| 真正重合的另一对 | 100% / 100% | **8.7e-3** |
| 不重合的各对 | — | **5.3e+1** 起 |

**结论**：按参数判分不开（0.039 的圆心差与一个量化步长同量级，判据无从落脚）。

## 判据返工了一次：轨迹偏差 → 共同拟合的残差

第一版判据是「A 的取样点到 B **拟合出来的**支撑的偏差」。它在上面这个半径 60 的夹具上成立
（重合 ≤ 8.7e-3，不重合 ≥ 53），换到端到端用的半径 120 就不成立了——那张图上同一个圆的边界
被切成五条子弧，它们两两的偏差最大 **0.054**，是点本身存储误差的五倍还多。

原因是那条判据在**外推**：一条 48° 的短弧由量化过的控制点反解出来的圆，圆心误差会被放大
`1/(1−cos(θ/2))` 倍，评估到半圈之外时误差跟着放大。放大倍数由弧的跨度决定，因此容差没有
可推导的来源——只能取一个魔法数，而本仓库不收魔法数。

改成**共同拟合的残差**：把两条片段的取样点放在一起拟合出一条支撑，取最大残差。它问的是
「有没有一条支撑同时容得下这些点」，是**内插**，误差上界就是点自身的存储误差。量出来：

| 半径 | 同一个圆上的片段，残差最大 | 不同圆之间，残差最小 |
|---|---|---|
| 60 | 3.0e-3 | 5.76 |
| 120 | 5.7e-3 | 11.5 |
| 400 | 4.7e-3 | 38.4 |

同圆一侧**不随半径漂移**且始终在一个量化步长（0.01）之内，异圆一侧隔着三个数量级。容差因此
取一个量化步长，而这个数是推出来的不是试出来的。

这与上一个变更里那条「**验证落在轨迹上而不是拟合参数上**」同源，但更进一步：那一条说的是
别看参数，这一条说的是**连轨迹都别拿对方的参数去算**。

## 容差的来源

归一容差取 **一个坐标量化步长**：`10 ** -COMPOSE_GEOMETRY_PRECISION`，也就是 0.01。

推导：同一个点被两块填充各自存进文档，各自舍到两位，因此两份最多差一个步长；盒尺寸也舍到两位，
经 `projectComposeCurveToBox` 折算成几何上的位移，在 120 单位的盒上再添不到 0.005。合起来的上界
约 0.012，量到的最差值 8.7e-3 落在里面。

它**不是**相对量。相对量（今天的 `NODE_EPSILON_RATIO * 包围盒`）在这一档只有 3.2e-5，比误差
本身小了两个数量级——那正是既有叠边去重够不着的原因。

**偏小的方向是安全的**：归一够不着就退回今天那个「求解退化」，是一个**看得见**的失败；偏大
才危险（把两条真的不同的边收成一条，产出一个用户没画过的形状）。当前的余量是 5300 倍，因此
调用方漏传一个放大过的量化步长时，结果是失败而不是错答案。

## 节点容差的下限也是推出来的

同一个角点被两个对象各自写进文档时，每一轴上差一个步长来自几何自身的舍入、再差一个步长来自
归一化偏移的舍入，因此两轴合起来的距离上界是 `2√2` 个步长。量过：端到端那张图上同一个角的
两份相距恰好一个步长，落在这个上界之内。

## 三件事必须一起落地

单独任何一件都不成立，这一点有量过的证据：

1. **只补节点合并容差**（把 epsilon 抬到 0.01）：这个夹具上仍然 `degenerate`，一点没改。
   上一次撤回它时看到的「几像素大的退化形状」是另一个夹具上的表现，方向一致——容差只是让
   求解跨过某一关，答案仍然是错的。
2. **只做归一不补容差**：归一之后两条弧落在同一个圆上，但它们的**端点**仍差 0.007，是两个
   不同的节点，环还是接不起来。
3. **不丢零长子边**：归一 + 容差之后，按对方端点切出来的那两截尾巴长度落在容差之内，两端
   并成同一个节点。既有代码只丢零长**线段**，零长的弧会留下来，绕行走到那里读不出朝向。

## 规范支撑怎么选

组内选一条代表，全组重算到它上面。选法 MUST 与**输入顺序无关**——同一批对象换一个选择顺序
就选出另一条支撑的话，同一次运算会写出不同的产物，而屏幕上没有东西解释为什么。这与既有那条
「同一块面，从哪儿点都 MUST 写出同一个环」是同一条判断。

因此按支撑自身的数值做**字典序**取最小：圆按 `(cx, cy, r)`，直线按它的规范式
`(nx, ny, c)`（单位法向定向到上半平面，共线的两条因此得到同一组数）。

**不取平均**：平均依赖组的成员集合，而成员集合依赖容差的传递性——A 与 B 重合、B 与 C 重合而
A 与 C 差得刚好超一点时，分组结果取决于扫描顺序。取字典序最小让「代表是谁」只由组里出现过的
支撑决定。

## 为什么不在别处修

- **不改协议**（给填充存「这条边与谁共用」）：那是既有那条「MUST NOT 存边级引用」的禁令——
  存了就要回答「这条边是与哪个对象的第几个交点」，而一条直线穿过一个圆有两个交点。
- **不提高存储精度**：`COMPOSE_GEOMETRY_PRECISION` 是全仓库的显示与写入精度，为一处求解改它
  会让每一处读数跟着变。而且提高精度只把误差推小，不改变「两份独立存储」这个结构。
- **不让填充重求时复用邻居的边**：跟随那一侧是 O(k²) 的按清单重求，它连**邻居是谁**都不问。

## 归一也让求面受益，因此住在共用那一层

`buildGraph` 是求面与布尔共用的一层。油漆桶点一块由既有填充边界围出来的面，踩的是同一个坑。
按既有那条「各写一份的话，下一个改退化处理的人只会改到其中一处」，归一 MUST 落在共用层，
两个调用方都把自己的量化步长传下来。
