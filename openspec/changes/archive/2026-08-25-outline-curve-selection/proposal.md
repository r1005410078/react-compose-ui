# 选中一条曲线时画它的轮廓，不画包围盒

## Why

选中一条斜线，图面上出现的是一个**巨大的轴对齐矩形**加八个手柄，而线只是它的对角线。线越接近
45 度，这个矩形越大；拖端点时它还一直在变。用户的原话是「包围盒会不断变大，很疑惑」。

调研两边的做法，结论一致——**都不给线画轴对齐矩形**，但路子不同：

| | 做法 |
| --- | --- |
| AutoCAD | **根本没有包围盒**。选中的对象画成加粗高亮的线本身，夹点落在端点与中点上 |
| Figma | 线的 `height` 是 **0**，方向由 rotation 承载，因此框天然贴着线。**这只是 Line 工具的特判**——钢笔画的两点路径是 vector network，框仍是轴对齐的 |

### 为什么不照搬 Figma

两个各自独立的阻碍：

1. **我们的选区框本来就不跟旋转。**`screenBounds = worldRectToScreen(selectionBounds)`，
   `SelectionLayer` 画的是一个轴对齐 `<rect>`；旋转过的矩形今天也是画一个更大的 AABB。
   把线的方向搬进 `Transform.rotation` **并不会让框贴合**——照搬 Figma 的前提是先做「有向
   选区框」这件大得多的事。
2. **`rotation` 是独立且可打关键帧的属性。**把方向存进它，意味着拖端点要回写 `rotation`，
   与旋转动画轨道抢同一个字段；而且它只对两点直线成立，弧与多段线无解——Figma 自己也只对
   Line 工具特判。

### 为什么这不是一条新判断

`selection-layer.tsx` 的注释里已经写着几何编辑不画框的第一条理由：

> **盒不是曲线的轮廓**（一条对角线的包围盒里绝大部分是空的，这正是命中不按包围盒判的那条
> 理由的视觉版本）

这句话**在普通选中时一字不差地成立**。它当初只被应用在几何编辑上，是因为那一刀只碰几何编辑。
这一刀把它扩到普通选中，不引入任何新原则。

## What Changes

- **单选一条曲线且工具是 `select` 时**：沿真实几何画一条高亮轮廓，**不画**选区矩形、八个
  Resize 手柄与四条边缘命中带。
- **`scale` 与 `rotate` 工具下照旧画盒**与各自的手柄：盒不是消失了，只是不再是**默认**呈现。
  用户要做的是盒操作时，盒就在。两个工具都已存在于工具栏，不新增入口。
- **双击进入几何编辑仍然多给夹点**：选中 = 轮廓，几何编辑 = 轮廓 + 夹点 + 十字光标。
  AutoCAD 把两者合成一态（它没有单独的顶点模式），我们有，因此夹点留给它——两态必须可区分。
- **多选照旧画整体包围盒**：那个框表达的是「这一堆」，不是某个对象的轮廓。混选线与矩形时
  不做逐对象呈现。

## 用现成的东西

`stageCurveOutline(document, index, entityId)` **已经存在**——几何编辑的轮廓就是它画的。
`rotate` 与 `scale` 已经是独立工具，旋转把手本来就只在 `tool === 'rotate'` 下绘制。
因此这一刀**不需要任何新能力**：宿主多派生一条世界折线，覆盖层多认一个输入。

## Impact

- Specs：`stage`（一条 MODIFIED）
- 代码：`packages/stage/src/stage-overlay/`（`selection-layer`、`resize-handles-layer`、
  `overlay-types`）、`packages/stage/src/stage-surface/`（派生轮廓）
- **文档零改动**：盒仍在 `LayoutItem` 里，命中、框选、Auto Layout、Inspector、动画一行不改，
  没有迁移。这一刀纯粹是呈现。

## 明确不做

**Inspector 的尺寸 W/H 不动。**「不断变大」在属性面板上也表现为拖端点时 W/H 一直跳，
Figma 对线显示 W=长度、H=0。那是**另一件事**——它要回答「曲线的尺寸该是什么」，而本刀只回答
「选中时画什么」。单独立项。
