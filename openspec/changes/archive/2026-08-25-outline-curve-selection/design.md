# 设计说明

## 判据是「盒是不是这个对象的轮廓」

这一条已经在仓库里被应用过两次，结论各不相同，但用的是同一句话：

| 对象 | 盒是它的轮廓吗 | 选中时画什么 |
| --- | --- | --- |
| 矩形、图片、容器 | 是 | 盒 |
| 文字（编辑态） | 是——文字占满自己的盒 | 盒，只去掉填充 |
| 曲线 | **不是**——盒里绝大部分是空的 | 几何轮廓 |

因此这一刀**不是给曲线开特例**，而是同一条判据第三次给出它自己的答案。判据本身一个字没改。

## 为什么 `scale` / `rotate` 下要把盒画回来

盒不是错的，它只是**不是轮廓**。当用户明确在做一件盒操作时——按比例缩放、绕盒心旋转——盒就是
他正在操作的那个东西，此时不画反而说不清手柄从哪来。

这也解决了「拿掉盒之后怎么缩放曲线」：能力没有消失，只是从「随时都在」变成「进那个工具」。
两个工具都已存在，不新增入口，也不违反「模式必须是对象作用域且有明确的进出」——工具本来就是
显式进出的。

## 为什么选中不给夹点

AutoCAD 选中即出夹点，因为它**没有单独的顶点模式**：`Command:` 提示下的夹点就是它的选中态。
我们有——双击进入的几何编辑会话是一条已经交付的能力，还带着十字光标、拾取框与热夹点两级
`Escape`。

如果选中也出夹点，两态在屏幕上就只差一个十字光标，而用户无法判断自己在哪一态——**能不能拖出
一个新形状**这件事必须一眼可辨。因此：

```
选中           轮廓
几何编辑       轮廓 + 夹点 + 十字光标 + 拾取框
```

轮廓在两态都画，是有意的连续性：进出几何编辑时对象的呈现只**增减夹点**，不整体换一套。

## 多选为什么不逐对象画

多选框回答的是「这一堆的范围」，那是一个真实的、用户正在操作的矩形（接下来的移动、对齐、
分布都作用于它）。它不宣称任何单个对象的轮廓，因此「盒不是轮廓」那条不适用。

混选一条线和一个矩形时呈现不一致——线有轮廓、矩形没有——只会让人以为线被特殊对待了，而实际上
此刻两者受同一个整体框支配。

## 轮廓从哪来

`stageCurveOutline(document, index, entityId)` 已经存在，几何编辑的轮廓就是它画的：投影到盒、
经世界矩阵、拍成折线。选中态复用它，**不另写一份**——两份实现的分叉症状是「双击前后线的轮廓
差半个像素」，而那种偏移只在特定缩放下现形。

**两态由不同的层画同一条几何**：几何编辑态归可编辑路径层（它还要画夹点与采样点），选区层
此时让位，否则两条重叠出一条更粗的线。因此用例断「轮廓还在」时要断**那一层的**元素——断选区
层的会红，而那不是缺陷。

覆盖层保持哑：宿主派生好世界折线传进来，`SelectionLayer` 只负责换算到屏幕并画。它不认识文档，
这条边界不动。

## 判别性

| 用例 | 钉住的东西 | 改前 |
| --- | --- | --- |
| 选中斜线不出选区矩形与 Resize 手柄 | 主行为 | 必红 |
| 选中斜线画出的轮廓沿几何而不是沿盒 | 轮廓真的贴合 | 必红 |
| `scale` 工具下矩形与手柄回来 | 能力没消失 | 改前绿，防误删 |
| 选中一个矩形 Entity 仍画盒 | 没有波及非曲线 | 改前绿，防扩大 |
| 多选一条线加一个矩形仍画整体框 | 多选不受影响 | 改前绿 |

第二条是这一刀真正的判别性所在：只断言「矩形不见了」的话，把轮廓画成盒的四条边同样能通过。
断言方式是取轮廓上的采样点，验证它落在几何上而不是包围盒的边上——斜线的包围盒角与几何相距
最远，那里最能分辨。
