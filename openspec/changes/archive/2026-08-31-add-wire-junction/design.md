## 上下文

`Wire` 今天只回答「这一端绑到了哪个端口」，而 `Ports` 长在符号上。导线与导线之间没有关系可言，
因此「交叉」与「连接」在文档里是同一份数据，在图上是同一堆像素。

外部惯例调研（决定了下面几条决策的边界）：

| 来源 | 做法 |
| --- | --- |
| GB/T 4728.3（等同 IEC 60617-3） | 连接 = 实心圆点；交叉不连接 = 直接穿过，**不得**加点；连接线不应在交叉点改变方向 |
| KiCad | 一条线的起点或终点落在另一条线上时自动加节点；只连接两个东西时不画点；交叉默认直接穿过，跳线（Hop-over）默认 None |
| Altium Designer | T 型接头自动生成 junction；`Break Wires At Autojunctions` 把被接入的线在该点断成两段；`Convert Cross-Junctions` 把四通转成两个相邻三通 |
| AutoCAD Electrical | 止于另一条线时按图纸样式画圆点或角接；交叉处按**图纸级**样式画缺口或半圆环，可翻转、可删除、可整张设成 Solid |

## 目标 / 非目标

- 目标：让「接上了」成为文档里读得出来的事实，且在图上与「交叉」一眼可分。
- 目标：符号或任一条支路移动时，接头跟着走。
- 非目标：跳线弧（hop-over）。见决策 4。
- 非目标：自动路由。既有那条「正交只把落点拽回轴向，不替用户决定拐几次」原样成立。
- 非目标：网络（net）与导线编号。节点只表达「这几条线接在一起」，不表达它叫什么。

## 决策

### 决策 1：连接来自取点时的捕捉，不由坐标反查

用户把光标挪进容差、看着标记亮起、然后落笔——这本身就是一次显式意图。这是既有那条「绑定跟着
取点来源走」的第二次应用，理由逐字相同：事后按坐标反查会让一条恰好路过的线莫名其妙地接上，
而那个绑定在屏幕上完全不可见。

推论：**键入坐标画出来的线永远不接**，即使落点分毫不差——它没有来源。

### 决策 2：那个圆点是一个真实的 Entity

节点 = 填实的整圆（`curve` 的第五个起点）+ 一个 `Ports`。导线照旧 `{entityId, portId}` 绑上去。

- 白拿：既有求解让三条支路的端点跟着节点走；移动节点三条线一起动；失效判定、Inspector 的解除
  入口、`port` 最高捕捉优先级、命中与框选全部复用。
- **协议一个字节不改**，因此不需要迁移、版本号不动。

考虑过的替代：

- **给 `Wire` 加「绑到某条线第 i 段的 t 处」**：几何编辑随时插顶点，段索引会漂；而且它给同一个
  点造了第二种绑定语法，`getComposeWireEndState` 要为它分一支。
- **渲染层按坐标反查画点**：见决策 1；且交叉与连接的坐标一模一样，反查只能猜。
- **新增一个 `junction` Renderer 类型**：整圆是扫掠 360 的弧、矩形是四顶点的闭合多段线，这是同一
  条判断的第三次应用——另立类型会让归一化、平移、距离、特征点、渲染与校验六条路径各多一支逐字
  相同的实现。身份由 `Composition.presetId` 承担，与圆角手柄的判据同源。

### 决策 3：T 接把被接入的那条线在节点处断成两段

不断的话，节点只是**压在**那条线上：那条线一移动，节点与它就分家，而这在屏幕上要过很久才看出来
——正是「端点画在端子上」与「真的接上了」逐像素相同的那个老问题。

三家接线软件都这么做（Altium 的选项就叫 `Break Wires At Autojunctions`）。代价写在明处：场景树里
一条线变成两条，外加一个节点；三件事在**同一个事务**里完成，撤销一步回到原样。

被接入的那条线若两端有绑定，断开后**靠近哪一端的那一半继承哪一端的绑定**，另一半那侧绑到节点。
两段的描边、虚线与 marker 从原线整份复制——用户看到的仍是同一条线。

### 决策 4：交叉不画任何记号；跳线是非目标

「无点即不连」是 GB 与 IEC 的判据本身，跳线只是可选加强（KiCad 默认 None）。跳线要在渲染、命中与
导出三处各算一遍两条线的交点，而交点随任一条线移动而变。

将来要做时，它属于**页面级呈现选项**（AutoCAD Electrical 就把它做成图纸级样式），MUST NOT 做成
会话视图状态——它是会被发布出去的像素，与网格设置不是一回事。

### 决策 5：节点恒画点；支路 ≤1 时节点自删

这是对 KiCad「只连接两个东西时不画点」的**有意偏离**。理由是我们的节点是一个真实的对象：一个存在
但不画的对象点得中却看不见，而这块画布上已经吃过这个亏（空心图形的盒接管点击）。两通上多一个点是
冗余而不是错——GB 禁止的是在**交叉**上加点。

支路降到 1 时节点自己删掉：它已经不表达任何连接。降到 0 由删除最后一条支路的那一步一并收掉。

### 决策 6：四通允许，不自动错开

在这个模型里四通不会自己冒出来：连接必须是端点接到线上，凑出四通要用户接两次。行业里避免四通的
理由是「圆点在复印中丢失会让含义翻转」，那是纸质链路的风险；自动错开要替用户改他刚点下的几何，
而那一步在屏幕上没有任何解释。真需要时做成**导出时**的一次规整。

### 决策 7：`nearest` 排在捕捉的最后

它够得着整条线、永远命中，排在任何点状候选之前会把端点整个吞掉——而「把这个角对到那个端子上」
正是画图时最常做的事。只对带 `Wire` 的 Entity 产出：接到线身中间是接线特有的手势。

标记用沙漏形（AutoCAD 的 nearest 记号），与端口实心圆、捕捉方框都不同：这块画布的规矩是形状先
分开、颜色再分开。

## 风险 / 权衡

- **一条线变两条**：场景树上多出一项，用户可能读作「我的线断了」。缓解：两段外观完全一致，且
  接头处有点；断线只发生在用户刚刚接上的那一次。
- **节点被误当成一个可拖的小圆**：它确实可拖，而拖它就是移动接头，三条线跟着走——这正是想要的。
- **节点的填色是接入时从被接入的导线复制的一份快照**，此后不跟随。做成绑定会让同一份事实有两处
  来源；用户改导线颜色后节点不跟，由他自己改（与两段导线各自可改是同一档）。
- **`nearest` 让整条导线成为捕捉目标**，密集图上可能在不想接的时候吸上去。缓解：它排在最后，
  任何端点、中点在容差内都压过它。

## 迁移计划

无。既有文档一个字节不变，没有新协议字段，`ComposeDocument` 版本号不动。

## 待解决问题

- T 接后场景树里一条线变两条能不能接受？（决策 3 取「能」；替代方案是自动 Group，代价是多一层
  结构与跟着变的拖动语义）
- 跳线弧进不进 v1？（决策 4 取「不进」）

## 实现中修正的两处判据

两处都是同一类缺陷：**判据取窄了，而取窄的后果在屏幕上看不见**。

1. **接入的落点模式**原本只列 `nearest` 与 `endpoint`。中点的优先级高于 `nearest`，因此瞄准一段
   线的正中间落笔时命中的是 `midpoint`——那一下会画出一条像素级正确却从未接上的线。三种模式
   现在一视同仁：它们都是导线上的点。

2. **「是不是导线」原本判 `Wire` Component**。`Wire` 只记录「这一端绑到了哪个端口」，两端都还
   没接上时根本不写它——而那正是一张图上最常见的状态（先画线、后接符号）。症状是「新画的导线
   接不上，接过一次之后就能接了」。判据改成宿主注入的谓词（`Wire` 或 `wire` Preset），与
   「一个 Entity 能不能几何编辑由宿主注入谓词」是同一条既有边界。

## 已知欠账

- **节点在 z 序上排在后画的那条导线之下**：批次里节点先建、新线后建，而 z 序就是子级顺序。
  后果是在接头正中央按下去抓到的是那条线而不是节点。图上仍读得出（点比线粗），挪接头要先绕开
  那几个像素。修它要让创建顺序或子级顺序把节点排到最后，那是另一次变更。
