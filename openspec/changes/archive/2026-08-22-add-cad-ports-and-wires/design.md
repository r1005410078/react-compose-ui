# 设计

## 决策 1 · 端口挂在块定义上，不挂在实例上

一个端口是**符号的一部分**：断路器有两个接线柱，画一次，插一百个实例都有。挂在实例上意味着
每插一次都要重新声明，而且同一个符号的不同实例可以有不同端口——那样它就不是同一个符号了。

代价是端口必须用块局部坐标表达，因此 `PORT` 命令要做一次逆变换（世界 → 块局部）。逆变换在
**handler** 里做，理由见决策 4。

比例为 0 的实例不可逆，`PORT` 在那种实例上被拒绝并给出可定位的错误。这不是理论情况：镜像
符号用负比例是常规用法，手滑写成 0 完全可能。

## 决策 2 · 导线几何求解，不存储

```
CadInsert  : 块局部几何 --(比例→旋转→平移)--> 世界几何      已有
CadWire    : {entityId, portId} --(查实例→查端口→同一条变换)--> 世界端点   本步
```

两者是同一条原则的两次应用。收益不是「少存两个数」，而是**「移动后重解」这段代码根本不存在**：

- `MOVE` / `COPY` / 拖动 / 将来的旋转、镜像、阵列，全部自动正确。
- 撤销、重做、外部写入、DXF 导入——任何改变实例位置的路径都自动正确。

存坐标的方案必须在每一条这样的路径上挂一个重解钩子，而**漏掉一条的症状是「线错位」，
它看起来像渲染 bug，不像数据 bug**，排查方向从一开始就是错的。

## 决策 3 · 端口捕捉排在端点之前

`CAD_SNAP_MODES` 的顺序即优先级。端口插到最前面。

理由是一个**静默失败**：端口几乎总是画在符号线段的端点上（接线柱就是那根短线的头）。同等
距离下若端点胜出，用户点在接线柱上，得到的是一条自由端点的导线——屏幕上像素级正确，移动
符号时才暴露。没有任何视觉线索能让用户在画的当刻发现它。

捕捉标记因此也必须能区分：端点是方框、中点三角、交点叉号，**端口用菱形**。用形状而不是颜色
区分是既有约定——用户在余光里判断「捕到的是不是我想要的那个特征」。

## 决策 4 · 会话规划，handler 解算

`WIRE` 会话只产出两个世界坐标点；**绑定在 `cad.wire.add` 的 handler 里完成**。
`PORT` 会话只产出「哪个实例 + 一个世界点」；**逆变换在 `cad.block.add-port` 的 handler 里完成**。

这条界线是既有的，本步只是沿用：会话是纯状态机，拿不到文档（`CadCommandContext` 只给图层、
选择集与块的 id/名字）。既有注释写得很直白——「给会话整份文档，规划与求解的界线就消失了」。

handler 侧的收益是 **handler 是纯函数**：同一份文档 + 同一条命令 ⇒ 同一批 patch。撤销后重做
不会产出不同的绑定。

绑定判据是「端点坐标与某个已解算端口坐标相等」，容差 `1e-9`。之所以敢用相等而不是拾取半径：
这个点是**捕捉管线吐出来的**，端口捕捉命中时 `resolveCadPoint` 直接短路返回捕捉点，而端口
世界坐标由同一段代码、同一批输入算出，是逐位相同的。容差只吸收将来可能插入的中间运算，不
承担「靠近就算」的语义——那是捕捉的职责，不该有第二处实现。

## 决策 5 · 删除设备把导线端点冻结成自由端点

三个选项：

| 方案 | 问题 |
| --- | --- |
| 连带删除导线 | 用户没选中的东西消失了。多选删除时尤其吓人 |
| 留下悬空引用 | 文档非法，事务被校验器整批打回，删除动作直接失败 |
| **冻结为自由端点** | 采用 |

冻结的位置是删除前最后一次解算的世界坐标，因此**图上什么都没变**——那台设备消失了，线还在
原处，末端悬空。这正是用户在纸上做同一件事时看到的样子，撤销一步即完全恢复。

`cad.entity.remove` 因此要认识 `CadWire`。这不是越界：保持文档合法是删除 handler 本来就有的
职责，`rootIds` 与 `entities` 同批写入是同一条理由。

## 决策 6 · 拖动预览改走文档解算

今天的预览把选中图元的线段整体平移。导线一进来这条路就断了：

```
拖动一台设备
  ├─ 设备被选中     → 预览平移 ✅
  └─ 导线未被选中   → 预览不动 ❌，但提交后它会动
```

修法不是「预览时也把导线找出来平移一下」——那是在预览侧重新实现一遍 `translateCadEntity` 的
语义，两份实现迟早分叉。改为：

```ts
const preview = dragDelta ? previewCadTranslate(document, selection, dragDelta) : document
const segments = collectCadVisibleSegments(preview)
```

`previewCadTranslate` 逐个调用 **handler 用的同一个** `translateCadEntity`。预览与提交因此不是
「一致」，而是**同一段代码**。

顺带修掉一个今天就存在但看不见的问题：两端都绑定的导线**平移是 no-op**（它的位置由两端决定，
不由自己决定）。按屏幕像素平移的旧预览会把它画得跟着走，松手弹回原处。

性能：`collectCadVisibleSegments` 本来就在每次指针移动时为捕捉跑一遍，拖动期间多跑一遍是同
一个量级。真正需要索引时该优化的是那个函数本身，不是在这里绕开它。

## 决策 7 · 不变量由校验器承担

路线图要求「变体切换要求端口 id 稳定，这条要立成不变量而不是靠约定」。

本仓的变体就是两份块定义，切换即改实例的 `blockId`。因此不变量的自然落点是**文档校验**：

```
wire.unknown-entity  端点引用的 Entity 不存在
wire.not-instance    端点引用的 Entity 不是块实例
wire.unknown-port    该实例的块没有声明这个端口 id
```

任何改 `blockId` 的路径——命令、外部写入、DXF 导入、将来的变体 UI——都要过这一关。写成命令级
检查只能挡住写过检查的那一条路径。

块定义内部同样拒绝 `CadWire`（`block.nested-wire`）：块内容是块局部、自包含的，而导线端点引用
顶层 Entity id，两者语义不相容。与既有的 `block.nested-insert` 是同一条理由。
