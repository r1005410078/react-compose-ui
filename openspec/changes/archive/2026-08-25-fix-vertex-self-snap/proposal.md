# 顶点模式的自捕捉与靶区

## Why

### 一、同一个形状的其他顶点吸不上（缺陷）

进顶点模式后，**本对象的所有特征点都不参与捕捉**。实测（矩形四顶点，坐标都不在网格上）：

```
悬停：
  本对象的另一个顶点 403,505  ->  无捕捉
  本对象的边中点   303,305   ->  无捕捉
  别对象的端点     603,305   ->  endpoint
拖 v0 时：
  拖到本对象顶点   403,505   ->  无捕捉
  拖到别对象端点   603,305   ->  endpoint
```

「把这个角对到那个角上」是画图时最常做的事之一，而它今天做不到。

根因是仓库自己写下的那条规则**粒度错了**：「正在编辑的对象不参与捕捉，否则夹点会被自己的
端点吸回原处」。理由只对**被拖的那一个顶点**成立——它的原位置就在指针底下——但实现是整个
Entity 排除，把同对象的其他顶点、边中点全部一起收走了。

它在屏幕上的样子有欺骗性：用户看到的是「只有一个顶点会变色，其他都不变」，以及「顶点不在
网格上就永远落不上去」——后者是因为捕捉够不着时网格接管，而顶点不在格点上。两句话是同一个
原因。

**既有用例覆盖不到它**：多角度那两条都是把探针线的夹点拖到**另一条线**的端点上，恰好是唯一
能工作的情形。盲区是构造出来的——用了两个对象，排除规则从来没生效过。

### 二、靶区够不着时网格把点拽走

优先级本来就是对的：`resolveComposePoint` 捕捉命中即短路，根本不过网格。真问题是 12 屏幕
像素的靶区够不着——此时网格接管，把落点拽到最近的格点上，看起来就像网格把捕捉挤掉了。

实测各方位角的捕捉半径整齐地都是 11～12 像素，**没有角度上的偏差**：这不是几何问题，是靶区
大小问题。

### 三、捕捉标记读不出来，也压住了拾取框

标记原先与橡皮筋、作用对象轮廓、选区框同为 accent 色，混在里面读不出来；而它回答的是一个
是非问题——**吸上了没有**。它还被做得比拾取框大，反过来把拾取框罩在里面。

## What Changes

- **排除从 Entity 级降到点级**：悬停时**不排除任何东西**；拖某个夹点时**只排除那个顶点的
  原位置**。同对象的其他顶点与边中点因此恢复可捕捉。
- **特征点靶区在开着网格吸附时加上网格自己的够及范围**（半条对角步长）。网格已经在把落点
  搬走、最远就是这么远，扩大同样的量不引入任何用户尚未接受的位移；网格越粗、拽动越大、靶区
  也越大。关掉网格吸附时退回基数。
- **捕捉标记改成橙色半透明底**，并**缩到拾取框以内**：拾取框在外，标记在内。
- 用例补上同对象顶点这一类，多角度覆盖。

## Impact

- 规范：`stage` 的「曲线几何编辑会话」一条 MODIFIED（自捕捉的粒度）、`stage-engine` 的
  「特征点捕捉」一条 MODIFIED（靶区与网格的关系）。
- 代码：`packages/stage-engine`（`findStageFeaturePoint` 增加点级排除）、
  `packages/stage`（几何编辑会话传排除点、靶区计算、标记样式）。
- 破坏性：无。`findStageFeaturePoint` 的既有签名保持可用，新参数可选。

## Non-Goals

- **不处理拖动期相邻边中点的陈旧**。拖 `v0` 时文档还没更新，与它相邻的两条边的中点在文档里
  仍停在旧位置。它们离得至少半条边、通常在靶区之外，因此 v1 不额外剔除——这是一个记录在案的
  近似，不是疏漏。真要修得把捕捉候选改成读预览几何，那会让捕捉认识会话状态。
- **不做对象 rollover 高亮**（AutoCAD 的 `SELECTIONPREVIEW`）：它是选择的反馈，作用域是整个
  画布，不属于顶点模式。
- **不改捕捉的优先级**：`port > endpoint > midpoint > center > quadrant` 与「捕捉命中即短路、
  不过正交与网格」都不动——本刀已经确认那两条是对的。
