# 符号导线

## Why

11a 让端口能被捕捉到了，但捕出来的点**没有任何绑定**：线画在像素级正确的位置上，符号一搬走
就断开，而屏幕上看不出任何差别——这正是 11a 定下「端口捕捉排在端点之前」时要防的那个错误，
现在把另一半补上。

主接线图的日常动作是「把这台刀闸往右挪 20」，此后每一条接到它上面的线都必须跟着走。手工维护
线形在一张有几十根线的图上是不可能的。

## What Changes

- **`Wire` 是可选 Entity Component**（core），记录**哪一端绑到了哪个端口**：
  `{ start?: { entityId, portId }, end?: { entityId, portId } }`，缺席即自由端。
  **自由端不存点**——`Curve` 就是那个点。CAD 的 `CadFreeEndpoint` 要存坐标，是因为它的导线
  没有盒；这里存第二份等于给同一个端点造两个事实来源。
- **几何求解不存储**，与块实例几何是同一条原则：收益不是少存两个数，而是「移动后重解」那段
  代码根本不存在——移动、复制、撤销、导入全部自动正确。`resolveComposeWires(document,
  snapshot)` 是纯函数，把绑定端写进导线的 `Curve` 与盒。
- **求解住在布局 Runtime**：它是**唯一**产出「同一次求解的文档 + 快照一致对」的地方，而导线
  求解会改导线自己的盒——文档与快照分头产出会让命中比渲染晚一帧。编辑器、预览与动画三条渲染
  路径因此各自零改动地拿到已解算的导线。
- **导线与它绑定的实例 MUST 同父级**，违反时给出可判别的校验码。端口的父级坐标要按实例的
  盒与旋转换算，跨层级还要合成祖先链的变换；限制在同一父级把「嵌套时静默错位」变成一条读得
  出来的问题，而符号与导线本来就摆在同一块场景里。
- **`WIRE` 命令**产出带绑定的导线：取点落在端口上就绑，落在别处就是自由端。绑定是**取点时
  记下的来源**，不是事后按坐标反查——按坐标反查会让一条恰好路过端口的普通线莫名其妙地绑上。
  `LINE` 不绑定：绑定改变对象此后的行为，意图必须显式。
- **拖动导线端点即改接线**：几何编辑（步骤 10）的夹点拖动落在端口上就绑到那个端口，落在别处
  就解绑并留在落点。这是改错接线的唯一入口，也让「夹点拖了却被求解覆盖」这个怪现象消失。
- **悬空引用不让文档非法**：被绑定的实体删掉后，导线保留最后写下的几何并在 Inspector 标为
  失效。这与实例动画「指向不存在的 id 时保留原值并在 Inspector 标为失效」是同一条既有判断，
  也因此**不需要 CAD 那套「删除时把端点冻结成自由端」**——那条规则的存在理由是 CAD 的校验器
  拒绝悬空引用，会让整批删除被打回，而这里不拒绝。

## Non-Goals

- **不做拐点与自动路由。**折线导线的价值几乎全部来自自动路由（曼哈顿走线、避障），单独加拐点
  只是把手工维护线形的负担交回给用户。CAD 侧同样只有两个端点。
- **不做跨父级绑定**（见上）。
- **不做端口方向约束**（输入只能接输出之类）。端口眼下只有 id 与位置，约束需要先有类型。
- **不画端口标记**（沿用 11a 的非目标）。
- **不做导线的批量重连**（换一个组件版本后端口 id 变了）。11a 已把「端口 id 稳定」写成前提，
  真正需要重连时那是一次显式的迁移，不是编辑器的日常动作。

## Impact

- 包：`core`、`layout-engine`、`stage-engine`、`stage`、`materials`
- Specs：`compose-document`（ADD 2）、`layout-engine`（MODIFY 1）、`stage-engine`（ADD 1）、
  `basic-materials`（ADD 1）
- 破坏性：无新协议版本（`Wire` 缺席即今天）。编辑器把交给 Stage 的文档换成布局 Runtime 那份
  **已解算**的文档——它与快照本来就该是一对，今天分头取正是「命中比渲染晚一帧」那类缺陷的来源。
