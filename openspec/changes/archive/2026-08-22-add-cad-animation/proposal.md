# CAD 动画

## Why

图纸也要能动：**电流流向**、告警闪烁、拓扑图上的数据包流动。一张静止的一次接线图说明的是
「接线是这样的」，会动的那张说明的是「现在电从这边过来」——后者才是运行值班盯着的东西。

读代码之后结论比路线图预期的还乐观：**协议、采样、插值与运动路径一行都不用改**。
`ComposeAnimationTrack.path` 是相对 Entity 的属性路径，今天是 `['Appearance','opacity']`，
明天就可以是 `['CadStroke','dashOffset']`；`applyComposeAnimationAtTime` 只读 `entities`、
只写 `entities`，连动画清单都不碰。

前置（图元的 per-entity 外观）已由步骤 8.4 交付。

## What Changes

### 清单落在文档级

页面那套把清单挂在 Frame 的 `Animations` Component 上、动画文件按根 Frame 分区，因为 Frame
是六重隔离边界之一就是动画时间线。而 **CadDocument 没有 Frame，也不需要分区**——一份 CAD
文档就是一个时间线作用域。因此 `CadDocument.animations` 是一个顶层数组，比页面那套更简单。

轨道仍然住在被动画 Entity 的 `Animation` Component 上，与页面完全相同：复制、删除都自动带上
动画，不需要任何补偿逻辑。

### 采样器泛型化，一行不改逻辑

`applyComposeAnimationAtTime` 的签名从 `ComposeDocument` 放宽到「任何带 `entities` 的文档」。
函数体一个字符都不动——它本来就只认识 `entities`。

这不是为了复用而扭曲一个函数，而是**把它已经具备的通用性写进类型**。写第二份 CAD 采样器意味
着缓动求解、路径写入与引用保持要维护两遍，而那三件事没有任何 CAD 特有之处。

### `CadStroke.dashOffset` 与 `FLOW` 命令

上一刀刻意留下的字段，现在有了真实消费者。`FLOW` / `FL`：选中导线 → 得到一条**流动**的线。

命令一次做两件事——给没有线型的图元补一个默认虚线，再建一条从 0 走到一个虚线周期的
`dashOffset` 轨道。这不是职责不清：用户的意图是「让这根线看起来在流动」，而实线上的偏移动画
**看不见任何变化**，交付一个没有视觉效果的动画等于没交付。

### 采样只作用于渲染，不作用于命中

画布渲染采样后的文档，而命中、捕捉与框选**继续用作者写下的那份**。

这条必须立成规则而不是碰巧：动画是文档在某一时刻的**呈现**，不是文档本身。让命中跟着采样跑
意味着用户要去点一个正在移动的目标，而拖动它时基准还会每帧变化。既有的拖动预览
（`previewCadTranslate`）已经是同一条路子——图面渲染的从来就不一定是文档本身。

## Impact

- `@compose-ui/animation`：采样器签名泛型化，实现不变。
- `@compose-ui/cad`：文档级清单与校验、`dashOffset`、`FLOW` 命令与一条 handler。
- `@compose-ui/cad-canvas`：播放会话（rAF 播放头）与采样渲染，`animationEnabled` 可关。
- 协议：`schemaVersion` **不变**。既有 `.cad.json` 不含 `animations`，读作空清单。

## 本步刻意不做

- **几何轨道**（位置、端点、插入点）：一旦几何会动，「渲染用采样、命中用原件」这条规则就会
  产生用户可感的分歧——看得见的线和点得中的线不在一个地方。那个分歧要么用「动画期间禁止
  编辑」解决，要么用一个明确的播放模式解决，都是独立的一刀。本步只动外观，几何纹丝不动，
  因此不存在分歧。
- **时间线面板**：`animation-panel` 是与文档协议解耦的独立组件，接进 CAD 画布要先定「CAD 的
  编辑模式长什么样」。命令行先把纵向流程跑通。
- **动画文件与脚本绑定**：页面那套按 Frame 分区、由页面 setup 驱动，CAD 既没有 Frame 也没有
  页面脚本。等 CAD 真的需要外部驱动时再谈。
- **变体切换轨道**（断路器合闸）：它是结构变更而不是数值插值，需要一种 step 轨道。路线图把
  它列为唯一未决问题，本步不猜。
