# 设计

## 决策 1 · 清单落在文档级，不模仿 Frame 那套

页面文档把动画清单挂在 Frame 上，理由写在 AGENTS.md 里：Frame 是六重隔离边界，其中一重就是
动画时间线；一个页面上摆着多块场景，各自播各自的。

CadDocument **没有 Frame**，而且也不需要有：一份图纸就是一个时间线作用域。因此清单是顶层的
`CadDocument.animations`。

这是「比页面那套更简单」而不是「少做了一层」。硬要移植分区意味着先在 CAD 里造一个没有别的
用途的分组概念，只为了让两边的代码长得像。

轨道的归属**照抄**：仍然住在被动画 Entity 的 `Animation` Component 上。理由在 CAD 里同样成立
——`ERASE` 删掉一根导线，它的流动轨道跟着消失，`COPY` 复制一个符号，动画也跟着复制，两处都
不需要补偿代码。

## 决策 2 · 泛型化采样器，而不是写第二份

`applyComposeAnimationAtTime` 的实现只做三件事：遍历 `entities`、按轨道路径不可变写入、
保持未命中对象的引用。**没有一处认识 Frame、清单或 ComposeDocument 的其余字段。**

因此签名放宽为

```ts
function applyComposeAnimationAtTime<TDocument extends { entities: Readonly<Record<string, ComposeEntity>> }>(
  document: TDocument, animationId: string, timeMs: number,
): TDocument
```

函数体一个字符不动。这不是为复用而扭曲，而是把它**已经具备**的通用性写进类型。

第二份实现的代价不是行数，是**缓动求解**：cubic-bezier 要由 x 反解 t、牛顿法在近水平处发散
要退回二分——这段数值代码没有任何 CAD 特有之处，抄一遍就是给自己安排两处都要修的 bug。

## 决策 3 · 采样只作用于渲染

图面渲染采样后的文档；命中、捕捉、框选与命令**继续读作者写下的那份**。

理由不是省事，是**语义**：动画是文档在某一时刻的呈现，不是文档本身。让命中跟着采样跑，用户
要去点一个正在移动的目标，而拖动的基准还会每帧变化——那是一类无法解释的手感。

这条不是新发明。既有的拖动预览用 `previewCadTranslate` 产出一份预览文档喂给渲染，而命中始终
在原文档上——图面画的从来就不一定是文档本身。本步只是给同一个位置再接一层。

**本步只动外观，因此不存在可感的分歧**：几何一动不动，看得见的线和点得中的线在同一个地方。
几何轨道要等「动画期间怎么编辑」有答案之后再谈，那是独立的一刀。

## 决策 4 · `FLOW` 一次做两件事，因为用户的意图是一件事

`FLOW` 给没有线型的图元补一个默认虚线，再建 `dashOffset` 轨道。

看起来是两件事，但**实线上的偏移动画在屏幕上没有任何变化**——`stroke-dashoffset` 只对虚线
有意义。只建轨道的话，用户执行完命令、看着一根纹丝不动的实线，会认为命令失败了。

轨道从 `0` 走到 **一个完整虚线周期**（`dash + gap` 之和），配合 `loop` 播放模式，接缝处正好
对齐——走到周期长度时的图案与 0 处逐像素相同，因此循环看不出跳变。取半个周期或一个随手写的
常数都会在每次循环时闪一下，而那种缺陷要盯着看几秒才能确认。

偏移取**负值**方向：`stroke-dashoffset` 增大时图案向起点方向退，而用户期待的「流动」是顺着
线的方向走。

## 决策 5 · 播放是会话状态，不写进文档

播放头由画布的 rAF 会话推进，与视口、网格设置一样属于**会话级视图状态**，不写进
`CadDocument`——图纸是无限的，也不带播放进度。

有动画就播，没有动画就不起 rAF（`running` 为假时不空转）。CAD 的动画是**环境性**的（电流一直
在流、告警一直在闪），不是入场动画，因此没有「播放一次」的按钮。宿主可用 `animationEnabled`
关掉，与 `autoFitContent` 是同一种「会话级、宿主可控」的东西；依赖确定性画面的用例必须显式
关掉它，而不是去赌某一帧的相位。

## 决策 6 · 校验只管本文档能判定的事

CAD 侧校验清单本身：id 唯一且非空、`durationMs` 是有限正数、`playbackMode` 合法。

轨道的形状校验**复用** `@compose-ui/animation` 的入口，但**轨道指向不存在的 Component 不算
错误**——那是采样器早就处理好的情形（静默跳过而不是凭空造一个 Component），而图元可能先有
轨道后有外观。把它升级成校验失败会让「先建动画再改线型」这条顺序变成非法，而它完全合理。
