# stage 增量

## ADDED Requirements

### Requirement: 会话把已落地的几何扩到同一个 Entity 上

效果带着「替换本次会话上一个建出来的 Entity」标记时，Stage MUST 走 `entity.curve.set`
改那一个 Entity 的几何，MUST NOT 再建一个：曲线几何写入只有那一条漏斗，它在同一个事务里
写 `Curve` 与 `LayoutItem`。

栈里没有可替换的对象时（它已经被外部撤销掉了）MUST 退回新建，并把新建出来的记进栈——
会话因此自己愈合，而不是从此每一步都写不进去。

**落地父级 MUST 取这个 Entity 当前的父级，MUST NOT 重算。**新建那一支按几何紧包围盒的中心
挑父级，而那个中心随着导线变长一直在动：每一步重算会让一条画到一半的线突然从一个场景搬到
另一个场景——局部坐标、绑定合法性与它在场景树里的位置一起变，而用户只是多点了一个点。

效果带着「这一条还没画完」标记时，Stage MUST 跳过**接入节点**（建节点、把被接入的导线断成
两段、三条支路改绑），只写几何与端口绑定。接入改的是**别人的**文档：中途路过另一条导线并不
是接线意图，先接上、下一下又走开，留下的是一个谁也没接的孤儿节点，而对方的线已经被切开了。
端口绑定不受此约束——它每一步按当前几何重算，是自我纠正的。

取消结果带着效果时，Stage MUST 先落地那个效果、再决定重开还是结束会话：`Escape` 的第一级是
「放弃这一条」，而这一条已经在文档里，重开会把记录清掉，此后没有人知道该删谁。

#### Scenario: 第三个点改的是同一个 Entity

- **WHEN** `WIRE` 依次取三个点
- **THEN** 文档里只有一个导线 Entity，它的几何有三个顶点
- **AND** 第二个点落地之后它就已经在场景树里

#### Scenario: 中途路过另一条导线不建节点

- **WHEN** `WIRE` 的中间某个点吸附到另一条导线的线身上，随后继续取点并结束
- **THEN** 文档里没有节点 Entity，被路过的那条导线仍是一条

#### Scenario: 最后一个点落在另一条导线上仍然接入

- **WHEN** `WIRE` 的最后一个点吸附到另一条导线的线身上，随后结束
- **THEN** 建出节点，被接入的导线断成两段，三条支路各绑到节点

#### Scenario: 放弃这一条时线也消失

- **WHEN** `WIRE` 取过两个点（线已经在文档里），用户按 `Escape`
- **THEN** 这条线从文档里消失，命令仍在跑且提示回到第一步

## MODIFIED Requirements

### Requirement: 命令会话的参考点跟着文档走

Stage MUST 记住一次绘图会话里**它自己建出来**的 Entity。当其中最后一个不再存在于文档时，
Stage MUST 让会话回退一个点，使参考点（橡皮筋起点、下一段的出发点）与文档一致。

不这么做的症状是：`LINE` 画 a→b→c 之后按 `Control+Z`，b-c 那一段消失了而橡皮筋仍从 c 出发，
下一个点会从一个**已经不存在的地方**连出去。会话的状态是它自己的，文档在它脚下变了而它不知道。

判据 MUST 是「我建的那个 Entity 还在不在」，MUST NOT 是「用户按了哪个键」：拦截
`Control+Z` 只覆盖那一个键，而删除、外部同步、别的命令都能让同一件事发生。这也让 Stage
不必复制编辑器的撤销键位——两份键位一旦漂移，撤销就只有一半生效。

**同一条规则 MUST 覆盖「Entity 还在、但被改小了」这一档**：会话把几何扩在同一个 Entity 上
时（导线），撤销撤掉的是最后那一次几何写入，Entity 并没有消失。因此 Stage MUST 一并记住
**上一次写进去的顶点数**，文档里的顶点数比它少时按差值回退同样多个点。只判存在的症状是：
撤销一下、再点一下，那个拐点又回来了——文档与会话各说各话，而用户无从解释。

协调时 MUST 丢弃那一步的效果：文档已经先动了，效果描述的是同一件已经发生的事，再执行一次
会把它下面那一段也删掉。

记录 MUST 分「已经在文档里见过」与「还没见过」两态，且只有**见过的**那个消失才算删除。
派发之后新 Entity 要过一趟 React 才到得了 `document`，而在那之前它**也不在文档里**——少了
这一位，「还没到」与「被删了」分不开，症状是画第二段时第一段被自己撤掉，屏幕上只剩一条线。

会话结束时 MUST 清空这份记录；它描述的是**这一次会话**建了什么。

#### Scenario: 撤销之后参考点回到上一个点

- **WHEN** `LINE` 依次取 a、b、c 三个点，然后撤销
- **THEN** b-c 那一段消失，橡皮筋从 b 出发
- **AND** 再取一个点时，新的一段从 b 连出去

#### Scenario: 撤销之后导线的顶点数与会话一致

- **WHEN** `WIRE` 依次取 a、b、c 三个点，然后撤销
- **THEN** 这条导线回到两个顶点，橡皮筋从 b 出发
- **AND** 再取一个点时它是第三个顶点，而不是第四个

#### Scenario: 协调不重复删除

- **WHEN** 撤销让会话建出来的最后一个 Entity 消失
- **THEN** 只回退会话，MUST NOT 再删掉它前面那一段

#### Scenario: 刚建出来还没到文档的那一个不算被删

- **WHEN** 连续取点，每一段落地之后立刻取下一个点
- **THEN** 每一段都保留，MUST NOT 因为新 Entity 尚未到达 `document` 就把它当成被删

#### Scenario: 新会话不继承上一次的记录

- **WHEN** 一条 `LINE` 结束之后再启动一条
- **THEN** 新会话不因为上一条建过什么而回退

### Requirement: 会重开的命令与两级 Escape

命令提交后，Stage MUST 检查该命令定义的 `repeat`：为真时立刻以同一个命令 id 重开一次全新
会话，提示回到第一步。

**`activeCommandId` MUST NOT 在重开期间闪成 `null`。** 宿主的工具栏按下态读它，闪一下会让
按钮抖动；重开 MUST 在同一次更新里完成，而不是「结束、再启动」两拍。

重开 MUST NOT 触碰选择集：绘图命令提交之后本来就不选中新建的对象，重开不改这一条。

**会重开的命令里 `Escape` MUST 分两级**，与几何编辑里 `Escape` 的两级（先熄灭热夹点、再退出
会话）同构：

- 当前这一条**已经取过点** → 放弃这一条，命令留着并回到第一步
- 当前这一条**一个点都没取** → 退出命令

不分级的话，连续取点的命令（`WIRE`）的 `Enter` 变成「结束这一条并开始下一条」，唯一的退出
只剩 `Escape`，而它此刻的含义（放弃整条命令）会把用户刚画一半的东西一起扔掉。

**「放弃这一条」MUST 连它已经落进文档的部分一起放弃**：导线从第二个点起就在文档里了，只清掉
会话会在图上留下半条线，而用户读到的是「按了取消，它还在」。要删哪一个由会话在取消结果里
说出来，Stage 落地它——引擎不认识 Entity id。

不声明 `repeat` 的命令 `Escape` 语义不变（放弃整条命令）：那里没有「下一条」可言。

#### Scenario: 画完一条接着画下一条

- **WHEN** `WIRE` 取够两个点并按回车结束这一条
- **THEN** 命令仍在跑，提示回到第一步，且已落地的那条导线保留

#### Scenario: 连画三条得到三个 Entity

- **WHEN** 连续画三条导线，每条两个点、各按一次回车
- **THEN** 文档里有三个导线 Entity，中途没有按过 `Escape`

#### Scenario: 按下态不抖

- **WHEN** 连画多条导线
- **THEN** 上报的当前命令 id 始终是 `WIRE`，MUST NOT 出现过 `null`

#### Scenario: Escape 先放弃这一条

- **WHEN** 一条新导线已经取过第一个点，用户按 `Escape`
- **THEN** 这一条被放弃，命令仍在跑且提示回到第一步
- **WHEN** 再按一次 `Escape`
- **THEN** 命令结束

#### Scenario: 不重开的命令 Escape 不变

- **WHEN** `RECTANGLE` 取过一个角点后按 `Escape`
- **THEN** 命令直接结束
