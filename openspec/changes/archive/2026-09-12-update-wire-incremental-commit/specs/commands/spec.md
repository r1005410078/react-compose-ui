# commands 增量

## MODIFIED Requirements

### Requirement: 多步提示命令会话

系统 MUST 提供由**键盘启动**、按提示逐步取得输入的命令会话协议。会话 MUST 由命令定义创建，
而不是由指针事件触发——命令驱动的编辑范式里，交互从输入命令名开始，取点是命令进行中的一步。

每一步 MUST 声明它接受哪些输入种类（点、文本、关键字），并可携带关键字选项与默认值。会话
推进 MUST 返回四态之一：给出下一步提示、提交一个效果、被取消、或拒绝本次输入并停在原提示。

拒绝 MUST NOT 结束会话：多步取点里点错位置、打错关键字是常态，结束整条命令会让用户把已经
走完的几步重来一遍。

**取消 MAY 携带一个效果**：会话在中途已经把东西写进文档时（`prompt` 那一档的 `commit`），
「放弃」必须说得出要回收什么。会话是唯一知道自己落地过什么的一方，而效果类型对消费者泛型，
因此这个字段 MUST NOT 让本包认识任何文档协议。不携带效果的取消 MUST 与从前逐字相同——中途
什么都没提交的会话是绝大多数。

效果类型 MUST 对消费者泛型；本包 MUST NOT 认识任何文档协议。

#### Scenario: 命令由文本启动并按别名解析

- **WHEN** 用户输入命令别名并确认
- **THEN** 对应命令的会话被创建并给出第一步提示
- **AND** 别名匹配不区分大小写，未知输入不创建会话

#### Scenario: 多步取点直到提交

- **WHEN** 会话依次收到满足各步要求的输入
- **THEN** 每一步返回下一步的提示
- **AND** 命令完成时返回一个待提交的效果

#### Scenario: 关键字改变后续流程

- **WHEN** 某一步提供了关键字选项而用户输入其中一个
- **THEN** 会话按该关键字的语义推进
- **AND** 未列出的关键字被拒绝且会话停在原提示

#### Scenario: 非法输入不结束会话

- **WHEN** 某一步收到它不接受的输入种类
- **THEN** 会话返回拒绝并附带说明
- **AND** 下一次输入仍按原提示判定

#### Scenario: 取消结束整条命令

- **WHEN** 一条中途什么都没提交过的会话收到取消
- **THEN** 会话结束且不提交任何效果
- **AND** 已经收集的中间输入被丢弃

#### Scenario: 中途落地过的会话取消时说出要回收什么

- **WHEN** 一条在 `prompt` 步里提交过效果的会话收到取消
- **THEN** 取消结果可以带上一个效果，宿主据此回收它落地的东西
