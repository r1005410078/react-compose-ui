# 变更：导线每点一下就落地

## 原因

`WIRE` 连续取点，但**攒到回车才提交**：点了两下、三下，画布上只有一条预览，场景树里什么都
没有，属性面板也没有可看的东西。用户读到的是「这条线还不存在」——而他已经确定了两个点，那
两个点就是文档里的事实。

`LINE` 逐段落地的理由（「曲线是普通页面 Entity，画一段就该在场景树里出现一行」）对导线一字
不差地成立。导线当初攒着提交，为的是**一条导线是一个 Entity**（逐段落地会让中间的拐点退化成
「两个自由端刚好重合」，符号一挪接头就裂开）——那条理由约束的是**产出几个 Entity**，不是
**什么时候写进文档**。两者可以同时成立：第二个点起就把这一条建出来，之后每一下扩它一个顶点。

## 变更内容

- `WIRE` 取到第二个点时 MUST 把这条导线**建出来**；之后每取一个点 MUST 走 `entity.curve.set`
  扩它一个顶点。产出仍然是**一个** Entity，拐点仍然不参与绑定。
- `U` MUST 对称地把已落地的几何收回一个顶点；收到只剩一个点时 MUST 删掉那个 Entity。
- 第一次 `Escape`（这一条已经取过点）MUST 把已落地的这一条一起删掉——「放弃这一条」在屏幕上
  必须是这条线消失，而不是留下半条。
- 预览 MUST 只画**待定的那一段**（与 `LINE` 同一条规则）：已落地的部分已经是真的 Entity，
  再画一遍就是同一条线画两遍。
- 端口绑定每一步都按当前几何重算（自我纠正）；**接入节点只在结束那一步做**——中途路过另一条
  导线不是接线意图，先接上再走开会留下一个把别人劈成两半的孤儿节点。
- 落地父级在**第一次落地时**定下，之后不再重算：扩一条已经在文档里的线不该把它搬家。

## 影响

- 受影响的规范：`commands`、`stage-engine`、`stage`
- 受影响的代码：`packages/commands/src/command/command-types.ts`、
  `packages/stage-engine/src/drafting/line-command.ts`、`drafting-types.ts`、
  `packages/stage/src/drafting/use-stage-drafting.ts`、`drafting-entity.ts`
- 顺带收掉两处与代码矛盾的陈旧规范：`WIRE 不再是一条命令`（它就在词汇表里）、以及把 `WIRE`
  当成两点命令写的那两条重开场景
- 不在本变更内：`PLINE` 的提交时机（它不是接线，攒到结束才提交是它与 `LINE` 存在差别的全部
  理由）
