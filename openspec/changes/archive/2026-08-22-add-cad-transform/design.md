# 设计

## 位移是「按 Entity 类型分派」而不是统一改坐标

CAD 的 Entity 现在有两类，位移的含义不同：

- `CadLine`：两个端点各加一个位移。
- `CadInsert`：只改 `position`，**块定义一个字节都不动**。块存在的理由就是「改一次定义，全部
  实例跟着变」，位移若下沉到块内几何，移动一个实例会把所有实例一起搬走。

因此需要一个「平移一个 Entity」的领域操作，按 Component 分派。新增图元类型时在这里补一支，
而不是让每个调用方各自认识所有 Component。

## 拖动是第二个入口，不是第二份事实来源

拖动与 `MOVE` 命令**派发同一条命令**，撤销一步都回到动之前。这与场景尺寸胶囊和 Inspector
几何分组的关系是同一条既有约定：两个入口、一份事实。

判据是**能不能撤销到同一个状态**。若拖动走自己的写入路径，就会出现「用命令移动能撤销、用
拖动移动撤销回到别处」这类只有用户能发现的不一致。

## 拖动的仲裁位置：命中**已选中**的图元

优先级插在 `cad.select` 之上、`cad.command-point` 之下：

```
cad.command-point (30) → cad.move (25) → cad.select (20) → cad.marquee (10)
```

claim 条件是**按下点命中的图元已经在选择集里**——这正是 AutoCAD 的行为：点未选中的对象是
选中它，点已选中的对象并拖动是移动它。条件写成「已在选择集里」而不是「命中任何图元」，否则
第一次点击就会变成一次零位移的移动，用户再也选不中东西。

命令正在消费点输入时本插件不参与：那时按下是给命令的一个点。这一条由优先级顺序天然保证，
不需要额外判断。

## 位移必须接吸附

AGENTS.md：**画布上每一条产出几何的手势都必须接吸附**。移动的第二点走
`resolveCadPoint(…, 'pointer', …)`，与画线取点是同一条管线，因此捕捉、正交与网格全部白拿——
把一条线的端点捕到另一条线的端点上，正是接线图最常用的动作。

**判据是缩放**：`world = (屏幕 - 视口) / zoom`，zoom 恒为 1 时未吸附也看起来是整数，因此这条
手势必须在非 100% 缩放下验证。

## COPY 连续取点

AutoCAD 的 `COPY` 放下一个副本之后继续等下一个落点，直到用户结束。这不是可有可无的打磨：
接线图里「同一个符号摆一排」是高频动作，每放一个都要重敲一次命令会让人放弃用它。

实现上是同一个会话循环给出多次 `commit`——但协议里 `commit` 是终态。因此 COPY 每放一个副本
就**发一条命令并保持会话**，用 `prompt` 继续要下一个点；用户结束时才走 `commit`。这要求
命令步骤能「带着一条命令继续」，是本次唯一的协议扩展点。

## 一次移动是一个事务

多选移动派发一条 `transaction.batch`，与 `LINE` 的多段一致：一次撤销回到命令开始之前，
而不是逐个图元撤销。
