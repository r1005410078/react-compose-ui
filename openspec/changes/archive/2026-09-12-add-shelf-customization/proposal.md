# 变更：自定义工具栏与物料面板

## 原因

面板可拖之后，工作区里还有两样东西是写死的：工具栏上有哪些按钮，物料面板里有哪几段。宿主
想把自己的 `MIRROR` / `ALIGN` 上架、现场想把用不到的按钮拿掉、想给「变电站」工作区只留
`Symbols / 变电站` 那一支——今天都做不到。

**工具栏是入口的货架，不是能力的清单。**能力在动作目录与命令词汇表里，工具栏上的每个按钮只是
其中某一条的快捷入口，所以它能按工作区增删排序而不违反「不改命令可用性」那条边界：从货架上
拿掉一个按钮，那条命令照样能敲、能按快捷键、能在命令面板里搜到。逐格核过今天的 16 格，没有
一格是「按钮即唯一入口」——八条绘图命令各有命令行、单键与命令面板三条路，容器与文字虽然没有
命令别名，但在动作目录里，因此命令面板搜得到、`stage.drawContainerTool` 也敲得出来。这条
反过来成为一条不变量：**只有按钮而没有第二条入口的功能不进目录**。Photoshop 的工作区正是这么存
工具栏的（Customize Toolbar 的结果随工作区保存），Blender 的工具架也按工作区不同。

**两个内建也因此各有一条默认货架，不再共用。**这不只是「可以不同」，而是当前就有一处缺陷在等着：
16 格工具栏在 1280 默认窗口下已经贴着溢出线——画布列 600px，示例应用的预览按钮占掉约 40，
工具栏自己要约 545，余量不到半格；而溢出是**从尾部**收进「更多」的，尾部正是那八条绘图命令。
再窄 20px，绘图工作区最先丢掉的恰好是它存在的全部理由，而页面的容器与文字排在前面活下来。
两边共用一条顺序，必然有一边是错的。

物料面板在 `add-builtin-workspaces` 里已经是货架（`sections`），本变更给它编辑面：对话框与
瓦片右键。两个货架一个模型，对话框也长得一样，一起做省一半。

设计稿第 6、7 节：
https://claude.ai/code/artifact/bb4abedb-212a-4a4e-abc8-6eb6c2c19047

**以 `add-builtin-workspaces` 落地后的规范为基线。不考虑兼容性。**

## 变更内容

### 新增

- **两条内建默认货架**：页面与绘图**不再共用**一条。页面留下选择、指示器、吸附、网格、容器、
  文字、`RECTANGLE`、`ARROW`；绘图留下选择、指示器、吸附、正交、极轴、网格、八条绘图命令与
  文字，不留容器。判据是「这个工作区的活儿要不要它」，收走的是入口不是能力。
- **工具栏货架**：工具栏改为按目录 id 列表渲染（含 `'separator'`），每个工作区一条
  （定义上的可选 `toolbar`，缺席即该工作区的默认货架）。目录来自三处：动作目录（工具与开关）、命令
  描述符（绘图命令，用 `ComposeCommandDescriptor` 的标题与分组）、宿主 `toolbarItems` prop
  （图标 + 标题 + 指向一个动作或命令 id，与 `commands` 同一条注入边界）。不在目录里的 id
  跳过不报错——宿主关掉某条命令，货架上那格自然消失。「选择」固定在第一位不可移除——它是
  取点命令结束后回去的地方。复合项（极轴 ▾、网格 ▾）整体上下架，不能拆开——拆开会得到一个
  没有开关的菜单。「设计 / 动画」与保存不在货架上——它们是文档级 chrome。
- **自定义工具栏**：右键任一按钮——从工具栏移除、在此处插入分隔、自定义工具栏…；对话框是
  Photoshop Customize Toolbar 那两列（货架 / 未放入），拖动排序、跨列移动、插分隔、重置为默认。
- **自定义物料面板**：右键瓦片——基础组件的「从面板隐藏」；文件夹来源瓦片的「只看这一组」与
  「在资源里打开此文件夹」（文件夹来源里的瓦片不能单个隐藏，那会让「新导入的自动出现」变成
  谎言）；以及「自定义物料面板…」。对话框：面板标题、货架拖动排序、文件夹来源两个开关
  （分组 / 折叠）、基础组件单项勾选、「添加来源…」复用资源浏览器的文件夹选择、搜索框开关、
  重置为默认。
- **偏好字段**：`workspace.toolbars[id]` 与 `workspace.palettes[id]`，与布局快照并列；改过货架
  同样点亮修改点，重置与另存为一并处理。
- **两条补进动作目录的动作**：`stage.canvasSettings` 与 `stage.toggleTransformGizmo`，默认都不
  绑键。它们是「货架不得成为唯一入口」这条不变量的直接产物——落地时发现这两格**只有按钮**
  （画布设置只在网格 ▾ 菜单里，指示器一条动作 / 键位 / 命令词都没有）。不补的话它们就该按规则
  退出目录，连排序都不能参与。

### 修改

- 「平铺式默认画布工具栏」：那条顺序拆成**两条**默认货架，页面一条、绘图一条。
- 「工作区管理」：修改点、重置与另存为覆盖两条货架。
- 「实例级编辑器偏好」：加 `toolbars` 与 `palettes`。
- 「混合组件目录」：加瓦片右键；`paletteHidden` 的判据由全局改为**按当前工作区的工具栏货架**
  判定——只对「因为工具栏已提供入口而藏」那一类，物料自身有理由的（Wire）恒成立。

### 不做

- 按工作区改按钮的含义、图标或快捷键：一个 id 一个含义；改快捷键走设置里既有的键位页。
- 凭空造一个目录里没有的按钮或物料：货架永远是目录的子集。
- 让用户手动勾出 `paletteHidden` 的 Preset：它是否藏着由判据算出来，不是一个可勾的开关——
  页面里出现圆的瓦片是那条判据的结果，不是用户勾的。
- 只有按钮、没有第二条入口的功能进目录：那会把「按工作区增删货架」变成按工作区改能力。

## 已定的取舍

| 事项 | 取值 | 理由 |
| --- | --- | --- |
| 页面留 `RECTANGLE` / `ARROW` | 留 | 大屏页面真会画的只有分区框与指示；圆、弧、多边形、折线、导线不出现 |
| 绘图不留容器 | 不留 | 接线图里的盒是矩形曲线（可改形状、可拖圆角），容器仍在基础组件段与快捷键上 |
| 页面不留正交 / 极轴 | 不留 | 它们约束的是取点方向，而页面留下的两条命令一条轴对齐、一条只取两点 |
| `paletteHidden` 判据 | 按当前工作区的货架 | 不改的话页面里既没有圆的按钮也没有圆的瓦片 |
| 画布设置 / 指示器 | 各补一条动作 | 它们此前只有按钮一个入口，而货架可增删；不补就得退出目录 |
| 对话框与右键 | 都进这一期 | 列表一旦是数据，对话框只是编辑它的 UI；两个货架同一套 |
| 「选择」 | 固定首位不可移除 | 取点命令结束后回去的地方，拿掉之后无处可回 |
| 复合项 | 整体上下架 | split button 拆开会得到一个没有开关的菜单 |

## 影响

- 规范：`editor-workspace-layout`（MODIFIED 2 条、ADDED 3 条）、`editor-preferences`
  （MODIFIED 1 条）、`component-library`（MODIFIED 1 条，含 `paletteHidden` 判据改写）。
- 代码：`packages/editor`（工具栏按列表渲染、目录、`toolbarItems`、两个对话框、右键菜单、偏好
  字段）、`packages/component-library`（瓦片右键、货架编辑回调）。
- 端到端：移除按钮后能力仍在、宿主上架、窄窗口溢出与货架顺序、物料右键与对话框。
