# 设计说明

## 为什么默认不 reparent，且只用几何比例一个判定条件

Figma 论坛上专门有帖子要求关掉自动吸入（"Disable auto-nesting/auto-reparenting while moving
objects"），逃生方式是按住 Space 键。这说明"碰到容器边缘就吸入"这个默认值本身就是有争议的设计，
不是不假思索照抄的对象。

这个项目选择反过来做默认值：**默认拖拽保持坐标重叠的兄弟节点（也就是现状，零新代码）**，只有指针
明确进入容器内部才触发高亮和 reparent。好处是不需要用户记一个"退出"快捷键——只要不想进容器，别把它
拖到容器中心就行。

判定条件曾考虑写成"进入内部达到比例**或**停留超过阈值"，但两个条件 OR 在一起等于没有约束：快速从
容器中心划过会立刻触发吸入，恰恰就是要避免的那个行为。停留计时也不适合拖拽——拖拽过程中用户的手是
连续移动的，要求他悬停等待与"跟手"的直觉冲突，而且延迟多少都会显得迟钝。因此只保留几何比例这一个
条件：指针进入容器包围盒内部达到规定比例才算数，贴边掠过不触发。具体比例留给实现阶段按手感调参，
不在 spec 里写死数字。

## 为什么 reparent 落地时不在拖拽手势里区分 Flow / Absolute

"盖在容器上面"其实有两种语义：不进父级（保持兄弟）、进父级但不参与 flow（Absolute 覆盖层）。
`createReparentCommand` 已经能算出两种结果，差别只在 `targetManagesFlow` 这个布尔值怎么定。

如果让拖拽手势本身决定「进去参与排队」还是「进去但不排队」，就需要一个新的修饰键或第二次确认动作，
而这个决策的使用频率显著低于"要不要进入这个容器"本身。更省心的分工是：**拖拽只回答"进哪个容器"，
容器内部要不要参与 flow 排队交给 Inspector 已有的 Flow/Absolute 切换二次调整**。这样拖拽手势的状态
机维持简单——只有"要不要吸入"一个判定，不需要在吸入的同时再判定第二件事。

## 为什么容器内重排不烘焙 Absolute，但只做 nowrap

场景树排序已经证明了"同容器内改 `Hierarchy.childIds` 顺序、不碰 `LayoutItem`"这条路径可行——见
`packages/editor/src/editor-controller/scene-operations.ts` 的 `planMove`：同父级移动只发一条
`moveEntity`，跨父级才走 `createReparentCommand`。画布版本本质是同一件事，只是插入位置的输入源从
"指针在哪两行之间"换成"指针在主轴上更靠近哪个兄弟的中点"，因此同样只需要 `moveEntity`，
`packages/core/src/builtin-commands.ts` 的 transform 补丁逻辑完全不参与。

`flexWrap: nowrap` 时，容器内所有子项沿单一主轴排布，指针位置到各兄弟中点的距离有唯一的大小顺序，
插入位置因此有唯一解——这和场景树的一维列表本质相同。

`flexWrap: wrap` 时，子项分布在多行/多列，指针位置离最近兄弟中点的欧氏距离不再对应到一个无歧义的
"插入序号"：同一个指针位置，理解成"这一行的第 3 个"和"下一行的第 1 个"往往都说得通。做一套二维最近邻
启发式不是不可能，但复杂度和收益不成比例，容易做出一个"有时候对有时候不对"的功能，比不做更糟。因此
首期对 wrap 容器维持现状，交给用户在场景树里排序。

## 容器高亮的范围限定在容器本身

候选容器的高亮描边是本变更新增的唯一视觉反馈。被拖动目标自身的选中框与变换手柄**保持现状不变**——
高亮画在目标容器上、手柄画在被拖动节点上，是两个不同对象，不存在反馈叠加冲突，没有理由借这次改动
去改既有的拖动视觉。

顺带记录一个既有约定供实现参考：`packages/stage/src/stage-overlay.tsx` 里 `resizeVisible` 已经用
`!textEditing` 抑制过一次手柄，说明"某种会话态抑制手柄"这个模式在本仓库有先例；但那是因为文字编辑态
下拖拽语义变成了选文本，与本变更的情况不同，不应照搬。

## 与既有手势原子性保证的关系

`stage-engine/spec.md`「手势预览与原子提交」已经规定了 preview/cancel/一次提交的通用保证。本变更的
两个新分支（reparent、容器内重排）都遵循同一套模型：拖动过程中只发布 preview effect，Pointer Up 才
产生命令，Escape 或失去指针捕获则不产生任何命令。不新增第二套提交时机语义。
