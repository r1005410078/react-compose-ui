## 上下文

框选判定目前内联在 `interaction-controller.ts` 的 `finish` 分支里，只有
`intersects(area, bounds)` 一条规则，既无法单测判定语义，也没有任何模式概念。工具栏已经存在
「主按钮 + chevron 下拉」范式（形状工具），本变更沿用同一交互与 ARIA 结构，不引入新的 UI 模式。

## 目标/非目标

- 目标：把框选判定变成可选模式，并提供一个能从节点上方起框的独立工具。
- 目标：判定规则成为 `stage-engine` 内的纯函数，用 Vitest 覆盖全部模式与边界。
- 非目标：套索、多边形套索、刷选等改变「框的形状」的维度。
- 非目标：真实路径级命中测试；本变更仍以世界 AABB 为判定几何。
- 非目标：把模式持久化进文档。模式是编辑器会话偏好，不是文档数据。

## 决策

- 决策：模式维度只表达命中判定几何，与已有选区的布尔组合（Shift 加选、Alt 减选）留给修饰键。
  两者正交——模式是持久设置，布尔组合是逐次手势的临时意图，混进同一个下拉会让菜单语义变形。
- 决策：`directional` 模式需要原始拖拽方向，而 `rectFromPoints` 已归一化矩形，因此判定函数
  显式接收 `direction: 'ltr' | 'rtl'`，由手势的 `startWorld.x` 与 `currentWorld.x` 推导，
  不让调用方从归一化矩形反推。
- 决策：`marquee` 工具下命中节点也起框，`select` 工具维持「空白才起框」。这是两个入口唯一的
  行为差异，模式设置对二者一致生效。
  - 考虑过的替代方案：模式只作用于 `marquee` 工具。被否——同一个画布上两种框选行为不一致，
    用户无法预期。
  - 考虑过的替代方案：移除 `select` 的空白框选。被否——破坏性变更，且没有收益。
- 决策：模式由 editor 持有并作为受控 prop 传入 Stage，与现有 `tool`/`onToolChange` 对称，
  `stage` 与 `stage-engine` 都不持有模式的事实来源。

## 风险/权衡

- 旋转节点的世界 AABB 大于其实际图形，`contain` 对旋转节点偏严格（框住了图形却没框住 AABB
  时不选中）→ 在 spec 中显式写明以 AABB 为判定几何，行为可预期；真实路径判定留待后续变更。
- 新增工具会挤占工具栏横向空间 → 与 select 同组放置，不新增分组。
- 默认键位 `B` 需确认不与现有键位冲突：现有 Stage 单键已占用 V/M/S/R/H/C/L/O/T/F/G/I，`B` 空闲。

## 迁移计划

纯新增能力。`intersect` 为默认模式，未设置 `marqueeMode` 的宿主行为与当前完全一致，现有
e2e 与单测不需要改判定预期。回滚即移除新工具与 prop，判定退回单一 `intersects`。
