# 设计

## 决策 1 · `CadGeometry` 是伞，`CadCurve` 保持是曲线

上一刀刚把遍历从 `CadSegment` 泛化成 `CadCurve`。文字来了，有两条路：

| 方案 | 结果 |
| --- | --- |
| 把 `text` 塞进 `CadCurve` | 名字变成「凡是画得出来的东西」，而每个读到它的人都要先发现这一点 |
| **加一层伞 `CadGeometry`** | 采用 |

`CadCurve` 不是随手起的名字：线段与圆弧共享一整套数学——都有端点、都有中点、都能求到点的
距离、都能拍扁。文字与它们**一个共同运算都没有**。伞类型让「曲线」继续指曲线，而遍历返回的
是更宽的「图纸上画得出来的东西」。

代价是多一个类型名。收益是下一个非曲线图元（图案填充、光栅图像）不必再纠结一次。

## 决策 2 · 文字按盒子命中，这不是对既有规则的破例

AGENTS.md 立着一条规则：

> 命中判据是点到几何的距离而不是包围盒：直线没有盒模型，按矩形判定会让两条交叉线互相遮挡
> 对方的命中区。

**这条规则的理由是「盒子里大部分是空的」，不是「盒子不好」。** 一条 45° 对角线的包围盒里，
线本身只占对角，另外两个三角形是空的；点在那两个三角里却被判成命中，用户会觉得自己点到了
看不见的东西。

文字反过来：它**占满**自己的盒子。盒子就是用户看见的那块墨。AutoCAD 也是点在文字框内即选中。

因此实现上不需要任何例外分支——把文字的「距离」定义成

```
框内            → 0
框外            → 到框边的距离
```

命中的「最近者胜出」、框选的窗口/交叉判定、按 owner 聚合，全部沿用既有代码。规则没有被破坏，
只是它对不同几何给出了不同的、正确的答案。

## 决策 3 · 命中框与字形的对齐由「等宽字体 + 固定比例」承担

字宽要字体度量，而 `cad` 是无 DOM 包。三条路：

1. **宿主测量后写进文档** —— 文档从此带着一份测量结果，换字体、换平台就过期。
2. **宿主测量后注入遍历** —— 遍历要多一个参数，而它今天被四个消费者共用，其中两个（命令与
   校验）根本拿不到 DOM。
3. **等宽字体 + 文档化的前进宽度比例** —— 采用。

等宽字体让「一个字符占 `字号 × 比例`」从近似变成几乎精确，而且这正是 CAD 的惯例：AutoCAD 的
默认 `txt.shx` 就是等宽的，图纸上的标注本来就该对齐成列。

这条耦合必须当作**不变量**记下来：`CAD_TEXT_ADVANCE_RATIO` 与图面 CSS 里的字体栈是一对。
换掉字体而不换比例，命中框会从字形上慢慢漂开——而这种偏差在短标签上看不出来，要等到有人写
一串长文字才暴露。

垂直方向同理：基线以上 `ASCENT_RATIO`、以下 `DESCENT_RATIO`，两个常数与字号相乘。

## 决策 4 · `height` 是字号，不是大写字高

DXF 的 TEXT `height` 指大写字高（cap height）。本协议用**字号（em）**。

理由是「一个数用在几个地方」：字号是渲染直接要的那个数（SVG `font-size`），也是命中框直接要
的那个数。若存大写字高，渲染要除以一个 cap/em 比例，命中要乘回来——而那个比例**随字体而变**，
于是同一个猜测被钉进两处，然后各自漂移。

DXF 导入时做一次显式换算，换算写在导入器里，是一个有名字、可测试的地方。

## 决策 5 · `insertion` 捕捉同时覆盖文字与块实例

AutoCAD 的 `INS` 捕捉同时管文字插入点与块插入点，因为它们是同一件事：**这个对象是从哪个点
放下去的**。

顺带补上了块实例的插入点捕捉——此前没有，而「把标注对齐到符号的插入点」是接线图里的日常
动作。优先级排在 `quadrant` 之后、`intersection` 之前。

## 决策 6 · `TEXT` 的三步提示，字高在会话内记住

`指定插入点 → 指定字高 → 键入文字`，与 AutoCAD 一致。

字高那一步同时接受三种输入：回车用默认值、键入数字、在图上指一点（取它到插入点的距离）。
三者复用既有的 `point` / `text` / `accept` 输入类型，不需要给命令协议加任何东西。

默认值只在**一次命令会话内**记住。AutoCAD 用系统变量跨命令记，本仓没有那个概念；为一个值
引入一套系统变量机制是把一次开销换成一份长期负担。

**空文字被拒绝**，与半径为零的圆同一条理由：它在屏幕上不存在，却仍然参与命中与捕捉，成为
一个点不中也删不掉的幽灵。
