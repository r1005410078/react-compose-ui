# 设计

## 决策 1 · 整圆是 `sweep = 360` 的弧，不另立 `CadCircle`

DXF 有 `CIRCLE` 与 `ARC` 两个实体，本步只做一个 Component。

理由是**下游路径的份数**。命中、框选、捕捉、平移、块变换、渲染、校验，七条路径。两个
Component 意味着每条路径各写两支，而这两支的差别只有「要不要判角度」——

```
点到弧的距离 = | dist(p, center) − r |          角度落在扫掠内
             = min(到两端点的距离)              角度落在扫掠外
```

整圆的扫掠覆盖全周，所以第二支永远不会走到。一个 Component 让「整圆」自然退化成弧代码的一个
特例，而不是七处 `if (isCircle)`。

渲染是唯一需要分支的地方：SVG 的 `A` 命令在起终点重合时画不出任何东西（弧长为零是合法解），
因此 `|sweep| >= 360` 走 `<circle>`。这一处分支写在渲染里，而不是渗进协议。

## 决策 2 · `sweep` 而不是 `endAngle`

单给终止角，`start=0, end=10` 分不出 10° 的短弧与 350° 的长弧。DXF 靠「逆时针从 start 到 end」
这条**外部约定**消歧，本步不打算把一条隐式约定塞进类型。

`sweep` 带符号：正为屏幕顺时针，与 `transformCadBlockPoint` 的旋转、`parseCadCoordinate` 的
极坐标取同一个约定。三处若不一致，「45 度」会在命令行、插入参数与弧之间指向不同方向，而这种
错误要等到把三者摆在同一张图上才看得出来。

## 决策 3 · 遍历返回几何联合，而不是把弧拍扁

`collectCadVisibleSegments` 改名 `collectCadVisibleCurves`，返回值从 `CadSegment` 变成

```ts
type CadCurve =
  | { kind: 'segment'; start; end }
  | { kind: 'arc'; center; radius; startAngle; sweep }
```

拍扁方案的账：下游一行不改，代价是渲染要么跟着画多边形（缩放上去肉眼可见），要么绕开这条
遍历单独画圆。后者正是 AGENTS.md 点名的分叉——

> 与命中、框选、捕捉共用同一条可见性遍历：渲染跟它们分叉时，会出现「看得见却点不中」。

而且圆心与象限点在拍扁之后**不存在**：它们不是任何一段线段的特征点。接线时想捕的恰恰是这
两个点，所以拍扁不只是画得糙，它把这个图元最有用的部分弄丢了。

联合类型的代价是四个消费点各加一支。这笔开销是一次性的，而且它换来的是**下一个曲线图元
（椭圆、样条）只需要再加一支**，而不是重做一次架构。

## 决策 4 · 精确与近似的分界线

| 用途 | 做法 | 为什么 |
| --- | --- | --- |
| 命中 | 闭式解，精确 | 判据是距离；比线段还便宜，没有理由近似 |
| 窗口框选 | 紧包围盒，精确 | 盒完全在框内 ⟺ 弧完全在框内（盒是紧的） |
| 交叉框选 | 拍扁，近似 | 精确的弧–矩形求交开销与收益不相称 |
| 捕捉 | 闭式解，精确 | 捕捉的意义就是精确 |
| 渲染 | SVG 原生弧 | 浏览器自己会光栅化 |

**紧包围盒不能用整圆的盒子凑合**：一段 90° 的弧，整圆盒是四倍面积，窗口框选会把明明框住了的
弧判成没框住。求紧盒要判 0/90/180/270 四个轴向极值角是否落在扫掠内——落在内就取该方向的极值，
否则取两端点。约二十行，精确。

交叉框选的拍扁按**弦高误差**而不是固定段数：固定段数在大半径上误差发散，而弦高误差直接就是
「最多偏几个世界单位」，可以拿它跟命中容差比。

## 决策 5 · 块内的弧按缩放是否等比分流

块实例的 `scale` 分轴，负值表示镜像——这是接线图的常规用法，不是边角情况。

- **等比**（`|sx| == |sy|`，含镜像）：结果仍是精确圆弧。镜像会翻转扫掠方向与起始角，这一步
  必须做对，否则镜像后的符号看着对、弧的走向反了。
- **非等比**：圆变椭圆，而本步不引入椭圆图元。此时**拍扁成线段**。

第三条路是按 `|scale.x|` 硬算成圆——它会画出一个用户没有画过的形状，而且**没有任何提示**。
拍扁是明确的降级：形状是对的，只是不再是解析弧，捕捉退化到线段特征点。

## 决策 6 · `ARC` 用三点定弧

AutoCAD 的 `ARC` 默认次序就是起点 → 弧上一点 → 终点，这也是手上只有图纸时最自然的输入：
三个位置都能直接从图上捕到，而「圆心 + 起止角」要求用户先知道圆心在哪。

实现是标准的三点外接圆：两条中垂线求交。**三点共线时无解**（外接圆退化成直线），此时拒绝
并停在原提示等下一个点——共线在实际操作里很常见（用户沿着一条既有线连点三下）。

扫掠方向由中间那点决定：它落在起点→终点的哪一侧，弧就往哪边鼓。这一步写反的症状是弧永远
往同一侧鼓，而用户会以为是自己点错了。
