# 变更：把画布右键菜单与剪贴板切成独立能力

## 原因

[路线图](../../../docs/stage-plugin-kernel-roadmap.md) 步骤 5 的第三刀。上一刀切出键盘能力
之后，`compose-stage.tsx` 还剩 2339 行，其中约 260 行属于同一条用户能力——**在画布上右键，
对选中对象做剪贴板、层级、编组与视图操作**：110 行菜单 JSX、90 行可用性派生、60 行执行函数，
分散在文件的三处。

上一刀顺带暴露了两处问题，都只有把这块切出来才能修：

**视图子菜单是键盘动作的一份手抄。** 「适配选择」的缩放求解连同 `8 / 0.1 / 0.85` 三个魔法数
在菜单 JSX 里被原样写了第二遍，放大/缩小的 `1.2` 也是。键盘那一刀把第一份搬进了 Hook，
两份实现从此住在两个文件里——不合并就等着它们分叉。

**菜单里有 14 处硬编码中文。** `编组`、`取消编组`、`删除`、`视图`、`工具`、`网格吸附` 等
绕过了 `stage-i18n`，而同一个菜单里的复制/剪切/粘贴走的是 `messages`。AGENTS.md 明令
chrome 文案不得硬编码；把这段搬进新模块而不修，等于把违规固化进一个新文件。

## 变更内容

- 新增 `stage-viewport-actions.ts`：`fitViewportTo` 与 `zoomViewportBy` 两个纯函数，连同
  缩放上下限与步长常量。键盘 Hook 与右键菜单**共用同一份**，附单测。
- 新增 `use-stage-clipboard.ts`：剪贴板状态（受控/非受控）、`executeClipboard`、来源 ID 解析
  与 copy/cut/paste 三项可用性判定。
- 新增 `stage-context-menu.tsx`：整棵菜单成为受控组件，props 即它的完整契约。层级顺序、
  编组/取消编组的可用性派生跟着一起进去——它们只有这一个消费者。
- `stage-i18n.ts` 补齐 14 条菜单文案。**zh-CN 文案逐字保持不变**，因此黄金图与 e2e 文本
  选择器不受影响；这一刀补的是 en-US 那一半此前根本不存在的翻译。

## 影响

- 受影响的规范：`stage`（适配层组织、chrome 文案）
- 受影响的代码：`stage-surface/compose-stage.tsx`、`use-stage-keyboard.ts`、`stage-i18n.ts`、
  三个新增模块
- 用户可见行为：zh-CN 无变化；en-US 下右键菜单此前显示中文，现在显示英文。
