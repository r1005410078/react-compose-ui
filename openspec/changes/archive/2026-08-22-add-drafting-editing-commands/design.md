# 设计

## D1 · 选择语义分流点：Context 上的一个标记，而不是一套新插件

Stage 的点选是 **DOM 驱动**的（Entity 节点上的 `onPointerDown` 产出 `hit.kind === 'entity'`），
落到 `entity-select-move` 插件；框选落到 `marquee` 插件。两处各有一行「下一个选择集是什么」的
判断，这一行正是页面语义与 CAD 语义唯一的差别。

因此在 `StageInteractionContext` 上加 `selectionMode?: 'replace' | 'accumulate'`：

| | 无修饰键点击 | Shift 点击 | 无修饰键框选 | Shift 框选 |
| --- | --- | --- | --- | --- |
| `replace`（默认，页面） | 换成它 | 切换 | 换成框内 | 并入 |
| `accumulate`（绘图，CAD） | **加入** | **移出** | **并入** | **移出** |

**为什么不写第二套插件**：两套插件会把「命中一个 Entity 之后该做什么」复制两份，而那里面
还有双击进文字编辑、锁定判定、拖动接管、幽灵 ID 过滤四件与选择语义无关的事。选择语义是这条
路径上的**一个分支**，不是一条平行路径。

**为什么不把选择集代数下沉到 `core`**：`cad` 有 `applyCadSelection`，形状确实一样。但插件这边
要的是四行分支，而 `applyCadSelection` 的契约里还有「内容不变时原样返回入参」——那是
`ComposeCadCanvas` 为了按引用判断重绘加的，Stage 这边由仲裁器统一发效果，用不上。下沉会
让两个消费者各自绕开一半契约。**步骤 2 搬点输入管线是因为搬过去的是一整条求解**；这里搬过去
的是一个 `if`，够不着那条门槛。

## D2 · 选择集归宿主，会话只是镜像

CAD 的命令会话自己攒 `picked`（`selection` 输入是**并入**）。Stage 不能照抄：选择集在 Stage
里**已经存在**——它有选中框、有属性面板、有 Esc 清空、有场景树联动。让会话攒第二份，
Shift 移出就会只改宿主那份而会话不知道，用户看着两个对象被移出、命令仍然移动三个。

因此绘图命令的 `selection` 输入语义是**替换**：宿主在选择集变化时把**当前完整选择集**喂进去。
会话仍然是纯状态机（喂一串输入即可测试），只是它的语义从「攒」变成「记住宿主最后告诉我的」。

这是对 CAD 会话的一处有意偏离，理由是两边的选择集所有权不同，不是疏漏。

## D3 · MOVE 与拖动共用的是**提交漏斗**，不是拖动预览

CAD 的判断是「拖动与 `MOVE` 派发同一条命令，是第二个入口而不是第二份事实来源」。这条在
Stage 仍然成立，但共用的位置要选对：

```
拖动手势：planMovePreview（激活阈值 + 平移吸附 + 落点解析）→ planMoveCommit → planTransformCommit
MOVE 命令：                        ← 点输入管线已求解 →            → planTransformCommit
```

`planMovePreview` 里的三样东西**都是拖动特有的**：

- **激活阈值**（`MOVE_ACTIVATION_DISTANCE`）区分「点一下」和「拖一下」。命令没有这个歧义，
  用户已经明确取了两个点；沿用它会让小位移的 MOVE 静默什么也不做。
- **平移吸附**（`snapTranslation`）在命令路径上是**违规**的：基点与位移点已经各自过了点输入
  管线（指针取点吸过、键入坐标刻意没吸）。再吸一次会把键入的 `@100,0` 改写掉，直接违反
  「键入的坐标不被任何吸附改写」这条不变量。
- **落点解析**（`resolveStageDropTarget`）会跨父级重挂载。CAD 的 `MOVE` 是纯平移，本刀照此：
  用户敲 `M` 的意图是「挪一段距离」，不是「放进那个容器」。要重挂载就用拖动。

共用点因此定在 `planTransformCommit`——它是拖动、resize、rotate 三条手势的共同提交口，产出
**一条** `entity.transform.set`（`updates[]`），因此多选 MOVE 是**一步撤销**。

位移由 `transformedSelection(index, ids, translationMatrix(dx, dy))` 求出，与拖动预览用的是
同一个函数。

## D4 · COPY 的落点必须精确，因此 `createDuplicateCommand` 要让出那个 `+10`

`createDuplicateCommand` 对同父级绝对定位的根偏移 `+10, +10`——那是「Ctrl+D 复制一份，别让它
正好盖住原件」的语义。`COPY` 有真实位移，偏移会让每一个副本都错开 10px，而这个错误在图上
看着像手抖。

改成可选参数 `offset`，默认仍是 `{ x: 10, y: 10 }`；`COPY` 传自己的 `delta`。**不新写一条复制
路径**：ID 重映射、子树克隆、Hierarchy 修补、插入位置这四件事一份就够。

`COPY` 用 `prompt` 状态携带 `commit` 连续放置，与 CAD 一致：位移始终以**最初的基点**为起点，
不是上一个副本的落点——连续放置时用户心里的参照是那一个基点。

## D5 · 预览画包围盒轮廓，不画幽灵

完整幽灵（把被移动的 Entity 按位移重渲染一遍）需要把绘图会话的位移接进仲裁器的
`previewTransforms` 通道，而绘图会话**不在仲裁器里**——它是 Stage 自己的状态。为一次预览
打通这条通道，等于让绘图命令去伪装成一个手势会话。

Overlay 已经能拿到 `index`，`getWorldBounds(id)` 就是包围盒。画平移后的轮廓是十几行，
且与橡皮筋、十字线同层同坐标系。ERASE 用同一套轮廓做「待删高亮」。

这是本刀刻意的近似，记在此处以免后来者当成漏做。

## D6 · `ERASE` 提交后清空选择集

已删 ID 留在选择集里会指向不存在的 Entity。既有代码在几处各自过滤幽灵（`entity-select-move`
就有一行 `filter`），但那是防御，不是语义。AutoCAD 里 `ERASE` 之后选择集是空的，本刀照此
直接清空——比逐处过滤更像用户看到的事实。

## D7 · 三条命令的取点管线与 `LINE` 完全一致

`MOVE`/`COPY` 的基点与位移点走 `resolvePointerPoint`（捕捉 → 正交 → 网格）或键入坐标
（不被改写），与 `LINE` 是同一段代码。因此**基点可以捕捉到某条线的端点**，这正是 CAD 里
把一个符号对齐到导线端点的做法。

判据仍是缩放：`world = (屏幕 − 视口) / zoom`，因此本刀的命中/捕捉端到端断言必须在非 100%
缩放下跑。
