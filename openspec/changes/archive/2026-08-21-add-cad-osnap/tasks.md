## 5. 实施中的发现与偏离

- [x] 5.1 **改了上一轮的计划**：原说「6b 把选择集一起做」，实际拆开了。两者风险来源互相独立
      ——捕捉是几何与渲染，选择是手势竞争与契约扩展，捆在一起会让任何一处出问题都拖住另一处。
- [x] 5.2 **交点是唯一 O(n²) 的一项**，因此先用捕捉半径的包围盒过滤候选线段（O(n)，通常剩不到
      五条）再两两求交。不建空间索引：候选过滤已经把常数压得很低，索引要处理增量维护与失效，
      属于当前没有证据支持的复杂度。
- [x] 5.3 **只在命令正等待取点时求解捕捉**：空闲时算既没有消费者，又会在每次指针移动上做无谓
      的几何计算。
- [x] 5.4 **捕捉半径按屏幕像素给出、除以缩放换成世界单位**：捕捉本质是屏幕概念，视图缩小时
      同样的屏幕半径必须覆盖更大的世界范围，否则放远了就再也捕不到。
- [x] 5.5 平移进行中不上报悬停——那时光标位置代表的是视图位移，拿它求捕捉毫无意义。
- [x] 5.6 `onHoverPoint` 从内部 latest ref 读取而不是进依赖数组，与本文件既有的
      `viewport`/`onViewportChange` 一致：宿主传内联箭头也不会让指针处理器每帧换身份。
