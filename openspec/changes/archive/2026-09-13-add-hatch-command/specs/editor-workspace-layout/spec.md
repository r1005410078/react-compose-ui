## ADDED Requirements

### Requirement: 绘图货架有填充这一格

编辑器的**绘图**工具栏货架 MUST 含 `HATCH` 一格，排在 `TRIM` 之后、文字之前：两者都是「对着
已经画好的图做一下」，而它产出新对象这一点又让它属于绘图那一段。

**页面**货架 MUST NOT 含它：页面那条只留 `RECTANGLE` 与 `ARROW`，而大屏的分区底色本来就是一个
矩形的 `backgroundPaint`，用不着求面。

目录项的 `entrance` MUST 声明 `{ kind: 'command' }`，自定义对话框的来源列因此印出它的第二条入口
——那句「拿掉一格不会拿掉那项能力」的承诺 MUST 是可核对的。

这一格是绘图货架的第 17 格，因此默认窗口下尾部一格会被收进「更多」。这是加一格的代价，
自定义对话框可以把它拖回来。

#### Scenario: 绘图货架含填充

- **WHEN** 编辑器在绘图工作区，工具栏按默认货架渲染
- **THEN** 货架上有填充这一格，排在修剪之后

#### Scenario: 页面货架不含填充

- **WHEN** 编辑器在页面工作区，工具栏按默认货架渲染
- **THEN** 货架上没有填充这一格，而 `HATCH` 仍然能从命令行启动

#### Scenario: 来源列印出第二条入口

- **WHEN** 打开工具栏自定义对话框
- **THEN** 填充那一行的来源列印出它的命令入口

### Requirement: 工具栏图标可以带一个运行期的颜色

`StageToolbarIcon` MUST 能接受一个可选的颜色参数，供填充那一格把**当前填充色**画进桶里。
它是这套图标里第一枚带参数的。

该颜色 MUST 经 `style` 内联下发，MUST NOT 写成 presentation attribute：前者压得过样式表继承的
`fill: none`，也不依赖 `var()` 在属性里被替换。

图标 MUST 画在 20×20 画幅上（这套图标按 20px 渲染，一个单位就是一个设备像素），
轮廓 MUST 走 `currentColor`，**只有漆面填那个颜色**：整桶填色时近白漆在深底、近黑漆在浅底
都会与轮廓糊成一块，桶的剪影就没了。

它 MUST NOT 用「单色桶 + 底部色带」的形态：色带是只出现在这一枚图标上的新记号，而这套图标的
记号词汇表只有五个；它还会落在版式规则里只许夹点方块进的那一圈。

#### Scenario: 桶里印着当前色

- **WHEN** 当前填充色是某个值
- **THEN** 填充那一格的桶身漆面以该色绘制，轮廓仍跟随主题

#### Scenario: 两套主题下剪影都成立

- **WHEN** 当前填充色接近主题的前景色或背景色
- **THEN** 桶的轮廓仍然可辨，图标不退化成一个色块

#### Scenario: 其余图标不受影响

- **WHEN** 渲染任何一枚不带颜色参数的图标
- **THEN** 它与本要求引入之前完全一致
