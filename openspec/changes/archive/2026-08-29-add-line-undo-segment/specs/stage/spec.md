## ADDED Requirements

### Requirement: 命令会话的参考点跟着文档走

Stage MUST 记住一次绘图会话里**它自己建出来**的 Entity。当其中最后一个不再存在于文档时，
Stage MUST 让会话回退一个点，使参考点（橡皮筋起点、下一段的出发点）与文档一致。

不这么做的症状是：`LINE` 画 a→b→c 之后按 `Control+Z`，b-c 那一段消失了而橡皮筋仍从 c 出发，
下一个点会从一个**已经不存在的地方**连出去。会话的状态是它自己的，文档在它脚下变了而它不知道。

判据 MUST 是「我建的那个 Entity 还在不在」，MUST NOT 是「用户按了哪个键」：拦截
`Control+Z` 只覆盖那一个键，而删除、外部同步、别的命令都能让同一件事发生。这也让 Stage
不必复制编辑器的撤销键位——两份键位一旦漂移，撤销就只有一半生效。

协调时 MUST 丢弃那一步的效果：文档已经先动了，效果描述的是同一件已经发生的事，再执行一次
会把它下面那一段也删掉。

记录 MUST 分「已经在文档里见过」与「还没见过」两态，且只有**见过的**那个消失才算删除。
派发之后新 Entity 要过一趟 React 才到得了 `document`，而在那之前它**也不在文档里**——少了
这一位，「还没到」与「被删了」分不开，症状是画第二段时第一段被自己撤掉，屏幕上只剩一条线。

会话结束时 MUST 清空这份记录；它描述的是**这一次会话**建了什么。

#### Scenario: 撤销之后参考点回到上一个点

- **WHEN** `LINE` 依次取 a、b、c 三个点，然后撤销
- **THEN** b-c 那一段消失，橡皮筋从 b 出发
- **AND** 再取一个点时，新的一段从 b 连出去

#### Scenario: 协调不重复删除

- **WHEN** 撤销让会话建出来的最后一个 Entity 消失
- **THEN** 只回退会话，MUST NOT 再删掉它前面那一段

#### Scenario: 刚建出来还没到文档的那一个不算被删

- **WHEN** 连续取点，每一段落地之后立刻取下一个点
- **THEN** 每一段都保留，MUST NOT 因为新 Entity 尚未到达 `document` 就把它当成被删

#### Scenario: 新会话不继承上一次的记录

- **WHEN** 一条 `LINE` 结束之后再启动一条
- **THEN** 新会话不因为上一条建过什么而回退
