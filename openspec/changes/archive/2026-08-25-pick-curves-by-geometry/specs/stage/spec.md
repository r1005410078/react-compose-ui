# Stage 规范增量

## MODIFIED Requirements

### Requirement: 线状节点不以包围盒拦截指针

带 `Curve` 的 Entity 在 Scene 中 MUST 作为线状节点渲染：节点盒本身 MUST NOT 接收指针事件，
命中 MUST 由物料内部的透明加宽 stroke 承担。

该 stroke 的宽度 MUST 为 `COMPOSE_CURVE_PICK_TOLERANCE` 的两倍（与视觉线宽取较大者），
MUST NOT 另取一个数。容差是**屏幕量**——它表达鼠标能瞄多准，MUST NOT 随画布缩放变化；
实现上因此 MUST 反向除掉画布缩放。

命中区 MUST NOT 沿线身越过端点：命中层的 `stroke-linecap` MUST 为 `butt`。`round` 会让命中
区从两端各伸出半个带宽，使它成为包围盒的**超集**，而这条能力的整个理由是「盒里绝大部分是
空的」。端点还是接线图上密度最高的地方——`LINE` 逐段落地，相邻段共享端点，越过端点意味着
它们互相偷点击，而用户看不出这是容差造成的。拐角不受影响：那由 `stroke-linejoin` 承担。

线状判定 MUST 依据 `Curve` Component 而不是 Renderer 类型——「这个 Entity 是不是线状的」是
几何问题，按物料类型枚举会在每加一种线状物料时漏掉一处。

**填充过的曲线是例外中的例外**：填色区域是用户看见的墨，因此它 MUST 接收指针事件——命中层
在有可见填充时 MUST 同时覆盖填充区域，未填充时 MUST 只覆盖描边。空心图形的内部 MUST NOT
命中：那正是「包围盒里绝大部分是空的」这条理由覆盖的情形。

#### Scenario: 包围盒空角不选中曲线

- **WHEN** 在非 100% 缩放下点击对角线包围盒内远离线身的空角
- **THEN** 该曲线不被选中

#### Scenario: 容差之外的邻近位置不选中

- **WHEN** 在离线身 5 个屏幕像素处点击
- **THEN** 该曲线不被选中

#### Scenario: 命中区不越过端点

- **WHEN** 沿线身方向、在端点外侧数个像素处点击
- **THEN** 该曲线不被选中

#### Scenario: 点击线身选中曲线

- **WHEN** 点击曲线的线身
- **THEN** 该曲线被选中并打开其属性面板

#### Scenario: 填充过的形状内部可点

- **WHEN** 一个整圆曲线有不透明填充，用户点击它的圆心附近
- **THEN** 该曲线被选中

#### Scenario: 空心形状内部不可点

- **WHEN** 同一个整圆曲线没有填充，用户点击它的圆心附近
- **THEN** 该曲线不被选中

### Requirement: Stage 十字光标

Stage MUST 在绘图命令进行期间绘制十字光标，并 MUST 按**当前等待的输入类型**切换形态：命令
等待取点时绘制十字线，命令等待选择对象时绘制拾取框，其余情形不绘制。

**空闲时 MUST NOT 绘制**：页面编辑器的静息光标是箭头，十字光标只在「正在取点」这件事发生
时出现。形态推导 MUST 留在本包，共享组件 MUST NOT 认识它。

绘制期间 MUST 隐藏系统光标。画了十字线却留着系统箭头会让屏幕上出现两个光标，而用户会以为
十字光标失效了。绘制与隐藏 MUST 由同一个判定驱动，MUST NOT 各判一次。**反向同样违规**：
收走了系统光标却没画十字线时，屏幕上一个光标都没有，而那通常发生在用户最需要看清落点的
那一下。因此隐藏 MUST 只有一个来源，MUST NOT 由「取点覆盖层是否挂载」之类更宽的条件驱动
——覆盖层还承载捕捉标记与橡皮筋，它挂着的时候十字光标未必在画。

指针位置的跟踪 MUST 覆盖**手势进行期**。手势会在 Stage 根节点上获取指针捕获，而按 Pointer
Events 规范，获取捕获会向原目标链派发 `pointerleave`，此后的 `pointermove` 一律重定向到捕获
元素。跟踪因此 MUST NOT 只挂在图面上——那样每次拖动都会先收到一次 `pointerleave` 把位置清空，
再也收不到后续移动，症状是**一拖动十字线就断**。

绘制 MUST 复用 `@compose-ui/canvas-kit` 的共享十字光标，MUST NOT 另写一份。十字线长度 MUST
按视口较短边取百分比而不是贯穿整个图面；同时绘制两者时 MUST 在拾取框处断开；touch 指针
MUST NOT 绘制，也 MUST NOT 隐藏系统光标；指针离开 Stage 时 MUST NOT 残留光标。

十字光标 MUST NOT 绘制在一个**本次跟踪开始之前**观测到的指针位置上。指针位置只在需要绘制
时才跟踪，因此上一次会话留下的那个坐标可以任意陈旧——它是上一条命令最后一次点击的地方，而
不是指针现在所在的地方。症状是会话一开始十字线停在别处，等用户动一下鼠标才跳到正确位置，
而双击进入几何编辑时这一跳尤其显眼：起点是很久以前的某个点，终点是用户刚刚双击的地方。

因此：跟踪停止时 MUST 清掉已记录的位置；由指针事件启动的会话 MUST 用**该事件**的位置播种；
无从得知指针位置时（例如从命令行敲入命令）MUST NOT 绘制，直到收到第一次 `pointermove`。
浏览器不提供查询指针当前位置的接口，因此「先不画」是这一档唯一诚实的答案，而它严格好过
画在一个错误的地方再跳过去。

宿主 MUST 能关闭十字光标，并 MUST 能配置十字线长度百分比与拾取框半边长。

**Stage 的拾取框 MUST NOT 参与任何命中判定**，它只表达靶区位置——判定始终由物料的 stroke
完成，框只是把同一个数画出来。点选那一档的拾取框半边长默认值 MUST 为
`COMPOSE_CURVE_PICK_TOLERANCE`，MUST NOT 另取一个数：这一档用户选的就是曲线，框比真实容差
大好几倍等于教用户瞄错。

拾取框与顶点模式那一档 MUST NOT 为了看起来一样大而互相迁就：两档各自 MUST 表达自己那一档
真实抓得到的范围（顶点模式派生自夹点命中半径，见另一条 Requirement）。夹点本来就是比发丝线
更大的目标，两个框不一样大是对的。

#### Scenario: 取点时画线并收走系统光标

- **WHEN** 绘图命令正等待取点，指针在图面上
- **THEN** 图面绘制十字线
- **AND** 图面上的系统光标不可见

#### Scenario: 等待选择对象时只有拾取框

- **WHEN** 绘图命令正等待选择对象
- **THEN** 图面绘制拾取框，没有十字线

#### Scenario: 会话开始时不画在陈旧位置上

- **WHEN** 一条命令结束后指针移动过，随后从命令行启动新命令且不再移动指针
- **THEN** 图面不绘制十字光标，直到指针再次移动

#### Scenario: 由指针事件进入的会话就地绘制

- **WHEN** 双击一条曲线进入几何编辑会话，之后不移动指针
- **THEN** 十字光标绘制在该双击点上

#### Scenario: 拾取框与曲线容差同源

- **WHEN** 宿主未配置拾取框半边长，绘图命令正等待选择对象
- **THEN** 框的半边长等于 `COMPOSE_CURVE_PICK_TOLERANCE`

#### Scenario: 拖动期间十字线不断

- **WHEN** 在绘制十字光标的状态下按下并拖动指针，手势因此取得指针捕获
- **THEN** 整个拖动过程中十字线持续绘制并跟随指针
- **AND** 任何时刻「有十字光标」与「系统光标被收走」都同真同假

#### Scenario: 空闲不绘制

- **WHEN** 没有活动的绘图命令
- **THEN** 图面不绘制十字光标
- **AND** 系统光标可见

#### Scenario: 宿主关闭十字光标

- **WHEN** 宿主关闭十字光标，绘图命令正等待取点
- **THEN** 图面不绘制十字光标
- **AND** 系统光标可见

### Requirement: 曲线几何编辑会话

`ComposeStage` MUST 提供曲线的几何编辑会话：select 工具下双击一个带 `Curve` 的未锁定 Entity
MUST 进入该会话，`Escape`、在空白处按下、切换工具或选中集不再**恰好只有该 Entity** MUST
退出。会话状态 MUST 住在 Stage 自己这里，与画布内文字编辑同构；宿主 MUST NOT 需要为进入或
退出接线。

某个夹点被点亮时，`Escape` MUST 先熄灭它而 MUST NOT 退出几何编辑会话；再按一次才退出。
两级与 AutoCAD 的热夹点 → 温夹点 → 取消选择同构。

进入会话时 MUST 清掉命令行上残留的 notice。用户此刻站在一个会取点的状态里，而残留的那句
（例如上一条命令被取消时留下的「已取消」）在说一件已经过去的事。

会话 MUST 是**单对象作用域**：Shift 累加选中另一个 Entity MUST 退出会话。会话的全部呈现
（夹点、轮廓、十字光标、被排除出捕捉的那一个 Entity）都只描述一个对象，而会话又抑制了选区
包围盒与手柄；把它按在多选状态上会让第二个被选中的对象在图面上完全隐身。

会话期间 MUST 显示该 Entity 的夹点，并 MUST 复用既有的可编辑路径覆盖层与路径手势通道，
MUST NOT 另写一套顶点渲染或拖拽。

指针停留在某个夹点的命中区上时，该夹点 MUST 改变呈现。夹点的可见图形比它的命中区小，没有
悬停反馈时用户唯一能确认「按下去会抓到它」的办法是按下去试。该反馈 MUST NOT 引入每帧
`pointermove` 都要写一次的 React 状态——它是纯视觉的，可由样式派生。

会话期间 MUST NOT 为该 Entity 显示任何 Resize 或旋转手柄。盒的角手柄与角顶点几乎压在同一个
像素上，两个含义叠在一起谁也点不准。该抑制与文字编辑那条是同构的两条独立规则。

会话期间 MUST NOT 绘制选区包围盒。三条理由，任何一条单独成立：

1. **盒不是曲线的轮廓。**一条对角线的包围盒里绝大部分是空的——这正是命中判据不按包围盒的
   那条理由，视觉上同样成立：那个矩形宣称了对象并不占据的面积，而且比线本身显眼得多。
2. **拖夹点时它是过期的。**选区盒由手势的预览变换推出，而夹点拖动不产生预览变换（它走本地
   几何预览），因此整个拖动过程中盒停在拖动**之前**的位置。它不只是多余，它在说谎。
3. **它要表达的信息已经有人表达了。**可编辑路径覆盖层沿**真实几何**画出轮廓，夹点也落在
   对象上——「选中的是谁」比一个矩形说得更准。

文字编辑态只去掉填充而保留边框，因为文字盒**就是**那个对象的轮廓；曲线不是，因此整个矩形
都不画。两者是同一条判断在不同形状上的两个结论。

会话期间 MUST 绘制十字光标并收走系统光标，判定 MUST 与绘图命令取点期间共用同一个解析结果。
拾取框 MUST 只在**既没有点亮任何夹点、也没有拖动**时绘制，其余时候 MUST 只绘制十字线。
没点亮也没拖动的会话正是「等着抓点什么」的状态，框表达可抓的靶区；一旦抓住——不论是按住
拖着还是点亮了等着——那件事已经发生，框只会挡住落点。

**捕捉标记 MUST NOT 在没有夹点被会话作用着的那一档绘制。**拾取框与捕捉标记回答的是两个
不同的问题：框说「这一块是靶区」，在「等着抓点什么」的那一档有意义；标记说「落点吸上了
什么」，而那一档**没有落点**——命令行提示就是「命令：」，与 AutoCAD 一致（对象捕捉标记只在
命令正在请求一个点时出现）。在别的对象的端点上亮起标记，会让用户以为那些对象也能改形状。

判据 MUST 是**同一份事实**：拾取框已经在读「有没有夹点被作用着」来决定画不画，捕捉标记
MUST 读同一份，MUST NOT 各判一次。

**拖动期与点亮期照旧绘制**：那两档正在放置一个点，而「把这个角对到那个角上」正是几何编辑
最常做的事，一起收走会毁掉这条能力。

该拾取框的半边长 MUST 由夹点的命中半径派生，MUST NOT 复用点选那一档的配置值。顶点模式是
Stage 里唯一一处存在**统一命中容差**的地方——可抓目标只有夹点，而每个夹点的命中区都一样大，
因此这里的框可以真的表达「压住了就抓得到」。派生 MUST 取命中圆的**内切**关系而不是外接：
框内一律抓得到，宁可少说不可多说。两个值分开写死会让下一个改命中半径的人漏掉框。

拖动夹点 MUST 先经与绘图命令**同一条**落点解算（特征点捕捉、正交、网格），移动阶段 MUST 只
更新本地预览，结束阶段 MUST 派发一条 `entity.curve.set`。落点越出当前盒时 MUST NOT 钳制——
盒与几何由该命令重新归一化，撤销一步 MUST 回到原几何。

拖动某个夹点期间，**只有那个顶点自己的原位置** MUST NOT 参与特征点捕捉：它就在指针底下，
不排除的话夹点会被吸回原处，用户要把指针拖出容差半径才动得了。

排除 MUST 是**点级**的，MUST NOT 把整个 Entity 收走。理由只对被拖的那一个点成立，而同一个
对象的其他顶点与各段中点正是用户最常要对齐的目标——「把这个角对到那个角上」。做成 Entity 级
时它在屏幕上的样子有欺骗性：用户看到「只有一个顶点会变色，其他都不变」（变色的那个在别的
对象上），以及「顶点不在网格上就永远落不上去」（捕捉够不着，网格接管，而顶点不在格点上），
两句话是同一个原因。

排除 MUST 只在**有夹点被会话作用着**时成立——没有夹点被作用时既不解算落点也不绘制标记，
排除与否没有任何可观察后果。这一条曾经写成「未拖动时不排除任何东西」并以空闲档的捕捉标记
观察，而那个标记本身就是上面禁止的那个。

捕捉标记与落点解算 MUST 读同一份排除，否则会出现「标记在这里、点落在那里」。

曲线绘制手势结束后 MUST 直接进入该 Entity 的几何编辑会话。绘图**命令**产出的 Entity
MUST NOT 自动进入：命令仍握着光标与提示，两个正在取点的东西叠在一起会让 `Escape` 的含义
说不清。

宿主传入 `editablePath` 时 MUST NOT 进入几何编辑会话：覆盖层至多渲染一条路径，而两条路径
指向不同的事实。

#### Scenario: 双击曲线进入并显示夹点

- **WHEN** select 工具下双击一条未锁定的直线曲线
- **THEN** 图面显示它的三个夹点
- **AND** 该 Entity 的 Resize 手柄、旋转手柄与选区包围盒都不显示

#### Scenario: 只有既没点亮也没拖动时才画框

- **WHEN** 会话已开始而指针尚未按下
- **THEN** 图面同时绘制十字线与拾取框
- **AND** 按住某个夹点拖动期间只绘制十字线，且十字线全程跟随指针
- **AND** 原地单击点亮一个夹点之后同样只绘制十字线

#### Scenario: 悬停在夹点上改变它的呈现

- **WHEN** 指针停留在某个夹点的命中区上
- **THEN** 该夹点的呈现与未悬停时不同
- **AND** 指针移开后恢复

#### Scenario: Shift 累加退出会话

- **WHEN** 一条曲线正在几何编辑会话中，用户 Shift 点选另一个 Entity
- **THEN** 会话退出，夹点消失
- **AND** 两个 Entity 按多选的既有规则显示选中呈现

#### Scenario: 拖端点把轴对齐的线掰成斜的

- **WHEN** 在非 100% 缩放下双击一条水平直线，把它的一个端点拖到另一个高度并松手
- **THEN** 文档里该曲线的两个端点不再等高
- **AND** 只产生一条可撤销记录，撤销后回到水平

#### Scenario: 拖中点整条线搬走并按中点捕捉

- **WHEN** 在非 100% 缩放下拖一条直线的中点夹点到另一条曲线的端点附近并松手
- **THEN** 该直线的中点精确落在那个端点上，而不是指针的裸坐标
- **AND** 线的长度与方向不变

#### Scenario: 拖夹点时不被自己吸住

- **WHEN** 拖动一个夹点，指针仍在该夹点的捕捉容差之内
- **THEN** 落点跟着指针走，不被该曲线自己的端点吸回原处

#### Scenario: 同一个形状的其他顶点仍可捕捉

- **WHEN** 一条多段线正在几何编辑会话中，把它的一个顶点拖到**同一条多段线**的另一个顶点附近
- **THEN** 落点精确落在那个顶点上，图面显示捕捉标记
- **AND** 同一条多段线各段的中点同样可以命中

#### Scenario: 空闲档不画捕捉标记

- **WHEN** 会话已开始、没有任何夹点被点亮或拖动，指针靠近**另一个** Entity 的端点
- **THEN** 图面不绘制捕捉标记
- **AND** 十字线与拾取框照常绘制

#### Scenario: 点亮之后不排除自己的其他点

- **WHEN** 点亮一条多段线的某个顶点，指针靠近**同一条多段线**自己的另一个顶点
- **THEN** 图面显示该顶点的捕捉标记，落点精确落在它上面

#### Scenario: 退出会话恢复手柄

- **WHEN** 几何编辑会话中按下 `Escape`
- **THEN** 夹点消失，该 Entity 按其 TransformConstraints 恢复显示手柄
- **AND** 选区包围盒一并恢复

#### Scenario: 画完曲线停在几何编辑里

- **WHEN** 用曲线绘制工具拖出一条新曲线并松手
- **THEN** 新 Entity 被选中并处于几何编辑会话，图面显示它的夹点

#### Scenario: 宿主运动路径优先

- **WHEN** 宿主已传入 `editablePath`，用户双击一条曲线
- **THEN** 不进入几何编辑会话，图面仍只渲染宿主那条路径
