# 曲线的命中一律按几何，不按包围盒

## Why

「盒里绝大部分是空的，因此曲线的命中按点到几何的距离判定」这条判断，仓库里**只落实了一半**。
两处报障各暴露一半，量出来的事实如下。

### 一、点选：命中区越过端点，而容差是 AutoCAD 默认值的两倍

在一条独立的水平线上逐点量，命中区的实际边界：

| 方向 | 越过几何多远 |
| --- | --- |
| 垂直于线身 | 6px |
| **沿线身越过端点** | **6px** |

第二行是缺陷：**命中层硬写了 `strokeLinecap: 'round'`**，命中区因此从两端各多伸出半个带宽，
成为包围盒的**超集**。描边层的 cap 是作者选的（`props.strokeLinecap`），命中层却不跟着——
两层用不同的 cap 没有任何理由，只是没人量过。端点还是接线图上密度最高的地方：`LINE` 逐段
落地，相邻段共享端点，越过端点意味着它们互相偷点击，而这个错误在屏幕上完全不可见。

第一行不是缺陷而是**量级判断**：`MIN_HIT_WIDTH = 12`（±6）。容差是屏幕量这一点是对的——它
表达鼠标能瞄多准，本就不该随缩放变。可疑的是大小：AutoCAD 的 `PICKBOX` 默认值是 3（半边长），
现在是它的两倍，而符号只有几十像素宽的接线图正是它最不合适的场合。

**这里有一处必须写下来的更正**：最初拿来当证据的是一张「36×36 的曲线命中区几乎填满整个盒」
的采样网格，而那条曲线是一个 40×20 的**矩形**——几何本来就跑在盒的四条边上，±6 的带填满它
的内部是正确行为。斜线的实测恰恰相反：命中区是一条干净的斜带，包围盒空角点不中。「点击区域
是包围盒那么大」这句话在**框选**上完全属实（见下一节），在点选上只对矩形类形状成立，而那是
它应有的样子。

因此容差那一项的判别性用例 MUST 是**离线身 5px 处点击**（改前命中、改后不命中），而不是
「小尺寸曲线的空角」——那个位置改前改后都点不中，用它当用例会得到一条永远绿的假判别。

### 二、框选：根本没按几何判定

一条左上→右下的斜线，在它右上角的空白里拖一个 40×34 的窗交框，全程不碰线身：

```
空角里窗交 → 选中了这条线
空角里窗口 → 没选中（正确）
```

`resolveMarqueeSelection` 对所有 Entity 一律用世界 AABB。窗口（`contain`）恰好没暴露问题——
要求整个盒进框，对未旋转曲线等价于几何；窗交（`intersect`）则是纯粹的盒判定。

这不是疏漏而是**明写的欠账**，函数注释里就是：「判定几何使用节点的世界 AABB……真实路径级
判定留待后续变更。」

值得注意的是 `StageSceneIndex.entityAtPoint` **已经**做了盒/曲线分流（盒按包含、曲线按距离）。
框选是三条命中路径里唯一一条没跟上的，而它们本该给出一致语义。

### 三、进入几何编辑时十字光标画在一个很旧的位置上

指针位置只在**需要绘制时**才跟踪（`pointerTracked`），命令之间不跟踪。因此会话一开始读到的
坐标是**上一次会话里最后观测到的**那个，可以任意陈旧。量出来：

```
P1（上一条命令最后一次点击） 724,428
P2（命令之间把鼠标移到的地方） 454,588
命令行启动后，未移动鼠标  →   728,428   ← 停在 P1，连 P2 都不是
```

双击进入几何编辑时它表现为「十字线从某个旧点跳到双击点」——起点是很久以前的某个位置，终点
是用户刚刚双击的地方。命令行启动同病同源，只是没有那一下双击做参照，不容易被看出来。

### 四、几何编辑空闲档在别的图形上亮起捕捉标记

三个状态下量同一个动作（悬停在**另一条**线的端点上）：

| 状态 | 捕捉标记 | 十字线 | 命令行提示 |
| --- | --- | --- | --- |
| A 没进几何编辑 | 0 | 无 | 已取消 |
| **B 几何编辑，什么都没点亮** | **1** | 有 | **命令：** |
| C 点亮了一个夹点 | 1 | 有 | 指定新位置 |

B 档的提示就是「命令：」——没有任何落点，而捕捉标记回答的正是「落点吸上了什么」。在别的对象
的端点上亮起标记，用户会以为那些对象也能改形状。AutoCAD 的对象捕捉标记只在命令正在请求一个
点时出现，B 档在那边同样什么都不显示。

**这不是漏改，是当初的决定**：规范里有一条 Scenario 明写「未拖动时……图面显示该顶点的捕捉
标记」，用它来观察「未拖动时不排除任何点」。但那个观察点本身就是缺陷——一旦空闲档不解算落点，
「排不排除」就没有任何可观察后果，那条规则收敛成已经写下的「排除的是被会话作用着的那个夹点」。

判据是**同一份事实**：拾取框已经在读「有没有夹点被作用着」来决定画不画（`gripTarget`），
捕捉标记漏读了它。

**拖动期与点亮期照旧**：那两档正在放置一个点，「把这个角对到那个角上」是几何编辑最常做的事，
一起收走会毁掉这条能力。

### 为什么四条合成一刀

前两条是同一句判断的两个缺口，改法共用同一批几何：点选那半要一个更小的容差，框选那半要
「框与几何相交」。分两次排队会让「命中按几何」这句话在中间态里仍然只对一半成立，而两次都要
碰 `core` 的曲线几何模块。

后两条是同一次操作里的两个缺陷：**用户双击进入几何编辑时，一次就同时看见它们**。它们都落在
`stage` 的同一份会话状态上（`pointerScreen` 与 `gripTarget`），分开排队意味着「进入几何编辑」
这条路径要被验证两遍。

现有规范挡不住任何一半：`stage` 只要求命中区「MUST 显著大于视觉线宽」，既无上界也不禁止越过
端点；`stage-engine` 则**明文规定**用 AABB。既有的两条空角用例都用大尺寸曲线，因此全绿。

## What Changes

### 点选

- **容差的事实来源落进 `core`**：新增 `COMPOSE_CURVE_PICK_TOLERANCE`（屏幕 px，点到几何的
  距离），值取 AutoCAD `PICKBOX` 的默认值 **3**。住 `core` 的理由与 `COMPOSE_SCENE_SIZE_PRESETS`
  一样——`stage` 与 `materials` 之间没有依赖关系，各写一份必然漂移。
- **`materials` 的命中层按它算宽度**：全宽 = 2 × 容差（仍与视觉线宽取 max），并把
  `strokeLinecap` 从 `round` 改成 `butt`——命中区 MUST NOT 越过端点。
- **Stage 的拾取框改由同一个常量派生**（默认半边长 6 → 3）。`PICKBOX` 在 AutoCAD 里本来就是
  这两件事的同一个数：框的半边长就是拾取容差。规范里那句「容差散在各物料的 stroke 宽度里，
  没有全局的那个数」随之失效，一并改掉。

### 框选

- **`core` 新增曲线与矩形的相交判定**（`curve-geometry.ts`，与既有平面形状运算同模块）：
  线与多段线按线段，弧复用既有的 `flattenComposeArc` 拍扁——「非等比拍扁成多段线」是这个仓库
  已经做过的同一条选择。
- **`resolveMarqueeSelection` 按 Entity 类型分流**：盒模型仍用世界 AABB，带 `Curve` 的 Entity
  改按几何。分流形状照抄 `entityAtPoint` 已有的那一条，三条命中路径因此给出一致语义。
- **填充过的曲线，框落在填充区内同样算命中**：填色区域是用户看见的墨，与点选那条规则一致。
- 顺带修一处上一刀的残渣：Scenario「判定按拖拽方向切换」仍写着「以 `directional` 模式解析」，
  而该取值已被删除。

### 明确不做

**十字光标在命令行启动那一档先不画。**浏览器不提供查询指针当前位置的接口，因此这是唯一诚实
的答案；它严格好过画在一个错误的地方再跳过去。

**非曲线 Entity 的旋转仍用 AABB。**旋转矩形的 AABB 同样大于其图形，改法也在同一行，但那需要
矩形对凸四边形的判定（另一套机器），而两处报障与可见症状都在曲线上。这一条欠账**保留在注释
与规范里**，不静默删除。

## Impact

- Specs：`stage`（三条 MODIFIED）、`stage-engine`（一条 MODIFIED）、`basic-materials`（一条
  MODIFIED）、`compose-document`（两条 ADDED）
- 代码：`packages/core`（新常量 + 相交判定）、`packages/materials/src/curve/renderer.tsx`、
  `packages/stage-engine/src/hit-testing/marquee-selection.ts`、
  `packages/stage/src/stage-surface/compose-stage.tsx`、`packages/stage/src/types.ts` 与
  `packages/stage/src/drafting/use-stage-drafting.ts`
- 行为变化：曲线更难点中、更难被窗交框误选（这正是目的），拾取框画得更小，十字光标在拿不到
  指针位置时先不画，几何编辑空闲档不再亮起捕捉标记。`pickRadius` 的**默认值**变了，显式传值
  的宿主不受影响；仓库内没有宿主传它。
