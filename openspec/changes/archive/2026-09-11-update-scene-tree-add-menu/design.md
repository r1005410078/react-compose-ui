## 上下文

场景树的 `+` 走 `create-suggested`，宿主的 `planCreate` 把它固定解释成「建一个容器」。
画布右键的「添加组件」菜单刚落地，货架视图（`resolveComposeComponentShelfView`）已经把
基础 Preset 与项目组件按分组求值成一份可呈现的清单。

## 目标/非目标

- 目标：`+` 弹出与画布右键**同一份**货架，选中即添加。
- 非目标：第三级菜单。既有那份货架视图明写「菜单里没有第三级」，这里照搬，不为一个入口另立一套。
- 非目标：在菜单里检索。检索框就在它左边一格，两个检索面挨着只会让人问哪个管哪个。
- 非目标：把物料面板的拖拽也搬过来。拖拽表达的是「放到画布上那个位置」，而这颗按钮不指向画布。

## 决策

- **决策：两处入口共用一份货架，不各建一份。**
  它们列的是同一批东西（基础组件 / 项目组件 / 资源文件夹），各写一份的症状是「画布右键里有、
  场景树里没有」，而两边都对的那一刻没人会去检查。实现上是同一个 memo 的同一个返回值分给两个
  消费者，条目 id 也是同一套。

- **决策：菜单不携带落点，落点由宿主按选区决定。**
  这颗按钮坐在检索栏上，**不指向树里的某一行**——`create-suggested` 那套「选中容器就追加到它
  子级末尾」的算法在这里没有输入。而宿主那条点击添加的既有路径（`external.add` 不带
  clientPoint）本来就按选区落点：取选区所在的公共容器，位置放在它的中心。两者给出的是同一个
  答案，因此不必在协议里多带一个 `parentId` 去承诺一件宿主并不读的事。
  考虑过的替代：沿用 `{ type: 'create'; parentId; index; itemId }`。那样树会算出一个落点、
  宿主转手丢掉——协议里写着的东西没人读，是下一个人踩的坑。

- **决策：新增一个 `add` 意图，而不是给 `create` 加一个可选 `itemId`。**
  两者回答的不是同一个问题：`create` 说「在树的这个位置放一个新节点」（落点是它的全部内容），
  `add` 说「用户从货架里挑了这一样」（身份是它的全部内容）。合成一个会得到一个**一半字段永远
  为空**的载荷，而哪一半为空取决于宿主有没有传 `addMenu`。

- **决策：`addMenu` 缺席或为空时，`+` 的行为一个字节不变。**
  `scene-tree` 是可独立嵌入的包，不能要求每个宿主都备一份货架；而「没有货架就没有新增按钮」
  会让这颗按钮在示例与测试宿主里凭空消失。

- **决策：菜单复用共享右键菜单，按按钮矩形定位，不新造一个下拉 Primitive。**
  `useComposeContextMenu` 的 `openAt` 本来就收一个点，喂它按钮的左下角即可，WAI-ARIA 的菜单
  语义、键盘与焦点陷阱全部白拿。**按按钮矩形而不是按指针**：键盘激活时指针坐标是 `(0,0)`，
  菜单会飞到屏幕左上角。焦点返回由调用方接管 `onOpenChange` 补上——`openAt` 只在右键事件那条
  路上记返回目标，而这里不是右键。
  考虑过的替代：照 `EditorBrandMenu` 手写一个 `role="menu"`。那是编辑器自己那颗标志按钮的
  一次性实现，搬过来等于把整套键盘与焦点逻辑再写一遍。

- **决策：按钮变成菜单触发器时要说出来（`aria-haspopup="menu"` + `aria-expanded`）。**
  同一颗按钮在两种宿主配置下一种当场建东西、一种弹菜单，屏幕阅读器用户得能读出它是哪一种。

- **决策：新增之后把落进去的那个容器展开。**
  新对象会被选中，但**选中一行看不见的行，与什么都没发生在屏幕上没有区别**——而用户此刻正
  看着树，不是看着画布（从物料面板点瓦片时他看的是画布，所以那条路不需要这一步）。
  展开**选中的那个容器**就够，不必等落点回传：选区是容器时它就是落点；选区是叶子时落点是它的
  父级，而那个父级此刻一定是展开的，否则这个叶子自己就看不见。只挑文档意义上的容器
  （带 `Hierarchy` 的），因为组件实例的「展开」是投影它的内部层级，不是这里要的那件事。

- **决策：菜单封顶到 `min(60vh, var(--available-height, 60vh))`。**
  货架可以很长（项目组件加上每一个资源文件夹，实测 1884px），不封顶时定位器会把整块菜单顶到
  屏幕上沿，按钮附近一项都看不到。回退值**必须给**：`--available-height` 是定位器算完之后才
  写上去的，而它是按元素此刻的布局高度挑的位置——首次测量时那个变量还不存在，`max-height`
  整条失效，于是又按未封顶的高度选位（踩过）。

## 风险/权衡

- 老用户的肌肉记忆：按一下不再当场出现一个容器，要多选一次。代价是显式的，收益是那颗按钮从
  「建容器」变成「加任何东西」；容器仍在菜单里，且排在基础组件的头一批。
- 货架被宿主裁剪到空时菜单也空。此时 `addMenu` 为空数组，按钮退回 `create`——不呈现一个按下去
  什么都没有的菜单。
