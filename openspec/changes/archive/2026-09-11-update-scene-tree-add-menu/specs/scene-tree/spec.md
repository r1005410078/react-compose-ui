## ADDED Requirements

### Requirement: 新增菜单与新增意图

SceneTree MUST 支持宿主提供一份**新增菜单**：一组分组，每组含标题与若干条目，条目只有 id、
标签与可选图标。条目 id 对 SceneTree MUST 是不透明的——本包不认识资源、组件或 Preset。

菜单非空时，新增按钮 MUST 成为菜单触发器并声明 `aria-haspopup="menu"` 与 `aria-expanded`；
菜单 MUST 以**按钮矩形**而不是指针坐标定位，使键盘激活得到的位置与鼠标一致；关闭后焦点
MUST 回到该按钮。用户选中一项时 SceneTree MUST 只发出一次 `{ type: 'add'; itemId }` 操作意图，
MUST NOT 自行改变节点数据、选择或展开状态。

该意图 MUST NOT 携带落点：新增按钮不指向树中的任何一行，落点由宿主决定。

菜单缺席或为空时，新增按钮的行为 MUST 与既有的建议插入位置一致，即发出 `create` 操作意图。

#### Scenario: 从新增菜单选中一项

- **WHEN** 宿主提供了非空新增菜单，用户点击新增按钮并选中其中一项
- **THEN** 组件发出一次携带该条目 id 的 `add` 操作意图
- **AND** 不发出 `create`、选择或展开操作意图

#### Scenario: 键盘打开新增菜单

- **WHEN** 用户用键盘激活新增按钮
- **THEN** 菜单出现在该按钮附近而不是视口左上角
- **AND** 关闭菜单后焦点回到新增按钮

#### Scenario: 没有新增菜单时行为不变

- **WHEN** 宿主未提供新增菜单或提供的菜单为空
- **THEN** 点击新增按钮按建议插入位置发出 `create` 操作意图
- **AND** 不呈现任何菜单

## MODIFIED Requirements

### Requirement: 新增节点入口

系统 MUST 在检索框附近显示且只显示一个新增节点图标按钮，并在节点与空白区右键菜单中
提供相同新增动作。按钮和菜单 MUST 使用相同的建议插入位置算法。

宿主提供了非空新增菜单时，该按钮改为打开那份菜单并发出 `add` 意图；右键菜单中的新增动作
MUST 保持发出 `create`——它指向用户右键的那一行，落点是它存在的理由。

#### Scenario: 使用新增按钮

- **WHEN** 用户点击检索框附近具有可访问名称的新增按钮
- **THEN** 未提供新增菜单时，组件根据当前选择发出一个 `create` 操作意图
- **AND** 提供了非空新增菜单时，组件改为打开该菜单

#### Scenario: 从选中节点右键新增子节点

- **WHEN** 用户右键点击允许包含子项的选中节点并执行新增
- **THEN** `create` 操作使用该节点 ID 作为 `parentId`
- **AND** 默认编辑器将新节点插入该父节点并展开它

#### Scenario: 连续新增多个节点

- **WHEN** 宿主连续处理多个 `create` 操作意图
- **THEN** 每次操作均创建具有稳定唯一身份的新节点
- **AND** 场景树、Canvas 和 Inspector 对同一节点的选择与内容更新保持同步
- **AND** 删除其中一个节点不影响其他已创建节点

#### Scenario: 计算建议插入位置

- **WHEN** 选中节点可以包含子项
- **THEN** 建议插入到该节点子级末尾
- **AND** 不可包含子项时建议插入到该节点之后
- **AND** 无选择时建议插入根节点末尾

#### Scenario: 使用上下文菜单新增

- **WHEN** 用户在节点或空白区打开上下文菜单并选择新增节点
- **THEN** 组件使用与新增按钮相同的插入位置规则发出 `create` 操作意图
- **AND** 该行为不受宿主是否提供新增菜单影响
