# 设计：把 WIRE 合并进 LINE

## 决策 1：推翻的是「意图必须显式」，不是「不按坐标反查」

这两条规则写在同一段里，容易被当成一条。它们不是。

**「绑定 MUST 来自取点时记下的来源，MUST NOT 事后按坐标反查」原样保留。**它挡的是一条几何上
恰好路过端口的线被追认成接线——用户没有把光标停在那里，捕捉标记没有亮过，什么意图都没表达。
这条规则合并之后仍然是绑定的唯一来源。

**推翻的是它后面那半句**：「`LINE` MUST NOT 产生绑定，即使它的端点吸附到了端口上」。吸附
发生过就意味着用户把光标挪到了端口的容差里、看见标记亮起、然后落笔。那是显式意图。再要求
他先在两条画法一样的命令里选对一条，是把同一个意图要求说两遍，而说错的代价不对称（见提案）。

判据因此收成一句：**绑定跟着取点的来源走**。来源是端口就绑，不是就不绑，与哪条命令产出它
无关。

## 决策 2：跨父级不绑，而不是绑了让文档非法

`wire.parent-mismatch` 是 `issues` 里的一条，文档校验会拒绝。落地父级按线段紧包围盒中心
判定，因此「从帧内符号的端口拉一条线到帧外」是一次很平常的手势，而它会产出一份非法文档。

三个可能的做法：

1. **绑上，让校验报错。**用户画了一条线，得到一条他不认识的文档错误，而错误的成因（父级）
   在屏幕上完全看不见。
2. **绑上，并把线搬进符号的父级。**它悄悄改变了线的落点归属，而用户刚刚明确地把它画在了
   别处。
3. **不绑，并说出为什么。**

取 3。**不绑是可见的降级**——Inspector 显示这一端自由，几何编辑里能看到它没跟着符号走；
非法文档是不可见的，而且它阻断的是保存这类与画线毫无关系的操作。命令行本来就在解释每一步，
多说一句话是它的本职。

这条同时**修好了 `WIRE` 今天的一个坑**：它现在也会产出跨父级绑定。合并把它一起带上，因为
两者此后是同一条路径。

## 决策 3：`WIRE` 不留成别名

留成别名意味着敲 `WIRE` 与敲 `LINE` 得到同一条会话。那不是兼容性，是让同一件事有两个名字，
而这正是本刀要消除的东西。仓库既有的判断已经做过两次同样的取舍：工具切换让位给
`RECTANGLE` 这类命令、`edit.delete` 让位给严格更强的 `ERASE`——都是**删掉**而不是保留成
别名。

`WI` 一并消失。它没有第二个含义可以承接。

## 决策 4：连续画线时每一段各自绑

`LINE` 逐段落地，第 `i` 段的起点与第 `i-1` 段的终点是同一次取点。那次取点若来自端口，两段
都绑到它。

这不是重复绑定：两段是两个 Entity，它们**都**真的碰到了那个端子。接线图上「从端子拉出去、
拐两个弯、接到另一个端子」画出来就是三段，头一段绑左端子、末一段绑右端子、中间那段两端
自由——每一段的绑定各自正确，且符号移动时头尾两段自动跟上。

反过来做（只让整条链的首尾绑）需要引入「一条链」这个概念，而 `LINE` 的产物里根本没有它：
每段都是独立 Entity，链只存在于用户的记忆里。

## 决策 5：解绑放在 Inspector，不放在画布

画布上没有能表达「解除这一端」的手势。拖开端点会连几何一起改，而用户此刻想改的只有绑定；
右键菜单在取点进行中已经被指派给回车，而不在取点中时端点不是一个可命中的目标。

Inspector 已经在显示两端的三种状态，解除按钮就摆在它显示的那一行上——用户读到「已绑到
`sw1.A`」的同一处就能取消它，不需要先知道这个功能在哪。

两端都解除后整个 `Wire` 删除：不带任何绑定的 `Wire` 读不出意图，与曲线外观「三项全清就整个
删掉」是同一条判断。

## 决策 6：`StageDraftingEffect.wire` 删除而不是恒为 true

标记的含义是「这条命令产出的是导线」。合并之后没有第二种线，标记恒为真，而恒为真的标记会让
下一个读代码的人以为还存在另一种情形。

两点会话工厂的 `extras` 因此只剩 `arrow`。工厂本身留着——它仍然服务 `ARROW`，而「只有一个
消费者」在本仓库不是把抽象折回去的理由（`canvas-kit` 与 `interaction-kernel` 都是这么判的）。

## 不做

**不追溯已有的线。**用户此前用 `LINE` 画的、端点正压在端口上的线不会自动绑上。绑定来自取点
时的来源，那份来源在提交的那一刻就不存在了；按坐标反查正是决策 1 明确保留下来的禁令。

**不为「我就是不想绑」做画布上的修饰键。**按住某个键取点即不绑，是给一个罕见情形造一个要记
的键。退路已经有了（画完在 Inspector 里解除），而修饰键的发现成本比它高。
