## ADDED Requirements

### Requirement: 场景只渲染与裁剪窗口相交的子树

Stage 的 Scene MUST 只为与**裁剪窗口**相交的 Entity 建立 DOM 节点；不相交的子树 MUST 整棵
跳过。

判据 MUST 是**子树**包围盒而不是 Entity 自身的盒：子级是绝对定位的，容器不裁剪时子级可以画在
父盒之外，按自身盒裁会让「父在屏外、子在屏内」的整棵子树消失。带 `Clip` 的容器是例外——它的
后代画不到自己盒外，因此子树包围盒**就是**自身盒。

小图上可见集等于全集，渲染输出 MUST 逐字节不变。

#### Scenario: 屏外的子树不进 DOM

- **WHEN** 一份五千实体量级的文档打开且大部分内容落在可视区之外
- **THEN** DOM 里的 Entity 节点数与可视区相称，而不是与文档规模相称

#### Scenario: 父在屏外而子在屏内

- **WHEN** 一个不裁剪的容器自身盒完全落在窗口之外，但它的某个子级落在窗口内
- **THEN** 该子级仍然被渲染

#### Scenario: 可视区内的都在

- **WHEN** 任取一个落在图面可视区内的 Entity
- **THEN** 它在 DOM 里有对应节点

### Requirement: 裁剪窗口是量化的，内容不随帧重建

裁剪窗口 MUST 是一个**离散**值：以视口中心为心，尺寸只由**量化后的缩放档位**决定，外扩之后
四条边各自**向外**吸到格子上。场景内容的记忆化 MUST 依赖这个窗口的身份，MUST NOT 依赖视口
本身。

理由是既有的那条约束仍然成立：内容子树与视口解耦，是因为让它随帧变化会让每一个平移帧都为全部
Entity 重建 element 并做 fiber diff。裁剪若直接依赖视口，等于用一个每帧全量 diff 换掉一个每帧
全量样式重算。

**缩放 MUST 量化，窗口尺寸 MUST 只认档位而不认档内的真实缩放**：缩放是连续量，窗口按真实可
视区取尺寸时几乎每一帧都换一个窗口。窗口因此 MUST 按档内**最宽**的那个可视区取尺寸，
「窗口恒包含可视区」才在整个档内成立。

**吸附 MUST 向外**：向外吸让「窗口恒包含可视区」由构造成立。就近吸时每条边最多向内让半格，
于是要求外扩量严格大于半个步长，而那种数值关系一旦被后来者调参调破，症状是拖到某处边缘闪一下
空白——一个只在特定平移位置出现、极难复现的缺陷。

**窗口的格数 MUST 由档位定死，只有左上角随平移走**：两条边各自吸各自的时，格数会在相邻两个
整数之间来回跳，于是平移每过一格换**两次**窗口而不是一次。

**换窗那一帧 MUST NOT 一次性挂上或卸下整条带子**：新进窗口的与离开窗口的 Entity MUST 从
下一帧起分批逼近目标，每帧一批；一批装得下时 MUST 当帧到齐。没变的子树 MUST 交回同一个
元素对象，React 才能在它上面跳过。

这一条**只在外扩量存在时才成立，而它正是外扩的全部用途**：新进的带子按构造整条落在可视区
之外，晚几帧到达用户看不见。推论：大图平移时 DOM 里的节点数是**最终一致**的，读它的用例
必须先等它稳定；小图上换窗仍是同步的。

MUST NOT 把这一趟重建交给低优先级渲染：React 的低优先级渲染每收到一次高优先级更新就整个
重来，而平移每一帧都是一次高优先级更新，连续拖动时它永远完不成，直到过期强制刷出——用户看到
的是图要等很久才出来。

缩放跨档、豁免变化与文档变化引起的目标变化 MUST 当帧到齐——新进的节点可能已在可视区里，
正在编辑或正被拖动的那个必须当场在。

#### Scenario: 换窗不落在平移帧上

- **WHEN** 用户连续平移越过量化步长，触发一次换窗
- **THEN** 那一帧不挂不卸任何 Entity，新进与离开的从下一帧起分批处理

#### Scenario: 停下之后图立刻补全

- **WHEN** 用户在大图上连续平移之后停下
- **THEN** 可视区内的每一个 Entity 在几帧之内进入 DOM，而不是等待数秒

#### Scenario: 连续平移不重建内容

- **WHEN** 用户连续平移不足一个量化步长
- **THEN** 裁剪窗口不变，场景内容不重建

#### Scenario: 档位内缩放不重建内容

- **WHEN** 用户以视口中心为锚点在同一个缩放档位内来回缩放
- **THEN** 裁剪窗口不变，场景内容不重建

#### Scenario: 任何位置上窗口都盖住可视区

- **WHEN** 视口停在任意平移位置、任意缩放
- **THEN** 可视区被裁剪窗口完全包含

### Requirement: 裁剪只影响渲染，不可被查询读出

命中测试、框选、吸附候选、场景树与选区几何 MUST 全部按文档与布局快照求解，MUST NOT 读取裁剪
结果。裁剪集合 MUST NOT 作为公共查询暴露，也 MUST NOT 与 `hiddenEntityIds` 合并。

两者语义相反：`hidden` 是渲染与命中**两边都没有**，裁剪是**只有渲染这一边没有**。合并会让
「看得见」与「点得到」分家。

#### Scenario: 屏外对象仍可被框选

- **WHEN** 框选区域覆盖到一个当前没有 DOM 节点的屏外 Entity
- **THEN** 它照常进入选择集

#### Scenario: 屏外对象仍提供吸附候选

- **WHEN** 拖动一个对象，其对齐候选来自一个屏外 Entity 的边
- **THEN** 该候选照常参与吸附

### Requirement: 按 id 查 DOM 的目标必须豁免裁剪

MUST 豁免：正在文字编辑的 Entity、正被手势作用的 Entity、选择集内的 Entity、以及组件实例下钻
的宿主实例。豁免 MUST 沿祖先链向上传播——祖先不在 DOM 里，后代也挂不上去。

判据是**任何一条会按 Entity id 去 DOM 里查节点的路径，它的目标必须豁免**，而不是枚举场景：
新增这类查询时必须同时进豁免集。

**豁免的作用范围 MUST 由豁免的理由决定，分两级**：

- 理由是「有人按这个 id 去 DOM 里找节点」时，找的就是那**一个**节点，因此只豁免它自己加祖先
  链。选择集与实例下钻宿主属于这一级；做成整棵子树会让「选中一块场景」当场关掉整块场景的裁剪。
- 理由是「这棵子树此刻的几何由预览变换决定、索引里的那份是过期的」时，过期的是**整棵**子树，
  因此整棵豁免。手势作用的对象属于这一级；只豁免根的话，把一个容器拖出一屏之外时它自己还在、
  里面的东西却按旧位置被判掉，屏幕上是「抓着的盒子中途空了」。

**裁剪 MUST 按「被裁掉的」而不是「该渲染的」交给渲染层**：渲染层据此只跳过被点名的，因此场景
索引还不认识的 Entity（预览文档里刚建出来、尚未提交的那些）一律照常渲染。

#### Scenario: 编辑中的文字被平移出视口

- **WHEN** 用户正在画布内原地编辑文字，此时视口平移使该 Entity 落到窗口之外
- **THEN** 该 Entity 仍然渲染，编辑焦点与已输入内容不丢失

#### Scenario: 拖动中的对象被拖出视口

- **WHEN** 用户拖动一个对象，使其落到裁剪窗口之外
- **THEN** 该 Entity 仍然渲染，手势不中断
