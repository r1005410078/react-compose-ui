# Stage 细节裁剪：屏幕上小到读不出来的实体不建节点

## Why

视口裁剪落地之后，**工作档**（放大到能读图的那一档）平移已经落到 p50 10ms；而**缩到整张图都在
可视区的那几档**平移仍是每帧 34ms——用户在这几档看总图、找位置，感到的就是这个。

这几档裁剪按定义帮不上忙：可见集就是全集。而 Chrome trace 拆开看，34ms 里 27ms 是 Blink 的
合成层划分（`PaintArtifactCompositor::Update`），它只与 **DOM 里的节点数**有关，与节点画没画出
像素无关。用合成页逐项验证过：`will-change`、去掉恒等 `transform`、去掉 `isolation`、
`overflow: clip`、`contain: paint` 都降不下来——这是每个节点每帧要付的固定账，**只能靠少建节点**。

那这几档的节点在画什么？量了 `app/public/ems.dxf`（5381 个实体）：

| 缩放 | 文字的屏幕字号 | 最大边不到 1 像素的曲线 |
| --- | --- | --- |
| 0.119（适配） | 1810 个全部 < 2px | 1916 条 |
| 0.205 | 1808 个 < 2px | 1010 条 |
| 0.295 | 1807 个 < 2px | 931 条 |

这张图的文字高度是 2.5–5 个图纸单位（接线图的标注），放到工作档 0.735 也只有 2–4 像素——
**它们在这几档一个字都读不出来**，画出来的是一片灰色的绒。曲线里有近两千条整个形状落在一个
像素之内（端子的小圆、符号里的短线），画出来是一个定位被量化过的点。

去掉它们之后同一档平移的帧时间（有头 Chromium、真实 rAF 间隔）：

| 适配档 0.119 | p50 / p95 |
| --- | --- |
| 现状 | 33 / 42 ms |
| 去掉字号 < 4px 的文字 | 21 / 25 ms |
| 再去掉最大边 < 1px 的曲线 | **10.6 / 12 ms** |

这不是新发明：AutoCAD 的 `QTEXT` 与几乎所有 CAD 查看器都在文字小到某个阈值之后不再画字。

## What Changes

### 可读性是裁剪的第二个判据

视口裁剪回答「在不在窗口里」，细节裁剪回答「在这个缩放下画出来读不读得出」。两者产出同一个集合
——「被裁掉的」——交给场景层，豁免（文字编辑中、选中、手势作用中、实例下钻宿主）、按文档顺序
分批、按「被裁掉的」而不是「该渲染的」交给渲染层，全部沿用。

### 阈值由物料声明，判定由 Stage 执行

Stage 不认识物料，它只知道每个 Entity 的世界包围盒与缩放。因此**多小算读不出来由 Renderer
Definition 声明**（`minimumLegibleSize`，屏幕像素，两轴各自可选），Stage 只做「声明的每一轴都
低于阈值就不建节点」这一件事。文字声明高度 5px（约 4px 字号），曲线声明两轴各 1px；没有声明的
Renderer（容器、图片、组件实例、宿主自定义物料）永不因细节被裁。

### 判定按缩放档位而不是真实缩放

与视口裁剪同一条约束：可见集只随**档位**变，档内缩放不重建内容。判定用档位的**最小**缩放
（档内最不利的那一端），因此「一个 Entity 在档内某个缩放下可读、却被裁掉」不可能发生。

### 可读性引起的增减走分批，不当帧到齐

视口裁剪规定「缩放跨档 MUST 当帧到齐」，理由是新进的节点可能已在可视区里。细节裁剪带进来的
节点确实在可视区里，但它们的尺寸就在可读阈值上——放大跨过阈值那一帧一次性挂上一千八百个文字
是一个 50–80ms 的长任务，而让它们在几帧里按文档顺序陆续出现，用户看到的是几像素高的字在
一百多毫秒里补齐。**跨档时由窗口带进来的仍然当帧到齐，由可读性带进来的分批。**

## 本步刻意不做

- **不做迟滞**：档位本身是离散的（一个八度四档），阈值只在档位边界上翻转；在边界上来回缩放会
  来回翻，靠分批把每次翻转摊薄。要不要迟滞等实测有人抱怨再说。
- **不给文字画占位**（AutoCAD `QTEXT` 画一个框）：占位仍然是一个节点，账一样要付；而这几档
  的文字本来画出来也只是一片绒。
- **不改 Preview 与导出**：细节裁剪是编辑画布的性能取舍，预览与发布出去的页面一个像素不变。
- **不动 `--compose-canvas-zoom`**：那是缩放那一档的另一笔账，另立项。

## Impact

- `stage-engine`：`culling` 增加可读性判定的纯函数；窗口与可读性合成同一个「被裁掉的」集合
- `component-registry`：`ComposeRendererDefinition.minimumLegibleSize` 可选字段
- `materials`：文字与曲线各声明一个阈值
- `stage`：`useStageCulling` 接入；场景层对可读性引起的增减一律走分批
- 规范：`stage`、`component-registry`、`basic-materials`
