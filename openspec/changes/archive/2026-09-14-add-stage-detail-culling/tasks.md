## 实测（`ems.dxf`，5381 个实体，有头 Chromium、真实 rAF 间隔、生产构建、1280×720）

平移（滚轮，来回 120 帧）：

| 缩放 | DOM 节点 修前 → 修后 | p50 修前 → 修后 | p95 修前 → 修后 |
| --- | --- | --- | --- |
| 0.119（适配） | 5381 → 1663 | 33 → 13.8 ms | 42 → 22 ms |
| 0.205 | 5381 → 2101 | 36.8 → 14.5 ms | 50.5 → 22.6 ms |
| 0.295 | 5381 → 2353 | 30.9 → 13.5 ms | 43.6 → 26.9 ms |
| 0.735（工作档） | 1480 → 901 | 10.3 → 8.4 ms | 15.6 → 13.8 ms |

跨过可读阈值：从适配档以 Ctrl+滚轮连续放大 110 帧到 1.66，文字在最后二十几帧里按档位陆续回来
（0 → 16 → 18 → 36 → 49），那些帧 8–12ms，与同缩放下的稳态无异——分批生效，没有一次性挂上的
长帧。开头那些 35–63ms 的帧是适配档附近的缩放帧本身（`--compose-canvas-zoom` 的样式重算），
与本刀无关、也不因本刀改变。

留在 DOM 里的文字：适配档下 170 个，全部在组件实例内部——实例作为整体不声明阈值，是提案写明
的边界；端到端因此只数实体自己的文字物料。

端到端的两处返工都记在用例注释里：图面底部坐着命令行，框选的起止点要按场景包围盒定位；
`Escape` 的含义是退回上一层分组而不是清空选区，清空要点空白。
