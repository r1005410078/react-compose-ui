# 设计说明

## 夹点 id：`m{段下标}`

顶点是 `v{下标}`，段中点用 `m{下标}`——第 `i` 段从顶点 `i` 连到顶点 `i+1`，闭合多段线的收尾
那一段下标是 `顶点数 - 1`。

前缀分开而不是复用 `v`：`applyStageCurveGrip` 要按 id 分派到两种完全不同的操作（移动一个既有
顶点 / 插入一个新顶点），而它手上只有 id。

## 插入发生在每一帧，但不会插出一串

拖动期每一帧都拿**文档里的**几何加上同一个 grip id 重新求一次（`applyGripAt` 走
`stageCurveBoxGeometry`，那是文档的几何，不是上一帧的预览）。因此 `m2` 在任何一帧都表示
「在第 2 段中间插一个顶点」，插入的永远只有一个。

提交之后夹点重新派生，那个新顶点变成一个普通的 `v{i}`——它此后与别的顶点没有任何差别。

## 角色与角度住在夹点上，不由覆盖层推

`StageCurveGrip` 增加 `role`（`vertex` | `insert`）与可选 `angle`。覆盖层只认「画方块还是画
条形、条形转多少度」，不认识多段线。

角度由夹点给出而不是覆盖层从邻居算：覆盖层拿到的是一串**扁平的顶点**，它不知道谁和谁相邻，
更不知道闭合多段线的收尾段接的是第一个顶点。让它去猜等于把多段线的结构知识复制进渲染层。

**世界角度就是屏幕角度**：Stage 的视口只有平移与缩放，没有旋转。这一条要写下来——将来若真给
视口加了旋转，这里是会静默错位的地方之一。

## 形状：方块与条形

曲线的几何夹点改成方块（AutoCAD 的形状，也是用户截图里的形状）。菱形留在运动路径上：它的
理由是「与时间线关键帧同形」，而那条理由只在那里成立——运动路径的顶点**就是**关键帧，曲线的
顶点不是。

条形沿段方向摆，长宽比让它一眼不同于方块。两者共用同一个命中半径：可见形状比命中区小，
悬停态照旧靠既有的 `:hover +` 纯 CSS 读，不引入每帧都要写的 React 状态。

## 判别性

| 用例 | 钉住的东西 | 改前 |
| --- | --- | --- |
| 三顶点多段线出 3 个顶点夹点 + 2 个中点夹点 | 中点夹点存在 | 必红（只有 3 个） |
| 闭合四顶点多段线出 4 + 4 | 收尾那一段也算 | 必红 |
| 拖中点夹点后几何变成 4 个顶点，且新顶点在落点上 | 拖它是**插入**而不是平移 | 必红 |
| 拖完再拖同一个位置，顶点数是 5 而不是 6 | 每帧只插一个 | 必红 |
| 中点夹点与顶点夹点渲染成不同形状 | 两个动作看得出区别 | 必红 |
| 直线的中点夹点仍是平移 | 只改多段线 | 恒绿——**护栏** |

最后一条是护栏：直线的中点是 `move`（平移），AGENTS 明写它不是「拖线身的第二个入口」而是
走特征点捕捉的那一个。这一刀不得顺手把它也改成插入——直线插一个顶点就不是直线了。
