# 设计

## 1. 指针跟踪为什么必须挪到根节点

拖动期间十字线断掉，根因不在十字光标本身，而在**指针位置的来源**。

今天 `onPointerMove` / `onPointerLeave` 挂在 `.compose-stage__surface` 上。手势一开始，
`use-stage-pointer-session` 在 **`rootRef`**（Stage 根节点）上 `setPointerCapture`。按 Pointer
Events 规范，设置捕获会向**原目标链**派发 `pointerout` / `pointerleave`，此后 `pointermove`
一律重定向到捕获元素。根节点是图面的**祖先**，因此：

1. 图面收到一次 `pointerleave` → 指针位置被清成 `null`；
2. 此后的 `pointermove` 目标是根节点，冒泡只会往上走，**再也不会经过图面**。

挂到根节点同时解决两件事：捕获期事件直接命中它；非捕获期事件从图面冒泡上来，照样命中它。
坐标仍按 `surfaceRef` 的矩形换算，因此世界坐标一个字不改。

`pointerleave` 的语义也变得更准：从「离开图面」变成「离开整块 Stage」。命令行就在 Stage 里，
指针从图面移到命令行时**不该**熄灭十字光标——用户正要去敲坐标，而那条线钉着的正是他要改的
那个落点。

**不选的两个方案**，理由记在这里免得后来者重走：

- **`pointerleave` 时判断有没有手势在跑，有就不清**：捕获派发的 `pointerleave` 与真的移出
  图面是同一个事件，靠「有没有手势」区分等于用一个相关量去猜另一个；而且它留下「手势结束时
  指针到底在不在图面上」这个没人回答的问题。
- **从 window 级的手势路由里回灌指针位置**：那条路由属于手势会话，让绘图的指针跟踪去读它，
  等于把两个本来独立的东西绑在一起——手势会话以后改捕获策略就会静默弄坏十字光标。

## 2. 两条隐藏规则里删哪一条

留 `[data-crosshair]`，删 `:has(> .compose-stage__drafting)`。

`[data-crosshair]` 读的是 `resolveComposeCanvasCrosshair` 的返回值，也就是规范指定的**唯一
判据**；它的注释还记着为什么用根节点属性而不是 `:has()`（`:has()` 在旧一些的浏览器里整条
规则被丢弃，症状正是「系统光标没隐藏」，且只在部分浏览器上出现）。

`:has()` 那条读的是覆盖层挂没挂，而覆盖层的挂载条件是 `pointerTracked`——它比十字光标宽：
指针位置为 `null` 时覆盖层仍然挂着（里面还有捕捉标记与橡皮筋），十字光标却已经不画。两者
本来就不该对齐，因此它不是「重复的第二份」，而是**判据不同的第二份**，更该删。

修完之后第 1 节那个洞被堵上，这条规则在拖动期也不再是必要的——但它仍然要删：不变量是
「只有一个判据」，而不是「两个判据碰巧一致」。

## 3. 会话作用域收成单选

存续条件 `selectedIds.includes(target)` 改成「选中集恰好是目标一个」。

判据是**会话的全部呈现都只描述一个对象**：夹点、轮廓、十字光标、以及被排除出捕捉的那一个
Entity。多选时这些呈现对第二个对象一句话都没有，而选区盒与 Resize 手柄又被会话抑制掉了，
于是第二个对象在图面上完全隐身——它明明被选中了。

「Shift 累加退出会话」与既有的三个退出口（`Escape`、点空白、选中别的 Entity）是同一件事的
第四种写法：**选中集不再只是它了**。规范里那句「选中别的 Entity MUST 退出」本来就该这么读，
本刀把它写死。

## 4. 拾取框的半边长为什么不复用 `pickRadius`

`pickRadius`（默认 8）服务的是命令等待选择对象那一档，而规范写明**它不参与任何命中判定**：
Stage 的点选是 DOM 驱动的，容差散在各物料的 stroke 宽度里，没有全局的那个数。

顶点模式是唯一的例外：那里的可抓目标只有夹点，而每个夹点的命中区都是同一个
`LINE_ENDPOINT_HIT_RADIUS`。因此这一处的框可以**真的**表达「压住了就抓得到」。

要让它诚实，框的**内切圆**才是命中区，所以半边长取 `LINE_ENDPOINT_HIT_RADIUS / √2 ≈ 7.07`
而不是 10——取 10 的话四个角伸到 14.1，用户在角上按下去会落空，而那正是他最相信框的时候。
（反过来取 7.07 时框的四条边内切于命中圆，框内一律抓得到，框外一小圈也抓得到——**宁可少说
不可多说**。）

这个值**跟着 `LINE_ENDPOINT_HIT_RADIUS` 派生，不新增常量也不写字面量**：两者一旦分开写，
下一个改命中半径的人不会想到还有一个框要跟。

## 5. 悬停态用纯 CSS

夹点的可见菱形与命中圆是两个元素（菱形 `pointer-events: none`，命中圆 `pointer-events: all`）。
把命中圆**排到菱形之前**，用 `:hover + 菱形` 改填充。

- **不引入 React 悬停态**：那是每帧 `pointermove` 一次 `setState`，为一个纯视觉反馈重渲整个
  覆盖层；而仓库的规则是「只保存最小且不可派生的状态」。
- **调换渲染顺序不影响命中顺序**：菱形是 `pointer-events: none`，它排在命中圆之后还是之前，
  在**可命中元素**之间的先后一个字不变。切线手柄仍然最后渲染，「切线命中优先于顶点」照旧。
- **拖动期悬停态自然消失**：捕获在根节点上，`:hover` 随之从命中圆上移走。这与本刀不做热夹点
  是自洽的——拖动中的那个夹点跟着预览几何走在光标底下，不需要再变一次色。
