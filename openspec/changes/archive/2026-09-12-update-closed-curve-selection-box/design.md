# 设计

## 上下文

「选中一条曲线时画它的几何轮廓，不画包围盒」这条规则落地时，判据写的是**盒是不是这个对象的
轮廓**，而实现读的是 `isComposeRectangleCurve`。两者不等价：判据是一句关于**面积**的话，
实现却只认一种顶点排布。

## 决策

### 决策 1：判据是「闭不闭合」，不是「是不是矩形」

- **内容**：`polyline` 且 `closed`，或扫掠绝对值为 360 的 `arc`（整圆）→ 画盒 + 八个手柄；
  其余 → 画几何轮廓。
- **原因**：闭合图形占据的就是它盒里的那块面积，盒宣称的是真话。开放几何才是这条判据要挡的
  东西——一条对角线的包围盒里绝大部分是空的，线越接近 45 度它越大，拖端点时还一直在变。
- **矩形不再是特例**：它是「闭合四顶点多段线」，这条规则的一个实例，呈现一个像素都不变。

### 决策 2：不用面积占比，哪怕它更准

- **考虑过**：`几何面积 / 包围盒面积 > 阈值` 才画盒。它确实更贴近判据本身——闭合的三角形只
  填盒的一半，L 形闭合折线更空。
- **否掉的理由**：那个阈值是一个魔法数，本仓库没有第二处需要它；更糟的是**同一个形状会在你
  拖一个顶点时突然换一套 chrome**——盒与手柄凭空出现或消失，而用户找不到任何解释。
- **代价写在明处**：闭合不是完美的代理。这是一次**明知不完美而选它**的取舍，理由是它一句话
  说得清、从文档里读得出来、且不会在手势中途翻转。

### 决策 3：整圆算闭合，一段弧不算

- **内容**：`isComposeFullCircle` 为真的 `arc` 算闭合。
- **原因**：整圆是一块面积，填自己盒的 78.5% 且四条边都被切到；一段弧是一条开放的线，它的盒
  正是「大半是空的」那一类。`arc` 上本来就没有 `closed` 字段，因此这一支必须显式判。
- **先例**：`projectComposeCurveToBox` 早就在用 `closed: isComposeFullCircle(curve)` 表达
  同一件事，本条只是让选中呈现读同一个答案。

### 决策 4：`isComposeRectangleCurve` 删掉而不是留着

- **原因**：它唯一的消费者就是这条判据。留着会让「盒是不是这个对象的轮廓」有两个读起来都像
  答案的入口，而它的 TSDoc 整段在讲那条**已经被放宽了的**旧规则——下一个人读到它会以为矩形
  仍是特例。
- **不是「顺手清理」**：它是公共导出，删除是破坏性变更，因此必须走这条流程说出来。

## 风险 / 权衡

- **闭合但很空的形状会拿到一个大半是空的盒**（L 形闭合折线、细长三角形）。接受：见决策 2。
- **公共 API 删了一个导出**。仓库内无第三方消费者，`isComposeClosedCurve` 是严格更一般的
  替代。
