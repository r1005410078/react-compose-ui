# 变更：自定义工作区

## 原因

画一次接线图和搭一张大屏页面，用的是同一副面孔。编辑器里能「造出东西」的入口有两类，侧重
完全不同：**工具**（工具栏与命令行——取点、造几何、靠捕捉与十字光标）和**基础组件**（物料
面板——拖放、造盒、靠布局求解与数据绑定）。搭页面九成时间在后者，画接线图九成时间在前者。
路线图决策 10 关上了「按任务切模式」这条路（模式必须是对象作用域）；Blender 给了另一条：
**Workspace 不是 Mode**——Mode 改可操作元素与键位含义，Workspace 只改面板怎么摆、默认值是什么，
顶部一排标签随时切，切错了没有代价。

业务往后怎么变说不准。把「符号库该在左还是在右」写死在代码里是把不确定性押在自己身上；交给
Dockview 的拖拽押在用户身上，而他们比我们清楚。因此**先做机制，再做内建**：本变更把工作区
做成「一份 Dockview 布局快照 + 几样会话默认值」，面板可拖、拖过的样子随工作区记住、可另存成
新的、宿主可按业务注入。内建列表本变更只含一个 `page`（今天的布局，取名「页面」）；第二个
内建「绘图」由 `add-builtin-workspaces` 加上，工具栏与物料面板的货架由
`add-shelf-customization` 加上。

**它不是模式**，由三条硬边界保住：不改手势语义、不改命令可用性（命令行词汇表、快捷键、动作
目录两边完全相同）、不写文档（切换不产生事务、不进撤销历史、不打断正在取点的命令）。
**它也不绑定文档**：没有「绘图文件」这种文件类型——决策 1 与 5 把 CAD 文档删掉之后接线图画在
`.page` 的场景里，同一个页面上常常既有 KPI 卡也有主接线。「打开一张接线图就该落在绘图里」靠
按文档记忆，不靠绑定。

设计稿第 4、5、8、9、10、12、13 节：
https://claude.ai/code/artifact/bb4abedb-212a-4a4e-abc8-6eb6c2c19047

**以 `restructure-editor-chrome` 落地后的规范为基线**（单一 Dockview、通栏文档标签条）。
**不考虑兼容性**：四区不变量、临时布局状态、按文档类型记忆三条直接删除，偏好结构直接换新
形状，不写迁移。

## 变更内容

### 新增

- **工作区定义**（`ComposeEditorWorkspaceDefinition`）：稳定 `id`、已本地化 `title`、可选
  `icon` 与 `description`（切换器上的提示）、`layout`（用面板名描述的 `preset`：左右两侧各一列
  上下堆叠的组、底部一条；或不透明快照）、`session`（角度约束、增量角、网格可见、十字光标
  臂长、变换 Gizmo）。**不给宿主 builder 函数**——那要把 `DockviewApi` 交给宿主，而公共入口
  不得转导 Dockview 成员；面板名的 preset 宿主写起来也不需要认识 Dockview。定义里没有任何
  能改变命令集、按钮含义或快捷键的字段。
  `COMPOSE_DEFAULT_WORKSPACES` 本变更只含 `page`；宿主经 `workspaces` prop 替换列表，重名抛错。
  宿主注入的与用户另存的在模型里是同一种东西，差别只在谁给了初始布局。
- **面板可拖**：去掉 `locked: 'no-drop-target'` 与 `disableDnd`。三条硬约束由代码保证：画布
  面板可搬不可关（标签无 ×，`removePanel` 拒绝）；每种面板至多一个（拖是搬不是复制）；时间线
  面板不进快照（动画模式叠加的，切换后加回）。浮动组与弹出窗口关闭。
- **布局快照**：用户改过布局后 `toJSON` 记入偏好 `workspace.layouts[id]`（防抖），激活时
  `fromJSON`；快照对宿主不透明（带 Dockview 版本号的 opaque 值），校验失败丢掉回到 builder，
  不报错不阻塞。三级回退：记忆 id 不在列表 → `lastUsed` → 第一个；快照失败 → builder；builder
  也没有 → 从列表删掉并提示。
- **切换不打断画布**：画布、场景图、属性面板各自渲染进一个稳定的宿主元素，Dockview 面板只把
  它搬进自己的盒子；`fromJSON` 重建盒子之后把同一个元素搬进新盒子，一个组件都不重挂载，
  正在取点的命令继续等它的点。
- **切换器**：文档标签条右端的 `radiogroup`，方向键按索引循环；hover / focus 提示这个工作区
  会换的东西。切换依次应用布局、会话开关；记入 `lastUsed` 与当前文档的 `byDocument`。会话开关
  的改动记入当前工作区，切回时恢复。
- **按文档记忆**：激活标签时应用该文档记着的工作区，没记过不切；点切换器记成当前文档的新
  记忆；新建文档继承当前。记忆是偏好，不写页面文件。它取代「边缘面板按文档类型记忆」：键从
  文档类型细到文档，值从折叠状态扩到整份布局。
- **管理菜单** `▾`：另存为工作区…、重命名、重置布局、删除、只看画布。**保存没有按钮**——
  松手即记入，面板挪位后段上出现修改点（分栏尺寸 / 折叠 / 活动标签记入但不点亮），「重置」
  拉回基线（内建与宿主注入的基线是定义自带的 builder 或 layout，自定义的是创建时的快照）。
  另存为只问名字，显示名重复自动加序号，创建即切换。删除要确认，确认框写明记着它的文档数与
  回退去处。内建与宿主注入的不可删、不可重命名，菜单项灰掉并标明而不是藏起来。
- **只看画布**：`api.maximizeGroup(canvas)` / `exitMaximizedGroup`，按工作区记忆。
- **偏好字段** `workspace`：`lastUsed`、`byDocument`、`layouts`、`custom`，经
  `onPreferencesChange` 交给宿主持久化。
- **动作目录**：切换到某个工作区、下一个 / 上一个、只看画布、另存为、重置；可在命令行键入；
  默认不绑键——`Ctrl+PageUp/Down` 在浏览器里是切标签页，拦不住。

### 修改

- 「四区编辑器工作区」「固定中央画布」「临时布局状态」「场景下方工具分栏」「Dockview 场景工具
  布局」「边缘面板按文档类型记忆展开状态」六条删除：四区降为内建 `page` 的 builder 摆出的初始
  布局，画布可搬不可关，序列化进偏好，按类型记忆并入按文档记忆。
- 「文档标签条」：右端在设置按钮之前加入工作区切换器与管理菜单。
- 「设计与动画模式切换器」：时间线面板不进快照，切换工作区后加回。
- 「实例级编辑器偏好」：多一个 `workspace` 字段。

### 不做

- 第二个内建工作区、物料面板货架、新建种子：`add-builtin-workspaces`。
- 工具栏货架与两个自定义对话框：`add-shelf-customization`。
- 浮动组与弹出窗口：画布只有一个宿主元素，弹到别的窗口就没了。
- 按工作区改命令集、按钮含义或快捷键：schema 里没有这个字段，这比写 MUST NOT 更硬。
- 项目级默认工作区（`app.json`）：文档记忆已让「打开就对」在第二次打开时成立。
- 显式「保存」按钮：会造出「拖过但没保存」这个没有用途的状态。
- 由工作区控制 Inspector 分组的显隐：那条的判据是「父级有没有 Auto Layout」，与工作区无关。

## 已定的取舍

| 事项 | 取值 | 理由 |
| --- | --- | --- |
| 内建列表 | 本变更只含 `page`（页面） | 机制先于内建；「绘图」在下一个变更 |
| 只看画布 | 进这一期 | Dockview 原生 `maximizeGroup` 加一条动作，对「大」贡献最大 |
| 另存为 | 进这一期 | 快照模型下只是复制一份 JSON 加起名；不进的话拖拽的价值只剩一半 |
| 切换器键位 | 默认不绑 | 浏览器占着 `Ctrl+PageUp/Down`，一个默认就失效的键位比没有更差 |

## 影响

- 规范：`editor-workspace-layout`（REMOVED 6 条、MODIFIED 2 条、ADDED 9 条）、
  `editor-preferences`（MODIFIED 1 条、ADDED 1 条）。
- 代码：`packages/editor`（`workspace-layout/` 新增 `workspace-definition.ts`、
  `workspace-switcher.tsx`、`workspace-menu.tsx`、`use-workspace-session.ts`、快照存取校验、
  稳定宿主元素；`editor-preferences`；动作目录）。`stage`、`stage-engine`、`core`、`commands`、
  `component-library` 不动。
- 端到端：`editor-workspace.spec.ts` 新增拖拽 / 切换 / 另存 / 删除用例；黄金图不重录（chrome
  由上一个变更定型，本变更默认布局逐像素不变）。
