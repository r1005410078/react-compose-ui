## 上下文

调研对象是 Blender 与 Photoshop 的 Workspace：工作区是**一份面板布局**加几样默认值，顶部标签
随时切；面板可拖，拖过的样子随工作区自动记住（没有保存键）；「另存为 / 重置 / 删除」在标签
的菜单里。Blender 另有 Mode，那是对象作用域、改可操作元素与键位含义的东西——本仓库已经有它的
对应物（几何编辑、文字编辑、实例下钻），路线图决策 10 也只允许这一类。三级阶梯：工作区
（编辑器级）> 动画开关（文档级，唯一的全局语义分叉）> 几何编辑（对象级）。三级各自回答不同的
问题，因此互相正交：切工作区不碰动画开关，进几何编辑不碰工作区。

基线是 `restructure-editor-chrome` 之后的编辑器：一个 Dockview 7 实例，边缘组、折叠、
`toJSON / fromJSON`、`maximizeGroup` 全是原生；`locked` 与 `disableDnd` 仍然开着。

## 目标 / 非目标

- 目标：工作区模型与注入；面板可拖、随工作区记住、可另存；按文档记忆；切换不打断画布。
- 非目标：第二个内建、货架、种子、浮动组、按工作区改命令集、项目级默认、显式保存、Inspector
  分组显隐。

## 决策

### 决策 1：工作区不是模式，不绑定文档

Mode 对应「可操作元素的种类」，Workspace 对应「面板怎么摆」。这个产品里「画接线图」与「搭
页面」操作的是同一批 Entity，没有任何一个键需要两种含义，因此没有冲突需要模式化解。三条硬
边界：不改手势语义、不改命令可用性、不写文档。

不绑定文档：没有「绘图文件」这种文件类型，同一个页面上常常既有 KPI 卡也有主接线；给页面文件
加 `kind: 'drawing'` 等于把决策 1 删掉的第二个世界换个名字装回来。**命名跟着判据走**：`kind`
回答「它是什么」，被校验、渲染、迁移读到；偏好回答「我想怎么看它」，只被编辑器 chrome 读到，
换个人打开同一张图可以不一样。工作区记忆因此是偏好；代码里已有的
`ComposeWorkspaceDocumentKind`（asset / page / component）才是 kind，不动。

### 决策 2：Dockview 是窗口管理器，工作区就是它的一份布局

面板可拖、可拆、可另存是 Dockview 本来就会的事，今天锁住是首版的选择不是原则。去掉 `locked`
与 `disableDnd`；三条硬约束由代码保证：画布可搬不可关、每种面板至多一个、时间线面板不进快照。画布组另外
保持 `no-drop-target`：它隐藏了组头，别的面板落进去会被吞掉。

宿主给初始布局用的是**面板名的 preset**（`{ left: [['sceneGraph'], ['componentLibrary', 'history']],
right: [['inspector']], bottom: [...] }`）而不是 builder 函数：builder 要把 `DockviewApi` 交给宿主，
而公共入口不得转导 Dockview 成员。preset 还有第二个好处——内建工作区的修改点基线可以直接从
preset 算出结构签名，不必真的建一遍再比。
自定义分三档：宿主注入（`workspaces` prop，带自己的初始布局）、用户拖拽（随工作区记住）、
用户另存（复制当前快照 + 起名，进 `workspace.custom`）。宿主注入的与用户另存的在模型里是同一种
东西。

### 决策 3：切换用 `fromJSON`，但画布不重挂载

`fromJSON` 会 `clear()` 重建面板，React 内容随之重挂载——Stage 里的命令会话、夹点、视口都会
丢；而「正在取点的命令继续等它的点」是「不是模式」这句话在屏幕上唯一能被证伪的形式。解法：
画布、场景图、属性面板的内容各自渲染进一个**稳定的宿主元素**，面板只把这个元素 `appendChild`
进自己的盒子；重建之后把同一个元素搬进新盒子，一个组件都没重挂载。拖拽移动本来就不重建
（`skipDispose: true`），这条只为切换而设。

否掉的另一条路：每个文档 panel 各自承载一棵三栏嵌套 Dockview。切文档时全部重挂载，边缘组
状态也变成每文档一份。

### 决策 4：快照对宿主不透明，失配即回退

快照进偏好而不是文档（它是「我怎么看」）；对宿主是带版本号的 opaque 值，不暴露
`SerializedDockview`。激活时校验：Dockview 版本变了、宿主关掉了某个面板、面板 id 不认识，都
丢掉快照回到 builder，不报错不阻塞。三级回退：文档记忆里的 id 不在列表 → `lastUsed` → 列表
第一个；快照失败 → builder；builder 也没有（自定义丢了快照）→ 从列表删掉并提示。任何一级都
不阻塞打开文档。

### 决策 5：切换器不是标签

它是文档标签条右端的一个分段控件，与「设计 / 动画」同族（`radiogroup`，方向键按索引循环，
活动段 accent 底）；文档标签是文档，它是控件，因此不吃标签的活动 / 非活动样式，也不会被当成
第三个文档。工作区在上、模式在下，两个切换器不同行、不同宽度，层级用位置说出来。

### 决策 6：保存没有按钮

松手即记入当前工作区，与主题、键位一样经 `onPreferencesChange` 交给宿主；段上的修改点表示
「与基线不同」，「重置」拉回基线——这就是撤销，因此布局改动不进编辑器撤销历史。显式保存会
造出「拖过但没保存」这个状态，而它没有任何用途。分栏尺寸、折叠、活动标签同样即时记入但不
点亮修改点：它们太频繁，点只回答「面板挪过位没有」。重命名的撤销边界是「再改回来」；删除
不可撤销，因此要确认。

### 决策 7：会话开关这一档很薄，如实写

网格可见（controller `useState(true)`）、角度约束与增量角（`useState('polar')`）、十字光标臂长
（`crosshairSize`）、变换 Gizmo 都是会话状态，工作区各记一份、切换时换入换出——不是因为初值
不同（本变更只有一个内建），而是让用户在某个工作区里改过之后切回来还在。网格步长是文档字段
（`document.canvas.grid`，经 `canvas.configure` 事务写入），切换时不碰——替用户改它等于在他没
动手的时候往撤销历史里塞一条。

## 风险 / 取舍

- 在两个不同工作区的标签之间来回切，面板会跟着翻。今天的按文档类型记忆下已经如此，用户没有
  反映过困扰；对同一个文档，面板是稳的。
- 稳定宿主元素是一个「React 不关心容器在哪」的约定，要用 StrictMode 组件测试钉住——端到端跑
  的是生产构建，挡不住这类回归。

## 迁移

不做。偏好里没有 `workspace` 字段时按默认值补齐。
