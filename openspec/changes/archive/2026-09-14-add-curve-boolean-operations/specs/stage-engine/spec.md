## ADDED Requirements

### Requirement: 五条布尔运算命令

`stage-engine` MUST 提供五条命令：`UNION`（别名 `UNI`）、`SUBTRACT`（`SU`）、
`INTERSECT`（`IN`）、`EXCLUDE`（`XOR`）、`FLATTEN`（`FLAT`），全部归编辑分组。

别名 MUST 照抄 AutoCAD 既有的 `UNI` / `SU` / `IN`——用户只记一套词。异或 MUST 用 `XOR`
而不是 `EX`：后者要留给将来的 `EXTEND`，而一个词只能指一条命令。

五条 MUST 走 `ERASE` 那条**两条次序共用**的状态机：启动上下文里已经选好合格的对象时
`prompt` MUST 为 `null`（宿主随即以 accept 推进、当场执行）；没选好时 MUST 提示选择对象，
把随后的点选与框选结果记下来。

`UNION` / `SUBTRACT` / `INTERSECT` / `EXCLUDE` MUST 要求至少两个操作数；`FLATTEN` 一个即可。
数量不够时 MUST 以可判别的说明拒绝，MUST NOT 什么都不做——「敲了没反应」与敲错字在屏幕上
无法区分。

五条 MUST NOT 取点：它们不进取点管线、不画十字光标、不声明 `fields`。

#### Scenario: 先选后执行

- **WHEN** 已经选中两个合格的形状，在命令行敲 `UNI` 并回车
- **THEN** 命令当场执行，不再提示选择对象

#### Scenario: 先执行后选

- **WHEN** 没有选中任何对象时启动 `UNION`，随后框选两个形状并回车
- **THEN** 命令以这两个形状执行

#### Scenario: 数量不够时拒绝

- **WHEN** 只选中一个形状就确认 `INTERSECT`
- **THEN** 命令以「至少需要两个形状」拒绝，文档不变

#### Scenario: 拍平接受单个对象

- **WHEN** 只选中一个圆角矩形就确认 `FLATTEN`
- **THEN** 命令执行

### Requirement: 操作数合不合格在解算层判定，命令会话只管数量

命令**会话**层 MUST NOT 读文档：它只知道选中了几个，因此只由它判断数量够不够。其余判据——
有没有几何、是不是贝塞尔、是不是直线、锁没锁、有没有导线绑着——MUST 由**解算**层判定，
那一层拿着场景索引，与填充解算读 `Lock` 是同一条既有边界。

拒绝 MUST 报**原因码**而不是文案（本包不认识 locale），并 MUST 带上挡住运算的那个 Entity
的名称——凡是能指出「是哪一个」的情形都要指出来。

原因码 MUST 互相可分，至少覆盖：不够（`too-few`）、不带几何（`no-geometry`）、锁定
（`locked`）、被导线绑着（`wired`）、还没有布局盒（`unresolved`）。

**哪些原因码挡得住这一次运算，由运算自己决定**，MUST NOT 收成一份全局清单：拍平不求交，
因此贝塞尔与直线在它这里都放行——那两条限制的理由是平面图的边还没有三次贝塞尔这一种，
而拍平一张平面图都不用建。

锁定的操作数 MUST 拒绝并说明，MUST NOT 静默跳过它——「你锁了它」和「我把它删了」是两件事。
被导线绑着的操作数在**会合并成新对象**的运算里 MUST 拒绝：删掉它会让绑定悬空，而悬空引用
不让文档非法，这个错屏幕上只在 Inspector 里现形，因此必须在事前拦住。

#### Scenario: 含容器时拒绝

- **WHEN** 选中一个矩形与一个容器后确认拍平
- **THEN** 解算以 `no-geometry` 拒绝，并带上那个容器的名称

#### Scenario: 锁定的操作数拒绝

- **WHEN** 操作数里有锁定的 Entity
- **THEN** 解算以 `locked` 拒绝并带上它的名称，文档不变

#### Scenario: 被导线绑着的操作数拒绝

- **WHEN** 有导线端点绑着某个操作数的端口
- **THEN** 解算以 `wired` 拒绝并带上它的名称

#### Scenario: 拍平放行贝塞尔与直线

- **WHEN** 操作数里含 `kind` 为 `path` 的曲线与 `kind` 为 `line` 的曲线，执行拍平
- **THEN** 解算成功——拍平不求交，那两条限制的理由在这里不成立

#### Scenario: 数量由会话判定

- **WHEN** 一个对象都没选就确认一条区域运算
- **THEN** 会话以可判别的说明拒绝，解算根本不被调用

### Requirement: 布尔解算与操作数次序

`stage-engine` MUST 提供解算入口，把选中的 Entity 投影进**世界空间**（与命中、框选、特征点
同一条链）后调用 core 的布尔求解。

操作数 MUST 按**层序从下到上**排列：`operands[0]` 是画在最下面的那一个。它 MUST 同时决定
四件事——`SUBTRACT` 的被减数、结果的外观、结果的名称、结果的父级与插入位置。一条规则四处用；
取不同来源会让场景树上那一行与画布上那块颜色指向两个不同的对象。

旋转过的与跨父级的操作数 MUST 支持：投影走世界空间，结果落成一条 `rotation` 为 0 的新曲线，
旋转已经烘进几何。这与填充跟随拒绝旋转边界不冲突——那条限制的理由是每帧要按盒快照重求，
而布尔是一次性的、事后不跟随。

解算结果 MUST 把「结果没有面积」与「求解退化」报成两种互相可分的拒绝，MUST NOT 合并。

#### Scenario: 被减数是最下面那一个

- **WHEN** 一个圆压在一个矩形上面，对两者求差集
- **THEN** 得到的是矩形减去圆，而不是圆减去矩形

#### Scenario: 旋转过的操作数

- **WHEN** 其中一个操作数 `Transform.rotation` 非零
- **THEN** 运算按它旋转之后的真实轮廓进行，结果的 `rotation` 为 0

#### Scenario: 跨父级的操作数

- **WHEN** 两个操作数在不同的容器下
- **THEN** 运算照常进行，结果落在最下面那个操作数的父级里

#### Scenario: 结果没有面积

- **WHEN** 对两个不相交的形状求交集
- **THEN** 解算报「没有重叠」，MUST NOT 报成求解退化

### Requirement: 布尔运算通过效果说出意图，不建 Entity

命令 MUST 只在效果上说出「对这些 Entity 做这一条运算」，MUST NOT 自己建 Entity、
MUST NOT 认识 Preset id——与既有的镜像、对齐、修剪、填充是同一条边界：引擎不认识 Registry。

一次运算 MUST 产出**一个**事务：新建结果与删除操作数在同一个事务里，撤销一步全回去。

#### Scenario: 一次运算一个事务

- **WHEN** 对两个矩形求并集
- **THEN** 文档历史里只多出一条记录，按一次撤销后两个矩形原样回来
