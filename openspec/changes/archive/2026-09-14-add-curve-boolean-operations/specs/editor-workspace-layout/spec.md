## ADDED Requirements

### Requirement: 工具栏的布尔运算 split button

编辑器 MUST 在工具栏目录里提供一格布尔运算，形态是 split button：按钮面直接执行**并集**，
`▾` 打开一个五项菜单——并集、差集、交集、异或，一条分隔线，然后拍平。分隔线 MUST 在那里：
前四条改变轮廓，拍平不改变轮廓，这是菜单里唯一需要表达的分组。

按钮面 MUST **固定**是并集，MUST NOT 记住上次用过的那一条。仓库对看不见的状态的既有判据是
「那个值有没有被印出来」，而一个只有认得图标的人才读得出来的按钮面不算印出来。
代价写在明处：第二常用的差集要多点一下 `▾`。

菜单每一行 MUST 印出**命令 id**：命令行在这个产品里是一等入口，而用户在菜单里才第一次看见
这个词；id 就在工具栏自己那张表里、也正是按下去派发的那一个，因此印出来的词与跑的那条命令
读的是同一份事实，敲进命令行同样能用。

**MUST NOT 印别名，也 MUST NOT 印快捷键**，两条各有自己的理由：

- **别名**（`UNI`/`SU`/…）住在 `stage-engine` 的命令定义上，编辑器够不着，抄一份就会漂——
  绘图命令按钮把提示写成命令名正是同一条既有决定。
- **快捷键**住在 `stage` 的键位表上，而键位的显示形式**按平台变**（`⌥⇧U` 在 Windows 上读作
  `Alt+Shift+U`）。编辑器手上只有它自己那张动作键位表，`drafting.*` 不在里面，因此它既拿不到
  绑定、也就无从按平台格式化——硬写一份 mac 的字形在 Windows 上直接是错的。目录里 `F8`/`F10`
  能写成字面量是因为那两个**跨平台同形**，这条豁免不推广到带修饰符的键位。

代价写在明处：`⌥⇧U/S/I/E/F` 这一组在界面上没有地方印，只写在目录项的声明里。要把它印出来，
得先有一条让编辑器读到 Stage 键位表的通道，那是另一件事。

菜单项 MUST NOT 表达「按下态」：它们各自是一次性动作，不是模式，也不是同一个动作的
参数——这与形状工具那种「一个动作的几个参数」不是一回事。

#### Scenario: 按钮面执行并集

- **WHEN** 选中两个形状后点击按钮面
- **THEN** 并集执行，菜单不展开

#### Scenario: 菜单列出五条

- **WHEN** 点击 `▾`
- **THEN** 菜单里有并集、差集、交集、异或、拍平五行，拍平之前有一条分隔线，
  每行右侧印着命令 id

### Requirement: 布尔运算这一格不是任何能力的唯一入口

布尔运算的五条命令 MUST 各自在工具栏之外**至少还有一条**入口——命令行（按名称或别名键入）
与快捷键都算。工具栏是入口的货架，用户把这一格从货架上拿掉 MUST NOT 拿掉这五项能力。

这一格 MUST 进**绘图**那条内建货架，MUST NOT 进页面那条。理由不是「页面用不上」——而是
16 格工具栏在 1280 默认窗口下余量不到半格，而溢出是从**尾部**收进「更多」的，加一格就会把
尾部那一格挤走。布尔运算在页面工作区仍然完整可用（命令行、`⌥⇧` 键位，以及用户自己把它加上
货架），收走的是一个默认入口而不是一项能力——这正是「货架不得成为任何能力的唯一入口」那条
规则允许的那一种取舍。

目录项上的「第二条入口」声明 MUST 逐项写明并被自定义对话框的来源列印出来：说明文案承诺
「拿掉一格不会拿掉那项能力」，印出来这句承诺才是可核对的。

#### Scenario: 页面工作区里没有这一格，命令照样敲得出来

- **WHEN** 在页面工作区的命令行敲 `UNI` 并回车
- **THEN** 并集照常执行，尽管工具栏上没有这一格

#### Scenario: 从货架上拿掉之后仍可用

- **WHEN** 用户把布尔运算这一格从工具栏货架上移除，然后在命令行敲 `UNI` 并回车
- **THEN** 并集照常执行

#### Scenario: 来源列印出第二条入口

- **WHEN** 打开工具栏自定义对话框，看布尔运算那一行
- **THEN** 来源列写着它的命令名

#### Scenario: 分隔线不吃掉一次方向键

- **WHEN** 菜单打开着，焦点在异或那一行，按方向键往下
- **THEN** 焦点落在拍平那一行——分隔线 MUST NOT 是一个按下去什么都不发生的可聚焦项
