## ADDED Requirements

### Requirement: 布尔运算的落地规划

`stage` MUST 把布尔运算的解算结果规划成命令。规划住在宿主而不是引擎，理由与填充同一条——
新建那一支要一个 Preset 与一个新的 Entity id，而引擎不建 Entity、不认识 Preset id。

**两支由操作数有几个决定**：

- **恰好一个**：MUST 原地改它的几何（`entity.curve.set`），MUST NOT 新建、MUST NOT 删除。
  判据是**这还是不是同一个对象**——拍平一个圆角矩形之后它还是那个矩形：名字没变、颜色没变、
  位置没变、层序没变，变的只是「顶点还是控制手柄」。走这一支因此保住了 id、动画轨道与导线
  绑定，用的又正是几何写入的那条**唯一漏斗**。
- **多于一个**：合并成一个新的带 `Curve` 的普通 Entity，全部操作数在**同一个事务**里删掉。
  这时它确实不再是原来任何一个。

新 Entity MUST 走**通用曲线 Preset**，MUST NOT 走矩形 Preset：圆角手柄的显形判据读
`Composition.presetId`，而两个矩形求并集之后得到的不再是一个矩形——给它发四个圆角手柄是在说
一件用户不打算做的事。

新 Entity 的 `Appearance`、`Renderer` props 与名称 MUST 取**层序最靠后**那个操作数的，
并 MUST 用 `entity.create` 载荷上的 `index` 插在它原来的位置；层序 MUST NOT 用第二条命令表达，
这样层序与创建在同一个事务里。

规划 MUST 再判一次操作数是否合格。这不是与会话那次重复：会话那次是为了给用户一句话，
规划这次是为了不写出非法文档，两者的失败后果不同。

**事务提交之后，选区 MUST 挪到产物上。**布尔运算**消费**用户自己建立的那份选区：操作数被
删掉之后不挪，选区就被静默清空，用户读到的是「我按了一下，东西没了」。判据与编组逐字相同
（编组同样是「消费选区、产出一个对象」，它也把选区挪到新建的那个 Group 上），因此这不是给
布尔运算开的一条新规则。这与「画完一条线不自动选中」不冲突：那一档用户本来就没有选区。

挪之前 MUST 先看事务提没提交——被拒绝的命令不改变文档，此时挪到一个根本没建出来的 id 上，
画布上会一个东西都不选中。原地那一支挪的是操作数自己（它本来就在选区里），写出来是为了让
这个答案只有一句话，而不是「有时候是产物、有时候什么都不做」。

#### Scenario: 拍平一个形状不换 Entity

- **WHEN** 选中一个矩形执行拍平
- **THEN** 文档里的 Entity 集合一个都没增减，那个 Entity 的几何变成 `path`，名称与外观不变

#### Scenario: 并集产出一个曲线 Entity

- **WHEN** 对两个重叠矩形求并集
- **THEN** 文档里多出一个带 `Curve` 的 Entity、少掉那两个矩形，且新 Entity 的填充与描边
  与原来画在下面的那个矩形一致

#### Scenario: 结果不带圆角手柄

- **WHEN** 对两个带 `cornerRadius` 的矩形求并集后选中结果
- **THEN** 画布上不出现圆角手柄

#### Scenario: 运算之后选中的是结果

- **WHEN** 选中两个矩形求并集
- **THEN** 选区恰好是新产出的那个 Entity，MUST NOT 为空

#### Scenario: 撤销一步全回去

- **WHEN** 执行一次布尔运算后按撤销
- **THEN** 结果 Entity 消失，两个操作数连同它们原来的层序一起回来

### Requirement: 布尔运算的八种拒绝各有一句话

`stage` MUST 为布尔运算的每一种拒绝给出**互不相同**的命令行说明：选择集不足、含不带几何的
对象、含贝塞尔路径、含直线、操作数锁定、操作数上接着导线、结果为空、求解退化。

结果为空时 MUST NOT 在文档里产出任何东西——竞品在这一档给一个空的布尔节点，那是静默的错；
把静默的错变成可见的错是这条的全部价值。

说明里 MUST 指出是**哪一个** Entity 挡住了运算（按名称），凡是能指出来的情形都要指。

#### Scenario: 交集为空

- **WHEN** 对两个不相交的形状求交集
- **THEN** 命令行说这两个形状没有重叠，文档一个字节不变

#### Scenario: 说明指名道姓

- **WHEN** 操作数里有一个锁定的 Entity
- **THEN** 说明里带着那个 Entity 的名称

### Requirement: 布尔运算的键盘入口

`stage` MUST 为五条布尔命令各绑一个默认快捷键：`Alt+Shift+U` / `S` / `I` / `E` / `F`，
分别启动 `UNION` / `SUBTRACT` / `INTERSECT` / `EXCLUDE` / `FLATTEN`。

它们 MUST 与绘图单键走**同一张**「键位 → 命令 id」映射表，MUST NOT 另开一条从键盘事件直达
命令的路径——否则绕开宿主的键位覆盖与接管两条通道。

`Alt` 这个修饰符在既有默认键位里一个都没用过，因此这五个 MUST NOT 与任何既有动作冲突。
与绘图裸字母同一条：同一个事件上还有别的动作时让路。

#### Scenario: 按下即执行

- **WHEN** 选中两个形状后按 `Alt+Shift+U`
- **THEN** 并集当场执行

#### Scenario: 命令进行中不启动

- **WHEN** 一条取点命令正在等一个点时按 `Alt+Shift+U`
- **THEN** 不启动新命令，已取的点不丢
