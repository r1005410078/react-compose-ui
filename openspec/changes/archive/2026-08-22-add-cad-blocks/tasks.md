## 7. 实施中的发现与偏离

- [x] 7.1 **「块即组件」不能按字面实现，读代码才发现。** `ComposeBaseComponentAsset.document`
      的类型是 `ComposeDocument`，而 `validateComposeDocument` 要求 `rootIds` 每个根带 Frame、
      每个 Entity 带 `LayoutItem`——CAD 图元两样都没有。Variant 的操作代数也只对得上一半：
      `move-entity` 带 `parentId`/`beforeEntityId`，假设内容是一棵树，CAD 是平坦的。
      因此本刀按 DXF 的原始形状做，块表住在文档里；资源化另起一刀。
- [x] 7.2 **可见性遍历收敛成一条。** 命中、框选、捕捉与**渲染**原先各写一遍「哪些图元可见」，
      加上块展开之后四份会立刻分叉——最难排查的一类不一致正是「看得见却点不中」「点得中却
      捕不到」。统一成 `collectCadVisibleSegments`，返回值带 `ownerId`。既有 79 条用例一条没改
      就全绿，这本身是这次收敛正确的证据。
- [x] 7.3 **框选要按 owner 聚合再判定**。块实例展开成多段，逐段判定会让窗口模式选中「只框住
      一半的符号」。窗口要求每段都在框内，交叉只要有一段碰到。
- [x] 7.4 **`scale` 定成 `{x, y}` 而不是单个数**。接线图要镜像符号（一个断路器画一遍，左右
      支路各插一个镜像），负比例是常规用法。补一个轴比事后改协议便宜。
- [x] 7.5 **命令行原先根本发不出 `text` 输入**：键入内容要么被当坐标解析，要么当关键字。块名
      是自由输入，因此补了一档，排在坐标之后、关键字之前，靠本步的 `accepts` 区分而不是靠猜
      内容。
- [x] 7.6 **嵌套块在命令层与校验层各拦一次**。只靠校验器的话，用户提交后拿到的是一条指向
      `blocks/…/entities/…` 的路径，看不懂自己做错了什么。
- [x] 7.7 e2e 两次实测修正：拖拽改用 `page.mouse.move` 绝对坐标——按下之后指针被 surface 捕获，
      `locator.hover` 的可操作性检查会认为元素被挡住而重试到超时；点选坐标是我自己算错了，
      基点取拐角之后实例横跨 160→200，原来点的 220 在它外面。
- [x] 7.8 捕捉用例第一版**证明不了捕捉**：端点恰好落在网格上，捕捉与网格给出同一个答案。
      改成用键入坐标画一条端点不在网格上的线（143,87）当捕捉目标，两者的答案才分得开。
