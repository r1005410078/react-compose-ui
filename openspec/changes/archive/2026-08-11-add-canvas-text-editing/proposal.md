# 变更：画布内原地文字编辑

## Why

目前画布上创建的文字无法在画布内编辑，改文案只能到 Inspector 的 text 属性里改。对"在客户现场快速
搭建大屏"的实施工程师来说，这是最高频动作走了最绕的路径：每写一句文案都要在画布和属性面板之间来回。

缺的是创建之后的那一步：光标没有落进去，用户还得再去别处输入。同时 `draw-text` 原本支持拖拽创建
固定尺寸文字，但那条语义在"点一下就开始打字"的流程里只会碍事——见下方决定 1。

调研确认 Figma 的模型是：点击画布创建文字并立刻进入编辑态可直接打字；编辑态不显示八向变换手柄，
只有一个细边框加文本光标；点击别处或 `Esc` 提交；对已有文字双击、或选中后按 `Enter` 重新进入编辑；
退出时内容为空则删除该文字图层。本变更采用同一套模型。

## What Changes

- Renderer Definition 新增可选的**原地文字编辑契约**：声明承载文本的 value prop 名称。Registry 校验
  该 prop 存在且为 value contract。Stage 只消费这个契约，不识别具体 Renderer 类型——`stage` 不依赖
  `materials`，不能靠 `type === 'text'` 硬编码。
- Registry 新增按 Entity 的**编辑中值覆盖**通道，并让 Renderer 得知自身处于编辑态。编辑期间文档不变，
  而 measurement 现在只从文档 Entity 解析 props，没有这条覆盖 Auto width 就不会实时变宽。覆盖同时
  作用于运行时 props 与测量输入，并令 measurement revision 前进复用既有失效链路。
- StageInteractionController 新增无 DOM 的**文字编辑会话**：`draw-text` 点击创建后自动进入编辑、
  select 工具双击已有可编辑 Entity 进入编辑、选中后 `Enter` 进入编辑；`Esc`、点击画布其他位置、
  选区变化都退出编辑。会话只发布 effect，不持有 DOM。
- Controller 输入协议补三项事实：`pointer.down` 携带**连击计数**（现有事件没有任何双击信息）、context
  提供**可编辑判定**入口、surface 在 `drawing.commit` 建完实体后**回灌新建 Entity**（ID 由 surface 铸，
  Controller 拿不到）。三项都是普通数据，不引入新端口。
- Stage 在编辑态改变覆盖层呈现：**不显示八向缩放手柄与旋转手柄**，改为单一编辑边框；编辑态期间
  屏蔽该 Entity 的移动、缩放、旋转手势与框选。
- 文本提交为**一条可撤销事务**：退出编辑时若内容变化则发一次 `entity.renderer.props.set`；内容为空
  则改为发一次 `entity.delete` 删除该文字实体；内容未变化则不产生任何事务。
- Text 物料声明该编辑契约，并让 Renderer 在编辑态以原地可编辑方式渲染，保持字号、字重、颜色、
  对齐与最终呈现一致。
- 编辑态输入 MUST 走 Hug measurement 的既有失效链路，使 Auto width 文字在输入过程中实时改变宽度。

## 首期边界

- 只支持**纯文本单 prop** 的原地编辑，不支持富文本、区段样式、超链接或多 prop 编辑。
- 不实现"编辑态下点另一个文本图层直接开始编辑"这条 Figma 快捷路径；首期一律先退出再进入。
- 不引入"手动改尺寸后 Hug 自动变 Fixed"的联动。
- 不提供画布内的字体、字号等排版工具条；排版仍在 Inspector 调整。

## 待确认决定

以下两条按下述取舍写入规范，评审时可推翻：

1. **`draw-text` 只按点创建，移除拖拽创建固定尺寸文字。** 最初评审时曾主张保留两种语义（Fixed size
   换行 vs Auto width 增长），理由是拖拽创建已经可用、移除属于净损失。评审后推翻：文字工具的动作
   就是"点一下开始打字"，拖出一个尺寸既不显示也不该显示尺寸标注，留着只会让按下后多出一个用户
   并不想要的自由度。需要固定尺寸换行的文字，改为创建后拖动其变换手柄或在 Inspector 里设宽度——
   Hug → Fixed 的切换本来就有。
2. **空文本退出时删除实体。** 与 Figma 一致。空 Hug 文字会塌缩到接近零尺寸，留在文档里既不可见
   也很难再在画布上选中，只会污染场景树。删除动作是普通可撤销事务，`Ctrl+Z` 可恢复。
