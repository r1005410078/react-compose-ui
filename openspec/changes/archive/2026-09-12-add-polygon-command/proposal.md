# 变更：`POLYGON` 命令画正多边形

## 原因

**画一个正多边形现在只能手动摆顶点。**`PLINE` 逐点取，用户得自己算六个顶点的坐标；
`CIRCLE` 画得出外接圆却画不出内接的那个形状。而这个产品的用户在接线图上画的正是六角
螺母轮廓、三角警示框与多边形分区框——这三样都是「围着一个中心、按边数等分」出来的，
而不是「一个点一个点摆」出来的。

AutoCAD 的 `POLYGON` 把这件事拆成三个问题：几条边、以哪个圆为准、圆多大。三个问题各自
对应一步取值，而**本仓库的命令会话协议已经能表达这三步**——四态推进、关键字、单字段
参数化、`preview(point)` 全部现成。缺的只是这条命令本身，以及宿主侧一条从未被走过的
输入路由。

## 变更内容

### 新增

- `POLYGON`（别名 `POL`）三步会话：**边数** → **中心点** → **内接/外切圆的半径点**，
  产出一条闭合多段线（`kind: 'polyline'`、`closed: true`），落地走 `curve` Preset。
- **第一步同时问边数与档位**：两者并排印在光标旁（数值框 + 圆头胶囊），`Tab` 换档，命令行的
  `I`（内接）/ `C`（外切）关键字是第二个入口且只列出能切过去的那一个。中心步与半径步既不
  显示也不受理它——半个残留比全留或全删都糟。
- 第一步**也收点**：点一下即取用当前边数与档位，并把那一下当作中心点。十字光标在这一步是
  画着的，让它真的能落点比把它画成装饰要好。
- 默认边数与档位都记在本次编辑会话，边数印在尖括号里（`输入边数或指定中心点 <6>`）、档位
  印在胶囊里，直接确认即取用。
- **`+` / `-` 两个关键字增减边数**，**每一步**都可用，并显示在后两步的提示里
  （「指定内接圆半径 [6 边]」）。
- `ComposeCommandPrompt` 加一个可选的 `cursorInput`：声明这一步在光标旁印什么（一个当前值 +
  可选的一个二选一档位）。`fields` 覆盖不了它——那说的是「这一步的**点**怎么参数化」。
- **`Alt` + 滚轮**是这两个关键字的第二个入口：半径步上多边形正在跟着光标预览，滚一格就当场
  多一条边，边数因此不必回到命令行去打。
- 工具栏绘图命令组多一个按钮。
- 顶点数学落在 `core/curve-geometry.ts`——那个模块整个放在一起，不按消费者拆。

### 修改

- **命令行 MUST 能把只要文本的一步交给会话。**`ComposeCommandInputKind` 里的 `'text'`
  一直定义着，但在本变更之前**没有任何一处产出它**：既有命令要么取点、要么选对象、
  要么打关键字。边数步是它的第一个消费者。
- **只等一个数的那一步在光标旁印出来。**命令行在图面底部，而用户的眼睛此刻在光标上——
  「敲一个数」这句话说在他没有在看的地方等于没说。框**只渲染**，输入端仍然只有命令行一个。
  这一档跟踪指针但**不画十字光标**：十字线的含义是「这里可以落一个点」，而这一步点下去
  什么都不会发生。
- **圆角手柄收成只有矩形才出。**它此前对矩形、`PLINE`、多边形一视同仁——「选中即出」的理由是
  「改圆角是最常做的调整之一」，而那句话对矩形成立，对一个六边形符号不成立：选中之后多出
  六个点，十二边形多出十二个，全都在说一件用户不打算做的事，还挡住了里面的图形。判据读
  `Composition.presetId`（矩形是 `rect`，`PLINE` 与多边形都是 `curve`），**不加任何字段**
  ——它已经是文档里「建它的那条命令说了什么」的唯一记录。圆角仍可在属性面板改。
- **`canvas-kit` 的滚轮 Hook 接受一个拦截谓词。**宿主注入，返回真表示本次滚轮已被消费。
  谓词由宿主给出而不由本包判断——判据要读「哪条命令在跑、这一步接受什么」，而
  `canvas-kit` 不认识文档、选择集或命令。

## 三处有意偏离 AutoCAD

照抄的前提是没有理由偏离。这三处各有理由，其余全部照抄（3–1024 边、内接/外切的定义、
「等边闭合多段线」这个产物）。

1. **内接/外切不单独占一步**，做成第一步上的一个**档位字段**——和边数一起问、一起印在光标
   旁，直接确认就走。AutoCAD 把它做成一道必须回答的问题，而它在这里已经有值。形状照搬
   `CIRCLE` 的 `D`/`R` 与「只列出能切过去的那一个」，**但不搬「不跨命令记忆」**：那一条的
   理由是那份状态看不见，而胶囊把它印出来了。
2. **首个默认边数取 6 而不是 4。**四边形有 `RECTANGLE` 这个更快的入口，走这条命令的多半
   是六边、三边。第一次之后默认就跟着用户走了。
3. **不实现「键入半径时底边水平」。**AutoCAD 发明这个固定朝向，是因为在它那里键入的数值
   不携带方向；而本仓库的裸数字走 `applyComposeFieldOverride`，它从**当前落点**出发只替换
   活动字段，另一个分量（角度）保持不变——`radius` 与 `polar` 的数学逐字相同。于是「拖出
   一个大概的朝向，再打一个精确的半径」自然成立，一行特判都不用写。

## 非目标

- **不做 `Edge` 分支**（取一条边的两个端点定多边形）。判据沿用 `ARC` 那一条：AutoCAD 有
  十一种起算方式，我们只做三点式，因为**加一种起算方式就是加一条会话分支**。中心 + 半径
  覆盖这里的绝大多数——用户是在往图上摆一个符号轮廓，不是在既有边上续几何。复活条件写
  清楚：出现「必须贴着一条已知长度的边落笔」的真实用例时再加，加进来的形状也是定好的
  ——中心步上多一个 `E` 关键字，之后两步取边的两个端点，其余一律不变。
- **不给单键快捷键。**七个绘图键（`L P R C A X W`）已经占满了与命令名有认读关系的字母，
  `P` 归 `PLINE`；剩下的字母与「多边形」没有任何认读关系，`G` 还会撞上 Group 的直觉。
  给一个记不住的键比不给更差，而「单键 MUST 同时是别名」这条规则的反向本来就不成立。
- **不为边数扩 `fields` 协议。**`fields` 说的是「这一步的**点**怎么参数化」，而边数不是点。
  光标旁那个框走的是另一条路（只渲染的提示框），因此协议一个字段都不加。
- **不给裸滚轮。**裸滚轮是画布平移、`Ctrl`/`Cmd` + 滚轮是缩放，两者在命令进行中 MUST 照常
  工作：这与「取点接管排在画布平移之下」是同一条判断——命令进行中仍要能平移与缩放画布，
  去看远处那个点。`Shift` 同样不用，浏览器已经把它映射成横向 delta，而那就是横向平移。
- **不放宽「取点命令进行中右键 = 回车」的判据。**它读 `awaitingPoint && gripTarget === null`，
  因此边数步上右键仍然弹上下文菜单。放宽要重新论证那条规则（它当初的两半理由里，「盖住
  正要落笔的地方」在这里不成立），而回车与命令行都够得着。
- **不为正多边形另立 `Curve` kind，也不加意图标记。**「各边等长」在用户拖动任一顶点之后
  就不再成立；`rectangle` / `arrow` / `wire` 那几个标记存在是为了让宿主挑一个特定 Preset，
  而多边形落在 `curve` 上，与 `PLINE` 一致。没有消费者的字段不进协议。

## 影响

- 受影响的规范：`stage-engine`（新增命令）、`stage`（文本输入路由、修饰键滚轮、圆角手柄
  收成只有矩形）、`canvas-kit`（滚轮拦截谓词）、`editor-workspace-layout`（工具栏按钮）
- 受影响的代码：
  - `packages/stage-engine/src/drafting/shape-commands.ts`（新会话与命令定义）
  - `packages/stage-engine/src/drafting/drafting-types.ts`（新增文案键）
  - `packages/core/src/curve-geometry.ts`（正多边形顶点）
  - `packages/stage/src/drafting/use-stage-drafting.ts`（`text` 路由、默认边数 ref）
  - `packages/stage/src/stage-surface/compose-stage.tsx`（文案接线、命令注册）
  - `packages/canvas-kit/src/wheel-navigation/use-canvas-wheel-navigation.ts`（拦截谓词）
  - `packages/stage/src/stage-surface/compose-stage.tsx` 与 `drafting/drafting-entity.ts`
    （圆角手柄的 Preset 判据）
  - `packages/editor/src/stage-toolbar/default-stage-toolbar.tsx` 与 `stage-toolbar-icons.tsx`
- **不碰文档协议**：产出的是既有的闭合多段线，已有文档一个字节不变。
- **顺带订正一处自相矛盾**：`平铺式默认画布工具栏` 的需求正文写着「导线 MUST 占一个按钮」，
  而它下面的场景写着「绘图命令组里有六个按钮，其中没有导线」。代码里导线按钮是在的，因此
  错的是那条场景（它是导线删除那一轮留下的残渣）。本变更要改按钮数量，绕不开它。
