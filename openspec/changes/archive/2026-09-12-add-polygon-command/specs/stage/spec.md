## ADDED Requirements

### Requirement: 接受文本的一步由命令行原样交给会话

当前提示接受 `text` 时，命令行 MUST 把用户提交的非空文本原样以 `{ kind: 'text' }` 喂给
会话：MUST NOT 先尝试解析成坐标，也 MUST NOT 掉进关键字兜底。

`ComposeCommandInputKind` 里的 `'text'` 一直定义着，但在本变更之前没有任何一处产出它——
既有命令要么取点、要么选对象、要么打关键字。少了这条路由，`POLYGON` 第一步收到的 `6`
会因为解析不成坐标、这一步又没有 `fields` 而变成 `{ kind: 'keyword', key: '6' }`，
于是命令行把它渲染成一个**可点的关键字**：关键字是一份枚举，边数不是。

判据 MUST 只看接不接受 `text`，MUST NOT 再要求「且不接受 `point`」：`POLYGON` 的第一步同时
收点（点一下即取用默认边数并把那一下当作中心）。键盘与指针是两条不同的通道，在那一步不会
撞车——它还没有参考点，直接距离输入无从谈起，因此裸数字只可能是那个自由字段的值。

**列出的关键字 MUST 压过自由文本**：输入与某个 `keywords` 项（不分大小写）相等时 MUST 派发
`{ kind: 'keyword' }`。这一支会把**所有**文本原样吞掉，末尾那条关键字兜底因此永远够不着——
症状是在第一步敲 `C` 换档，得到的却是「边数必须是 3 到 1024 之间的整数」。关键字是一份闭合
枚举，落在里面的输入不可能同时是那个自由字段的值。

Stage MUST NOT 解析或校验这段文本。「3 到 1024 的整数」是命令自己的规则，放在宿主等于让
同一条规则有两处来源，而两处判断迟早漂移。

空输入 MUST 仍然走 `accept`：默认值属于会话，这一条不因为多了文本这一路而改变。

#### Scenario: 接受文本的一步收到的是文本

- **WHEN** 当前提示接受 `text`，用户在命令行提交 `6`
- **THEN** 会话收到 `{ kind: 'text', text: '6' }`

#### Scenario: 文本步上的坐标写法不被当成点

- **WHEN** 当前提示接受 `text`，用户在命令行提交 `100,50`
- **THEN** 会话收到的仍是 `{ kind: 'text' }`，Stage MUST NOT 派发点输入

#### Scenario: 列出的关键字不被当成文本

- **WHEN** 当前提示接受 `text` 且列出关键字 `C`，用户在命令行提交 `C`
- **THEN** 会话收到 `{ kind: 'keyword', key: 'C' }`

#### Scenario: 文本步的空确认仍是 accept

- **WHEN** 当前提示接受 `text`，用户提交空输入
- **THEN** 会话收到 `{ kind: 'accept' }`

#### Scenario: 取点步不受影响

- **WHEN** 当前提示接受 `point` 而不接受 `text`，用户在命令行键入一个坐标
- **THEN** 它仍按坐标解析并经过点输入管线，与本要求引入之前完全一致

### Requirement: 修饰键滚轮在命令进行中增减数值

一条命令正在进行、且当前提示列出了 `+` 与 `-` 关键字时，`Alt` + 滚轮 MUST 转成对应的关键字
输入喂给会话（向前一格为 `+`、向后一格为 `-`），并 MUST 阻止本次滚轮走画布平移与缩放。

**裸滚轮 MUST NOT 被命令占用。**裸滚轮是画布平移、`Ctrl`/`Cmd` + 滚轮是缩放，两者在命令进行
中 MUST 一律照常工作。这与「取点接管排在画布平移之下」是同一条判断：命令进行中仍要能平移与
缩放画布，去看远处那个点。因此这条能力 MUST 挂在一个空闲时没有含义的修饰键上。

`Shift` MUST NOT 用作这个修饰键：浏览器已经把 `Shift` + 滚轮映射成横向 delta，而横向 delta
在这块画布上就是横向平移——占用它等于占用裸滚轮的一半。

滚轮 MUST 累加 `deltaY`、过阈值才走一格，MUST NOT 每收到一个事件就走一格：触控板的一次两指
滑动会发出几十个小 delta，那样边数会从 6 冲到 60。累加值 MUST 在方向反转时清零，否则反向滚动
要先抵消掉上一次的余量才有反应。

阈值 MUST 取**一次鼠标滚轮刻度**的量——那正是手感上的「一格」，浏览器把它报成像素模式下的
100～120 像素（Chrome / Safari）或行模式下的 3 行（Firefox）。它 MUST NOT 是一个凭空定的数。
这是本方案唯一的代价：wheel 事件本身没有「一格」的语义，而这个产品同时跑在鼠标与触控板上。

拦截 MUST 通过注入给 `canvas-kit` 滚轮 Hook 的谓词完成，MUST NOT 让 `canvas-kit` 认识命令。

提示没有列出 `+` / `-` 时 MUST NOT 拦截：`Alt` + 滚轮此时与从前一样是平移。

#### Scenario: 修饰键滚轮增减边数

- **WHEN** `POLYGON` 的半径步正在预览，用户按住 `Alt` 向前滚动一格
- **THEN** 边数加一，预览的多边形当场变形，且视口不变

#### Scenario: 裸滚轮仍然平移

- **WHEN** `POLYGON` 进行中，用户不按修饰键滚动滚轮
- **THEN** 画布平移，边数不变

#### Scenario: 命令进行中仍能缩放

- **WHEN** `POLYGON` 进行中，用户按住 `Ctrl` 或 `Cmd` 滚动滚轮
- **THEN** 画布缩放，边数不变

#### Scenario: 触控板的一次滑动不冲到上界

- **WHEN** 用户按住 `Alt` 在触控板上做一次两指滑动，浏览器发出数十个小 delta
- **THEN** 边数变化的格数与滚动距离成正比，MUST NOT 每个事件走一格

#### Scenario: 没有列出增减关键字时不拦截

- **WHEN** 当前提示没有列出 `+` 与 `-`，用户按住 `Alt` 滚动滚轮
- **THEN** 画布平移，与本要求引入之前完全一致

### Requirement: 光标旁的数值框与档位胶囊

当前提示声明了 `cursorInput` 时，Stage MUST 在指针旁画一个数值框：正在键入时印缓冲、状态
`active`；否则印 `cursorInput.value` 且状态 MUST 是 `ghost`（文字淡下去）。「这个数是我给的」
与「这个数是默认的」必须一眼可分，否则用户读不出直接确认会得到什么——而那正是把默认值印出来
的全部理由。

命令行在图面底部，而用户的眼睛此刻在光标上——「敲一个数」这句话说在他没有在看的地方等于
没说。`fields` 走不了这条路：它说的是「这一步的**点**怎么参数化」，而这一步要的不是点。

判据 MUST 由**提示自己声明**，MUST NOT 由宿主从 `accepts` 反推。反推有两处站不住：`POLYGON`
的第一步同时收点，「既不取点也不选对象」那条判据在它身上不成立；而且只有命令知道那个框里该
印什么值，宿主手上只有一句提示文案。

`cursorInput.toggle` 存在时，Stage MUST 在数值框右侧再画一个**档位胶囊**，印出当前档位。
胶囊 MUST 与数值框**形状不同**（圆头对方角），MUST NOT 出光标条，MUST 带一个换档标记。
方框是能打字的、胶囊不是——两个控件长得一样而按下去做的事不同，是最难自己发现的一类缺陷；
这块画布的既有规矩是形状先分开、颜色再分开。

`Tab` MUST 在这一档派发 `toggle.keyword`，与在命令行敲那个关键字**逐字等价**——键位与敲字是
同一件事的两个入口，不是两条实现。它 MUST NOT 参与字段轮转：档位不是一个能键入的数，把焦点
带到一个打不了字的地方是错的。

`Tab` 的两种含义 MUST 互斥且由构造保证：有两个数值字段的步 MUST NOT 声明 `toggle`（那一档
`Tab` 归锁定），声明了 `toggle` 的步 MUST NOT 有第二个数值字段。「同时成立时听谁的」在屏幕上
没有可解释的答案。

框 MUST 只渲染、MUST NOT 接收输入：输入端仍然只有命令行一个。把它做成真的 `<input>` 会撞上
「启动之后焦点交给命令行」，而命令由工具栏按钮启动时指针位置还未知，那一刻根本没有框可以聚焦。

**键入的值 MUST NOT 需要额外一次确认。**缓冲非空时，结束这一步的那次输入（取一个点）MUST 先
把缓冲以 `{ kind: 'text' }` 交给会话，再派发那个点。缓冲是**这一步的待定值**，不是一句还没
敲完的命令——不先交出去的症状是：光标旁那个框写着 `4`，点下中心之后落地的却是六边形，屏幕上
写着一件事、做的是另一件事，而用户没有任何办法看出来。

这与取点步早就成立的那条是同一句话：那里键入的值折进落点里，缓冲从来不会被静默丢掉；
`cursorInput` 那一档此前只有 `Enter` 会把它交出去，是这条规则唯一的漏网。

交出去被 `rejected` 时 MUST 停手，MUST NOT 继续派发那个点：值非法，此刻落一个点等于拿一个
用户没打算要的默认值成图，而拒绝的说明还会被下一步的提示顶掉。

这一档 MUST 跟踪指针（否则框没有可画的位置）。它 MUST NOT 单独决定画不画十字光标：`POLYGON`
的第一步同时收点，那一档的十字线由「正在取点」画出来，而它也确实点得下去。将来若有一步只印框
不收点，那里就 MUST NOT 画十字线——十字线的含义是「这里可以落一个点」。

指针从未进入过图面时 MUST NOT 画，直到收到第一次 `pointermove`：位置无从得知，先不画严格好过
画在错误的地方再跳过去。

#### Scenario: 边数与档位并排印在光标旁

- **WHEN** `POLYGON` 的第一步，指针移到图面上
- **THEN** 指针旁出现一个方框，内容是 `6` 且状态是 `ghost`
- **AND** 它右侧是一枚圆头胶囊，内容是「内接」，带换档标记且不带光标条

#### Scenario: Tab 换档

- **WHEN** 上述状态下按 `Tab`
- **THEN** 胶囊变成「外切」，命令行列出的关键字从 `外切(C)` 变成 `内接(I)`
- **AND** `Tab` 被接管，MUST NOT 落给浏览器的焦点导航

#### Scenario: 正在键入时印缓冲

- **WHEN** 上述状态下在命令行键入 `9`
- **THEN** 光标旁那个框的内容变成 `9`，状态从 `ghost` 变成 `active`

#### Scenario: 键入的值不必按回车确认

- **WHEN** `POLYGON` 的第一步键入 `4`（不确认），随后在图面上取中心点
- **THEN** 落地的是四边形，而不是默认的六边形

#### Scenario: 键入的值非法时不落点

- **WHEN** `POLYGON` 的第一步键入 `2000`（不确认），随后在图面上取一个点
- **THEN** 会话停在第一步并给出被拒绝的说明，MUST NOT 创建任何 Entity

#### Scenario: 指针没进过图面时不画

- **WHEN** 从命令行启动 `POLYGON` 之后指针一次都没有移动过
- **THEN** 光标旁没有框

#### Scenario: 后两步既不印胶囊也不接管 Tab

- **WHEN** `POLYGON` 走到中心步
- **THEN** 光标旁是两个坐标框，没有胶囊，`Tab` 仍是字段锁定
- **AND** 走到半径步之后只剩一个框，`Tab` 不被接管

## MODIFIED Requirements

### Requirement: 多段线的圆角手柄

单选一条**矩形**曲线时，Stage MUST 在每个角上画一个圆角手柄，**选中即出**，MUST NOT 要求
先进入任何模式：改圆角是最常做的调整之一，藏在一个模式后面等于把它藏起来。

**其余多段线 MUST NOT 出手柄。**「选中即出」的理由是「改圆角是最常做的调整之一」，而那句话
对矩形成立（底板、面板、分区框），对别的多段线不成立：一个六边形符号选中之后多出六个点、
十二边形多出十二个，全都在说一件用户不打算做的事，还挡住了里面的图形。圆角仍可在属性面板改，
因此这里收走的是一个入口而不是一项能力。

判据 MUST 读 `Composition.presetId`，MUST NOT 按几何反推：`RECTANGLE` 与 `PLINE` 连点四下再
闭合产出的都是闭合四顶点多段线，在几何上一模一样，而后者要的确实是折线。`presetId` 是文档里
「建它的那条命令说了什么」的唯一记录，也因此 MUST NOT 由 `stage-engine` 判断——引擎不认识
Preset id。

手柄 MUST 画在**角弧的圆心**上——沿两条边各进一个切线长。这个位置不是审美：顶点到圆心的位移
投影到角平分线上再乘半角正弦就是半径，因此拖动这件事本身就是在量它。半径为 0 时圆心与顶点
重合，此时 MUST 沿角平分线让开一个固定的屏幕距离，否则手柄压在顶点与缩放手柄上谁也抓不住。

手柄的形状 MUST 与顶点夹点、段中点夹点**互不相同**（圆 / 方块 / 条形）：两个手柄长得一样而
按下去做的事不同，是最难自己发现的一类缺陷。它 MUST 带一圈画布色垫底描边——半径到顶时它压在
选区轮廓那条线上，没有垫底就整个融进去了。

手柄 MUST 只出在**作者写下的那条曲线是多段线**时，MUST NOT 照投影之后的几何判断：非等比缩放
会把弧拍扁成多段线（命中与渲染需要那个近似），照投影结果判断就会给一段圆弧发出一整串圆角
手柄——而弧根本没有角。投影是给命中与渲染用的近似，不是「这条曲线是什么」的答案。

手柄 MUST 画在**钳制之后**的半径求出的圆心上：作者写下的半径可以超过相邻边一半（钳制在读取时
而不是写入时），用它求圆心会让手柄一路飘到盒外，而形状早就停在最大圆角上——屏幕上就是「手柄跟
弧脱节了，再拖也不见形状变」。

两个手柄在屏幕上靠得太近时 MUST **抽稀**（与已经画下的每一个都拉开最小间距才画）而 MUST NOT
整片隐藏：半径到顶时同一条边上的两个手柄落在同一点，叠在一起读不出是两个东西；但拥挤的那一档
恰恰是用户想把圆角调回来的那一档，全部收走等于「一拖到顶就再也调不回来」，而画布上没有别的
入口。四个手柄写的是同一个 `cornerRadius`，留下哪一个都给出相同的结果，抽稀不损失任何能力。
这与网格投影间距不足时抽稀而不是整片隐藏是同一条判断。

拖动中的**圆角预览轮廓** MUST NOT 因为手柄拥挤而一并消失：它是这次手势的反馈，而不是选区的
一部分，两者各自独立成立。

**几何编辑会话进行中 MUST NOT 画**：那一档的角上已经有顶点方块。

拖动 MUST 把落点反解成半径并写回**四个角共用的那一个** `cornerRadius`，走
`entity.curve.set`——它是曲线几何写入的唯一漏斗，撤销因此是一步。反解 MUST 取落点到顶点的
位移在角平分线上的**投影**而不是距离：手往旁边一偏半径就往上跳。

拖动中 MUST 显示半径读数，被量的那一段 MUST 是**圆心到弧上**（CAD 的半径标注）而不是尖角
顶点到手柄：圆角之后那个顶点根本不在形状上，标注从那里出发离真正在变的那条边最远。读数的
摆位 MUST 复用取点动态输入既有的标注规则，MUST NOT 为圆角另立一套。

#### Scenario: 选中即出

- **WHEN** 单选一个由 `RECTANGLE` 画出的矩形曲线
- **THEN** 四个圆角手柄显形

#### Scenario: 多边形不出圆角手柄

- **WHEN** 单选一个由 `POLYGON` 画出的六边形
- **THEN** 图面上一个圆角手柄都没有

#### Scenario: 同样的几何，只有矩形出手柄

- **WHEN** 用 `PLINE` 连点四下再闭合，产出与矩形逐点相同的闭合四顶点多段线并单选它
- **THEN** 图面上一个圆角手柄都没有

#### Scenario: 弧不出圆角手柄

- **WHEN** 单选一段被非等比盒拍扁成多段线的圆弧
- **THEN** 图面上一个圆角手柄都没有

#### Scenario: 半径到顶仍留得住可拖的手柄

- **WHEN** 一个矩形的圆角半径已经等于相邻边的一半，四个圆心两两重合
- **THEN** 图面上仍有可拖的圆角手柄，只是少于四个
- **AND** 拖动中的圆角预览轮廓照常显示
