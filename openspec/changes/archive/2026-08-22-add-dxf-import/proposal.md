# DXF 导入

## Why

到今天为止，图纸只能从零画起。而实施工程师手上**已经有图**——设计院给的一次接线、甲方给的
机房平面、厂家给的设备符号库，全部是 DXF。让他们照着重画一遍，这个工具就不会被用第二次。

DXF 的复用机制与本仓的模型是同一件事：`BLOCK ≙ 块定义`、`INSERT ≙ 块实例`。这不是巧合，
两者解决同一个问题；它也是当初选这个模型选对了的旁证。

前四刀把落点铺齐了：`LINE`、`CIRCLE`、`ARC`、`LWPOLYLINE`、`TEXT`、`INSERT` 现在都有对应的
图元，导入器只做**解析与映射**，不需要为它扩协议。

## What Changes

### 无 React、无 DOM 的导入器

`importDxfDocument(text)` 吃一段 ASCII DXF，吐出 `{ document, diagnostics }`。纯函数，喂字符串
断言 Entity——不碰交互内核，也不碰资源系统。

支持的实体：`LINE` / `CIRCLE` / `ARC` / `LWPOLYLINE` / `TEXT` / `INSERT`，加上 `LAYER` 表与
`BLOCKS` 段。

### 诊断是这个功能的一半

任何一份真实的 DXF 都带着我们表达不了的东西：`SPLINE`、`HATCH`、`DIMENSION`、三维实体、
带 `bulge` 的圆弧段。**静默丢弃是不可接受的**——用户拿导入结果与原图一对，发现少了东西却
没有任何解释，只会认为这个工具不可靠。

因此导入返回一份诊断清单：跳过了哪些实体类型、各多少个，哪些几何被降级，哪些图层缺失。
每一条都带机器码，可以被测试断言，也可以被界面呈现。

### 三条坐标约定必须一次做对

- **Y 轴翻转**：DXF 的 Y 朝上，屏幕的 Y 朝下。
- **角度随之取反**：翻转把逆时针共轭成顺时针。圆弧的起止角、文字与块实例的旋转全部要取反。
- **比例不变**：翻转与对角缩放矩阵可交换，`xscale`/`yscale` 原样带过来。

这三条是同一个矩阵恒等式的三个推论，设计文档里给出推导——**它们要么一起对，要么一起错**，
而错了的症状是「图看起来像镜像的」，很容易被误当成源文件的问题。

### 入口与「看得见」

资源浏览器里右键一个 `.dxf`，「从 DXF 导入」生成同目录下的 `.cad.json` 并打开它。

同时给 CAD 画布加上**打开时按内容取景**：真实图纸的坐标动辄在几千甚至几十万上，按默认视口
打开会是一片空白。一次看不见的导入等于没有导入——这与「块的端口看不见等于块只是一张贴图」
是同一条判断。

## Impact

- `@compose-ui/cad`：新增 `dxf/` 目录（分词、记录分组、映射、诊断）。协议**一个字段都不加**。
- `@compose-ui/cad-canvas`：打开时按内容取景（`autoFitContent`，默认开）。
- `@compose-ui/editor`：资源浏览器上下文菜单多一项。
- `app/`：一份演示用 `.dxf`，供端到端使用。

## 本步刻意不做

- **`bulge`（多段线的圆弧段）**：它要求 `CadPolyline` 带上逐顶点的 bulge，而那会牵动遍历、
  命中、捕捉与框选——是一刀独立的协议变更，不是导入器能自己解决的。本步按**弦**导入并给出
  诊断，因此不是静默的谎话。
- **`$INSUNITS` 单位换算**：本仓的 CAD 是无限图纸、没有图纸比例，1 个图形单位就是 1 个画布
  单位。换算只有在与真实尺寸或打印挂钩时才有意义，而那两件事都还不存在。
- **DXF 导出**：导入与导出是两个方向，各有各的取舍（例如我们表达得了而 DXF 表达不了的东西）。
  先让「已有的图能进来」跑通。
- **二进制 DXF 与 DWG**：ASCII DXF 是通用交换格式，另外两种要么是同一份数据的另一种编码、
  要么是闭源格式。
- **`SPLINE` / `HATCH` / `DIMENSION` / 三维**：没有对应图元。它们进诊断，不进文档。
