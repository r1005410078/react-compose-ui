## ADDED Requirements

### Requirement: 取点过程中的动态输入

命令等待取点且这一步声明了 `fields` 时，Stage MUST 在光标旁画出这一步的两个数值。

数值 MUST 取**解算之后**的落点——与橡皮筋终点、十字光标、捕捉标记同一个值。读裸指针的话，
开着栅格吸附时框里的数字会与线的终点对不上。

**呈现几何**（两份交互稿逐点量过，均照 AutoCAD 实机截图）：

- `absolute`：两个框并排贴在光标右下，带 `X` / `Y` 前缀。这一步没有「上一个点」，量不出长度
  与角度，因此不画任何标注。
- `polar`：一条与预览线**平行**、垂直偏移的长度标注线，两端各有一条延伸线分别引自原点与
  落点；一条从水平 0° 参考射线扫到预览线的角度弧，**半径等于当前长度**。
- `cartesian`：宽与高两条边长标注，**摆在靠近光标的那两条边外侧**（反向拖时换边）。永远摆在
  上边和右边实现最简单，但从右上往左下拖时标注会跑到图形另一头，视线要来回跳。
  `cartesian` MUST NOT 画角度弧——矩形轴对齐，角度恒为 0。

**一条规则管住所有框：框落在自己那条标注的中点上，标注在框后面断开。** 缺口本身就在说
「这个数说的是这条标注」，因此框里只有数字，不放图标。

**角度弧的半径 MUST 等于当前长度**：固定的小半径在小角度下退化成几个像素，等于没画；半径
跟着长度走之后弧长与角度成正比，再小的角也有一段读得出来的弧。

**弧长或标注线短于框宽时，框 MUST 移到标注的外侧且标注不断开**——否则框会把整条标注吃掉。

框宽按字符数估算（SVG 里量不到文本宽度而不做一次布局），因此字体与每字前进宽度 MUST 写在
一起：改了字号而没改常量，症状是标注断开的缺口与框对不齐。

**框尾标记由状态派生，且只有一处实现**：`locked` 挂锁、`active` 挂光标条、`idle` 什么都不挂。
它同时决定框宽，因此求宽与画标记 MUST 读同一个值——各判一次的症状是数字被标记压住。

**每个颜色 MUST 带字面量兜底。** `var()` 解析不到且没有兜底时整条声明在计算期失效，`fill`
退回初值**黑色**——那正好是深色画布上「什么都看不见」的样子，而它在浅色主题下反而正常，
因此极容易漏掉。

标注几何 MUST 是纯函数并可独立求值。它 MUST NOT 进 `canvas-kit`：那里的准入判据（不认识
文档或选择集）是必要条件而不是充分条件，而本几何只有一个消费者，「未来可能复用」不是提前
抽象的理由。

#### Scenario: 取第二点时长度与角度都在屏幕上

- **WHEN** `LINE` 取过第一个点，指针移到别处
- **THEN** 光标附近出现两个数值，一个是到第一个点的距离、一个是角度
- **AND** 两个值与预览线的终点一致

#### Scenario: 第一个点是绝对坐标

- **WHEN** 一条命令刚开始等待第一个点
- **THEN** 显示带 `X` / `Y` 前缀的两个绝对坐标，不画长度与角度标注

#### Scenario: 矩形不画角度

- **WHEN** `RECTANGLE` 取过第一个角点
- **THEN** 显示宽与高两个值，且没有角度弧

#### Scenario: 值取解算之后的落点

- **WHEN** 开着网格吸附，指针停在两个格点之间
- **THEN** 显示的数值对应吸附之后的落点，而不是裸指针

### Requirement: 命令行是动态输入的输入端

动态输入的文本缓冲 MUST 就是命令行那一个，光标旁的框 MUST 只渲染它，MUST NOT 是第二个可聚焦
的输入。

理由有二：焦点在命令启动时已经约定交给命令行；而命令由工具栏按钮启动时**指针位置还未知**
（浏览器不提供查询接口），那一刻根本没有框可以聚焦。

- 键入**裸数字**并确认 MUST 解释成**当前活动字段**的值，另一个字段取它此刻的值。这就是直接
  距离输入：方向由鼠标定好，只打一个长度。
- `Tab` MUST 锁定**离开**的那个字段，同时解开**进入**的那个；缓冲非空时锁定键入的值，为空时
  锁定它此刻的值。因此**任何时刻至多有一个字段被锁定**，且它永远是不在编辑的那一个。
  少了「进入即解锁」这一半，`Tab` 按两下就把两个字段全锁上了：落点已经完全确定，光标再也
  带不动任何东西，而屏幕上没有任何东西在说这件事。这个不变量 MUST 由写入处的构造保证，
  MUST NOT 靠事后校正。
- 锁定的字段 MUST NOT 再跟光标；指针可以走到锁定值之外，几何停在锁定处。
- 锁定 MUST 在落点解算**之后**生效：锁定值是用户键入的，与「键入的坐标不被任何吸附改写」
  同源；反过来会让网格把刚锁死的 300 挪成 296。
- 完整坐标写法（`x,y` / `@dx,dy` / `距离<角度`）MUST 仍然优先于裸数字。
- 取到一个点之后 MUST 清掉全部锁定与活动字段——它们描述的是上一步。

`Tab` MUST 只在「命令正在取点且这一步声明了字段」时被接管，其余时候一律放行：它是键盘用户的
焦点导航键，无条件劫持会把人困在命令行里。

**命令正在取点时，图面上的坐标字符与 `Tab` MUST 转交命令行。** 用户点完第一个点之后焦点就
在图面上了；不转交的话他必须把手移回命令行才打得出第二个点的坐标，而屏幕上没有任何东西在说
这件事。转交的字符 MUST 只是能起一个坐标的那些（数字与 `@` `,` `.` `<` `-`）——字母是关键字
与命令名，转交过去会把每一次误触都变成命令行里的垃圾。

转交 MUST 排在快捷键匹配**之前**：`Shift+2` 在 US 布局上打出的正是 `@`，而它同时是「适配
选择」的默认键；不抢在前面，用户想打 `@dx,dy` 会得到一次视口适配。带 primary 或 alt 的组合
MUST 放行——那些是剪贴板与缩放，不是坐标。

转交字符时 MUST NOT 阻止默认行为：聚焦之后那个字符要落进输入框里，拦下来就白转交了。

#### Scenario: 裸数字是直接距离输入

- **WHEN** `LINE` 取过第一个点，指针指向某个方向，用户键入 `100` 并回车
- **THEN** 第二个点落在该方向距离 100 处

#### Scenario: 打了长度 Tab 之后角度还跟着鼠标

- **WHEN** 用户键入 `260` 并按 `Tab`
- **THEN** 长度锁定为 260，活动字段变成角度
- **AND** 移动指针时落点始终在半径 260 上，指针走到更远处几何也不跟过去
- **WHEN** 接着键入 `30` 并回车
- **THEN** 落点在 30° 方向、距离 260

#### Scenario: 连按两次 Tab 不会两个都锁上

- **WHEN** 用户按两次 `Tab`
- **THEN** 只有第二个字段是锁定的，第一个回到活动且跟着光标
- **AND** 移动指针时落点仍然在变

#### Scenario: 完整坐标仍然优先

- **WHEN** 用户键入 `100,50` 并回车
- **THEN** 按绝对坐标落点，MUST NOT 被解释成活动字段的值

#### Scenario: 取到点之后锁定清空

- **WHEN** 锁定了长度并落下一个点
- **THEN** 下一步的两个字段都不再锁定，活动字段回到第一个

#### Scenario: 焦点在图面时数字转交命令行

- **WHEN** 用户点下第一个点（焦点因此在图面上），随后在图面上键入 `1`
- **THEN** 焦点移到命令行，且该字符落进输入框

#### Scenario: 焦点在图面时 Tab 直接锁定

- **WHEN** 焦点在图面上，用户按 `Tab`
- **THEN** 当前字段锁定为它此刻的值，焦点移到命令行

#### Scenario: 数值框在深色画布上看得见

- **WHEN** 动态输入显示出来
- **THEN** 框的填充与文字颜色都不是黑色

#### Scenario: 没有字段时 Tab 不被接管

- **WHEN** 命令正在等待选择对象
- **THEN** `Tab` 走浏览器默认的焦点导航
