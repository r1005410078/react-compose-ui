# 设计：组件文档的动画

## 1. 组件的动画内嵌在资产里，没有动画文件

页面那边的规则是「清单是会话镜像，事实来源是 `.animation.json`，一场景一份文件」。组件
**不套这条规则**，清单直接住在组件资产的文档里。

理由不是「文件太麻烦」，是**上一刀已经把这条路走死了**：实例读的是
`resolvedSnapshot.document`，而快照把整份组件文档原样嵌进实例 Entity 里，`Animations.items`
就在里面。给组件再配一个动画文件，就会出现两份清单——快照里那份是实例真正播的，文件那份
谁也读不到。第二份事实来源不会被察觉，因为两份在刚创建时是一样的。

推论还有两条：

- **组件是一份可移植的文件。**拖一个 `.component.json` 到别的项目里应该就能用；带 sidecar 的
  组件到了那边就是一个引用不到文件的空清单。
- **保存路径白拿。**清单在文档里，组件文档的保存本来就把整份文档写回资产，不需要任何
  「把镜像聚合回文件」的回写逻辑——那正是页面侧最复杂的一段。

因此组件文档的 `Animations.source` MUST 缺席。空态创建入口在组件文档下**不落文件**，
直接派发 `animation.create`。

## 2. 提取时动画 id 逐字保留

轨道按动画 id 分组：`Animation.clips[animationId]`。提取器复制清单条目时若顺手换一个新 id，
得到的组件会有一条动画、一堆轨道，而两者对不上——**时间线上什么都不动，文档校验也不报错**
（悬空分组由 `collectComposeAnimationIssues` 报告，不影响采样与命令）。

这条是本刀最容易写错也最难看出来的地方，因此判别性用例直接断言
`items[0].id` 等于子级 `clips` 的键，而不是「组件有一条动画」。

## 3. 复制，不是搬运

只复制**至少有一条轨道落在被提取实体上**的动画；源页面的清单条目原样留下。

- **不能只按「选区里有轨道」就把源条目删掉**：选区可能只是这条动画的一部分。一条动画同时
  给 A 和 B 打了点，用户只把 A 存成组件，删掉源条目会让 B 的轨道全部悬空——**用户没有选中
  B，B 却坏了**。
- 留下一条没有轨道的清单条目不是数据丢失，它在时间线上看得见，删除也是一步撤销的事。

反过来也不能把整份清单都复制过去：组件会凭空多出几条它一根轨道都没有的动画。

## 4. 复制时丢掉 `source` 与 `bindings`

- `source` 指向页面目录下的 `.animation.json`，跟着组件走就是一条跨作用域的悬空引用；
  而按第 1 节，组件根本不该有这个字段。
- `bindings` 指向页面 setup 的导出名。上一刀确认过：`ResolvedComponentContent` 不向嵌套文档
  传 `scriptScope`，那份声明在实例里**永远解析不出东西**。复制过去只会让用户在组件文档的
  动画检查器里看见一个绑好的变量名，而它在任何实例上都不生效。

驱动实例的是宿主侧的 `animationTime` Prop，这是上一刀定下的。

## 5. 不改 `promoteComposeEntityToFrame`

「升格只做一件事——加上 `Frame`」是一条明写的不变量，所有隐含升格都复用同一个纯函数。
清单复制**放在提取器里**，不放进升格：升格还有「在场景外画容器」等调用方，它们没有源清单
可搬，把一个只对提取成立的行为塞进共用函数，是给下一个人埋一个惊喜。

## 6. 那条禁令的前提失效了，但闸门还是要一条条开

规范里「组件文档与未启用页面系统的宿主本期不提供动画模式入口」是一句话，实现里却是两处
不同的东西：

- 模式切换器只渲染在 `page-document` 面板上 —— 这一处开。
- 空态创建入口要求 `activePageSession && pageProvider` —— 这一处**分流**而不是放开：页面走
  建文件那条，组件走直写文档那条。放开会让组件在用户的资源目录里落一个没人引用的动画文件。

**未启用页面系统的宿主保持不提供**：那条限制与组件无关，它说的是没有 page provider 的嵌入
场景，本刀不碰。

## 7. 作用域解析不用改（已查证）

`animationScopeFrameId` 解析 `controller?.document`，而组件文档面板活动时 controller 的文档
就是组件文档；组件文档单根且根必须是 Frame，`resolveTargetFrameId` 自然落在组件根上。
`animationRuntime = controller?.runtime` 同理——动画命令 handler 注册在当前 runtime 上，
组件文档有自己的 runtime，撤销/重做因此天然作用在组件文档的历史上。

这一节写下来是为了让「本刀为什么这么小」有据可查，不是要改什么。

## 8. 不做的几件事

- **Variant 的动画覆盖语义。**`instanceOverrides` 的 `set-field` 能改 `Animations`，但清单是
  数组，覆盖「数组只作为字段整体写入」，一条覆盖等于替换整份 `items`。这个粒度限制是已知的
  （上一刀记过），给它一个专门的答案要单独一刀。
- **在组件文档里播放预览。**时间线拖播放头已经能看姿态（采样走的是既有的 `displayDocument`），
  真正的「播一遍」需要组件文档侧的播放会话，与本刀无关。
- **动画模式下的实例下钻。**规范已明确禁止对实例内部打关键帧，本刀不动这条。
- **给组件配动画文件。**见第 1 节，是被否掉而不是延后。

## 9. 判别性用例

**提取器（`stage-engine` 单元）**：
1. **id 保留**——组件 `items[0].id` 等于被提取子级 `Animation.clips` 的键。换新 id 的实现在
   「组件有一条动画」上是绿的，在这条上是红的。
2. **部分选区**——一条动画同时给 A、B 打点，只提取 A：组件拿到的这条动画只含 A 的轨道，
   **源页面的条目仍在**且 B 的轨道没动。搬运式实现（删源条目）在这条上是红的。
3. **无关动画不复制**——页面上另有一条只给 B 打点的动画，组件里不出现它。
4. `source` 与 `bindings` 不出现在组件文档里。

**e2e**：矩形 → 打旋转关键帧 → 存成组件 → 放两个实例 → 各绑一个导出 → 两个姿态不同。
这条把上一刀那个手写资源换成真实路径，**刀闸故事第一次整条跑通**；手写资源随之删除，
两个脚本导出（`openMs` / `closedMs`）保留在 `?switch-demo` 下供绑定使用。
