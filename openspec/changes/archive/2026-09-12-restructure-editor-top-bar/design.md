## 上下文

本变更接在 `update-editor-chrome-density` 之后：那一次把顶栏从 44px 压到 30px、删掉保存按钮与
边缘把手、把三个布局开关立成折叠的唯一入口。它解决的是**密度**，没有动**归属**——顶栏里四种
作用域并列的问题原样留着，而中间那一列仍然没有头。

## 目标 / 非目标

- 目标：顶栏只承载应用与视图作用域；文档的东西挨着文档那一列；chrome 只有一种「被选中」的画法。
- 非目标：改手势、改命令、改 Dockview 分组、改文档协议。本变更全部是 chrome 的位置与呈现。

## 决策

### 文档标签条落在画布面板内容的第一行，不做成 Dockview 组头

三列在 Dockview 的网格里是同一行的兄弟，左右两组各自画 30px 的组头，而画布组明写着隐藏组头
（「边缘工具区」需求）。因此画布面板内容的**第一行**天然就从组头那条线开始——放一条 30px 的
标签条进去，它与左右面板头**逐像素齐平**，不需要任何对齐代码。

反过来把标签 portal 进 Dockview 的组头，在 `update-editor-chrome-density` 里已经评估过并放弃：
它要求文档成为 Dockview panel，而「文档 MUST NOT 是 Dockview panel」是既有需求——文档不参与拖放、
浮动与布局持久化，正是那条需求存在的理由。

### 不与 36px 工具栏合成一行

那是最省高度的做法（画布上方一个像素都不多），但**溢出会互相吃**：绘图工作区的工具栏货架在
1280 默认窗口下余量已经不到半格，而溢出是**从尾部**收进「更多」的；打开的文档数量没有上界。
两者同行时，多开一个文件就从工具栏尾部吃掉一颗按钮——而尾部恰好是绘图工作区存在的全部理由。
这不是推测：`add-shelf-customization` 落地时就量到过 16 格工具栏在 1280 下贴边。

分成两行之后两者各自溢出：标签行自己横向滚动，货架自己收进「更多」。

### 代价：画布上方 66 → 96px

顶栏 30 + 头部行 30 + 工具栏 37（36px 行高加它自己的 1px 下边框）= 97。今天是 30 + 37 = 67，
因为画布列的那 30px 是空的。换来的是三列
共一条头部线、顶栏不再混四种作用域、文档标签紧挨着它管的那一列。需要那 30px 时，工作区管理
菜单里的「只看画布」一次收走全部 chrome。

这条代价 MUST 写在明处而不是摊薄：它是本变更唯一的净损失。

### 一种选中画法：圆角底

三种画法收成一种，判据是**两态都要说得出话**：

- **下划线出局。**它只在活动那一格出现，另一态屏幕上没有任何东西可看；而它与「文字下的强调线」
  同形。圆角底两态都在说话——有底 / 没底。
- **贴满整格的方块出局。**它把标签画成格子，于是需要竖线来分隔，而竖线是把「我数得清有几段」
  画出来，那件事本来不需要用户去数。
- **hover 只改文字颜色。**底是「选中」的专用通道；hover 也上底会让「指着」与「选中」同形，
  而两者可以同时成立。

**工具栏的按下态保持蓝底**（`surface-selected`），不跟着改灰。这不是不一致的漏网，是分工：
顶栏与头部行回答**你在看哪一个**（导航，一组里恰好一个有底），工具栏回答**哪个开着**（状态，
可以同时开好几个）。同一块灰底在「可以同时为真」的一组里会读不出还剩几个开着。

留在明处的后果：编辑器里「选中」有两种颜色。判据是上面这条分工，不是审美。

### 工作区仍是 `radiogroup`，不改成 `tablist`

上一版设计稿曾经推过「文档标签搬走了，工作区因此可以变成真标签」。这一版把它推翻了，理由是
**呈现变了**：现在它是一组 pill 而不是标签的形状，而语义 MUST 跟着形状走——同形不同为是这个
仓库最难自己发现的一类缺陷。既有需求里「它不是标签，标签是文档」那句话照旧成立，只是画法
变安静了。

它与画布工具栏的「设计 / 动画」同形是**对的**：两者做的是同一件事——从 N 个里挑一个，挑完立刻
生效。同形同为，不是撞车。

### `＋` 是同一条流程的第二个入口

`＋` 打开的就是管理菜单里「另存为」那条流程（复制当前工作区并要一个名字），MUST NOT 是第二份
实现。多一个入口是允许的（「货架不得成为任何能力的唯一入口」约束的是**减少**入口）；两份实现
不允许，因为它们必然漂移。

`＋` 在 `radiogroup` 之外：它不是一个可以被方向键走到的工作区。

### 标志：实心，且不与布局开关撞形状

第一版画的是一个**描边**圆角矩形加三根引脚。它输在形状撞了——顶栏右端那三个布局开关就是描边
圆角矩形，两边成了一家人，而它们相距不到一屏。定稿是**两块实心圆角方块加一段正交导线**：
这个产品的画面就是这个——一堆块，块之间横平竖直的线。块用文字色，**只有线是彩色的**
（accent `#3687ff`），因为「把东西连起来」正是它做的事。

标志 MUST NOT 带文字标记：30px 一行里「Compose」要吃掉 60px，而它右边紧接着就是工作区；
标志的职责是那颗把手，不是署名。

### 菜单本期只有两项

设置、命令面板。「关于」「键盘快捷键」都没有现成的落地页，为一个菜单项现造一个页面不在本变更
范围内。设置因此**不是**唯一入口——`editor.settings` 动作与它的键位仍在，命令面板也搜得到。

## 风险 / 权衡

- **画布可视高度少 30px** → 「只看画布」是现成的补偿；1280×720 下画布仍有 600 余 px。
- **既有端到端用例大量依赖「标签条在顶栏、齿轮在右端」** → 这些断言必须跟着改，且改的时候要
  分清「位置变了」与「行为变了」：行为断言（打开、激活、关闭、脏点、保存）一个字都不该动。
- **样式靠层叠取胜的部分要有端到端量计算值** → `update-editor-chrome-density` 刚踩过：
  `app/src/App.css` 里一条**无层**的 `button { color: inherit }` 压过 `@layer components`，
  让工具栏图标的颜色从来没生效过。本次改的是背景与圆角，同类风险仍在，因此活动格的底色
  MUST 由端到端断计算值，而不是只断 class。

## 迁移计划

纯 chrome 变更，没有文档字段、没有持久化格式变化，因此**不需要迁移**。工作区布局快照不受影响
（面板与组的 id 不变）。回滚是把两个组件放回原处。

## 待解决问题

- 文档开得多了：横向滚动，还是尾部折成一个 `▾` 列表？倾向滚动 + 两端渐隐，与 Dockview 一致。
- 未启用页面系统时那一格固定画布（不可关闭）是否仍长成标签？倾向是——用户从资源文件切回来
  需要一条路。
- 标志菜单以后要不要收「关于」与「快捷键参考」，取决于那两个页面何时存在。

## 落地时发现的两件事

### Dockview 的标签底色只能靠改它自己的变量

给 `.dv-tab.dv-active-tab` 加选择器**只赢了一半**：圆角与高度进去了，底色没有。Dockview 内部那
几条规则带着 group 状态的前缀（`.dv-groupview.dv-active-group > … > .dv-tab.dv-active-tab`），
权重比外面写得出的高。因此这一处走它的变量（`--dv-*-tab-background-color`）而不是加选择器。

变量还要在**组**这一层再落一次：底部 Edge Group 自带一份更近的定义（`.dv-edge-group` 上），
写在 dockview 根上的那一份到不了它——症状是三块面板头统一了、底栏那一条还是深蓝。

### e2e 里的固定像素落点与视口适配是一对隐藏耦合

chrome 长高 30px → 画布矮 30px → 自动适配的缩放从 38% 掉到 33% → 场景框在屏幕上小了一圈 →
`drawContainer` 画出来的那个盒（它本来就比场景框大）**紧包围盒中心落到了场景之外**，于是被
升格成一块新场景。症状是「`stage-container` 找不到」，看起来像画布坏了，实际是落点数字过期。

这类落点因此必须留出纵向余量，并把「为什么这几个数不圆」写在助手里——它们不是随手取的，
是被「中心必须留在场景框内」钉住的。
