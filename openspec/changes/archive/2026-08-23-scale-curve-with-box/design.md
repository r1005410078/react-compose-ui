# 设计：曲线几何跟随盒

## 1. 机制是 `viewBox`，不是「resize 时重写几何」

两个候选：

| | 做法 | 为什么不选 |
| --- | --- | --- |
| A | 拖手柄时把几何一起缩放，维持「盒 = 紧包围盒」 | 只挡得住**手柄**这一条路径。布局求解也会改盒（`fill`、Auto Layout 的伸缩），而那里没有手势可以挂钩子——症状是「手动拖没问题、进容器就错位」 |
| B | `viewBox` = 几何紧包围盒，盒自由 | 谁改盒都对，因为换算发生在渲染而不是发生在某条写路径上 |

选 B。判据与仓库里那条既有的一样：**「导线几何求解不存储」的收益不是少存两个数，而是「移动后
重解」那段代码根本不存在**。这里同理——没有任何一条写路径需要「顺手把几何也缩一下」。

`shape/` 物料早就是按百分比画的（`rx="50%" ry="50%"`），它天然跟随盒，因此这条路已经被证明
走得通。区别只是百分比表达不了弧与多段线，而 `viewBox` 表达得了。

## 2. 不变量的新说法

旧：**盒尺寸是几何的派生（紧包围盒）**。
新：**`viewBox` 恒等于几何的紧包围盒；盒自由。**

`normalizeComposeCurveGeometry` 一行不改——它保证的正是「归一化后紧包围盒左上角恒为原点」，
那句话现在描述的是 viewBox 空间。变的只是**谁来决定盒**：

- 新建与绘制：`entity.curve.set` 在同一个事务里写 `Curve` 与 `LayoutItem`（现状不变），
  此刻盒 = viewBox。
- 之后：手柄、布局求解、动画轨道都可以单独改盒，几何不跟着改，渲染按比例拉伸。

**退化轴要钳。**水平线的紧包围盒高度是 0，直接当 viewBox 高度会得到除零。取
`max(bbox, COMPOSE_CURVE_MIN_EXTENT)`——这个常量今天已经用来钳 `LayoutItem` 尺寸，两处必须
取同一个值，否则水平线的几何会被拉伸一个说不清的比例。

## 3. 描边不能跟着 viewBox 拉

非等比 viewBox 会把 `stroke-width` 也按轴拉扯：一个宽扁的盒里，竖直笔画粗、水平笔画细，而
用户什么都没改。`vector-effect: non-scaling-stroke` 正是为此存在。

**它与既有的 `calc(<宽度>px / var(--compose-canvas-zoom, 1))` 不重复，两者各管一段：**

| 变换来源 | 谁中和它 |
| --- | --- |
| `viewBox` → 盒（本刀新增） | `vector-effect: non-scaling-stroke` |
| Stage Scene 外层 HTML 的 `transform: scale(zoom)` | `calc(px / var(--compose-canvas-zoom))` |

物料注释里已经写过 `non-scaling-stroke` 「在这里不管用」——那句话说的是**外层 HTML 变换**，
它只中和 SVG 文档片段*内部*的变换。而 viewBox 恰恰就在片段内部，所以这次它管用。这条区别
必须写进注释：不写的话，下一个人读到那句结论会把本刀的 `vector-effect` 当成无效代码删掉。

**虚线也被一起中和，这是实现时才确认的。**SVG 没有「只中和线宽、不中和虚线」的开关——
`non-scaling-stroke` 作用于整条描边几何。原本打算让虚线跟随 viewBox，做不到。

结果反而更好说：规则收成一句「**几何参与 viewBox 变换，描边不参与**」，没有例外。逐项列举
「线宽不参与、虚线参与」那种规则，下一个人只会改坏其中一项。既有的「虚线是世界单位、必须乘
zoom」说的是**画布缩放**，那一条不受影响。

## 4. 命中与捕捉必须应用同一个变换，而它们有两条路径

| 路径 | 谁做变换 | 本刀要改吗 |
| --- | --- | --- |
| Stage 点选（DOM 驱动，`pointer-events: stroke`） | 浏览器 | 不改 |
| `StageSceneIndex.entityAtPoint`（取色采样、距离判定） | 我们 | **改** |
| `findStageFeaturePoint`（特征点捕捉） | 我们 | **改** |

两条路径 MUST 给出一致语义——这是本仓库反复踩到的那一类缺陷（「画出来的和点得中的不在
一处」）。因此用例要同时断言 DOM 命中与索引命中，**且必须在非 100% 缩放下**：
`world = (屏幕 − 视口) / zoom`，zoom 恒为 1 时盒→几何的缩放与视口缩放会互相掩盖。

换算入口只有一个（`core` 的盒→几何变换与它的逆），三处消费同一份。写成各自算一遍的话，
下一个改盒语义的人只会改到其中一处，而漏掉的那处症状是「某些缩放下点不中」。

## 5. 弧在非等比缩放下拍扁，等比下仍是闭式解

把一段圆弧按 x/y 不同比例映射，得到的是**椭圆弧**，而椭圆弧没有可用的闭式点距。

照抄 `cad` 侧块内弧的既有判断，一字不差：**等比（含镜像）仍是精确弧，非等比拍扁成线段**。
不这么做的两条歧路都更差——按某一轴的比例硬算成圆会画出一个用户从未画过的形状；一律拍扁
会让**圆心与象限点消失**，而它们不是任何线段的特征点。

拍扁只作用于**命中与捕捉**。渲染始终由 viewBox 精确完成，因此屏幕上永远是真正的椭圆弧。
两者的误差由弦高控制，与 `cad` 的交叉框选同一个量纲。

## 6. 容差留在世界空间

一个诱人的写法是把光标点变换进几何空间再比距离。**不要**：非等比缩放会把「12px 的圆形容差」
变成椭圆，距离比较不再是标量，而这个错误只在扁盒上现形。

做法是反过来——把**几何**变换到世界空间，容差仍是 `12 / zoom`。代价就是上一节那条弧的分流，
而那条本来就要有。

## 7. 本刀不碰的三样

- **物料种类**（删 `shape/`、加椭圆与端点 marker）：那是步骤 8b。本刀改的是「盒与几何的
  关系」，两件事共用同一批文件但判据完全不同，混在一起会让「哪条断言在验哪件事」说不清。
- **顶点编辑**：步骤 10。本刀让拖**盒手柄**产生正确视觉，不引入任何新手势。
- **`entity.curve.set` 的载荷坐标系**：仍是 parent 局部坐标。命令内部多一步映射进几何空间，
  但**对调用方不变**——这是刻意的，否则每个产出曲线的地方都要认识 viewBox。
