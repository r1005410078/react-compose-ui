## 上下文

工作区 = 一份 Dockview 布局 + 一组画布会话开关 + 两条货架 + 新建种子；硬边界是不改手势语义、
不改命令可用性、不写文档。动画模式 = `useAnimationMode.active`，由顶栏切换器驱动，进入时
`ensureAnimationPanel` 动态加时间线面板、退出时移除并恢复折叠；时间线**不进布局快照**，工作区
切换后由 `restoreAnimationPanel` 加回来。`AnimationPanel` 宿主在非动画模式下渲染 `null`。

## 目标 / 非目标

- 目标：顶栏只剩一个切换器；时间线像别的面板一样可摆、可记忆；动画的语义分叉仍有明确进出。
- 非目标：改动画模式内部任何语义（作用域 Frame、自动记录、父级锁定、采样显示一律不动）。

## 决策

- **拆成两半的判据是「它改不改拖动的结果落在哪里」。**时间线面板、底部展开、变换指示器不改，
  归工作区；采样显示、自动记录、父级锁定改，归开关。变换指示器仍挂在开关上「跨过那一刻打开
  一次」——理由不变（动画态下误拖的代价不对称），而它作为会话开关本来就按工作区各记一份。
- **开关的进入是显式的，退出跟着可见依据走。**进入：按钮、动作、对时间线的交互；三条都是
  用户对「动画」这件事本身的动作，没有一条是切换布局的副作用。退出：时间线面板不可见即退出——
  屏幕上唯一说明「你的拖动会变成关键帧」的东西就是它，它不在的时候不允许那个状态存在。这与
  今天「点击其它底部标签退出动画模式」是同一条判据，只是把它写成规则而不是特例。
- **对时间线的交互即进入，不是隐式模式。**用户在拖播放头，屏幕上就有播放头在动、画布跟着采样，
  进入这一刻有完整的视觉解释。曾考虑关闭态把时间线渲染成只读——那要给 `animation-panel` 加一个
  `readOnly` 契约，且「鼠标动了没反应」正是本仓库明写要避免的状态。
- **工作区切换 MUST NOT 打开它，但会关掉它。**「不改手势语义」那条边界挡的是**静默改变**，
  关掉没有这个问题：切到没有时间线的布局，画布回到基础文档，采样态与时间线一起消失，用户看得
  见。打开则不行——按文档记忆会让「打开页面」等于「进了录制态」。
- **面板 id 不变**（`compose-animation` / `data-workspace-panel="animation"`），面板名叫
  `timeline`：id 是持久化在快照里的东西，改名等于让所有既有快照失配回退。
- **内建「动画」与「页面」只差布局的底部一行。**货架、会话开关与种子逐字相同，与「两个内建
  差别落在货架与种子上」那条判断是一回事——这个工作区存在的理由是把时间线铺开，别的都不该变。
  工具栏货架加一格 `animation.toggle`：它有动作目录与快捷键做第二条入口，进货架合规。
- **开关按钮住在编辑器的时间线宿主上，不进 `animation-panel`**：那个包不认识「模式」，它只知道
  会话与动作。

## 风险 / 权衡

- 比今天多一步：切到动画工作区之后还要按一下（或直接拖播放头）。换来的是只有一个切换器、时间线
  可拖可记忆、打开文档不会静默进入录制态。
- 切走再切回不恢复动画编辑：把它记成工作区会话开关能补上，但那是「切换改变手势语义」的
  另一半，先不做；等真有用户抱怨再立项。
- 十份端到端用例依赖 `getByRole('radio', { name: '动画' })`，统一改走辅助函数。
- `add-shelf-customization` 正在改工具栏货架的编辑面；本变更只往内建「动画」的默认货架加一格，
  不碰对话框。

## 迁移计划

- 偏好里 `workspace.byDocument` / `lastUsed` 指向的 id 不受影响；没有任何快照里含时间线面板，
  因此不需要快照迁移。
- 宿主若用了 `ComposeEditorWorkspaceChrome` 的 `editorMode` prop：删除即可，动画入口由内建
  工作区与动作目录提供。
