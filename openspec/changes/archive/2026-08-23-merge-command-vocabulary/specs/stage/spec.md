# stage 规范增量

## ADDED Requirements

### Requirement: 宿主注入的命令与内建命令同属一份词汇表

Stage MUST 接受宿主注入的命令定义，并把它们与内建的绘图/编辑命令合成**一个**注册表。用户在
命令行键入的名称 MUST 在这份合并后的词汇表里解析，MUST NOT 存在「面板里有、命令行敲不出来」
的动作。

宿主注入的 MUST 是**定义**而不是会话：解析、启动、推进与提示渲染仍住在 Stage。合并的是
「能敲什么」，不是「谁在跑」——把会话搬给宿主意味着提示文本、预览几何与捕捉标记要逐帧回传。

宿主命令的依赖 MUST 在注册时闭包捕获，MUST NOT 并进命令启动上下文：上下文保持窄（文案与
选择集），否则每加一条命令就要往它上面加一个绝大多数命令用不到的字段。

注入的定义**引用不可能稳定**：它们携带的可用性必须跟着选择集与文档走，因此每次变化都是一份新
数组。Stage MUST NOT 把合并后的注册表挂在渲染期的记忆化上——那条身份变化会一路传染到命令行的
提交回调与整个会话对象，使 Stage 每次文档或选择变化都重挂这批回调。解析只发生在用户提交命令名
的那一刻，注册表 MUST 在那时才建。

Stage 在启动一条命令前 MUST 检查它的可用性：`disabledReason` 非空时 MUST 把该原因显示在
命令行且 MUST NOT 启动会话。命令行的拒绝 MUST 三者可分——词不在词汇表里、词在词汇表里但
此刻不可用、会话进行中的非法输入。

#### Scenario: 键入宿主动作名执行该动作

- **WHEN** 用户在命令行键入一条宿主注入的命令名并确认
- **THEN** 该动作被执行
- **AND** 内建绘图命令的解析不受影响

#### Scenario: 不可用的命令给出原因而不是静默

- **WHEN** 用户键入一条当前不满足前提的宿主命令名
- **THEN** 命令行显示该命令的不可用原因
- **AND** 不启动任何会话，文档未发生变化

#### Scenario: 注入的命令变化不重挂命令行回调

- **WHEN** 宿主注入的命令定义因选择集变化而换成新的一份
- **THEN** 命令行的提交与键盘回调保持引用稳定
- **AND** 下一次提交仍按新的一份解析与判定可用性

#### Scenario: 未知命令与不可用命令可分

- **WHEN** 用户先键入一个不存在的词，再键入一条存在但不可用的命令
- **THEN** 两次得到不同的提示

### Requirement: 命令行历史与重复上一条

命令行 MUST 支持召回：用户 MUST 能用上下方向键在**本次会话提交过的文本行**之间来回移动，
被召回的文本 MUST 出现在输入框中可继续编辑。方向键 MUST 阻止默认的行内光标移动。

没有命令在跑时，空确认 MUST 重复**上一条成功启动的命令**；有命令在跑时空确认的既有含义
（推进一步）MUST 不变。

两者记的 MUST NOT 是同一个序列：文本行包含坐标与关键字，而它们不是命令名——共用一个序列会
让空确认把上一次键入的坐标当作命令去解析。

命令历史 MUST 与事务日志分开：前者记「用户敲了什么」，后者记「文档变了什么」，一条命令
可能产生零条或多条事务。

#### Scenario: 上箭头召回敲过的行

- **WHEN** 用户提交过若干行后按上方向键
- **THEN** 最近一行出现在输入框中
- **AND** 继续按上方向键依次召回更早的行，下方向键回到更近的行

#### Scenario: 空确认重复上一条命令

- **WHEN** 一条命令结束后，用户在没有命令在跑时直接确认空输入
- **THEN** 同一条命令重新启动

#### Scenario: 取过点之后重复的仍是命令

- **WHEN** 用户用命令行键入坐标完成一条命令后直接确认空输入
- **THEN** 重新启动的是那条命令，而不是把坐标当命令解析

#### Scenario: 会话进行中的空确认不变

- **WHEN** 一条命令正在等待输入而用户确认空输入
- **THEN** 会话按既有语义推进一步
- **AND** 不发生任何重复启动
