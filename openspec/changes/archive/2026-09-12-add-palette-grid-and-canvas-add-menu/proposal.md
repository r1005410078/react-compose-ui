# 变更：物料面板网格排法与画布「添加组件」菜单

## 原因

**放一个组件到画布上，眼下只有一条路：去左面板里拖。**手和视线此刻都在画布上，而画布右键菜单
里每一项都是对**已有对象**的操作（复制、层级、编组、视图、吸附），没有一项产出新内容。基础
容器与文字还有工具栏按钮兜底，**项目组件与符号一个画布入口都没有**——一张接线图上要摆几十个
符号，每摆一个都要把视线拉回左栏。

**面板这一侧的问题是另一个：一行一个太稀。**物料是**图形**，用户扫的是形状而不是读一列名字；
单列行里六个基础物料要 160px，而形状在 16px 的行首图标上几乎读不出来。这一版把它排成网格。

顺带两处硬伤：**基础组件名是界面上仅剩的英文**（容器叫 Container、矩形叫 Rectangle，而它旁边
的段标题、右键菜单、属性面板全是中文）；**右键菜单的字比周围 chrome 大一档**——实测菜单项
14px / 行高 32px，而场景树 13px / 22px、物料行 12px / 26px、命令行 13px、面板标签 12px，
菜单是这块界面上最大的一号字，且它马上要承载新的「添加组件」子菜单。

## 变更内容

### 新增

- **物料面板两种排法：网格与列表，默认网格。**网格画法定稿为「无框」：格子不画边框，只有图标
  与名字，悬停才出一块圆角底（底色与列表模式那一行完全相同）；图标 24px 按原生网格画；名字区
  固定两行高、两行封顶；列数 `auto-fill`，最小列宽 84px（280px 栏排 3 列）。
- **排法是编辑器偏好**（`palette.mode`），按面板记一份，不写文档、不进撤销历史。面板自身
  MUST NOT 持久化它——与货架同一条边界。
- **切换入口**：面板头一行，右端两颗图标按钮（网格 / 列表），与检索框共用这一行。
- **画布右键「添加组件」二级菜单**，二级内容就是物料面板那棵树、**一层展开**：基础组件、项目
  组件、每个文件夹各是一个分组标题，条目直接排在下面，文件夹不做三级菜单。选中一项即在**右键
  那一下的世界坐标**上创建，落点语义与从面板拖入完全一致。
- 菜单内容由**宿主注入**（`ComposeStageProps`），Stage 不认识组件目录协议——它不得依赖
  `@compose-ui/component-library`。形状照抄既有的命令注入：注入的是**能列出什么**，会话与呈现
  仍住 Stage。
- **基础物料的面板显示名改中文**：容器 / 组件切换器 / 曲线 / 圆 / 矩形 / 图表。

### 修改

- **检索框常驻**：此前由货架上的 `search` 开关决定显隐，页面工作区默认关着——而它是这块面板里
  唯一能在几十个符号中直达一个的入口。开关随之删除（含自定义对话框里那一行）。
- **共享右键菜单的字号与编辑器 chrome 对齐**：菜单项 14px → 13px、行高 32px → 28px，快捷键与
  分组标题 12px，图标仍 16px。Shadcn 默认的 `text-sm` 是为独立页面定的，这块界面比它密一档。

## 影响

- 规范：`component-library`（面板排法）、`editor-preferences`（排法进偏好）、`stage`（画布
  添加菜单）、`components`（菜单字号）、`basic-materials`（中文显示名）。
- 代码：`packages/component-library/src/component-library/`、`packages/components/src/context-menu/`、
  `packages/stage/src/stage-surface/stage-context-menu.tsx`、`packages/editor/src/`（偏好接线与
  菜单树注入）、`packages/materials/src/*/preset.tsx`。
- 测试：物料面板与右键菜单的组件测试、画布添加菜单的端到端，以及含面板或菜单的黄金图。
- **归档次序**：本变更对 `component-library` 与 `editor-preferences` 只**新增**需求，不改写
  `混合组件目录` 与 `实例级编辑器偏好`，因此与尚未归档的 `add-shelf-customization` 互不覆盖，
  两者归档先后都不丢内容。`混合组件目录` 里「瓦片样式沿用既有两列瓦片」那一句由本变更新增的
  排法需求取代，归档时应一并删去。
