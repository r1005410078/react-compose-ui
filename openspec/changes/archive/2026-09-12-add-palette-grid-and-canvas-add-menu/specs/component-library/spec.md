## ADDED Requirements

### Requirement: 物料面板的网格与列表两种排法

物料面板 MUST 提供两种排法：**网格**与**列表**，默认 MUST 是网格。排法 MUST 由宿主受控
（`mode` 与 `onModeChange`），面板自身 MUST NOT 持久化它——与货架同一条边界：面板只发出改动，
存在哪儿由宿主决定。本需求取代「瓦片样式沿用既有两列瓦片」那一句。

**网格的画法**：格子 MUST NOT 画边框，只有图标与名字；悬停或聚焦时出一块圆角底，底色 MUST 与
列表模式那一行**完全相同**——同一个面板换个排法，不该换一套视觉语言。图标 MUST 是 24px（按图标
原生的 24 网格画，不缩放）。名字区 MUST 固定两行高并两行封顶：一行的名字与两行的名字并排时，
图标才落在同一条水平线上；MUST NOT 单行截断——单行会把 `Dragged Card` 与 `Dragged Card Focused`
变成两个一模一样的 `Dragge…`，用户没有任何办法分辨。列数 MUST 用 `auto-fill` 跟着栏宽走，
最小列宽 84px。

**列表的画法**保持既有：一行一个，16px 图标、名字靠左、类别标签在行尾。

**检索框 MUST 常驻**在面板头一行，MUST NOT 由货架上的开关决定显隐——它是这块面板里唯一能在
几十个符号中直达一个的入口，藏在开关后面等于没有。因此 `ComposeComponentShelf.search`
MUST 删除：一个不再决定任何事的字段留着，只会让下一个读它的人以为它还管用。

切换入口 MUST 是面板头一行右端的两颗图标按钮，两者按下态互斥（`aria-pressed`）；货架开启搜索时
MUST 与搜索框同排。MUST NOT 只把它放进右键菜单——那条入口用户自己发现不了。

两种排法下，项目组件的「创建变体」入口 MUST 都够得着。

#### Scenario: 默认是网格

- **WHEN** 宿主挂载面板且不传 `mode`
- **THEN** 物料按网格排列，网格按钮为按下态

#### Scenario: 切换排法只上报不自存

- **WHEN** 用户点列表按钮
- **THEN** 面板发出 `onModeChange('list')`
- **AND** 宿主不回传新值时面板不私自改变排法

#### Scenario: 长名字在网格里可分辨

- **WHEN** 网格里同时有「Dragged Card」与「Dragged Card Focused」
- **THEN** 两个名字各排两行且互不相同，MUST NOT 都截断成同一个前缀

#### Scenario: 两种排法的悬停底一致

- **WHEN** 用户先后在网格与列表里悬停同一个物料
- **THEN** 两处的底色取自同一个 token

#### Scenario: 检索框常驻

- **WHEN** 用户在任一工作区打开物料面板
- **THEN** 头一行有检索框，货架上不再有控制它显隐的开关
