## MODIFIED Requirements

### Requirement: 取点提示可声明数值参数化

`ComposeCommandPrompt` MUST 接受可选的 `fields`，声明这一步的数值字段怎么参数化：

| 值 | 字段 | 原点 |
| --- | --- | --- |
| `absolute` | X、Y | 无（世界坐标） |
| `polar` | 距离、角度 | 上一个点 |
| `cartesian` | 宽、高 | 上一个点 |
| `radius` | 半径（**只有一个**） | 圆心 |
| `diameter` | 直径（**只有一个**） | 圆心 |

**原点 MUST NOT 出现在 `fields` 里**：它就是会话已经上报的那个 `reference`（橡皮筋的起点），
把同一个点放进两个地方只能靠约定保持一致。

`radius` 与 `diameter` 是**单字段**参数化。声明它们时：

- 呈现 MUST 只出一个数值框，MUST NOT 出第二个（哪怕是只读的）。圆是旋转对称的，半径点的
  角度对结果没有任何影响——**一个永远不影响结果的只读字段比没有更差**，它占着屏幕、占着
  `Tab` 的一个去处，却什么也不回答。
- `Tab` MUST NOT 被接管：没有第二个字段可去。
- 因此 MUST NOT 存在「锁定」这一档。锁定是 `Tab` 的产物；就算硬造出来，那一档里移动鼠标
  也不会改变任何东西，而**屏幕上不该出现一个鼠标动了也没反应的状态**。

字段 MUST 可选：不声明的步骤（选择对象、取基点）不显示数值，行为与从前完全一致。本包
MUST NOT 实现任何字段数学——它零运行时依赖，连坐标都不认识；`fields` 只是一个标签，由宿主
解释。

#### Scenario: 缺省时不影响既有命令

- **WHEN** 一条命令的提示不声明 `fields`
- **THEN** 会话行为与未引入该字段时完全一致

#### Scenario: 声明极坐标参数化

- **WHEN** `LINE` 取过第一个点
- **THEN** 「指定下一点」这一步的 `fields` 是 `polar`

#### Scenario: 声明单字段参数化

- **WHEN** `CIRCLE` 取过圆心
- **THEN** 「指定半径」这一步的 `fields` 是 `radius`

## ADDED Requirements

### Requirement: 取点提示可要求画出被量的那一段

`ComposeCommandPrompt` MUST 接受可选的 `measured`，声明「标注量的那一段」要不要由标注自己
画出来。缺省 MUST 是**不画**。

**标注量的那一段必须画出来**——不画它，标注的两条延伸线就从空处伸出来，用户读不出这个数说
的是什么。但它由谁画取决于它是不是形状的一部分：`LINE` 的预览线**就是**被量的那一段（再画
一遍就是同一条线加粗），而 `CIRCLE` 的预览是整圆、半径线不在里面。

因此这一条 MUST 由提示声明而 MUST NOT 由呈现层推导：只有命令知道自己的预览几何里含不含
这一段，呈现层拿到的只是一串预览折线，从里面反查「有没有一段正好从原点到落点」既贵又脆。

这 MUST NOT 被读成「预览几何与橡皮筋互斥」的例外：那一条禁止的是**同一个问题答两遍**，而
半径线与圆回答的是两个问题——形状是什么、你落在圆上的哪个点。

#### Scenario: 缺省不画

- **WHEN** 一条命令的提示不声明 `measured`
- **THEN** 呈现与未引入该字段时完全一致

#### Scenario: 圆的半径步要求画出来

- **WHEN** `CIRCLE` 取过圆心
- **THEN** 该步的 `measured` 为真
