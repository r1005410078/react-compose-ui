## 上下文

Stage 已有两套并行机制：`DEFAULT_STAGE_SHORTCUTS`（动作 → 键位，可被宿主覆盖与接管）与
`draftingSession.start(commandId)`（命令行与 `ComposeStageHandle.startCommand` 共用的启动
路径）。本变更只是把前者接到后者上。

## 目标/非目标

- 目标：按下 `L` 与在命令行敲 `LINE↵` 产生**完全相同**的会话。
- 非目标：动态输入、字符转交、拖动取点、关键字补齐。它们各自是后续的刀。

## 决策

**决策：新增七个 `drafting.*` 动作，而不是让键位直接映射到命令 id。**
直接映射看起来更短，但会绕开 `ComposeStageShortcuts` 的覆盖配置与 `onShortcutAction` 的
接管通道——宿主因此无法改键，也无法用自己的实现接管「画线」。动作是这两条通道的单位。

**决策：单键快捷键 MUST 同时是该命令的一个别名。**
用户只记一套词。`P`、`R`、`W`、`X` 因此要补进各自命令的 `aliases`。反过来不成立：
`WI`、`AR`、`REC` 这些多字母别名不需要有对应的快捷键。

**决策：命令会话进行中，图面上的单键不启动新命令。**
SDD 2.2 的最终形态是「命令进行中，图面上的可打印字符转交给光标旁的动态输入框」，而动态
输入还没有。在它到来之前，让单键启动一条新命令会**静默丢弃**正在进行的那一条——用户画到
一半按了个键，已取的点就没了。什么都不做是这条规则的安全子集：它不产生任何用户要撤销的
后果，而动态输入落地时把这一档接过去即可，不需要回头改语义。

**决策：`X` 给 `ARROW`，`A` 给 `ARC`。** `A` 只能给一条，弧比箭头更接近「基础图形」。
这是 SDD 待确认清单第 1 条，一个字母的改动，随时可对调。

- 考虑过的替代方案：**唯一前缀即执行**（命令行输入唯一匹配某条命令时自动执行）。已在
  SDD 2.1 明确拒绝——它要求用户在脑子里维护一张随命令集变化的表，`C` 今天唯一匹配
  `CIRCLE`，明天加一条 `CHAMFER` 就变成两个。

**决策：同一个事件上还有别的 Stage 动作时，绘图单键让路。**
实现期发现的：`shortcut-delegation` 已有一条用例把层级动作重绑到 `P`，而 `P` 现在也是
`PLINE` 的默认键。绘图键是七个**裸字母**，是本表里最容易被撞上的一类；宿主重绑是一次显式
选择，默认值应当退让。不让路的话，新增这七个默认键会静默夺走宿主已经绑好的键，症状是
「我绑的键失灵了」，而它只在宿主用了那几个字母时才出现。

**决策：编辑器不给绘图命令建动作目录项。**
`ComposeEditorActionId` 是 Stage 动作集的**子集**。给 `drafting.*` 建目录项会为已经能敲
`LINE` 的动作造第二个词——正是「已经有等价画布命令的动作不再造第二个词」禁止的那一类
（`edit.delete` 让给 `ERASE` 是同一条）。因此 `runShortcutAction` 对目录里没有的动作
MUST 回 `false`（= 没有接管），让 Stage 走自己的内建分支；回 `true` 会把这些按键静默吃掉。

## 风险/权衡

- **字母冲突**：`R` 与 `Shift+R`（旋转工具）、`C` 与 `primary+C`（复制）、`X` 与
  `primary+X`（剪切）只差修饰键。`matchesComposeKeybinding` 精确匹配修饰键，因此不会误触；
  但用例要显式钉住「带 primary 时仍是剪贴板动作」。与非绘图动作的同键冲突由上面的让路规则
  兜底。
- **可编辑目标**：焦点在命令行输入框里时 `isEditableTarget` 已经先行返回，单键因此不会
  在用户敲命令名的过程中触发。这是既有守卫，不需要新增。

## 迁移计划

纯新增，无破坏性变更。宿主未覆盖键位时得到新默认值；已用 `shortcuts` 覆盖的宿主不受影响
（未列出的动作取默认值，这是既有合并行为）。
