# DXF 入页面

## Why

DXF 导入是这条路线上**唯一还只通向旧世界**的入口：解析器、诊断聚合与坐标翻转恒等式全部
完好，产出的却是 `CadDocument`——一份用户既不能加动画、也不能绑数据、更不能发布的文档。

而页面世界现在已经齐了：曲线（步骤 8a/8b）、几何编辑（10）、端口（11a）、导线（11b）。
导入器缺的不是能力，是**目标**。

这一刀只换目标。拆除旧世界留给 12b——两半的风险完全不同：这一半是新增一条可验证的路径，
那一半是删掉四千行而不许有任何行为变化。

## What Changes

- **新包 `@compose-ui/dxf`**（无 React、无 DOM，只依赖 `core`）：三层纯函数
  （分词 → 记录 → 映射）原样搬过来，**只重写映射层**。分词与记录层一个字符不改——它们
  认识的是 DXF 的组码，与产出什么文档无关。
- **产出的是「导入计划」而不是文档**：`planDxfImport(text, { createSeed, idFactory })` 返回
  一块场景、若干组件资产与诊断。Entity 的 Preset 由**调用方注入**（与
  `createStageDraftingCurveCommand` 同一条既有做法），因此本包不认识 Registry 也不认识物料。
- **BLOCK → Component Asset v2**，**INSERT → 组件实例**。块基点写进实例的
  `Transform.pivot`（归一化盒坐标，允许落在盒外）——DXF 的旋转就是绕基点转，而步骤 3 定下
  pivot 时留的正是这个口子。
- **图层在导入期被求值掉，不进文档**（回答路线图「图层的归属」）：三样属性各有页面对应物
  ——byLayer 颜色求值进每个 Entity 的描边、`visible` 落成 `Visibility`、`locked` 落成
  `Lock`。图层名落成 Entity 名字。
- **场景按内容紧包围盒开**，几何归一化到场景原点。DXF 坐标动辄几千几十万，而场景是绝对
  坐标的原点。
- **导入产出一份新页面并打开它**，与今天右键 `.dxf` 的形状一致。资源浏览器上那一项改为
  「导入为页面」，旧的「导入为 CAD」随之消失。

## Non-Goals

- **不拆除旧世界。**`CadDocument`、CAD 标签页、`cad-canvas` 与 `importDxfDocument` 原地不动，
  12b 一并删除。这一刀之后 `importDxfDocument` 只剩测试在调用，那是**已排期**的删除而不是
  遗留。
- **不支持嵌套块。**沿用既有诊断 `dxf.nested-block`。组件实例套组件实例在页面世界里是可表达
  的，但它引出「实例内部再下钻」的一整套问题，不该由一个导入器顺手决定。
- **不支持非 1 缩放的 INSERT。**实例尺寸的唯一事实来源是组件根（既有不变量），缩放无处可放。
  按 1 导入并报告；「每个缩放值一份组件」是候选，等真实图纸暴露需求。
- **不读线宽与线型**（组码 370 / LTYPE）。今天的导入器也不读，加进来会引出「线宽是屏幕像素、
  虚线是世界单位」那对单位问题，与本刀无关。
- **不做端口**：DXF 里没有端口信息，凭几何猜端口会造出用户从未声明过的绑定点。
- **不做命名选择集**（AutoCAD GROUP）。图层名眼下的消费者只有场景树里的那个名字。

## Impact

- 包：新增 `dxf`；改 `editor`、`app`（演示夹具）
- Specs：`dxf-import`（新能力，ADD 6）
- 破坏性：资源浏览器上 `.dxf` 的右键项由「导入为 CAD」换成「导入为页面」。没有线上
  `.cad.json` 资产（既有判断），因此不写迁移器。
