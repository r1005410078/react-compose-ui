# 设计

## 决策 1 · 三层：分词 → 记录 → 映射

```
文本 ──分词──> (code, value)[] ──分组──> Record{ type, pairs[] } ──映射──> CadDocument
```

DXF 是成对出现的「组码 + 值」，每个组码 `0` 开启一条新记录。三层各自可测：分词只认行，分组
只认组码 0，映射只认记录。

**记录保留 `pairs` 数组而不是收成 map**：`LWPOLYLINE` 的顶点是重复出现的 `10`/`20`，收成 map
会只剩最后一个顶点，而这个错误在三角形上看不出来（三个点变一个点会直接被校验拦下），要等到
有人导入一条长折线才现形。

## 决策 2 · 坐标：一个矩阵恒等式，三个推论

翻转矩阵 `F = diag(1, -1)`，且 `F² = I`。DXF 里一个块实例的世界坐标是

```
p = I + R(θ) · S · b
```

（`I` 插入点，`θ` 旋转，`S = diag(sx, sy)` 比例，`b` 块局部坐标）。两边施加 `F`：

```
F p = F I + F R(θ) S b
    = F I + (F R(θ) F)(F S F)(F b)
    = F I + R(−θ) · S · (F b)
```

三个推论一次读出：

| | 结论 | 为什么 |
| --- | --- | --- |
| 位置 | `y → −y` | `F I` |
| 旋转 | **取反** | `F R(θ) F = R(−θ)`，翻转把旋转共轭成逆旋转 |
| 比例 | **不变** | 对角矩阵与 `F` 可交换，`F S F = S` |

圆弧的起止角同理：DXF 的角是 Y 朝上的逆时针，翻转后成为屏幕顺时针，而本仓的角约定正是屏幕
顺时针为正，因此 `startAngle = −dxfStart`、`sweep = −normalize(dxfEnd − dxfStart)`。

**这三条要么一起对、要么一起错。** 只翻位置不翻角度，图会「看起来像镜像的」——而那种症状
很容易被误当成源文件本身的问题，从而找错方向好几天。有一条用例专门用一段**不对称**的圆弧
（起角与终角都不是 90 的倍数）拦它：对称几何在翻转错误下看起来仍然正确。

## 决策 3 · 诊断是功能的一半，不是锦上添花

真实 DXF 一定带着我们表达不了的东西。三种处理方式：

| 方案 | 问题 |
| --- | --- |
| 静默丢弃 | 用户与原图一对，少了东西却没有解释——只会认为工具不可靠 |
| 整份拒绝 | 一个 `DIMENSION` 让整张图导不进来，而那张图 95% 是可用的 |
| **导入能导的，报告导不了的** | 采用 |

诊断带**稳定机器码**而不只是一句话：`dxf.unsupported-entity`、`dxf.polyline-bulge`、
`dxf.unknown-layer`、`dxf.nested-block`。可以被测试断言，也可以被界面按类别聚合成
「跳过了 12 个 SPLINE」而不是刷 12 行。

同类实体**按类型聚合计数**而不是每个一条：一张图纸有几百个 `DIMENSION` 很正常，逐条报告等于
没有报告。

## 决策 4 · `bulge` 按弦导入并报告，而不是在导入器里硬撑

`LWPOLYLINE` 的每个顶点可以带一个 `bulge`，非零表示该段是圆弧。

导入器**没法自己解决它**：`CadPolyline` 没有 bulge 字段，把一条带弧的折线拆成「多段线 + 若干
独立圆弧」会让它不再是一个对象——而「多段线是一个对象」正是上一刀的全部意义。

因此按**弦**导入（顶点照收，弧段变直线）并给出 `dxf.polyline-bulge` 诊断。真要支持它，该改的
是 `CadPolyline` 协议与那条遍历，属于另一刀。

## 决策 5 · 块基点决定块局部坐标的原点

DXF 的 `BLOCK` 记录带一个基点（组码 10/20），块内几何用块自己的坐标系表达，基点说明「块坐标
系里的哪一点对准插入点」。

本仓的块局部坐标以插入点为原点，因此 `局部 = DXF块坐标 − 基点`。翻转是线性的，先翻再减与
先减再翻等价。

名字以 `*` 开头的块跳过：那是 `*Model_Space` 这类布局块，不是符号。块内再出现 `INSERT` 时
跳过该实体并报告——本仓的校验器拒绝嵌套块，硬导进去会让整份文档不合法，一个符号毁掉一张图。

## 决策 6 · 图层按名字做 id，缺失的落回 `0`

DXF 的实体用**图层名**引用图层。本仓的 `CadPlacement.layerId` 必须指向存在的图层，因此直接
用名字当 id。

颜色只映射 ACI 的前九个标准色。完整的 256 色表是一张查找表，在有人真的需要之前不值得带着；
落不到表里的用默认色，不产生诊断——颜色不对与几何丢失不是一个量级的问题。

实体引用了表里没有的图层时**落回 `0` 并报告**。整份拒绝在这里同样不合理：一个拼错的图层名
不该让整张图导不进来。图层 `0` 在 DXF 里永远存在，文件没给也补一个。

## 决策 7 · 打开时按内容取景

真实图纸的坐标动辄几千、几十万。按默认视口打开一份导入结果，用户看到的是一片空白——他会
认为导入失败了，而实际上图就在两屏之外。

因此 CAD 画布首次量到真实图面尺寸后，若文档**有可见几何**就把视口取到它的包围盒上。空文档
不动（新建流程的手感不变，既有用例也因此不受影响）。宿主可用 `autoFitContent` 关掉，与 Stage
的 `autoFitActiveFrame` 是同一种「会话级取景」而不是文档状态。

一次看不见的导入等于没有导入，这与「块的端口看不见等于块只是一张贴图」是同一条判断。
