# 设计说明

## 语义合并之后只剩一句话

「段中点平移那一段」同时覆盖两种 kind：

- 两点直线只有一段，因此它就是「平移整条线」——原来那条规则是这条的**退化情形**。
- 多段线的每一段各有一个，相邻段共用端点，因此它们自动跟着伸缩。

合并的好处是它去掉了一处「同一个位置在两种 kind 上做不同的事」。id 仍然分开
（直线是 `move`，多段线是 `m{段}`）：`move` 不叫 `mid` 的理由没变——`mid` 在弧上表示改半径，
而按 id 查表的调用方手上没有 kind。

## 位移按中点算，不按指针算

与直线中点既有的做法一致：位移 = 落点 − 段中点。落点经过捕捉纠正之后，**段中点**精确落在那个
特征点上。按指针的原始坐标算会让段中点停在离目标几个像素的地方，而用户瞄的正是那个点。

## 形状：段中点一律条形

上一刀立的规则是「两个夹点长得一样而按下去做的事不同，是最难自己发现的一类缺陷」。直线的
中点做的事与两个端点完全不同，却和它们一样是方块——那正是这条规则要挡的情形，上一刀漏了。

AutoCAD 的 LINE 三个夹点都是方块，这里有意偏离：它有悬停提示与状态栏，我们没有，形状是我们
唯一能说这句话的地方。

角色名从 `insert` 改成 `segment`：名字要说的是「它作用在哪个东西上」，而不是上一刀恰好让它
做的那个动作——动作换了，位置没换。

## 判别性

| 用例 | 钉住的东西 | 改前 |
| --- | --- | --- |
| 拖多段线段中点后顶点数**不变**，该段两端各移同一位移 | 是平移不是插入 | 必红（顶点数加一） |
| 相邻段跟着伸缩：不相邻的顶点一动不动 | 只动那一段 | 必红 |
| 段中点落在捕捉到的特征点上，而不是指针裸坐标 | 位移按中点算 | 必红 |
| 直线的中点夹点画成条形 | 形状说出它做的事 | 必红 |
| 直线的中点仍平移整条线，长度方向不变 | 合并没有弄丢退化情形 | 恒绿——**护栏** |
