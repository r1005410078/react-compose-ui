# 变更：动画并入工作区——时间线成为面板，动画编辑成为显式开关

## 原因

顶栏今天有两个并排的切换器：「页面 / 绘图」是工作区，「设计 / 动画」是模式。两者看起来在切
同一件事，用户分不清哪个管什么；「动画」那颗按钮实际做四件事——往底部塞时间线面板、画布改显示
播放头处的采样文档、把拖动改写成关键帧并锁定原父级、顺手打开变换指示器。前一件和最后一件就是
工作区的货架与会话开关；中间两件是**语义分叉**，正是工作区那条硬边界（不改手势语义、不写文档）
禁止塞进工作区的东西。

把「动画」整个并进工作区违反那条边界：切一下工作区，同一个拖动从改位置变成打关键帧，屏幕上
没有东西解释为什么；按文档记忆的工作区还会让「打开这份页面」等于「进了录制态」。因此**拆开**：
布局那一半进工作区，语义那一半留成一个有明确进出的开关。

**以 `add-builtin-workspaces` 与 `add-shelf-customization` 落地后的规范为基线。**

## 变更内容

- **时间线成为可摆放的工作区面板**：`ComposeWorkspacePanelName` 加 `timeline`，preset 与快照都能
  摆它，随布局持久化；不再由模式动态加入 / 移除。任何工作区都可以摆时间线，内建里只有「动画」
  摆了它。
- **新增内建工作区 `animation`（动画）**：与页面同一套四区，底部边缘组为
  `[时间线, 资源, 命令, 日志]` 且**展开**、时间线活动；货架、会话开关与种子与页面逐字相同。
- **「动画编辑」是一个显式开关**，即今天动画模式的语义那一半：画布显示采样文档、自动记录改写
  编辑命令、拖动锁定原父级、跨过那一刻打开变换指示器。入口有三条：时间线面板 chrome 上的开关
  按钮（`aria-pressed`）、动作目录里既有的 `document.toggleAnimationMode`（命令面板与键位页）、以及**对时间线的
  任何一次交互**（播放头、打点、创建动画）。退出：再按一次开关、时间线面板不再可见（被其它
  底部标签盖住、被换掉的布局去掉）。
- **BREAKING** 顶栏的「设计 / 动画」切换器删除，`EditorModeSwitcher` 与 `ComposeEditorMode`
  不再导出；`ComposeEditorWorkspaceChrome` 的 `editorMode` / `onEditorModeChange` 删除。
- 工作区切换 MUST NOT 打开动画编辑；目标布局里没有时间线时 MUST 退出它——它唯一的可见依据
  没了。
- 端到端用例改用「切到动画工作区 + 创建 / 打开开关」的辅助函数进入动画编辑。

## 非目标

- 把动画编辑记成工作区会话开关（切回时自动恢复）：先不做，见 design.md 的风险一节。
- 时间线在关闭态的只读渲染：关闭态下时间线照常渲染，第一次交互即进入。
- 多动画选择、时间线面板的自定义货架。

## 影响

- 受影响的规范：`editor-workspace-layout`
- 受影响的代码：`packages/editor/src/workspace-layout`（定义、面板名、切换、chrome）、
  `packages/editor/src/compose-editor/compose-editor.tsx`（模式进出、面板增删逻辑）、
  `e2e/`（十份用例点「动画」单选）
- 与进行中的 `add-shelf-customization` 不冲突：本变更不碰「工作区管理」「工具栏货架」。
