# 变更：把 stage-surface 按用户能力分目录

## 原因

步骤 5 结束后 `stage-surface/` 有 42 个文件平铺。直觉上想建一个 `hooks/`，但 AGENTS.md 明确
禁止按技术类型横向堆放，仓库其余 12 个包也一个都没有。

**禁令是对的，理由具体**：按技术类型分，`use-stage-keyboard.ts` 进 `hooks/`、它的
`nudge-planning.ts` 进 `utils/`、两个测试进第三处——改一条能力要在三个目录之间跳，而「这三个
文件是一伙的」这条信息被目录结构抹掉了。按能力分，它们在一个文件夹里。

## 变更内容

按 AGENTS.md 的准入标准（三个及以上协同实现文件，或拥有自己的状态机/测试）筛出**六个**目录：

| 目录 | 成员 |
| --- | --- |
| `pointer-session/` | 会话生命周期、坐标归一化、根元素事件接线 |
| `keyboard/` | 动作级联、键位表、方向键微调 + 3 个测试 |
| `entity-creation/` | 效果分派、绘制实体、根层落点、资源落点 |
| `preview-document/` | 预览烘焙、线段几何、resize 实时求解 |
| `instance-drilldown/` | 下钻 Hook、下钻路径解析、内部选中框测量 |
| `screen-model/` | 屏幕模型、屏幕几何、选区派生、世界底图 |

**不够格的不建**：文字编辑只有 1 个文件、剪贴板与右键菜单只有 2 个，都留在根。为凑结构建
空壳目录同样是违规。

`stage-viewport-actions.ts` 被键盘与右键菜单**两个**能力共用，留在根——这正是「只有具有稳定、
单一、可说明的跨功能职责时才能上移」的适用场景。

每个目录有自己的 `index.ts` 控制导出；目录之间与宿主一律走目录入口，不再深层引用。
根目录从 42 个文件降到 13 个。

## 分目录立刻暴露的一处循环依赖

`entity-creation ⇄ preview-document`：`ShapeDirection`（两点图形端点的朝向）定义在
`drawing-entity.ts` 里，但用它的是预览烘焙与端点求解——`preview-document` 反向依赖了
`entity-creation`，而后者又要用前者的线段几何。

平铺时这条循环看不见，因为所有文件都在同一层。**这正是分目录的价值:它把隐含的依赖方向
变成显式的。** 修法是把类型移到读它的那一侧——它跟着**消费者**走而不是跟着产生者走，
`entity-creation → preview-document` 于是成为单向边。

## 一处操作教训

改完先跑 `bun run typecheck` 报了全绿,实际有真错误——turbo 服务了缓存结果。目录重排会让
大量文件路径变化,**必须用 `--force` 复核**,否则缓存命中率高的门槛形同虚设。真错误由
`vitest` 抓到:自动改写把测试的导入指向了目录入口,而入口没有导出那些符号。

## 影响

- 受影响的规范：`stage`（适配层组织）
- 受影响的代码：`stage-surface/` 全目录重排，`ShapeDirection` 换归属
- 用户可见行为：无。公共入口仍只有 `export { ComposeStage }`，全仓库无深层导入。
