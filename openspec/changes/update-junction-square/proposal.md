# 变更：接线点画成方块

## 原因

接线点今天是一个填实的**圆点**。改成**方块**。

**这条判据在领域里，不在代码里**：圆点是 KiCad 与多数原理图工具的画法，方块是端子类符号的
画法。哪一种对这个产品的读图习惯更对，是画法上的决定，因此规范只记结果与代价，不替它编一个
技术理由。

代码这一侧的账，一条一条：

- **不引入新 kind。**矩形是四顶点的闭合多段线，与整圆是扫掠 360 的弧是**同一条判断的两个
  实例**——这句话就写在现有那条要求里。因此「另立类型会让归一化、平移、距离、特征点、渲染与
  校验六条路径各多一支」那条理由原样成立，换形状一个字节都不欠它。
- **闭合性不变。**闭合多段线与整圆都算闭合，因此「选中时画盒而不画轮廓」这个答案不变，上一条
  变更那一整层（`resize: 'none'`、进不了顶点模式、面板只读）一个字节不动。
- **形状与端口记号分开了。**取点期间显现的端口记号是**实心小圆**，而接线点自己的端口就在它的
  盒心——今天那个蓝色小圆正画在红色圆点的正中央，两个同形的记号叠在同一个像素上回答两个问题
  （「这里可以接」与「这里已经接上了」）。分开是这块画布「形状先分开、颜色再分开」的既有规矩。
  说明白：今天两者还差着颜色与大小，因此这**不是**一处已经在咬人的缺陷，只是换过去之后顺带
  站到了规矩这一边。

**代价写在明处：方块与顶点夹点同形。**`vertex` 夹点就是方块。两者不会落在同一个对象上（接线点
进不了几何编辑会话），颜色也不同（夹点是 accent、接线点是导线的墨色），但这是换形状换来的**新的
一处同形**——圆那边撞端口记号，方这边撞顶点夹点，两个方向各有一处，没有一种形状是白拿的。

## 变更内容

- **`composeJunctionGeometry` 产出闭合四顶点多段线**（填满盒）而不是内切整圆。它是这个几何唯一的
  产出者，`materials` 的 Preset 与 `stage` 的接线命令都走它，因此改一处两边同时跟上。
- **`COMPOSE_JUNCTION_DIAMETER_RATIO` 改名 `COMPOSE_JUNCTION_SIZE_RATIO`**：方块没有直径，留着那个
  名字会让下一个读它的人以为几何还是圆。倍率仍取 **3**，不顺手调轻。
- **Preset 图标换成矩形图标**：场景树里那个图标是用户分辨它的一处，留着圆图标等于在两个地方说
  两句不一样的话。
- 端到端用例里定位接线点的选择子从 `circle` 换成 `polygon`——闭合多段线渲染成 `<polygon>`。

**不改的**：`presetId` 仍是身份的唯一承担者（四处判定一个字节不动）、端口 id 与位置、填色取自
接入那条导线的快照、`GeometryConstraints`、`paletteHidden`、接入与合并的规划、导线求解。

## 影响

- 受影响的规范：`basic-materials`（junction Preset 的几何与那条「填实的整圆」场景）
- 受影响的代码：
  - `packages/core/src/curve.ts`（`composeJunctionGeometry` 与常量改名）
  - `packages/core/src/index.ts`（导出改名）
  - `packages/materials/src/curve/definition.tsx`（图标）
  - `e2e/wire-junction.spec.ts`、`e2e/wire-merge-and-cut.spec.ts`、
    `e2e/wire-incremental-commit.spec.ts`、`e2e/junction-fixed-size.spec.ts`（定位选择子）
- 破坏性：`COMPOSE_JUNCTION_DIAMETER_RATIO` 是 `@compose-ui/core` 的公共导出，改名即破坏。
