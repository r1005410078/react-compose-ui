# 设计：导线每点一下就落地

## 决策 1：扩的是同一个 Entity，不是又一个 Entity

`LINE` 的「逐段落地」等于「每一段一个 Entity」，导线不能照抄这后半句——中间的拐点会退化成
两个自由端刚好重合，那不是绑定，符号一挪就裂开。因此本变更只搬前半句：**写进文档的时机**
提前到每一次取点，**产出几个 Entity** 一个字节不变。

落地方式因此分两种：第一次是 `entity.create`（此时要挑 Preset、定父级），之后每一次是
`entity.curve.set`（几何写入的唯一漏斗，同一条命令里写 `Curve` 与 `LayoutItem`）。

## 决策 2：`replaceLastCreated` 与 `pending` 是两个问题的两个答案

引擎建不了 Entity 也记不住 id（既有边界），因此它只能说出意图，由记着那份栈的宿主去解释：

- `replaceLastCreated`：这一步的曲线**替换本次会话上一个建出来的 Entity 的几何**，而不是
  新建一个。与既有的 `undoLastCreated` 同形——那一条说的是「把我上一段撤掉」。
- `pending`：这一条**还没画完**。宿主据此跳过**接入节点**：中途路过另一条导线并不是接线
  意图，先建节点、劈开对方，下一下又走开，留下的是一个谁也没接的孤儿节点，而它已经把别人
  的线切成了两段。

两个标记不能合并成一个：最后一步同时是「替换」与「画完了」，而中间每一步两者都成立。

端口绑定不受 `pending` 约束——每一步都按当前几何重算，因此末端吸上端口就绑、下一下走开就
解绑，任何一刻文档里的绑定都与屏幕上看到的一致。它是**自我纠正**的，接入不是：接入会改别人
的文档。

## 决策 3：`cancelled` 也要能带效果

`Escape` 在会重开的命令里分两级，第一级是「放弃这一条」。这一条已经落进文档了，因此放弃必须
把它删掉——`{ status: 'cancelled' }` 不带效果时宿主无从得知该删谁（引擎不认识 id）。

因此 `ComposeCommandStep` 的 `cancelled` 分支加一个可选 `effect`。它对 `TEffect` 泛型，
`commands` 包仍然零运行时依赖、仍然不认识任何文档协议。既有命令不受影响：不带这个字段的
`cancelled` 与今天逐字相同。

## 决策 4：会话回退跟着**几何**走，不只跟着「Entity 还在不在」

既有规则是「本次会话建出来的最后一个 Entity 不在文档里了，会话就回退一个点」，它挡的是
`LINE` 画到一半按 `Control+Z`。导线只有一个 Entity，撤销撤掉的是最后那条 `entity.curve.set`
——Entity 还在，只是少了一个顶点。只判存在的症状是：撤销一下，再点一下，那个拐点又回来了。

因此宿主在栈上多记一个**上一次写进去的顶点数**，文档里的顶点数比它少时按差值补发同样多次
`U`。这不是新规则，是同一条规则在「同一个 Entity 被改小了」这一档上的读数。

## 决策 5：父级在第一次落地时定下

`createStageDraftingCurveCommand` 按几何紧包围盒的中心挑落地父级。那个中心随着导线变长一直
在动，每一步重算会让一条画到一半的线突然从一个场景搬到另一个场景——局部坐标、绑定合法性与
场景树里的位置一起变，而用户只是多点了一个点。因此替换那一支读的是**这个 Entity 当前的
父级**，不重算。

## 决策 6：预览只画待定的那一段

已落地的部分是真的 Entity，由渲染器画。预览再画一遍就是同一条线画两遍，而两条线的墨色与
线宽不同（预览是 1px 虚线），叠出来的样子读不出哪一条是结果。`LINE` 的预览注释写的就是这
件事，本变更让导线与它一致。
