# 变更：场景外落点保留位置，场景默认统一不裁剪

## 原因

两个相互关联的行为问题（用户已确认取向）：

1. 从物料库/绘制工具在所有场景之外新建非容器 Entity 时，落点被钳制进激活场景边界，
   表现为「拖到外面被自动吸回容器」。用户期望保留拖放位置，只把层级挂进激活场景。
2. 场景的默认裁剪不一致：「新建场景」命令与初始场景（core 工厂）不裁剪，而在场景外
   画容器升格出的场景默认双向裁剪（容器 Preset 的 Clip 被升格原样保留）。用户确认场景
   应默认**不裁剪**。

两者组合自洽：场景不裁剪，因此保留在场景边界外的落点仍然可见，原本钳制要防的
「画了但没出现」不再成立。普通容器保持默认双向裁剪不变。

## 变更内容

- 空白工作区新建非容器 Entity：仍落进激活场景并换算局部坐标，但**保留世界落点、
  不再钳制进场景边界**；粘贴与各新建路径同规则。
- 场景外画容器升格为场景时，新场景的 Clip MUST 归一为不裁剪，与其它新建场景路径
  一致；显式对既有容器的升格不受影响（原地保留不变量不动）。
- 场景 Preset（`frame`）的默认 Clip 同步改为不裁剪。
- `stage-engine` 的钳制纯函数保留为公共原语，仅 Stage 不再在该路径使用。

## 影响

- 受影响的规范：`stage`(空白工作区的新建落点)、`basic-materials`(场景 Entity Preset)
- 受影响的代码：
  - `packages/stage/src/stage-surface/root-landing.ts`（去钳制；升格分支 Clip 归一）
  - `packages/materials/src/frame/preset.tsx`（defaultClip 不裁剪）
  - 相关单测与 e2e（在场景外绘制矩形落进激活场景 scenario 的钳制断言反转）
