## 上下文

曲线是带盒的普通 Entity，几何住 `Curve`，写入只有 `entity.curve.set` 一个漏斗；导线是带 `Wire`
的曲线，绑定住两端顶点。剪断导线的一段（`planStageWireCut`）已经落地：去掉整整一段、左半留原
Entity、右半新建、绑定各归各。本变更把「去掉一截」从「导线的某一段」推广成「任何曲线上、光标
底下、以交点或顶点为界的一截」，并给它一个由词启动的入口。

命令会话协议只认三种输入（点、文本、关键字）加选择集；点走点输入管线（键入 > 捕捉 > 网格 >
角度约束），选择集是宿主选择的镜像。`TRIM` 要的输入两者都不是。

## 目标/非目标

- 目标：一条规则覆盖直线、折线、矩形、圆与导线，三处（悬停预览、点选落地、拖动落地）读同一份
  纯函数——「看见的那一截」与「掉的那一截」不可能不是同一截。
- 目标：光标在空白处走的那几秒屏幕上也说得出「此刻在剪」。
- 非目标：**不做延伸**（`Shift` 切成 `EXTEND`）——延伸要选一个目标边界而修剪不用，两件事共用
  一个键、一个提示、一个光标，屏幕上读不出此刻按下去会加长还是剪短；`Shift` 先留着不占。
- 非目标：**不做在一点剪开**（`BREAK`）——两个重合端点在屏幕上与没剪之前逐像素相同。
- 非目标：**不做先选切割边的两步式**——它的价值是「只有选中的边才切」，而「只掉最近一格」已经把
  误剪的范围压到一格，多点一下比多选一步便宜。
- 非目标：**不做刀**——它切的是填色面积。
- 非目标：`path`（贝塞尔）v1 不受理，拒绝并说明。工程符号图导进来一个 `path` 都没有。

## 决策

### 决策一：`pick` 是第四种输入，不是 `point` 也不是 `selection`

`TRIM` 每一步要的是「一个落在对象上的点」：要知道是**哪个** Entity，也要知道落在它**哪儿**。

- 走 `point` 不行：点输入管线会把落点吸到网格或特征点上，而那个点可能已经不在光标底下那一截上
  ——用户瞄的是一截线，管线把它挪到了旁边的格点。十字线也会跟着画出来，而修剪不取点。
- 走 `selection` 不行：选择集是宿主选择的镜像，输入里只有 id；而且修剪 MUST NOT 改选择集——
  用户剪完还要接着操作刚才选中的东西。

因此 `commands` 包多一种 `ComposeCommandInput`：`{ kind: 'pick', targets: [{ id, point }] }`。
`targets` 是数组，因为拖动一笔碰到多条时要作为**一次输入**推进——一次输入、一个事务。点一下
是长度为 1 的退化情形。本包零依赖，`id` 只是字符串、`point` 只是两个数，不引入任何文档知识。

### 决策二：边界规则住在 `stage-engine`，相交与切片住在 `core`

「从落点向两边走到第一个交点或顶点」要读文档（别的曲线在哪儿、世界矩阵是什么），因此规划住
`stage-engine`（`resolveStageTrimPiece` + `planStageTrim`），与 `planStageWireCut` 同目录。

线段 × 线段、线段 × 弧、弧 × 弧的求交与「按曲线自身参数切出一截」是平面几何，住 `core` 的
`curve-geometry.ts` / `curve.ts`——与「曲线与矩形的相交判定住在 core」同一条判断：整个模块放在
一起，把弧的数学拆到两个包是「一半改了另一半没改」的温床。

曲线上的**位置**用它自己的参数表达：`line` / `polyline` 是 `{ segment, t }`，`arc` 是角度。
交点、顶点与落点都换成这个参数之后，「向两边走到第一个」就是在一维上排序取邻居——弧上按扫掠
方向走，整圆首尾相接。

### 决策三：交点按世界坐标求，贝塞尔与圆角拍扁

各曲线投影到盒、再乘世界矩阵——与命中、框选、特征点同一条链。切割边可以是任何带 `Curve` 的
可见 Entity（含导线、含自己：折线自交时另一段也是边界）。弧 × 弧、弧 × 线精确求交；`path`
作为**切割边**时拍扁（与非等比缩放那条同一个选择：产出的是一个位置，误差不呈现给用户）。

`cornerRadius` 的折线**按尖角顶点**求交与切片，MUST NOT 按圆角后的轮廓：多段线的顶点没有
bulge，落在角弧里的交点没法落成一个顶点。代价写在明处——剪口与画出来的弧差一个圆角的距离；
另一条路是在角弧上拒绝，但那会让圆角矩形在最常见的「一条线穿过角落」上无解。字段一个字节不改：
`cornerRadius` 本来就只作用于「角」，开放折线的两个端头不是角。

### 决策四：接线点不是切割边

节点是一个 `resize: 'none'` 的小形状（圆或方块，由「接线点画成方块」那条变更定），坐在导线
端点上。把它当切割边，每条支路的末端都会多出一截半个记号长的碎片——拾取框压在支路末端时预览会亮起一个几像素的段。它是一个**记号**不是几何，因此
「是不是切割边」由宿主注入（`isCuttingEdge`），与 `isWire` / `isJunction` 是同一条既有边界；
Stage 排除接线点与不可见的 Entity。

### 决策五：普通曲线也能剪，`wire` 只决定绑定怎么继承

`planStageWireCut` 上「只对导线成立」那条的理由是「把一个形状剪成两个是分割，不是用户抓着一段
时会想的事」。本变更推翻它：矩形的一条边要让给符号、六边形要开一个口，这些正是抓着一段时想做
的事。放宽之后 `wire` 选项只影响两件事——两半各自继承靠近自己那一端的绑定，以及剪到节点时
触发既有的支路清理与合并。

推论：顶点模式里**普通折线的段夹点** `Delete` 从 `unsupported` 改成剪断那一段，闭合折线去掉
一段即变开放。端段与唯一一段仍拒绝（缩短一截与删整条各有入口）。这与 `TRIM` 不矛盾：`TRIM`
在同样的段上会缩短或删整条，因为它的边界规则不同（交点、顶点、端头三级）且预览把结果画了出来；
段夹点 `Delete` 没有预览，因此保留那两档拒绝。

### 决策六：没有边界的孤线整条删除

两侧都走到了端头，这一截就是整条线。AutoCAD 与 Fusion 都删整条。规则不加例外；预览已经把整条
画成幽灵，「删整条已有 `ERASE`」那条「不造第二个入口」的判断在这里不适用——第二入口的代价是
用户读不出两个键位的区别，而这里两者的区别就画在屏幕上。

### 决策七：导线的绑定端跟着被去掉的那一截走

剪掉含端口那一截时，那一端的绑定随顶点一起消失。这与顶点模式里「绑定端顶点删不掉」**不矛盾**
——那条拒绝的理由是删掉顶点后绑定留在原地、下一帧求解把新的首顶点拉回端口、那一段变斜；这里
绑定与顶点一起走，剩下的线没有任何一段变形。剪到节点时支路数下降，既有的清理与合并规则在同一个
事务里接管（三支路变两支路即合并）。

### 决策八：悬停预览与落地读同一份纯函数

`resolveStageTrimPiece(document, index, entityId, worldPoint, options)` 是纯函数，返回
`{ from, to }` 两个曲线位置或 `null`。悬停时 Stage 用它画幽灵与剪口，点下时 `planStageTrim`
用它切片。拖动时轨迹的每一段与每条曲线求交，每个交点作为一次 `pick` 的目标；同一截碰两次只算
一次（按 `{ entityId, from, to }` 去重）。

幽灵的画法：那一截按 Entity 自己的描边色重画成点画、并叠一层画布底色把原墨压淡到约三成。
**不换色**——一条红导线上涂任何颜色都读不出来，淡掉在每种墨上都读得出来。剪口是与线垂直的
短划，用自己的颜色（`--stage-trim-cut`）：它回答「这一截的两头在这里」，不借 `danger`（那是
失效）、不借捕捉橙（那是吸上了没有）、不借 accent（那是选中了）。

### 决策九：光标是拾取框加徽标，不换光标

等待选择对象的命令（`ERASE`、`MOVE`）画的正是这同一个拾取框，而 `ERASE` 与 `TRIM` 都删东西——
两条命令光标一模一样、差别只写在屏幕底部，用户的眼睛此刻却在光标上。悬停预览只在压住一截时
出现，光标在空白处走的那几秒没有任何东西说此刻在剪。

**是徽标不是换光标**：拾取框必须留着——它是靶区、半边长是容差的事实来源，而一把剪刀的热点在
哪儿说不清。徽标由画拾取框的那一层一起画（同一个 `crosshair` 解析结果决定画不画），系统光标的
隐藏仍然只有 `resolveComposeCanvasCrosshair` 一个来源，不另开 `cursor: url()`。`canvas-kit`
一行不改：徽标是 Stage 的 chrome，摆在框的右下、刀尖指向框。

徽标由**提示声明**（`ComposeCommandPrompt.badge`）而不由宿主按命令 id 反推，与 `cursorInput`
同一条判断。角度固定，不跟着被剪的那一段转——它说的是命令，不是这一截的方向。

### 决策十：会话形状照抄 `COPY` 的「提交后仍在等」

每次 `pick` 推进一步：`{ status: 'prompt', prompt, commit: { trim: targets } }`——提交一个事务、
提示不变、继续等下一截。`accept`（回车、右键）与 `cancel` 结束。空闲 `Enter` 重复上一条命令的
既有规则因此覆盖它。不认启动上下文里的选择集：Quick 模式没有「先选切割边」这一档。

`Escape` 在拖动中放弃这一笔、会话留着；不在拖动中即退出。**不做会话内 `U`**：Stage 没有撤销
端口，`LINE` 的 `U` 是删自己建的那条，这里没有「自己建的」；每一下是独立事务，`Ctrl+Z` 逐下回退。

## 风险/权衡

- **拾取框同时压住两条线** → 取离光标最近的那一条，与点选一致；预览只亮一截。
- **整圆上只有一个交点** → 一个点剪不开一个圈，拒绝并说明「至少要两个交点」。
- **剪成两条后动画轨道** → 右半复制呈现但不复制轨道（位置轨道指着旧的盒），与导线剪断一致。
- **拖动轨迹与曲线求交的开销** → 只与视口内且拾取框够得着的 Entity 求交，轨迹按 `pointermove`
  采样；一笔通常几十段、图上几百条线，仍在一次 `pointerup` 里算得完。
- **`pick` 是 `commands` 的协议变更** → 只加不改：既有会话不声明 `pick` 就永远收不到它。

## 迁移计划

无数据迁移：协议、Schema 与版本号一个字节不改。`planStageWireCut` 的 `isWire` 选项改为可选，
既有调用方不动。
