## ADDED Requirements

### Requirement: 第一方图表物料

系统 MUST 提供开箱可用的图表物料，覆盖折线、柱状与饼三类。它们 MUST 住在一个**独立的包**里而不是基础物料包中——图表自带一个第三方图表运行时依赖，放进基础物料包会让只画方块与文字的宿主也装上它。该依赖 MUST NOT 出现在本包的公共 API 类型里：换掉图表运行时不该是一次破坏性变更。

三类图 MUST 由**一个** Renderer 承载，类型是它的一个三元 `kind` 字段，MUST NOT 各立一个 Renderer——三者只差底层的系列类型，另立会让绑定契约、Inspector、校验与渲染各多两支逐字相同的实现。

物料面板 MUST 出三格独立 Preset（折线图 / 柱状图 / 饼图），三者指向同一个 Renderer：用户在面板上找的是「饼图」，不是「图表，然后去属性面板改类型」。

数据模型 MUST 三类共用：一组类目与一组系列（每条系列有名称与一列数值）。饼图 MUST 取第一条系列、以类目作扇区名——让饼图另立一套数据形状会让「把柱图改成饼图」丢掉数据，而那正是用户最常做的一次尝试。

类目与系列数值 MUST 是可绑定的 Renderer prop，使页面脚本可以喂数据。

配色 MUST 来自 props，MUST NOT 内置一张按行业或语义划分的色表——色表因项目而异，内置一份等于替宿主做了一个多半要改的决定。

图表 MUST NOT 声明内容测量：它填满给它的盒，没有「内容有多大」这个问题。

图表 MUST 跟随**自身盒子**的尺寸变化重绘，MUST NOT 只监听窗口尺寸——画布缩放、Auto Layout 与属性面板改尺寸都会改变这个盒子而窗口一动不动，症状是图表画在旧尺寸上。

#### Scenario: 三格物料各画出对应的图

- **WHEN** 用户从物料面板分别拖入折线图、柱状图与饼图
- **THEN** 三个 Entity 各自渲染出对应类型的图
- **AND** 它们使用同一个 Renderer 类型，只有 `kind` 不同

#### Scenario: 改类型不丢数据

- **WHEN** 用户把一个已经填好类目与系列的柱状图改成饼图
- **THEN** 类目与系列原样保留，饼图以第一条系列作扇区

#### Scenario: 盒子变了图跟着重绘

- **WHEN** 图表所在的容器改变尺寸，而浏览器窗口尺寸不变
- **THEN** 图表按新的盒子尺寸重绘

#### Scenario: 数据可由页面脚本绑定

- **WHEN** 宿主把类目或系列绑定到页面脚本的导出值
- **THEN** 导出值变化时图表跟着更新
