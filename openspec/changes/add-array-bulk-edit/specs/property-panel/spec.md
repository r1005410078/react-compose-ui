## ADDED Requirements

### Requirement: 基本类型数组的批量录入

属性面板 MUST 为**元素是基本类型**（number 或 string）的数组分组提供一个批量录入入口：打开一块文本区，**一行一项**，确认后以解析结果整体替换该数组，并按一次受控变更提交。

元素不是基本类型时 MUST NOT 提供这个入口——「一行一个对象」没有意义。只读时 MUST 禁用它。

分隔符 MUST 同时接受换行、制表符与逗号：从表格里复制**一列**得到换行、复制**一行**得到制表符、从 CSV 粘来得到逗号，而用户不该为了这个差别做第二次操作。首尾空白 MUST 去掉，空项 MUST 丢弃。

任何一项不符合元素 Schema 时 MUST **整体拒绝**并指出是第几项，MUST NOT 只提交合法的那些：静默丢弃会让用户贴进 20 个数、看到 18 个，而屏幕上没有任何东西说明少掉的是哪两个。

文本区 MUST 以当前数组的值打开，每项一行，因此「打开、不改、确认」MUST 是一次无变化的提交。

#### Scenario: 一次贴进一列数

- **WHEN** 用户在 `array(number)` 字段上打开批量录入，贴进以换行分隔的 7 个数并确认
- **THEN** 该数组被替换为这 7 个数
- **AND** 只产生一次受控变更

#### Scenario: 从表格复制一行

- **WHEN** 粘贴内容以制表符分隔
- **THEN** 解析结果与换行分隔相同

#### Scenario: 非法项整体拒绝并指出位置

- **WHEN** 贴进的内容里第 3 项不符合元素 Schema
- **THEN** 不提交任何变更
- **AND** 面板指出是第 3 项有问题

#### Scenario: 非基本类型数组不出这个入口

- **WHEN** 数组的元素是对象
- **THEN** 该分组不提供批量录入动作
