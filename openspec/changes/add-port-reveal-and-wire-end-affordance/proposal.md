# 变更：端口在取点时显现，导线两端的接线状态画在图面上

## 原因

交互稿 `docs/mockups/drafting-wire.html` 的六个面板里，有三个到现在图面上什么都没有。

**一、接线点找不着。** 端口在图面上不画任何东西，唯一的入口是选中符号看 Inspector。用户要接
一根线，得先点开那个符号确认它有哪些端子、在哪儿，再回来画——而画的时候屏幕上又什么都没有。
今天只有捕捉标记会在吸上的那一刻亮一下，但它按定义**只标一个点**。

**二、只标一个点在接线图上不够。** 继电器的端子只隔几个像素。捕捉标记亮在其中一个上时，用户
看不出旁边还有两个，于是会以为自己够到的就是唯一的那个。

**三、导线接没接上，屏幕上完全看不出来。** 一条线的端点画在端子上，与真的绑到那个端口上，
渲染出来逐像素相同。今天唯一的判据是**挪一下符号看它跟不跟**——那是破坏性的验证，用户为了
确认一件事得先改一次文档再撤销。失效（绑的符号被删了）更糟：它是一个**缺陷**，却要等用户
主动选中那条线才显形。

## 变更内容

- **端口在取点时按符号整组显现**：命令正在取点、且光标进入某个带 `Ports` 的 Entity 的够及
  范围时，该 Entity 的**全部**端口一起画出记号。不是只亮最近的那一个。
- **不常驻**：没有命令在取点时一个都不画。一张接线图上几十个与几何无关的点会把图淹掉，而
  此刻用户还没有在找接线点。
- **选中一条导线时，两端各画一个接线状态记号**：自由 / 已绑定两种，与 Inspector 的三态同源。
- **失效常驻**：绑定指向的实体或端口不存在时，那一端**不选中也画**——它是缺陷，不该等到用户
  选中才显形。这是与前一条刻意的不对称。

## 影响

- 受影响的规范：`basic-materials`（MODIFIED：Inspector 不再是唯一入口）、`stage`（ADDED）
- 受影响的代码：`packages/stage/src/drafting/`、`packages/stage/src/stage-overlay/`
- **推翻一条既有判断**：`basic-materials` 现在写着「端口在图面上不绘制标记，因此 Inspector 是
  用户确认『这个符号有哪些接线点』的唯一入口」。本变更把它改成「取点时显现」，Inspector 降为
  编辑入口而不是唯一的查看入口。理由见设计文档——当初那句话的前提是「常驻会把图淹掉」，而
  「取点时才显现」不满足那个前提。
- 不改文档协议：`Ports` 与 `Wire` 一个字段都不加，全部是呈现。
