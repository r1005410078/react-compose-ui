## 决策

### 决策 1：工具栏是货架，三条约束保住它不变成模式

① 一个 id 一个含义一个图标，用户排的是顺序与有无，不是行为；② 目录不随工具栏变，工具栏永远
是目录的子集；③ **货架不得成为任何能力的唯一入口**——能上架的每一项都还有命令行、快捷键或
命令面板中的至少一条路，因此从任何货架上拿掉它都不改变命令可用性。定义的 schema 里只有
「一列目录 id」，没有能改含义的字段——宿主与用户想定制也定制不出一个模式来，这比文档里写
MUST NOT 更硬。

③ 是这三条里唯一需要**主动维护**的：它是对目录的准入条件，而不是对货架的约束。只有按钮、
没有第二条入口的功能一旦进了目录，「按工作区增删货架」就成了按工作区改能力。逐格核过今天的
16 格，没有一格违反它，因此这是一条守住现状的规则而不是一次重构。

条件是**至少一条**，因为两类目录项的第二条入口不是同一条：绘图命令走命令行与单键（它们
**不在动作目录里**，那是「已有等价画布命令的动作不再造第二个词」的直接后果，因此命令面板里
搜不到 `CIRCLE`），容器与文字反过来——没有命令词，走的是动作目录与快捷键。写成「三条都在」
会得到一条没有任何一项满足的规则。

**这条规则落地时抓到了两处真缺口**，两处都是「只有那颗按钮」：

1. **画布设置**——它在图面上的唯一入口是网格 ▾ 菜单里那一项。把网格从货架上拿掉就等于拿掉了
   编辑画布网格与吸附的能力。
2. **变换指示器**——一条动作、一个键位、一个命令词都没有，只有工具栏那颗按钮。

补的是 `stage.canvasSettings` 与 `stage.toggleTransformGizmo` 两条动作（默认都不绑键：进目录
是为了给它们第二条入口，不是为了多两个键位）。这不是顺手加功能——不加的话这两格就该按规则
**退出目录**，而那意味着它们连排序都不能参与，比加两条动作差得多。

判别性用例因此**逐项声明**每一格的第二条入口并当场验证那条入口真的存在，而不是维护一张
「这些都算通过」的白名单：白名单在加进新一格时永远绿，而这条规则要防的正是有人加了一格只有
按钮的功能。

曾经的 ③ 是「内建两个工作区默认同一条货架」。它被推翻了：那条不是约束，是一个**恰好成立的
现状**，而且它在当前尺寸下就是错的——16 格工具栏在 1280 默认窗口下余量不到半格，溢出从尾部
收，尾部正是八条绘图命令。共用一条顺序时，绘图工作区最先丢掉的恰好是它存在的全部理由。

### 决策 2：目录来自三处，货架只存 id

动作目录（工具与开关）、命令描述符（绘图命令）、宿主 `toolbarItems`（图标 + 标题 + 指向一个
动作或命令 id）。货架里 id 不在目录里的项渲染时跳过，与物料货架「文件夹找不到」是同一条处理。
「选择」固定首位；复合项整体上下架；「设计 / 动画」与保存不在货架上。

### 决策 3：右键是轻量入口，对话框是完整入口

移除一个、插一条分隔、只看这一组、跳到资源——不用开对话框。对话框才做排序、跨列、添加来源、
重置。两个对话框同一套骨架（拖动排序 + 重置为默认 + 取消 / 完成）。

### 决策 4：文件夹来源里单个文件不可隐藏

「新导入的自动出现」是物料货架成立的理由；给单个文件加显隐就把它变成了谎言。想少看，用
「只看这一组」或去资源里挪文件夹。基础组件那一段是唯一按单项勾选的：它只有四个，且每个都有
工具栏或命令上的第二个入口。

### 决策 5：`paletteHidden` 的判据跟着货架走

`paletteHidden` 今天有两种来源，此前混作一个布尔：**因为工具栏已提供入口而藏**（Arrow、
Circle），与**因为物料自身的理由而藏**（Wire——从面板拖出来的导线没有任何端口绑定，而那条粗线
正在宣称它是主回路）。

工具栏货架按工作区不同之后，第一种的判据不再是全局事实，必须按**当前工作区的货架**算。不改的
症状很具体：页面工作区的默认货架不含 `CIRCLE`，而圆的 Preset 又因为「工具栏已提供入口」被藏
着，于是页面里既没有按钮也没有瓦片，那条命令只剩命令行一条入口——**收走一个入口是意图，收走
全部可见入口不是**。

判定留在调用方（编辑器知道当前货架），`resolveComponentShelf` 拿到的仍是一组算好
`paletteHidden` 的 Preset，`component-library` 因此不需要认识工具栏。
