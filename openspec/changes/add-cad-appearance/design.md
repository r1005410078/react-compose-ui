# 设计

## 决策 1 · 全可选字段，缺省即回退

```ts
interface CadStroke { color?: string; width?: number; dashPattern?: readonly number[] }
```

三个字段各自独立缺省，而不是「有 `CadStroke` 就要给全套」。理由是**用户改的是一个属性**：
把一根线改成红色，不该顺带把它的线宽钉死成当前值——那样以后改图层线宽，这根线就不跟了。

因此清除某一项 = **删掉那个键**，而不是写一个哨兵值。JSON 里没有 `undefined`，写
`color: null` 会让「显式设成无色」与「跟随图层」变成两个都要处理的状态。三项全被清除时整个
Component 一起删掉，文档因此不会攒下一堆空壳。

解析是唯一的读取入口：`resolveCadStroke(document, entity)` 返回**已经落实**的颜色、线宽与
虚线，渲染只管画。既有文档不含 `CadStroke`，解析结果与今天逐字相同——这条由用例守着。

## 决策 2 · 线宽是屏幕像素，虚线是世界单位

看起来不一致，其实是照抄两个不同的领域概念：

| | 单位 | 缩放时 | 对应 AutoCAD |
| --- | --- | --- | --- |
| `width` | 屏幕像素 | **不变** | lineweight（显示宽度） |
| `dashPattern` | 世界单位 | 跟着缩放 | linetype（图上的实际长度） |

线宽回答「这根线画多粗」。放大图纸时它跟着放大，一根 3 像素的主干会变成一条色带，而用户
放大恰恰是为了看清结构。

虚线间隔回答「这根线的虚线段有多长」。它是图上的实际长度：缩小之后虚线变密，正是它要表达的
密度。写成屏幕像素的话，无论缩放到什么倍数虚线看起来都一样密——那条线就不再携带任何长度信息。

实现上因此是 `strokeWidth={width}` 与 `strokeDasharray={pattern.map((v) => v * zoom)}`。
两处的 `zoom` 一个有一个没有，容易被后来者当成漏写，所以这条要立在注释里。

## 决策 3 · 块实例的外观由实例决定

块内图元的 `CadStroke` 不参与解析，整个实例按实例自己的外观画。

这不是新判断，是**沿用图层的既有那条**：

> 实例自身的图层决定整个实例的可见性——块内图元各自的图层只在块定义内部有意义，让它们能
> 单独隐藏会使同一个块在不同插入处呈现不同，那不是块。

外观同理。技术上还有一层：可见性遍历返回的几何只带 `ownerId`（顶层对象），渲染拿不到「这一段
来自哪个块内图元」。要支持成员级外观，得让遍历额外携带每段的解析结果——而那会让**命中与捕捉
也背上只有渲染需要的数据**。等真的有人需要时再谈。

## 决策 4 · 三条命令共用一个会话工厂

`COLOR` / `LWEIGHT` / `LTYPE` 的流程完全相同：拿选择集（没有就先要）→ 收一个文本 → 提交一条
`cad.entity.stroke.set`。差别只在**怎么解析那个文本**。

因此做成 `createStrokePropertySession(context, { prompt, parse })`，与 `MOVE`/`COPY` 共用取点
状态机是同一种做法。三条各写一遍的话，「先选后执行」的两条次序、空选择集的处理、拒绝之后
停在原提示——这些边界会各自漂移。

解析失败一律 `rejected` 且**不结束命令**：打错一个颜色值就要重新选一遍对象，这在 CAD 里是
不可接受的手感。这与 `INSERT` 打错块名的处理一致。

## 决策 5 · `BYLAYER` 是清除，不是一个值

三条命令都接受 `BYLAYER`（大小写不敏感），语义是**删掉这一项覆盖**。`LTYPE` 额外接受
`CONTINUOUS`，因为「实线」在 AutoCAD 里是一个具名线型而不是「没有线型」。

把 `BYLAYER` 存成一个字面值是另一条路，但那会让解析多一个分支（「值是 BYLAYER 时改读图层」），
而这个分支必须出现在**每一个**读外观的地方。缺席即回退只需要一个 `??`。

## 决策 6 · 颜色接受十六进制与九个色名

`#rrggbb` 与 `red` / `yellow` / `green` / `cyan` / `blue` / `magenta` / `white` / `gray` /
`lightgray`——正好是 DXF 导入器已经在用的那九个 ACI 标准色，两处共用同一张表。

不接受任意 CSS 颜色名：那张表有一百多个条目，而 `cad` 是无 DOM 包，没有浏览器帮忙解析，
自己带一张表只是为了让 `rebeccapurple` 能用。十六进制已经覆盖了全部需求。
