# 图元外观覆盖

## Why

这是**步骤 8.5「CAD 动画」的前置**，路线图把它写得很明白：CAD 动画的主要对象不是几何而是
外观与状态——

| 想做的 | 动的是什么 |
| --- | --- |
| 电流流向 | 线的虚线偏移 |
| 告警闪烁 | 颜色 |
| 设备停运 | 线宽 / 线型 |

而今天 CAD 图元**一点外观都没有**：颜色一律来自图层（ByLayer），线宽写死 1 像素，没有线型。
动画没有可动的属性，做不下去。

外观本身也是独立的缺口。一张接线图靠线型区分**一次回路与二次回路**、靠颜色区分**电压等级**、
靠线宽区分**主干与支路**。只能按图层区分意味着「换一根线的颜色」要先新建一个图层——那不是
图层的用法。

## What Changes

### `CadStroke`：一个全可选字段的覆盖

`color` / `width` / `dashPattern`，**三者都可选**。缺省即回退：颜色回退到图层，线宽回退到 1，
线型回退到实线。这与 DXF 的 ByLayer 是同一个语义，也让既有文档一个字节都不用改。

### 两种单位，因为它们本来就不是一回事

- **线宽是屏幕像素**，不随缩放变化。它是「这根线画多粗」，与 AutoCAD 的 lineweight 一致——
  放大图纸不该让线变成一条色带。
- **虚线间隔是世界单位**，随缩放变化。它是图上的实际长度，与 AutoCAD 的 linetype 一致——
  缩小之后虚线该变密，那正是它表达的东西。

这个不对称是照抄领域惯例，不是疏漏。写反的症状是「放大之后线粗得看不清结构」或者「缩放时
虚线密度纹丝不动」，两者都要盯着看一会儿才反应过来。

### 三条命令

`COLOR`/`COL`、`LWEIGHT`/`LW`、`LTYPE`/`LT`，都是「选对象 → 给值」。`BYLAYER` 清除覆盖。
三条共用一个会话工厂，差别只在解析哪一种值——与 `MOVE`/`COPY` 共用取点状态机是同一种做法。

### 块实例的外观由实例决定

块内图元自己的 `CadStroke` 不生效，整个实例按实例自己的外观画。这**沿用图层的既有判断**：
让块内图元各自决定外观，同一个块在不同插入处会呈现不同，那就不是块了。

## Impact

- `@compose-ui/cad`：`CadStroke` 与解析、三条命令与一条 handler、平移不受影响。
- `@compose-ui/cad-canvas`：渲染读解析结果而不是写死的图层色与 1 像素。
- 协议：`schemaVersion` **不变**。既有 `.cad.json` 不含 `CadStroke`，解析结果与今天逐字相同。

## 本步刻意不做

- **`dashOffset`**：它只有被动画时才有意义，现在没有任何入口能设它。位置已经让好了——
  `CadStroke` 加一个可选字段不牵动别的东西，步骤 8.5 里它才有真实的消费者与用例。
- **DXF 的实体级颜色导入**：导入器现在把颜色全部按图层处理。补上它是导入器的一行映射，但
  需要先有本步的协议；单独一刀更清楚。
- **ByBlock**：AutoCAD 里还有一层「跟随块实例」的继承。本仓的块实例本来就整体决定外观，
  ByBlock 与 ByLayer 在这个模型里会退化成同一件事。
- **属性面板**：改外观走命令行，与本仓 CAD 的其余部分一致。面板是另一条产品线。
