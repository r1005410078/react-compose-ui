## 上下文

编辑器今天是三层 Dockview 7 实例：外层核心 + 底部边缘组；核心面板里嵌一层承载左 / 画布 / 右；
左栏里再嵌一层承载场景图 / 工具组。文档是中央组里的 panel，标签只在中央组头上。左右边缘组
折叠后是竖向图标轨。标尺带底色与边框。窄窗口下工具栏尾部被裁掉。

## 目标 / 非目标

- 目标：一个 Dockview、通栏文档标签条、无图标轨的边缘组、压在图面上的标尺、工具栏溢出。
  用户可见的差别是「整体看起来大」。
- 非目标：面板拖拽、布局持久化、任何工作区概念。这些在 `add-custom-workspaces`。

## 决策

### 决策 1：「看起来大」是分割数量，不是画布面积

通栏标签条对画布面积零贡献。差别在纵向竖线：今天 8 条（两条图标轨、两条标尺框、中央组两侧
边框、两条外框），之后 4 条。同样的像素，分割少的那张显大。因此本变更的每一项都在减分割，
没有一项在挪面积——属性面板不收、底部不折，那些是工作区的默认值，不在这里定。

### 决策 2：一个 Dockview

三层实例的每一层各画一圈边框，也让后续的跨栏拖拽不可能（拖拽要跨栏就得是一棵树）。收成一个：
场景图与工具组是两个普通组上下分栏，属性面板是一个普通组，画布组在中央，**只有底部用
Dockview 7 原生边缘组**（`addEdgeGroup`，原生折叠）。左右两侧不能是边缘组，这是 Dockview 的
结构决定的：它的边缘组住在外层 splitview 里、包着中间那一列，底部边缘组又住在中间那一列里——
左右一旦是边缘组，底部就被夹在它们之间，横跨不了全宽（今天要三层实例，正是为了绕开这一点）。
一个边缘组还只能装一个标签组，而左栏要装两个。本变更保留 `locked: 'no-drop-target'` 与
`disableDnd`——解锁是下一个变更的事，这里只换结构。

组建完之后再显式 `setSize` 一次初始尺寸：`addGroup` 的 `initialWidth` 只在网格当时有真实尺寸时
才算数，容器还是 0 时加进去的尺寸会在第一次真实布局后被摊成等份。

### 决策 3：通栏标签条在 Dockview 之外

Dockview 的标签条永远属于某个组，没有「一条标签条管着下面整个三栏」这种东西。因此文档从
panel 变成会话（今天已经是 `ComposeWorkspaceDocumentSession`），标签条是自定义 `tablist`。
代价：标签的键盘与 ARIA 自己写；Dockview 的标签拖动没了（本来就锁着）。齿轮跟着挪到标签条
右端——它是编辑器级 chrome，今天挂在场景组头上只是因为那是当时最外层的头。

### 决策 4：两侧去轨，折叠进面板头

图标轨是两条竖线，而它承载的信息（哪个面板、收没收）面板头都能说。左右两侧是普通组，收起就是
把那一侧的组 `setVisible(false)`——gridview 在一个分支的子节点全部隐藏时把整个分支收成 0，
左栏的两个组因此一个按钮一起收；折叠入口是场景组与属性组头上的按钮，收起后编辑器边缘留一条
8px 把手用于展开。画布组 `hideHeader`：它只有一个面板，文档标签在通栏标签条上。面板头统一
30px（`--dv-tabs-and-actions-container-height`），折叠后的底部边缘组也取这个高度。

### 决策 5：模式切换器与保存住在标签条右端

「设计 / 动画」与保存说的是「这个文档处于什么模式、保不保存」，是文档级 chrome，与文档标签
同一行。设计稿把它们画在画布工具栏行右端，实现时改了：默认三栏在 1280 宽下画布列 600px，
十六格工具栏本身就要 550px，再塞进切换器与保存，尾部的绘图命令在默认窗口里就已经进「更多」，
而绘图命令是这块画布最常用的入口。溢出规则仍然保留（1024 宽下照样收进「更多」），只是默认
窗口不该一上来就在那一档。代价说在明处：将来工作区切换器也会住在标签条右端，两个分段控件
同一行，届时靠位置与分组区分。

### 决策 6：标尺不占框

标尺带框时它是画面上两条额外的边；去掉底色与边框，它是坐标参照而不是框。刻度、游标线、
吸附一个像素不改——只改 `stage` 样式。

## 风险 / 取舍

- 三层收成一层是这一串变更里最大的一刀，十二张黄金图全部重录。放在最前面做，后面每一步都在
  它之上，黄金图只重录这一次。
- 文档从 panel 变会话之后，`renderer: 'always'` 保住的 Monaco 草稿要由会话自己保住——用例钉住
  「切走再切回，未保存草稿还在」。
