# 变更：多段线的四角联动圆角

## 原因

矩形现在是闭合多段线，而**多段线的角只能是尖的**——`Curve` 协议里顶点只有 `{x, y}`，没有
任何圆角或 bulge 字段。设备外框、柜体轮廓与面板底板画出来全是硬角，而这些东西在实机上是圆的。

改圆角今天唯一的办法是换回矩形物料，那等于用「不能改形状」换「能有圆角」——两件事都是用户
要的，不该二选一。

## 变更内容

### 新增

- `ComposePolylineCurve` 上一个可选 `cornerRadius`（几何空间的一个数）。**缺席即尖角**，
  因此既有文档逐像素不变，协议版本不动。
- 圆角求解住 `core/curve-geometry.ts`：一条圆角多段线归约成一列**有序的轮廓片段**
  （缩短的直段与角弧交替）。命中、框选、内部判定与渲染都读这**同一列**。
- 四个**圆角手柄**：小一号的空心圆加一圈画布色垫底描边，位置是**角弧的圆心**（沿两条边各
  进 `r`），因此拖动距离读出来就是半径。**选中即出**，与八个缩放手柄共存。
- 拖动时的半径读数：被量的那一段是**圆心到弧上**（CAD 的半径标注），读数复用动态输入既有的
  标注规则——框落在被量那一段的中点上、标注在框后面断开。
- 曲线 Inspector 的「圆角」数值字段，与手柄是同一个值的两个入口。

### 修改

- `composeCurveSegments`、`distanceToComposeCurve`、`isPointInsideComposeCurve` 走轮廓片段。
- 曲线渲染在 `cornerRadius` 在场时从 `<polyline>` / `<polygon>` 换成 `<path>`。

## 关键决策

- **四角联动一个值**，不是每角一个。顶点类型因此保持 `{x, y}`，归一化、平移、DXF 导入与
  既有文档一个字节不改。每角独立是这个字段向后兼容的一次扩展，随时可以接着做。
- **钳制在读取时而不是写入时**：每个角的可用半径是相邻两段长度的一半（按角平分线换算成切线
  长），但**不回写文档**。拖 resize 把矩形变窄，圆角自动收；拉回去圆角原样回来，作者写进去
  的那个数没被静默改写。
- **紧包围盒仍由顶点决定**，不由圆角后的轮廓决定。对矩形两者恰好相等（角弧与边相切）；锐角
  上圆角后的轮廓略小于顶点包围盒，这个偏差换来的是「拖圆角时盒一动不动」。
- **`cornerRadius` 为 0 时不写这个字段**：缺席与 0 是同一件事，留两种表示会让「有没有圆角」
  在两处读出不同答案。手柄拖回 0 即删除字段。
- **特征点仍在尖角顶点上**：捕捉回答「这个角在哪」，圆角只改墨。Figma 的顶点同样停在尖角。
- 半径到顶时同一条边上的两个手柄落在同一点，**那时不画**——两个手柄叠在一起等于都点不中。

## 非目标

- **不做每角独立的圆角**，也不做圆角的动画轨道。
- **不给多段线加 bulge**：一条多段线里的**弧段**是另一件事，圆角只是角上的一段定半径圆弧。
- **不给曲线以外的物料改圆角入口**：矩形物料的 `Appearance.borderRadius` 一个字节不动。

## 影响

- 受影响的规范：`compose-document`、`basic-materials`、`stage`
- 受影响的代码：
  - `packages/core/src/curve.ts`、`curve-geometry.ts`（协议、校验、轮廓片段）
  - `packages/materials/src/curve/`（`<path>` 渲染、Inspector 圆角字段）
  - `packages/stage/src/stage-overlay/`（圆角手柄层、半径读数）
  - `packages/stage-engine/src/interaction-kernel/`（命中类型与插件）
