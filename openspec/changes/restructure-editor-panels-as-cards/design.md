## 上下文

编辑器 chrome 最近连着改了三轮：`restructure-editor-chrome`（单 Dockview、文档标签条）、
`update-editor-chrome-density`（30px 头部行、面板头统一）、`restructure-editor-top-bar`
（应用顶栏、标志菜单、圆角选中画法）。三轮都在**贴边布局**里做，因此始终有两件事没解决：

1. **组的边界画不出来。**用户能拖动重排的单位是「组」，而组与组之间只有 1px 线，线两边同色。
2. **看得见的与拖得到的不是同一个东西。**线 1px，Dockview 的 sash 命中带 4px 且不可见。
   在贴边布局里这个问题**没法修**——把 1px 线加粗到 6px，那 6px 就是一条粗黑线。

本变更把边缘区做成卡片，顺带把上面第二条一并解决；并把 Inspector 那 122px 的空白还给画布，
因为卡片化的空间代价必须有地方付。

## 目标 / 非目标

- 目标：让「一块可折叠的区」在屏幕上是一个可见的对象；让沟槽同时是边界与命中带；
  给 Inspector 一条分配规则；把画布卡的头收成两行单一作用域。
- 非目标：改变 Dockview 的拖放语义、开启浮动组、改变任何命令或手势、改变面板内容的密度。

## 决策

### 卡的单位是「一颗折叠开关管的那一块」，不是 Dockview 组

第一版取的是「一张卡 = 一个 Dockview 组」，理由是**组才是用户拖动重排的单位**。那个答案被
推翻了：左边那颗折叠开关一按就收走两个组，把它们画成两张分开的卡，等于让一颗按钮同时抓走
两个看起来各自独立的对象。因此判据换成**顶栏那三颗开关各自管的那一块，加上画布**——四张卡与
三颗开关一一对应，剩下那张是唯一不能被收起的东西，这句话在屏幕上是自明的。

推论：拖一个面板到左区**不会长出第五张卡**，它落进左卡成为里面的第三段。卡的数量由**区**决定，
不由组的数量决定。顶栏不参与拖放、不进布局快照、搬不走，因此**不是卡**——给它一张卡等于宣称
它可以被搬走。

### 沟槽用 Dockview 7 的 `theme.gap`，不用 CSS 内缩

`dockview-core@7.0.2` 的 splitview 原生支持 `margin`，由 `DockviewTheme.gap` 注入
（`dockviewComponent.js`：`this.gridview.margin = theme.gap ?? 0`）。它把间距**算进布局**
（`view.layout(view.size - marginReducedSize, ...)`），并把 sash 摆到间距正中
（`offset + size - sashWidth / 2 + margin / 2`）。

考虑过的替代方案：给 `.dv-view` 加 `padding` 或给 `.dv-groupview` 加 `inset`。**否决**——
Dockview 用 JS 把内容尺寸算好再写进去，纯 CSS 内缩会让内容比可见卡宽 6px 并在右侧被裁掉。

sash 的宽度在 JS 里是常量 4（`const sashWidth = 4; // hardcoded in css`），只用于摆位；
可见宽度归 CSS。因此把 `.dv-sash` 的 CSS 宽度改成 6 并用 `margin` 抵掉那 1px 偏移，命中带
就与沟槽逐像素重合——这正是「看得见的就是拖得到的」在这次能兑现的原因。

### 左列的接缝由卡面越界绘制，而不是关掉那一段的 gap

`gridview.margin` 是**整棵树**的属性，没有「这一条边不要间距」的开关。因此左列两个组之间也会
有 6px 间距，而那正是「左区是一张卡」要否掉的东西。

解法是**把卡面与布局盒解耦**：卡的底、边框与圆角由 `.dv-groupview` 的伪元素画，它可以越过
自己的布局盒。左列上下两段各自向对方那一侧多画 6px 把沟槽填成卡色，并各自去掉朝向接缝的那条
边框与那两个圆角；沟槽里的 sash 仍然透明、仍然可拖。

代价说在明处：**卡内部那条上下分界的命中带仍然是看不见的 4px**——「看得见的就是拖得到的」
这条只对卡与卡之间成立。左区内部那条分界因此没有变好，这是把「卡 = 区」换来的一致性所付的价。

### 只动桌面这一个颜色

实测深色主题下 `workspaceBackground` 与 `panelBackground` 是同一个 `#101216`
（`packages/ui-context/src/providers.tsx`）。今天看不出问题，因为没有任何地方露出桌面。
卡片体、卡片头与画布**保持今天的颜色**，改的是它们之间那层底，这样既有的每一处对比度都不用
重新验算。浅色主题本来就有桌面色（`#f3f5f8` vs `#ffffff`），一个字不改。

**深色靠边框，浅色靠阴影**：深色底上投影几乎不可见（没有光可挡），浅色底上一条 1px 灰线读起来
像表格线。同一份结构，两种主题各用各的手段。

**不给卡片加悬停或激活高亮**：Dockview 的「活动组」跟着每一次点击到处跳，一圈会闪的边框比没有
更差；哪个组是活动的已经由标签的圆角底回答了。

### 卡内不画横线：分层交给已有的三档色阶

判据是**这一条服务的是谁**——标签行服务这张卡（chrome，`surface-raised`），工具行服务画布，
因此工具行取 `surface-sunken`，与画布连成一片；命令行回到 chrome 那一档。三档色本来就都在
主题里，**一个新 token 都不加**。

中途曾判断这样会留下「一条没有理由的边」（工具行与画布同色同宽无线，只有网格点无缘无故停住），
并据此设计了一块停靠岛。**那半条诊断是错的，来自一张没画标尺的稿子**：Stage 的标尺是 24px
（`--compose-stage-ruler-size`），横的贴画布顶边、竖的贴左边、交角那格是原点，底色与画布同为
`surface-sunken`。网格点并不是在工具行下面停住的，它停在**标尺内沿**——低 24px，而标尺自己带着
刻度与原点格，那就是那条边的理由。

停靠岛因此一并否掉：它落在标尺上，而标尺的 `cursor` 是 `crosshair`、**从上面往下拖会拉出一条
辅助线**，盖住的那一段是一处看不出原因的失灵。让开标尺就等于让开了岛的边赖以成立的连续网格，
那时它就是浮岛——而浮岛与本产品的模态取点互斥（命令进行中每一次点击都是在落一个点，岛会把落在
它身上的那一下吃掉）。**带着网格点的岛，不是压在标尺上，就是压在取点上。**

### 两行的内边距统一为 8，而不是把内容线凑到一起

要对齐的是**墨**：活动标签的灰底与选中工具的蓝底是两块实心矩形、上下相距 30px，它们的左边必须
是同一个数。文字落 17、图标落 13 不必对齐——那是文字块的 9 与图标按钮里 20/30 居中的 5，是两种
控件各自的内衬，眼睛对齐的是填充块的边。

已知未解的一条：蓝底与灰底仍然上下并排。语义分工（导航 / 状态）成立，视觉上确实吵；要动是把
工具的选中态从填充换成描边，**那是一次独立的取舍，不混在这次里做**。

### 模式切换器搬到标签行

它此前挤在会溢出的工具货架尾巴上。搬走之后两行各有一个单一作用域，而且它更靠近文档了。
规范要求的三条（常驻、带文字、不做成图标 toggle）全部保住；它与标签一样**钉在横向滚动区之外**。
控件加它前面那条竖线约 87px，正是上一次把绘图货架挤进「更多」的那 87px。

它改用头部行的画法（灰底圆角、去掉外框盒）。与工作区 pill 同形同为不是撞车——「从 N 个里挑
一个」本来就该长成那样。工具按钮的蓝底不受影响：工具回答「哪个开着」，模式回答「你在编哪一层」。

### Inspector 的分配规则抄引擎，不抄设计工具

第一版拿 Figma / Penpot / Excalidraw 作参照，**参照类选错了**。这个产品是场景树 +
Entity/Component 检查器 + 可停靠面板 + 时间线，那是引擎编辑器的架构。三家引擎的做法：

| 引擎 | 分列规则 | 常量出处 |
| --- | --- | --- |
| Unity | `labelWidth = max(⌈w × 0.45⌉ − 40, 120)` | `EditorGUI.cs`（`kLabelWidthRatio` 0.45 / `kLabelWidthMargin` 40 / `kMinLabelWidth` 120） |
| Godot | 每行一个 `name_split_ratio`，默认 0.5 | `editor_inspector.cpp` |
| Unreal | `DetailsView.column_width` 是 float 比例 | UE Python API |

结论因此换了：**问题不是「400 太宽」，是我们没有分配规则**。Unity 那条公式解出 `w ≈ 356`——
窄于它标签列钉死在 120，宽于它才按比例长，可见它的检查器就是照着 300–400 这一档设计的。

取 `clamp(88px, 38%, 148px)`：0.38 而不是照抄 0.45，因为 Unity 那条是给英文长词的
（"Rotation Constraint X"），我们最长的标签是四个汉字 48px。**上限 148 是我们自己加的一档**——
Unity 与 Godot 没有上限，因为它们的标签涨上去有用，而我们的标签涨过 148 就只是一条空白。
实现上不需要 JS：`grid-template-columns` 里的百分比按 grid 的内联尺寸解析，拖分隔条时写入的
px 值照旧覆盖它。

**288 是量出来的下限**：再收一档到 264 时轨道变成 `100 / 126 / 38`，「1280 × 720 (HD)」这条
最长的下拉被箭头压住——判据是**最长的那一行读不读得完**。因此 264 只做最小宽，不做默认宽。

真正挡路的是 `property-panel/src/styles.css` 的 `min-width: 300px`：不动它，右区拖到 288 只会
让面板溢出到卡片外面被裁掉。

## 风险 / 权衡

- **端到端几何断言会整片红。**画布内容顶边由 97px 变成 103px（顶栏 30 + 沟槽 6 + 卡边框 1 +
  标签行 30 + 工具行 36），左右栏起点各右移 6px。→ 这些用例本来就是钉这些数的，跟着改；
  黄金图重出。
- **样式靠层叠生效，可能静默失效。**本仓库已经有过一次（无层规则压过 `@layer components`）。
  → 卡面、桌面色、工具行底色三处的端到端 MUST 断**计算后的值**而不是只断 class。
- **`theme.gap` 是本仓库第一次用。**它改的是布局算术，收起 / 展开、快照恢复、edge group 折叠
  都要复验。→ 任务里单列一条回归。
- **左列接缝靠伪元素越界绘制。**若将来 Dockview 给 `.dv-groupview` 加了 `overflow: hidden`，
  这块会被裁掉。→ 用例断接缝处的背景色，坏了会红。

## 迁移计划

无数据迁移：所有改动都在样式与两个尺寸常量上。已保存的工作区布局快照仍然可读——快照里存的是
像素尺寸，沟槽由 `theme.gap` 在布局时扣除。回滚是把 `theme.gap` 置 0、桌面色改回
`#101216`、两个宽度常量改回 400 / 300。
