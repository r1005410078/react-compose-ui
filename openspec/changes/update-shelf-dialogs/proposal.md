# 变更：两个货架对话框改为拖拽，并共用一套骨架

## 原因

`add-shelf-customization` 把两个货架做成了数据，也写下了对话框该长什么样：**「两个对话框
同一套骨架（拖动排序 + 重置为默认 + 取消 / 完成）」**（该变更 `design.md` 决策 3），规范增量里
也写着「支持**拖动排序**与跨列移动」。落地时两个对话框都退成了**按钮驱动**的两列列表，理由
记在 `ToolbarShelfDialog` 的 TSDoc 里：可重排列表无论如何要写一遍完整的 WAI-ARIA 键盘重排，
先写按钮那一份。

那个理由**只证明了键盘那一份要先写，没有证明指针那一份不该有**。键盘重排已经在了，缺的正是
它之上的增强。而按钮那一版在三处上是坏的：

1. **打开即四个禁用按钮。**默认选中下标 0 的「选择」，而它固定不可移动、不可移除，于是
   上移 / 下移 / 从货架移除三颗全灰，只剩「插入分隔」。对话框第一眼就是坏的，而这不是配色
   问题——**操作是常驻的，对象是选出来的**，这个次序保证了「没有选中」那一档必然有一排死按钮。
2. **用两列 200px 的竖列表排一条横工具栏。**`ComposeDialogContent` 是 `max-w-md`（448px），
   两列各约 200px。而工具栏会**溢出到「更多」**，顺序的全部意义恰恰在那个切口上——
   `DRAWING_TOOLBAR_SHELF` 把八条绘图命令排在容器 / 文字之前，理由就是「溢出是从尾部收的」。
   竖列表画不出那条切口，用户排完不知道自己排掉了什么。
3. **没有图标。**用户在工具栏上认的是图形，对话框里只给了名字。

同时补上一处**声明与呈现的分家**：「每一格的第二条入口」今天以 `SECOND_ENTRANCE` 的形式
声明在 `toolbar-shelf.test.ts` 里，只有用例读得到。而对话框的说明文案正在向用户承诺
「拿掉一格不会拿掉那项能力」——把那份声明搬进源码并**印在瓦片上**，这句承诺就从一句要信的话
变成一句可核对的话。

设计稿：https://claude.ai/code/artifact/4c84236e-1245-49ce-b102-93105728ab3a

**以 `add-shelf-customization` 落地后的状态为基线。**

## 变更内容

### 新增

- **共用骨架 `ShelfDialogShell`**：标题 + 说明 + 左「编排区」右「来源列」+ 页脚
  （重置退到左端，取消 / 完成在右端）。两个对话框共用它与右列的行渲染；**编排区的内容各自
  提供**——工具栏是一条横排的格，物料面板是一列纵向的段卡。
- **两边互拖**：从来源列拖进编排区即上架，从编排区拖回来源列即移出，编排区内拖动即改顺序。
  落点画成**两格之间的一条插入线**；被抓走的那一件原位留影子；落区高亮回答「这里能放」，
  跟着光标那件东西上的徽标回答「松手会发生什么」。指针走 Pointer Events 与指针捕获，
  **不用 HTML5 拖放**。
- **键盘等价（抓起—移动—放下）**：编排区是 `listbox`，方向键移动焦点，`空格` 抓起 / 放下，
  抓起后方向键移动那一件，`Escape` 放弃，`Delete` 移出，`\` 在其后插入分隔；来源列
  `Enter` / `空格` 上架。状态经 live region 播报。
- **第二条入口印在来源列上**：`SECOND_ENTRANCE` 从 `toolbar-shelf.test.ts` 搬进
  `toolbar-shelf.ts`，成为目录的一个字段；来源列渲染它（单键、命令词，或「命令面板」），
  用例仍然验它真的在。
- **溢出切口**：工具栏编排区在「当前窗口下会被收进『更多』的第一格」之前画一枚标记，其后的
  格降到 42% 不透明。量不到工具栏宽度时**不画**。
- **物料面板标签页右键**：右键组件面板的标签即可「自定义物料面板…」。面板本身可以被折叠、
  可以一个瓦片都没有，而标签始终在。

### 修改

- 「自定义工具栏」与「自定义物料面板」两条需求：两列改为**编排区 + 来源列**，排序方式由
  「拖动排序与跨列移动」细化为上面那套指针与键盘的双通道，并要求两者共用骨架。
- `ComposeDialogContent` 增加一档更宽的尺寸（`size="wide"`，960px）；`max-w-md` 仍是缺省。
- `COMPOSE_TOOLBAR_CATALOG` 由 `[id, messageKey]` 扩成带图标名、分组与第二条入口的记录。

### 不做

- 把选中与键盘那一份换掉：拖动是**增强**，两条通道写同一份草稿。
- HTML5 Drag and Drop：它的落点指示与样式受浏览器摆布，且在 Playwright 里天生易碎；
  指针捕获这条路本仓库在画布上已经走熟了。
- 触摸拖动的长按启动：桌面编辑器，先不做；键盘那一份对触屏无解，这一点写在明处。
- 让来源列变成一棵资源树：物料那边仍然只列 `catalog.folders` 里的路径（`add-shelf-customization`
  已定的取舍）。

## 已定的取舍

| 事项 | 取值 | 理由 |
| --- | --- | --- |
| 拖动的启动判据 | 指针离开过按下点 | 与画布上夹点「点亮 vs 拖动」同一条判据，不引第二个阈值魔法数 |
| 落点呈现 | 两格之间的插入线 | 高亮被压住的那一格说的是「替换它」，而这里从不替换 |
| 原位影子 | 留 | 「松手落回原处」因此是可预期的，也说清了抓的是哪一个 |
| 徽标与落区高亮 | 分两处答 | 一个回答「能不能放」，一个回答「放下会怎样」，同一处答会有一个说不清 |
| 对话框宽度 | 960 | 一条 16 格的货架横排要这么宽；`max-w-md` 仍是别处的缺省 |
| 第二条入口 | 搬进源码并渲染 | 声明只被用例读到时会与 UI 的承诺分家；渲染它等于让用例守住 UI |
| 溢出切口 | 量不到就不画 | 与画布上「无从得知指针位置时先不画十字线」同一条 |
| 物料入口 | 面板标签右键 | 瓦片右键要求面板里至少有一个瓦片，而空面板正是最需要配置的那一档 |

## 影响

- 规范：`editor-workspace-layout`（MODIFIED 2 条、ADDED 1 条）、`components`（MODIFIED 1 条）。
- 代码：`packages/editor`（新增 `workspace-layout/shelf-dialog/`，重写两个对话框，目录扩字段，
  标签右键），`packages/component-library`（补一个按下标重排的纯函数），
  `packages/components`（Dialog 宽度档）。
- 端到端：拖动重排、跨列拖动、键盘抓放、标签右键。
