## 决策

### 决策 1：编排区画的是它将来的样子

两个对话框共用骨架，但**编排区的方向不同**：工具栏是一条横栏，因此货架横排；物料面板是纵的，
因此那边排的是一列段卡。骨架不变，方向由被编排的东西决定。

这不是审美偏好，它是两处东西成立的前提：

- **溢出切口**只在横排里画得出来。竖列表里没有「这一行放不下了」这件事，而那正是
  `DRAWING_TOOLBAR_SHELF` 把八条绘图命令排在容器 / 文字之前的全部理由。
- **段的选项**（文件夹的分组方式、基础组件列哪几个）只在纵排里长得下。工具栏的一格只有
  「在不在、排第几」，物料的一段还带开关。

因此「共用骨架」的可执行形式是：同一个对话框壳、同一条页脚、**同一列来源**、同一套拖拽语义与
同一份拖拽状态机；而不是「两个编排区逐像素相同」。

### 决策 2：拖动与键盘写同一份草稿，指针只负责算一个下标

草稿是一列 id（工具栏）或一列段（物料）加**一个插入下标**。指针那条路把落点换算成下标，
键盘那条路把方向键换算成下标，之后共用同一组既有纯函数写草稿。

换算是一个纯函数 `resolveShelfDropIndex(rects, point, orientation)`，两种朝向两支：

- `wrap`（横排换行）：**第一个满足「点在它这一行或更上，且点在它中线左侧」的下标**，都不满足
  即末尾。按阅读顺序比较，因此换行的一行行读下来是对的。
- `vertical`（纵排）：第一个中线在点下方的下标。

写成一个带朝向参数的函数而不是两个函数：两支的**契约**逐字相同（给一组矩形和一个点，回答插到
第几个之前），差的只是「哪条中线」；拆成两个的话，下一个改插入语义的人只会改到其中一处。

**拖动的启动判据是「指针离开过按下点」**，不是一个位移阈值。这条判据本仓库已经用过一次——
画布上的夹点按下不动是「点亮」、动过是「拖动」，理由也逐字相同：位移阈值是本仓库别处都不需要
的魔法数，而 `pointerup` 之前浏览器会补发一次原地 `pointermove`，因此「收没收到 move」不能当
判据。

### 决策 3：落点是两格之间的一条线，不是被压住的那一格

高亮被指针压住的那一格，说的是「松手会替换它」。而这两个货架里从来不发生替换——落点永远是
一个**位置**。因此画一条 2px 的插入线，它同时也是分隔线插进去的地方。

配套的两件：

- **原位留影子**（虚边、34% 不透明）。它让「拖到没有落点的地方松手会落回原处」是可预期的，
  也让用户在一屏十几格里看得出自己抓的是哪一个。
- **落区高亮与光标徽标分两处答**。高亮回答「这里能放」（编排区或来源列整体亮起），徽标回答
  「松手会发生什么」（`+` 加进来 / `×` 移出去）。合成一处的话，「拖到来源列上」那一档要么
  说不出是移出、要么高亮得像是要加进来。

### 决策 4：键盘那一份是「抓起—移动—放下」，不是「方向键直接移动」

方向键直接移动会占掉方向键**移动焦点**的含义，而 listbox 的焦点导航是这个 Pattern 的一半。
因此：方向键移动焦点，`空格` 抓起，抓起之后方向键移动那一件，再按 `空格` 放下，`Escape`
放弃并回原位。这与拖动是同一件事的两个通道——抓起对应按下，移动对应 `pointermove`，放下对应
`pointerup`——因此两条路读写的是同一份草稿与同一个插入下标。

`Delete` 移出、`\` 在其后插入分隔，两条都只在编排区里生效。来源列的 `Enter` / `空格` 上架。
每一步经 live region 播报（「已抓起 圆，第 6 格，共 11 格」），否则抓起之后屏幕阅读器用户
听不到任何东西在动。

### 决策 5：第二条入口从用例搬进源码

`SECOND_ENTRANCE` 今天声明在 `toolbar-shelf.test.ts` 里。规则本身（「货架不得成为任何能力的
唯一入口」）没变，变的是**谁读它**：搬进 `toolbar-shelf.ts` 之后，来源列把它印在每一条上，
而用例仍然验它真的在动作目录里。

好处是这份声明与 UI 的承诺**不会分家**。对话框的说明文案写着「拿掉一格不会拿掉那项能力」，
在此之前那是一句只能信的话；印出来之后，用户当场看得见「圆 · C」「多边形 · POLYGON」
「变换指示器 · 命令面板」。加进新一格的人也因此被迫回答那个问题——不回答，来源列上就是一条
没有下文的空白。

**没有键位也没有命令词的那一档印「命令面板」**，因为动作目录里的每一条都在那里搜得到；
这一档是真话，不是兜底文案。

### 决策 6：溢出切口量不到就不画

切口的位置来自工具栏此刻的实测宽度（`useToolbarOverflow` 已经在算了，它就是「更多」按钮出现
的依据）。对话框打开时工具栏就在屏幕上，因此这个数通常拿得到；拿不到时（工具栏被宿主替换、
或这一帧还没量完）**不画**，而不是猜一个。

这与画布上「无从得知指针位置时先不画十字线」是同一条：先不画严格好过画在错误的地方再跳过去，
而一条画错位置的切口会让用户按它排序，排出来的结果与他看到的不一致。

### 决策 7：物料面板的入口是标签右键

`add-shelf-customization` 给的两个入口是工作区管理菜单与**瓦片右键**。瓦片右键有一个洞：
它要求面板里至少有一个瓦片，而**一个瓦片都没有的面板正是最需要配置的那一档**（去掉了基础
组件、或者引用的文件夹没了）。标签始终在，因此把「自定义物料面板…」挂在标签的右键上。

不换掉瓦片右键：那上面的「从面板隐藏」「只看这一组」是**瓦片作用域**的，标签上给不出。
两处菜单各自回答自己作用域里的问题。

工具栏那边不需要对称的一条——它没有标签，而按钮右键没有这个洞：工具栏至少有「选择」。
