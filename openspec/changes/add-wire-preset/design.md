# 设计：一次接线图里，导线是什么颜色

## 领域取错了会得到相反的答案

第一稿调研的是 PCB 原理图工具，那里导线一律有自己的带色相的颜色（KiCad 绿、LTspice 与 Altium
深蓝）。**照抄到一次接线图上是错的，而且错得刚好相反**：绿在那里表示**分闸 / 停电**，也就是说
第一稿会把每一条新画的导线默认成「这条线没电」。

差别的根源是颜色在两张图上的地位不同：PCB 原理图上颜色是**空闲**的语义通道，那张图上没有别的
东西在用它；一次接线图上颜色**已经有含义**——红 = 合闸/带电、绿 = 分闸/停电，母线与线路另按
电压等级着色。

## 为什么答案是红而不是「保持中性」

中间还错过一次：从「颜色有含义」推出「所以默认别带色相」。这一步跨得太远——一次图上的导线并
不是没有默认色，恰恰相反，**储能、光伏这类图画的是正常运行的系统，整条一次回路是带电的，因此
实机上通篇是红**。默认取红不是给它硬安一个状态，而是取了最常见的那一档：实施工程师画完之后，
九成情况下它本来就该是红的。

「一条还没绑状态的线看起来在报告状态」这个顾虑仍然存在，但它的代价远小于反过来——默认中性时，
用户画完每一条线都要手动改色，而那是这个产品要替他省掉的工作。

颜色仍然留给数据绑定：`stroke` 是可绑定的 Renderer prop，项目要做拓扑着色时绑它即可。

## 为什么是 `#ff3b30` 而不是纯红

两者都是红，行业惯例上写的是纯红 `#ff0000`。选前者的唯一理由是**两个底都要读得出来**——场景
背景默认透明，导线与场景背景一样是会被发布出去的真实像素：

| 底色 | 对比度 |
| --- | --- |
| 编辑画布 `#11151b` | ≈ 5.1:1 |
| 白底页面 `#ffffff` | ≈ 3.6:1 |

纯红在深色画布上还会视觉上「振」。真需要逐字照抄行业值时，改这一个常量即可。

## 线宽仍然要改

电气制图区分主回路本来就是靠线宽——一次回路粗实线，二次回路与标注细实线。这与
`DEFAULT_CURVE_PROPS` 上那条既有注释不冲突：

> 曾经写的 2 在图面上明显偏粗：接线图靠**线的走向**而不是线的分量传达信息，加粗只会让密集区
> 糊成一片。

那个观察的前提是**所有线一起加粗**。只有主回路粗、标注与辅助几何细，恰恰是那条观察想要的
结果——分量差别本身成了信息，而不是均匀地把整张图加重一档。

## 连带：失效端点的记号不能再用红

导线的墨色变红之后，图面上「绑定失效」那个记号原本借的 `danger` 红就画不出来了——红记号压在
红线上等于没画。改用琥珀（告警色族里红之后的那一个）。它与捕捉标记的橙相近，但两者**形状
不同**（端点是圆、捕捉是方框），而这块画布上的规则本来就是「形状先分开，颜色再分开」。

## 为什么是新 Preset 而不是在落地处改 props

这条判断已经写在代码里，`ARROW` 就是这么做的：

> 走**另一个 Preset** 而不是在这里改 Renderer props：箭头的默认描边住在物料包里
> （`DEFAULT_ARROW_PROPS`），Stage 认识 Preset id 就够了，不必也认识 prop 名。

导线照抄这一条。反过来做的话，`stage` 就要认识 `stroke` 这个 prop 名与那个色值，而颜色是物料
的事——将来换主题、换默认色要改两个包。

## 不做什么

- **不动 `DEFAULT_CURVE_PROPS`**。普通几何的默认色（近白 `#d8e2f1`）该不该换是**另一个问题**
  （它受「近白 vs 透明场景背景」那条影响），记在 SDD §6 待确认里，不搭这趟车。
- **不内置电压等级色表**。色表因项目而异，内置一份等于替客户做了一个他多半要改的决定。
- **不按绑定状态改色**（绑上一个色、悬空另一个色）。那属于选中时的反馈，常驻改变文档的墨色会
  和运行状态色抢同一个通道。
