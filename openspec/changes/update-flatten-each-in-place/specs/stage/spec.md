## MODIFIED Requirements

### Requirement: 布尔运算的落地规划

`stage` MUST 把布尔运算的解算结果规划成命令。规划住在宿主而不是引擎，理由与填充同一条——
新建那一支要一个 Preset 与一个新的 Entity id，而引擎不建 Entity、不认识 Preset id。

**分支由运算是哪一条决定，而不是由操作数有几个决定**：

- **拍平**：不论几个操作数，MUST **逐个原地**改它们的几何（每个一条 `entity.curve.set`），
  MUST NOT 新建、MUST NOT 删除、MUST NOT 合并成一个对象。判据是**拍平改的是表示不是呈现**：
  顶点换成控制手柄，而名字、颜色、位置、层序、动画轨道与导线绑定一个字节不动，同一份图在
  拍平前后逐像素相同。合并会在两处违背它，且都是用户没有要求过的——一个对象只有一个填充，
  因此其余操作数的颜色被挤掉；若干条轮廓摞进一条 `path` 之后按 `nonzero` 填充，原本透明的
  相交区被填实。要把若干形状合成一个对象，那是 `UNION`。
- **区域运算（并集、差集、交集、异或）**：合并成一个新的带 `Curve` 的普通 Entity，全部操作数
  在**同一个事务**里删掉。这时它确实不再是原来任何一个。

**操作数是一块填充（带 `Hatch`）时，原地那一支 MUST 在同一个事务里删掉 `Hatch`**，几何与填充色
一个字节不动——与 Inspector 的「断开关联」同一件事。填充的几何是派生的：布局求解每一趟按边界
清单重求，几何与重求结果不同、清单又一致，就把多段线写回去；只写 path 不删 `Hatch`，拍平在
屏幕上什么都没发生。「顶点换成控制手柄、由作者接管形状」与「跟着边界走」不可能同时成立。

**拍平多个操作数时，全部改动 MUST 进同一个事务**：撤销一步回到拍平之前，而不是回到「拍平了
一半」。这与区域运算「新建与删除进同一个事务」是同一条。

区域运算的新 Entity MUST 走**通用曲线 Preset**，MUST NOT 走矩形 Preset：圆角手柄的显形判据读
`Composition.presetId`，而两个矩形求并集之后得到的不再是一个矩形——给它发四个圆角手柄是在说
一件用户不打算做的事。

区域运算的新 Entity 的 `Appearance`、`Renderer` props 与名称 MUST 取**层序最靠后**那个操作数的，
并 MUST 用 `entity.create` 载荷上的 `index` 插在它原来的位置；层序 MUST NOT 用第二条命令表达，
这样层序与创建在同一个事务里。

规划 MUST 再判一次操作数是否合格。这不是与会话那次重复：会话那次是为了给用户一句话，
规划这次是为了不写出非法文档，两者的失败后果不同。

**区域运算的事务提交之后，选区 MUST 挪到产物上。**它**消费**用户自己建立的那份选区：操作数被
删掉之后不挪，选区就被静默清空，用户读到的是「我按了一下，东西没了」。判据与编组逐字相同
（编组同样是「消费选区、产出一个对象」，它也把选区挪到新建的那个 Group 上），因此这不是给
布尔运算开的一条新规则。这与「画完一条线不自动选中」不冲突：那一档用户本来就没有选区。

挪之前 MUST 先看事务提没提交——被拒绝的命令不改变文档，此时挪到一个根本没建出来的 id 上，
画布上会一个东西都不选中。

**拍平 MUST NOT 挪选区**：它不删任何东西，操作数就是结果，选区本来就是对的。上面那条规则
存在的理由（操作数被删掉之后选区被静默清空）在这里不成立。

#### Scenario: 拍平一个形状不换 Entity

- **WHEN** 选中一个矩形执行拍平
- **THEN** 文档里的 Entity 集合一个都没增减，那个 Entity 的几何变成 `path`，名称与外观不变

#### Scenario: 拍平多个对象各自留在原地

- **WHEN** 选中两块颜色不同的填充与两个空心圆执行拍平
- **THEN** 文档里仍是四个 Entity，四条几何各自变成 `path`，两块填充各自留着自己的颜色，
  两个空心圆仍然空心

#### Scenario: 拍平多个对象撤销一步全回去

- **WHEN** 对四个对象执行拍平后按一次撤销
- **THEN** 四条几何一起回到拍平之前，MUST NOT 只回去一部分

#### Scenario: 拍平之后选区不变

- **WHEN** 选中两个形状执行拍平
- **THEN** 选区仍然是那两个形状

#### Scenario: 并集产出一个曲线 Entity

- **WHEN** 对两个重叠矩形求并集
- **THEN** 文档里多出一个带 `Curve` 的 Entity、少掉那两个矩形，且新 Entity 的填充与描边
  与原来画在下面的那个矩形一致

#### Scenario: 结果不带圆角手柄

- **WHEN** 对两个带 `cornerRadius` 的矩形求并集后选中结果
- **THEN** 画布上不出现圆角手柄

#### Scenario: 区域运算之后选中的是结果

- **WHEN** 选中两个矩形求并集
- **THEN** 选区恰好是新产出的那个 Entity，MUST NOT 为空

#### Scenario: 撤销一步全回去

- **WHEN** 执行一次区域运算后按撤销
- **THEN** 结果 Entity 消失，两个操作数连同它们原来的层序一起回来

#### Scenario: 拍平一块填充即断开关联

- **WHEN** 用户选中一块跟随着边界的填充并执行 `FLATTEN`
- **THEN** 它的几何变成 `path` 并在此后的每一趟布局求解里保持不变，`Hatch` 被删掉，填充色留着；撤销一步几何与关联一起回来
