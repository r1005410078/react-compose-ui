## ADDED Requirements

### Requirement: 画布右键「添加组件」

Stage 的画布右键菜单 MUST 提供「添加组件」一项，它是菜单里**唯一产出新内容**的一项，因此
MUST 排在最上面并与其余项之间留一条分隔——其余每一项都是对已有对象的操作。

**二级菜单就是物料面板那棵树，一层展开**：基础组件、项目组件、每个文件夹各是一个分组标题，
条目直接排在标题下面。文件夹 MUST NOT 展开成三级菜单——面板里它本来就是平级的一段，菜单里多套
一层会让同一棵树在两处长得不一样，鼠标还要多走一次悬停。条目多时菜单自身滚动。菜单里
MUST NOT 再放一个搜索框：面板的搜索更快，两处各一个只会分叉。

**菜单内容 MUST 由宿主注入**（`ComposeStageProps`：分组 + 条目，各带 id、名字与图标；选中时
Stage 回调 id 与世界落点）。`stage` MUST NOT 依赖 `@compose-ui/component-library`——它不认识
组件目录协议。注入的 MUST 是「能列出什么」，菜单的呈现与落点解算仍住 Stage，与既有的命令注入
是同一种形状，MUST NOT 引入第二种机制。未注入时 MUST NOT 渲染该项。

**落点 MUST 是右键那一下的世界坐标**，创建 MUST 复用既有的「根层落点按类型分流」：容器类升格
为一块新场景，其余落进激活场景并保留世界落点。MUST NOT 为菜单另写一套落点规则。

宿主 MUST 用喂给物料面板的**同一份**货架模型生成这棵树，MUST NOT 另建一份——各建一份的症状是
「面板里有、菜单里敲不出来」，而用户读不出为什么。

**呈现 MUST 与设计稿一致**：二级菜单的宽度 MUST 由内容决定（共享菜单的 176px 下限照旧），
MUST NOT 钉一个固定宽度——设计稿里那块更宽的菜单是照示例数据里的长英文名画的，真实内容是
中文短名时右边会空掉一大块，而项目组件的名字由用户自己起，长度本来就不受我们控制；
行首图标 16px 且**比文字暗一档**，只有高亮那一行提亮——这一列图标是认读辅助，与
名字同样亮会让整块菜单读成两列并重的表格。空的组 MUST NOT 渲染成一个只有标题的分组。

命令正在请求一个点时右键仍 MUST 推进 `accept` 而不是打开菜单，本条不改变那条既有规则。

#### Scenario: 从画布添加一个符号

- **WHEN** 用户在画布空白处右键并选择「添加组件 ▸ 符号库 ▸ 断路器」
- **THEN** 该组件实例创建在右键那一点的世界坐标上
- **AND** 落点与从物料面板拖入同一个符号得到的规则一致

#### Scenario: 文件夹不是三级菜单

- **WHEN** 二级菜单里有一个文件夹来源的段
- **THEN** 它渲染为一个分组标题，条目直接排在下面，没有可展开的三级

#### Scenario: 菜单树与面板同源

- **WHEN** 宿主的货架里藏掉一个基础 Preset
- **THEN** 该物料同时从面板与「添加组件」菜单里消失

#### Scenario: 空的组不出现

- **WHEN** 货架里有一个文件夹段，但那个文件夹下当前没有组件
- **THEN** 菜单里不出现该组的标题，其余组照旧

#### Scenario: 宿主不注入时没有这一项

- **WHEN** 宿主不提供菜单树
- **THEN** 画布右键菜单不出现「添加组件」，其余项不变
