# 文字图元

## Why

三类目标场景都以「谁是谁、谁连着谁」为主要信息，而现在图上**一个字也写不出来**：

- 网络拓扑：交换机得有名字，端口得有编号
- 一次接线：断路器要标 `QF1`，变压器要标 `T1`
- PCB 原理图：元件位号与阻值就是图的一半内容

其余缺的图元都只是**麻烦**而不是做不到——矩形可以用四条线或一个块凑，折线可以连着画。文字
凑不出来：没有任何既有图元能表达一串字符。一张没有标注的接线图交不出去。

## What Changes

### `CadText` 图元

`position` / `content` / `height` / `rotation` / `align`。`position` 是**基线上的对齐锚点**，
与 DXF 的 TEXT 同构。

`height` 是**字号（em 尺寸）**而不是 AutoCAD 的大写字高。大写字高与字号的比例随字体而变，
写进协议就等于把一个字体相关的猜测同时钉进渲染与命中两处，然后看它们各自漂移。DXF 导入时
做一次显式换算，比在两个地方各埋一个比例便宜。

### 遍历返回的是「几何」，不再只是「曲线」

上一刀把遍历从线段泛化成 `CadCurve`（线段 | 圆弧）。文字既不是线段也不是圆弧，因此：

```
CadCurve    = CadSegmentCurve | CadArcCurve      曲线仍然是曲线
CadGeometry = CadCurve | CadTextGeometry         遍历返回这个
```

不把 `CadCurve` 直接塞进文字：曲线共享一整套弧/段数学，它是个**真实的类别**，不是「凡是画得
出来的东西」的别名。加一层伞比把一个已经准确的名字弄脏便宜。

### 文字**就是**一个盒子，因此按盒子命中

CAD 的命中判据是「点到几何的距离而不是包围盒」——理由是一条对角线的包围盒里绝大部分是空的。
**这条理由对文字不成立**：文字占满自己的盒子，那个盒子就是用户看见的东西。AutoCAD 同样是
点在文字框内即选中。

因此文字的「距离」定义为：框内为 0，框外取到框边的距离。命中、框选与最近者胜出的仲裁全部
沿用既有代码，一行不改。

### 命中框与字形必须对齐，靠字体固定

字宽需要字体度量，而 `cad` 包无 DOM。做法是：**图面用等宽字体渲染**，包里用一个文档化的
`前进宽度 / 字号` 比例算命中框。等宽字体让这个近似接近精确，也符合 CAD 的惯例——AutoCAD 的
默认 `txt.shx` 本来就是等宽的。

这条耦合是**不变量而不是巧合**：换字体就必须同时换比例，否则命中框会从字形上漂开。

### 插入点捕捉

新增 `insertion` 捕捉模式，覆盖文字的对齐锚点**与块实例的插入点**——两者是同一件事，AutoCAD
的 `INS` 也同时管这两个。把标注对齐到符号的插入点是接线图里的日常动作。

### `TEXT` / `T` 命令

指定插入点 → 指定字高（回车接受默认值，也可以键入数字或指点取距离）→ 键入内容。三步与
AutoCAD 一致。字高的默认值在**一次命令会话内**记住。

## Impact

- `@compose-ui/cad`：文字几何与命中、`CadGeometry` 伞类型、协议与校验、遍历、捕捉、平移、
  块展开、`TEXT` 命令。
- `@compose-ui/cad-canvas`：`<text>` 渲染与等宽字体、插入点捕捉标记。
- 协议：`schemaVersion` **不变**。既有 `.cad.json` 不含 `CadText`，一律仍然合法。

## 本步刻意不做

- **多行文字（MTEXT）**：换行、段落宽度与自动折行是另一套模型，而位号与标签是单行。
- **原地编辑**：双击改字要在图面上开一个输入框，牵扯焦点、IME 与命令行的输入争夺。本步先让
  文字画得出来、选得中、移得动。
- **字高与旋转的后期修改**：没有属性面板，改法只能是删了重画。这是限制，不是缺陷——把属性
  编辑塞进这一刀会让纵向流程走不完。
- **文字参与对象捕捉的字形特征**（例如按字符定位）：没有消费者。
