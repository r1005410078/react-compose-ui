# 打磨几何编辑

## Why

两处同源的问题，都在「进了顶点模式，图面上该有什么」这一条上。

### 一、直线缺一个表达「整条线搬走」的夹点

一条直线只有两个端点夹点——它们**改长度和方向**，没有一个夹点表达「整条线搬走」。
AutoCAD 的直线是三个夹点（两端点 + 中点），中点拖动就是移动整条线；这个设计值得参考。

但「AutoCAD 有」不是理由，理由是它给了一件**今天做不到的事**：**按中点二维捕捉着移动**。

拖线身走的是**对齐吸附**——`snapCandidates` 出的是其他 Entity 盒的六条 `{ axis, value }` 参考
线，两个轴各自独立地吸。拖夹点走的是**特征点捕捉**——`findStageFeaturePoint` 返回一个二维点，
带 `port > endpoint > midpoint > center > quadrant` 优先级和捕捉标记。仓库自己写过这两条是
**姐妹查询，不是一个**。

因此「把这条导线的中点钉到那条线的端点上」今天只能靠两次一维吸附**碰巧**同时命中（直线的盒
中心恰好等于几何中点），没有标记、没有优先级，也吸不到端点以外的语义点。中点夹点让它成为一个
可以**刻意做出来**的动作。

### 二、选区包围盒在顶点模式下是干扰

一条对角线的包围盒占满一大片空白，比线本身显眼；它还带 10% 蓝色填充。三条理由任何一条单独
成立：

1. **盒不是曲线的轮廓。**这正是命中判据不按包围盒的那条理由——「一条对角线的包围盒里绝大
   部分是空的」——的视觉版本。
2. **拖夹点时它是过期的。**选区盒由手势的**预览变换**推出，而夹点拖动不产生预览变换（它走
   本地几何预览），因此整个拖动过程中盒停在拖动**之前**的位置。它不只是多余，它在说谎。
3. **它要表达的信息已经有人表达了。**可编辑路径覆盖层沿**真实几何**画轮廓，夹点也落在对象
   上——「选中的是谁」比一个矩形说得更准。

文字编辑态**已经**去掉了填充，CSS 注释写的理由是「填充会盖住正在编辑的文字，也容易和普通
选中态混淆」。这是同一条判断的第二次应用，只是结论更进一步。

## What Changes

- **`line` 的夹点由 2 个变成 3 个**：两个端点 + 一个中点。中点夹点平移整条线——两端同时走同一
  位移，长度与方向不变。
- **落点走与其余夹点相同的那条管线**，因此被捕捉的是**中点本身**：它落在另一条曲线的端点或
  中点上，而不是光标的裸坐标。这正是它相对拖线身的独有能力。
- **夹点 id 用 `move` 而不是 `mid`**：`mid` 在弧上已经是「改半径」，同一个字符串在两种 kind 上
  含义相反会让读代码的人绊一下。id 本来就是 per-kind 解释的，但自解释不花钱。
- **几何编辑会话期间不画选区包围盒**，与 Resize / 旋转手柄的抑制同一处判断、同一行条件。
  退出会话时一并恢复。

## Non-Goals

- **不给多段线段中点夹点。**AutoCAD 那里是**插入顶点**，而「顶点增删」在路线图的未定决策里
  已经立着（「要做，缺的是一种新手柄」）。段中点是它的天然位置，用来表示平移会把那条路堵死。
  多段线这一刀里没有平移夹点，这是**声明过的例外**，不是漏做。
- **不动弧。**弧保持 `center` 平移、`mid` 改半径。AutoCAD 的弧**没有**圆心夹点，我们有——那是
  有意的偏离：弧同样需要一个平移夹点，而圆心是它唯一既有几何含义、又没被占用的点。
- **不做多功能夹点**（悬停后 Ctrl 切换「拉伸 / 加长」那套菜单）。眼下每个夹点只有一个自由度，
  没有第二个含义要选。
- **不改拖线身的行为。**它仍然是移动，仍然走对齐吸附。两者是**同一个动作的两种精度**，不是
  两个入口——这与「拖着画」和「敲命令名」是同一条判断。
- **不改文字编辑态的选区呈现。**它只去掉填充、保留边框，因为文字盒**就是**那个对象的轮廓。
  两者是同一条判断在不同形状上的两个结论，不是不一致。
- **不修「拖夹点时选区盒过期」本身。**盒在会话期间不画，这条缺陷就没有可观察的表现了；真要
  让它跟着预览走，得让路径手势也产出预览变换，那是一次与本刀无关的改动。

## Impact

- 包：`stage-engine`（夹点派生与求解）、`stage`（选区层多一个条件）
- Specs：`stage-engine`（MODIFY 1）、`stage`（MODIFY 1）
- 破坏性：无。夹点集合是派生值，不进文档；既有文档一行不动
