## 上下文

十字光标由 `canvas-kit` 画、由 Stage 决定形态、由编辑器决定长度。样式是第四个维度：它既不
认识命令（不属于 Stage 的形态推导），也不随工作区变（不属于会话开关）——它回答「我想让光标
长什么样」，与主题、语言同一档。

## 目标/非目标

- 目标：两种样式可选、默认渐隐；设置对话框里可改；跨工作区、跨文档生效；随偏好持久化。
- 非目标：臂长的用户入口；第三种样式；按工作区各记一份样式。

## 决策

- **样式住在偏好而不是工作区会话。**会话开关的理由是「用户在某个工作区里改过之后切回来还
  在」，而样式没有按工作区分歧的场景——晕圈在页面与绘图里都是晕圈。做成会话开关会让偏好里
  每个 custom 工作区多抄一个字段，而那正是「逐字段重建、漏一条就退回默认」的温床。
- **渐隐用 `userSpaceOnUse` 的线性渐变，每条线一份。**四条线的起终点各不相同，一份渐变
  按 `objectBoundingBox` 在水平线上退化（高度为零的包围盒让渐变方向无定义），因此必须按
  用户空间给绝对坐标。渐变 id 用 `useId` 生成：同一页面可以有多个画布，写死 id 会串。
  渐变的 `stop-color` 走 CSS（`stop-color: var(--compose-canvas-crosshair, …)`）而不是
  属性——样式表规则压过呈现属性，写在属性上会被既有的 `stroke` 规则覆盖成纯色。
- **晕圈是第二组线，画在主线之下，不带 `data-*-crosshair-line` 标记。**既有用例与端到端都
  数「四条线」，晕圈线若共用标记会把四条数成八条；标记回答的是「十字线在哪」，晕圈不是
  十字线。晕圈色走 `--compose-canvas-crosshair-halo`，回落到 `--compose-workspace-bg`；
  Stage 的浅色主题图面底是 `--compose-surface-control`，因此 Stage 在浅色块里把它指过去。
- **设置对话框另起「画布」导航项。**外观管的是 chrome 主题，光标画在图面上，不属于它；
  塞进外观会让「外观」这个词同时指两块屏幕区域。单选卡沿用主题那一行的样式，改动即生效，
  与对话框里其他项一致。
- **偏好 → controller → Stage。**controller 由宿主创建、编辑器只拿到引用，偏好住在编辑器，
  因此同步方向与变换指示器一致：编辑器用 effect 调 `controller.setCrosshairStyle`，缺 setter
  的测试替身照常跳过。

## 风险/权衡

- 默认从均匀实线换成渐隐，所有用户的取点十字线外观都变 → 这是用户明确选定的默认；两端
  不透明度钉死在渐变里（中心 1、远端 0.15），远端不会淡到看不见。
- 渐变让每条线多一份 `<defs>` → 每帧最多四份，可忽略。
