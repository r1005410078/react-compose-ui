## MODIFIED Requirements

### Requirement: 应用顶栏

编辑器顶部 MUST 有一条高 30px、横贯全宽、位于 Dockview **之外**的应用顶栏。它 MUST 恰好是
四段：**标志 ▾**、**文档标签条**、**工作区切换器**、**三个布局开关**。标志与标签条 MUST 钉在
左端，工作区切换器与布局开关 MUST 钉在右端，中间是弹性空间。

**标志 MUST 同时是回页面库的门**：页面库成为应用入口之后，「回页面库」与「切到另一份打开的图」
是同类动作（去哪儿），它们 MUST 在同一排——分两行会让两个同类动作住在两个地方。

那一档标志与 `▾` MUST 是**两颗按钮**：去处不同的两件事不共用一个按下区，把两件事挂在同一颗上
用户读不出按下去会发生哪一件。标志 MUST 带 tooltip 与可访问名称「返回页面库」——一个 19px 的
图形说不出自己去哪。没有接页面库端口时它们 MUST 仍是一颗：那时标志只有「打开菜单」一个含义，
拆开会多出一颗按下去什么都不发生的按钮。

**应用菜单里 MUST 同时留一条「返回页面库」**，沿用既有那条「不得成为任何能力的唯一入口」：
标志是这条路的快捷入口，MUST NOT 是它唯一的入口——认不认得出那个图形取决于用户见没见过，而
菜单里那条带文字。两条 MUST 走同一条实现。

呈现页面库时 MUST NOT 渲染工作区切换器（那一屏没有画布，因而没有工作区），标签条与布局开关
照常。

段与段之间 MUST 只有间距，MUST NOT 画竖线：位置本身已经分好段，而竖线是把「我数得清有几段」
画出来，那件事本来不需要用户去数。

顶栏仍 MUST NOT 承载保存按钮或「设计 / 动画」模式切换器——它们是**文档**作用域，分别由
`document.save` 动作与画布列头承担。顶栏上的任何操作 MUST NOT 产生事务或撤销条目。

#### Scenario: 顶栏恰好四段

- **WHEN** 编辑器挂载且有文档打开
- **THEN** 顶栏从左到右是标志加 `▾`、文档标签条、工作区切换器、三个布局开关
- **AND** 顶栏上没有保存按钮、没有模式切换器

#### Scenario: 标志不是回库的唯一入口

- **WHEN** 用户打开应用菜单
- **THEN** 菜单第一条是「返回页面库」，其下是设置与命令面板
- **AND** 执行它与点击标志到达同一个地方

#### Scenario: 页面库状态下没有工作区切换器

- **WHEN** 用户点击标志回到页面库
- **THEN** 顶栏仍有标志与文档标签条
- **AND** 工作区切换器不再渲染

#### Scenario: 段之间没有竖线

- **WHEN** 用户查看应用顶栏
- **THEN** 段之间只有间距，没有任何竖向分隔线

#### Scenario: 顶栏不进历史

- **WHEN** 用户在顶栏切换文档标签、切换工作区并连续切换布局开关
- **THEN** 事务日志没有新行，撤销栈长度不变

### Requirement: 文档标签条

文档（页面文档、组件文档、资源文件文档）MUST 是编辑器会话而 MUST NOT 是 Dockview panel。

文档标签条 MUST 住在**应用顶栏**里，紧接标志之右。它 MUST NOT 住在画布列头：页面库那一屏
**没有画布列**，标签住在那里意味着一进页面库标签就消失——而标签正是「我手上开着哪几张图」，
去库里找下一张时最需要它。

标签条 MUST 在标签数超出可用宽度时横向滚动，MUST NOT 把工作区切换器或布局开关挤出顶栏。

标签 MUST 是圆角标签，并 MUST 遵循「chrome 的选中画法」：活动的一格是一块柔和的圆角底加
`text-strong`，静息只有文字。标签 MUST NOT 贴满整格、MUST NOT 用竖线相互分隔、MUST NOT 用下划线
或 accent 条表示活动。标签 MUST 显示文档类型图标、名称、未保存圆点与关闭按钮；关闭按钮 MUST 只在
hover / focus 时显出自己的底。

标签条 MUST 实现 `tablist` 可访问语义：方向键在文档间移动并激活，`Home` / `End` 到两端，
`Delete` MUST NOT 关闭。标签条上 MUST NOT 有保存按钮、布局开关、工作区切换器或设置入口。

**画布列头 MUST 保留**，并回答「正在编哪一份、哪一层」：一条**文档面包屑**。标签回答「我开着
哪几份」（应用作用域），面包屑回答「我正在编哪一份、哪一层」（画布那一列），两个问题分两处答。
它 MUST NOT 再承载文档标签。

画布列头 MUST NOT 承载「设计 / 动画」模式切换器：那颗切换器已随「动画编辑开关」删除——它把
布局（加时间线、展开底部）与语义（采样、自动记录、锁父级）捆在一颗按钮上，拆开之后布局那一半
归工作区、语义那一半归时间线 chrome 上的开关。在这一行把它装回来就是把那次拆分原样撤销。

进了组件层时面包屑 MUST 有多段，且除末段之外 MUST 可点——点一段即回到那一层，并 MUST 走场景树
根行返回的**同一条实现**：多一个入口允许，两份实现必然漂移。一个前几段点下去什么都不发生的
面包屑是在撒谎。

文档 MUST 由 `provider.id + assetKey（缺失时 entry.id）` 唯一标识，重复打开 MUST 激活现有标签
而非创建副本；资源文件文档 MUST 保留未保存 Monaco 草稿。关闭 dirty 文档或改动已打开资源的条目时，
系统 MUST 提供保存、放弃或取消决策，并只在保存成功或放弃后关闭；取消、保存失败或 revision
conflict 不执行关闭或对应 Provider 操作。中央画布组 MUST 只承载画布，画布 MUST 跟随活动文档。
文档 MUST NOT 参与 Dockview 拖放、浮动、布局持久化、ComposeDocument、History 或 Operation Log。

#### Scenario: 进页面库时标签还在

- **WHEN** 用户开着两份页面文档，点击标志回到页面库
- **THEN** 顶栏上那两个标签仍然在，点一下即回到对应文档
- **AND** 没有任何标签被关闭

#### Scenario: 画布列头回答的是层

- **WHEN** 用户查看画布列头
- **THEN** 上面是当前文档的面包屑
- **AND** 上面没有文档标签，也没有「设计 / 动画」切换器

#### Scenario: 面包屑点一段就回到那一层

- **WHEN** 用户从页面进入一个组件，画布列头上是「页面名 / 组件名」两段
- **THEN** 点击「页面名」那一段即回到该页面，与场景树根行的返回效果相同
- **AND** 末段不可点

#### Scenario: 标签多到放不下

- **WHEN** 打开的文档数超出顶栏可用宽度
- **THEN** 标签条自己横向滚动
- **AND** 工作区切换器与三个布局开关仍在顶栏右端可见

### Requirement: chrome 的选中画法

表示「选中 / 活动」的画法 MUST 只有一种：**一块柔和的圆角底**加 `text-strong`。它作用于
应用顶栏（含其中的文档标签条与工作区切换器）与头部行——头部行指左栏面板头、画布列头与右栏
面板头。这些位置 MUST NOT 用下划线或 accent 条、
MUST NOT 贴满整格、MUST NOT 用竖线分段。hover MUST 只改文字颜色而 MUST NOT 上底——底是「选中」
的专用通道，hover 也上底会让「指着」与「选中」同形，而两者可以同时成立。

画布工具栏的按下态 MUST 保持既有的 `surface-selected` 底，MUST NOT 跟着改成灰底：顶栏与头部行
回答**你在看哪一个**（导航，一组里恰好一个有底），工具栏回答**哪个开着**（状态，可以同时开
好几个）；同一块灰底放进「可以同时为真」的一组里，读不出还剩几个开着。

活动格的底色 MUST 由端到端用例断**计算后的值**而不是只断 class：本仓库已经有过一次样式靠层叠
静默失效（无层规则压过 `@layer components`），只断 class 的用例挡不住它。

#### Scenario: 几处长一个样

- **WHEN** 用户查看工作区切换器、文档标签条与左右面板头
- **THEN** 它们的活动项都是圆角底加更亮的文字
- **AND** 都没有下划线、没有 accent 条、没有竖线分隔

#### Scenario: hover 与选中可分

- **WHEN** 指针悬停在一个未选中的文档标签上
- **THEN** 它的文字变亮而没有底
- **AND** 活动标签的底不变

#### Scenario: 工具栏按下态不跟着变

- **WHEN** 用户查看画布工具栏里被按下的选择工具
- **THEN** 它的底仍是 `surface-selected`，与顶栏活动格的灰底不同色
