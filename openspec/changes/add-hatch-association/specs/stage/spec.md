## ADDED Requirements

### Requirement: 填充在边界改动之后自动跟随

宿主 MUST 在**事务提交**之后，为受这次改动影响的填充重求一遍几何。

**要不要算 MUST 由清单过滤**：这次事务的 `targetIds` 与某块填充的 `Hatch.boundaryIds`
有交集才为它重求，交集为空时 MUST 一次都不跑——绝大多数事务（挪一个符号、改一段文字、
调一个颜色）与任何一块填充都不相干。没有 `boundaryIds` 的填充 MUST NOT 参与。

**跟不跟 MUST 由清单判定**：重求出来的那份边界清单与存着的那份**相同**时 MUST 跟随，
**不同**时 MUST NOT 改动几何，只标过期。拓扑变了时「跟上」意味着一次用户没有要求过的形状
改变，而那正是本能力被推迟至今的原因。

**求不出面时 MUST 保留原几何并标失效**，MUST NOT 静默留在原地，也 MUST NOT 自动断开关联——
失效必须是一个**可见且可恢复**的状态：把缝补上之后它自己就回来了。

跟随成功时 MUST 把 `Hatch.seed` 重取到新几何的**最大内切圆圆心**，并 MUST 把 `boundaryIds`
更新成这次求出来的那份——不更新的话，一块填充会被一个早就搬走的对象永久拖着，
每次挪它都白跑一次求解。

跟随的写入 MUST 并进**同一个事务**：撤销一步，边界与填充一起回去。

跟随 MUST NOT 在手势期跑：判据是「文档变没变」而不是「手在不在动」，而手势期走的是预览变换，
一个字节都还没写进文档。

#### Scenario: 拖顶点之后填充跟上

- **WHEN** 用户拖动某条边界曲线的一个顶点并松手
- **THEN** 这块面的几何在同一个事务里按新边界重新求出

#### Scenario: 不相干的改动不触发求解

- **WHEN** 用户移动一个不在任何填充边界清单里的符号
- **THEN** 没有任何填充被重求，几何一个字节不变

#### Scenario: 拓扑变了只标过期

- **WHEN** 一个原本压在矩形上的圆被整个挪出去，边界从「三边一弧」变成「四条边」
- **THEN** 填充几何不变，并被标为过期

#### Scenario: 边界断开时标失效

- **WHEN** 边界被剪开，落点处已经没有封闭的面
- **THEN** 填充保留原几何并被标为失效，且 `Hatch` 仍在

#### Scenario: 撤销一步全回去

- **WHEN** 用户在一次跟随发生之后按撤销
- **THEN** 边界与填充几何同时回到改动之前

#### Scenario: 手势期不跟随

- **WHEN** 用户正拖着一条边界曲线、尚未松手
- **THEN** 填充几何停在原处

### Requirement: 填充落地时记下边界清单

`HATCH` 落地新建一块填充时，MUST 把这次求解用到的那几个边界 Entity 的 id 写进
`Hatch.boundaryIds`。

它 MUST 取**已经算出来的那一份**——层序（把填充插在最靠后的那条边界之下）用的就是它，
MUST NOT 为此再求一次。

改某个既有 Entity 填充的那一支 MUST NOT 写 `Hatch`：那一支根本不产出填充 Entity。

#### Scenario: 新建那一支写下清单

- **WHEN** 填充落成一个新 Entity
- **THEN** `Hatch.boundaryIds` 是围出这块面的那几个 Entity 的 id

#### Scenario: 改既有对象那一支不写 Hatch

- **WHEN** 这块面的边界恰好是某一个 Entity 的完整几何
- **THEN** 只写那个 Entity 的 `Appearance.backgroundPaint`，不产出任何 `Hatch`
