## 上下文

`add-hatch-command` 已落地，填充是带 `Curve` + `Hatch` 的普通 Entity，`Hatch` 只存一个
`seed`。那一份明写「`Hatch` MUST NOT 存边界对象的标识」，理由是「存了就要回答**这条边是与哪个
对象的第几个交点**，而一条直线穿过一个圆有两个交点，选哪一个是个启发式」。

**这条禁令针对的是「边」级引用，本变更存的是「Entity」级 id，因此那条理由不适用**：
一组 id 不需要回答「第几个交点」，它只回答「围出这块面的是哪几个对象」。禁令的「边」级那一半
原样保留——本变更仍然不存段下标，理由见决策 2。

调研过的三种存法：AutoCAD 存**三份**（烘死的环几何 + 边界对象句柄 + 落点），Figma 的
`VectorRegion.loops` 存**段下标**，Illustrator Live Paint **什么都不存**、实时算。

## 目标 / 非目标

- 目标：边界形变时填充自动跟上；拓扑变了时不替用户换形状；边界断了时保留几何并说出来。
- 目标：不为跟随付每帧的账。
- 非目标：手势期跟着变形（只在提交那一刻算，见决策 5）。
- 非目标：跨对象的拓扑级身份（Figma 那条抄不了，见决策 2）。
- 非目标：自动分组（见决策 7）。

## 决策

### 决策 1：存 Entity id 的清单，它同时是过滤器与判据

- **决策**：`Hatch.boundaryIds?: string[]`，缺席即不跟随。
- **两个用途**：与事务 `targetIds` 求交决定**要不要算**；与重求出来的那份比对决定**跟不跟**。
- **理由**：「这次改动与我有没有关系」和「边界还是不是那几个」问的是同一件事的两面，一份清单
  答完。而它**连算都不用算**——落地那一刻已经有了（今天叫 `belowIds`，用来把填充插在最靠后
  那条边界之下），用完就扔。
- **缺席即不跟随**：与 `Hatch` 自己「缺席即不是填充」、`Clip`「缺席即不裁剪」同一条。
  这条回退让迁移不需要做。

### 决策 2：不存段下标

- **决策**：只存 id，不存「用到了哪几段」。
- **理由**：段下标在顶点被增删之后就错位。Figma 能用它的前提是**整块面在一个 VectorNode 里**，
  它自己的文档写明跨对象要先 Flatten；而我们的面天生跨多个 Entity，各自还会被加段删段。
- 更细的粒度眼下没有消费者，按仓库的规矩不进协议。

### 决策 3：清单相同即跟随，不同即过期

- **决策**：重求之后比对清单，相同就写进去，不同就标过期、几何一动不动。
- **理由**：拓扑变了时「跟上」意味着一次**用户没有要求过的形状改变**——圆整个挪出去之后，
  跟上就是把填充换成整个矩形。`add-hatch-command` 留下的那个问题正是在这里被挡住的。
- **代价写在明处**：这一档要按一下「重新生成」。它比 AutoCAD 多一步，而 AutoCAD 省下那一步的
  代价是**静默**——它在这一档直接失联并停在原地，没有记号、没有报错。
- Illustrator Live Paint 在同一处的答案是「两个 face 合并，按面积大的那个取色，另一个静默丢掉」
  ——同样是静默，同样不取。

### 决策 4：落点是这块面的身份，跟随之后重取到最大内切圆圆心

- **决策**：跟随成功后把 `seed` 重取到该面的**最大内切圆圆心**（pole of inaccessibility）。
- **理由**：落点停在用户当初点的地方时，它**一定**会在某次变形之后被吞掉——用户点填充时爱点
  在空的地方，也就是角落，而角落最容易被吞。重取之后它离每条边界都最远，边界要吞掉它就得先把
  整块面压扁到比内切圆还窄，**而那时求解本来就会失败**。
  于是结果是「标失效」这个看得见的答案，而不是「悄悄换成另一块面」这个看不见的答案。
  **把一个静默的错变成一个可见的错，是这条全部的价值。**
- **代价**：`seed` 不再是「当初那一下点在哪儿」，Inspector 上那行只读文案要改口成「锚点」。
  这值得换：那个字段**唯一的消费者**就是求解，没有别人读它。
- **只在跟随成功之后重取，不在落地那一刻重取**：刚填出来的那块面，用户点的地方就是他心里那块
  面，此时把点挪走只会让「重新生成」变得不可预测。
- 算内切圆要把弧边采样成折线。它**只用来选一个点，不产出任何几何**，因此这处近似不违反
  「这块画布上每条几何都是真几何」。

### 决策 5：只在提交那一刻算

- **决策**：跟随挂在事务提交上，不在手势期。
- **理由**：判据是「文档变没变」而不是「手在不在动」——手势期走的是预览变换，一个字节都还没写
  进文档。因此跟随天然是每次手势一遍，而不是每帧一遍；撤销也白拿，跟随写进**同一个事务**。
- **与导线的不对称是有理由的**：导线求解确实住在布局 Runtime 里每帧跑，但它只需要查一个端口的
  位置，而求面是两两求交。
- **代价写在明处**：拖动过程中填充不跟着变形，松手才跳一下。

### 决策 6：断开关联 = 删掉 `Hatch`

- **决策**：Inspector 给「断开关联」，不给「跟不跟随」开关。
- **理由**：布尔开关会造出一块**看不见的状态**——两块长得一样的填充，一块跟一块不跟，屏幕上
  没有任何东西解释为什么。而断开关联做的是一件说得清的事：删掉 `Hatch`，缺席即不是填充，
  它变回一条普通闭合多段线，从此和别的曲线一样。
- 它**本来就是**一条闭合多段线，因此不需要为「脱离关联的填充」发明任何新东西。
- 入口在 Inspector 而不在画布上，与导线的「解除绑定」是同一条例外理由：**画布上没有能只断开
  关联而不动几何的手势**。

### 决策 7：不做自动分组

- **决策**：填充落地时 MUST NOT 建 Group 把边界包起来。
- **它修的不是坏掉的那一档**：组能让整组一起挪时填充跟着走，可那一档本来就不坏（框选一起拖，
  两者都在选区里）。真正坏掉的是**相对运动**，而那在组里照样做得到。
- **两条硬拦路**：(a) 一个对象可以同时是好几块面的边界，而一个 Entity 只有一个父级；
  (b) `wire.parent-mismatch` 是文档**非法**——把带端口的符号卷进新组而导线没进去，
  一次填色就让校验不过、保存被阻断，而这两件事在用户眼里毫无关系。
- **层序也保不住**：组只占一个 z 位置，夹在中间、不是边界的符号会被整片盖住，
  正是已落地那份判定为错的样子。
- 本仓库**已经拒绝过一次拿 Group 当别的用**：DXF 的图层没有退化成 Group，理由逐字相同。

## 风险 / 权衡

- **一次事务改了很多边界** → 框选一百个对象一起挪时可能命中几十块填充。需要一个上限，
  或超过某个数量时退回「全部标过期」。退回那一档**是安全的**——它就是今天已落地的行为。
- **落点被边界横扫而过** → 一条线从落点上扫过去时清单没变，因此会跟随，而结果是填充跳到线的
  另一半。决策 4 把这一档压得很窄，但压不到零。见「待定」。
- **跨多步撤销时清单是否自洽** → 跟随写进同一个事务，单步没问题；跨多步要有用例钉住。
- **弧边采样求内切圆** → 只用来选点，不产出几何。

## 迁移计划

不需要迁移。`boundaryIds` 是可选字段，**缺席即不跟随**：已落地的每一块填充行为逐字不变，
仍然只标过期、仍然要按一下「重新生成」，而那一下会把清单补上。协议版本不变。
回滚 = 忽略这个字段，填充退回手动关联。
