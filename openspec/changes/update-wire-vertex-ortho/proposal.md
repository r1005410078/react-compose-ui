# 变更：导线的顶点模式恒保横平竖直

## 原因

「导线的夹点会话钉死正交」已经落地，但它**只对端点成立**：参照取相邻顶点的那条逻辑只回答
首顶点与末顶点，内部拐点与段夹点拿不到参照，正交于是退化成「相对自己的原位置」——而那不
保证形状。屏幕上的结果是：

- 拖**内部拐点**：它只沿一根轴走，另一根轴上的相邻段当场变斜。
- 拖**段夹点**：沿平行于该段的方向平移时，两头的相邻段一起变斜。
- 删掉一个内部拐点：两段垂直的走线合成一段斜的。

「只走横平竖直」是导线的**规范**而不是辅助（斜着走的导线不是用户的选择，是一张画错的图），
画线时钉住、进了顶点模式就掉一半，等于这条规范只在一半的入口上成立。

## 变更内容

- **导线不出内部拐点的顶点夹点**：正交折线上的内部拐点两根轴各被一条相邻段钉死，它一个
  自由度都没有——留一个拖不动的方块比不留更糟，而能拖就意味着相邻段变斜。改形状的入口是
  段夹点，加拐点的入口仍是在段上双击插入顶点。
- **导线的段夹点只沿垂直于该段的方向平移**：垂直平移让相邻段伸缩、整条线仍然横平竖直；
  平行平移让两头的相邻段变斜。
- 段夹点那一档**不再钉角度约束**：几何只剩一个自由度，再钉一次正交会让沿段方向的那半边
  拖动什么都不发生。
- 求解那一侧加一个「这条曲线的每一段都必须保持轴对齐」的选项；引擎仍然不认识导线。

## 影响

- 受影响的规范：`stage`、`stage-engine`
- 受影响的代码：`packages/stage-engine/src/geometry-editing/curve-grips.ts`、
  `packages/stage-engine/src/drafting/{vertex-command,drafting-types,drafting-edits}.ts`、
  `packages/stage/src/geometry-editing/use-stage-geometry-editing.ts`
- 不在本变更内：拖一个拐点时**连带挪相邻顶点**保持正交——相邻顶点若是已经接在端子上的那一端
  会被拽下来，而求解下一帧又把它拉回端口，走线当场又变斜；真答案是自动路由，而那要回答
  「拐点该拐在哪儿」
