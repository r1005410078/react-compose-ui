## 上下文

命令会话是四态推进（`prompt` / `commit` / `cancelled` / `rejected`）。Stage 收到 `commit`
就派发效果并 `endSession`，命令随之结束、`activeCommandId` 回到 `null`。

## 目标/非目标

- 目标：`WIRE` 与 `ARROW` 画完一条接着画下一条，`Escape` 退出。
- 非目标：
  - **一条导线取多个点**（折线导线）。它的价值几乎全部来自自动路由，而路由还没有；手画的
    拐点在挪一下符号之后就得重画，比直线还糟——直线至少会自己跟过去。
  - 一个全局的「保持工具」开关（Visio 那种）。它把「这条命令是不是成批用的」变成用户要维护
    的状态，而那件事命令自己知道。

## 决策

**决策：`repeat` 是命令定义上的一个标记，不是宿主的一个模式。**
「画完之后接着画」是这条命令的性质，不是画布的状态。做成模式的话，同一条 `WIRE` 在两种模式
下行为不同，而屏幕上没有任何东西说明为什么；做成标记则「哪些命令会接着画」可以从注册处读出来。

**决策：只有 `WIRE` 与 `ARROW` 声明，判据是「用户画完之后想对它做什么」。**
这是当初判定 `RECTANGLE` 该产出矩形物料的同一条判据：

- 导线画完，九成是接下一条 → 重启
- 矩形画完，九成是填色、调圆角、往里塞东西 → 结束

这个不对称是**设计**，不是遗漏。反证：给所有命令都重启，画一个矩形之后想调它得先按一次
`Escape`，而那一下按键不携带任何信息——正是这套交互从一开始就在删的东西。

**决策：重启的是一条全新会话，不继承任何点。**
继承上一条的终点会让它退化成链（`LINE` 的语义），而一条导线只有两端。全新会话也让「重启」
的实现只有一句话：跑一遍 `start(同一个 id)`。

**决策：`Escape` 在会重启的命令里分两级。**
不分级的话，`ARROW` 改成连续取点之后 `Enter` 是「结束这一条并开始下一条」，唯一的退出只剩
`Escape`，而它此刻的含义（放弃整条命令）会把用户刚画一半的东西一起扔掉。分级之后：

- 当前这一条**已经取过点** → 放弃这一条，命令留着
- 当前这一条**一个点都没取** → 退出命令

它与几何编辑里 `Escape` 的两级（先熄灭热夹点、再退出会话）同构，不是新概念。判据读的是
**这一条取过点没有**这一份事实，与提示里显示第几步读的是同一份。

**决策：重启 MUST NOT 触碰选择集。**
今天绘图命令提交之后**不选中**新建的对象，重启也不改这一条。（顺带记下：如果将来改成
「画完即选中」，重启对矩形之类的命令就更没有位置了，而对导线没有影响。）

## 风险/权衡

- **`activeCommandId` 在重启的一瞬间会不会闪一下 `null`**：不能闪。工具栏的按下态读它，闪
  一下会让按钮抖动；重启必须在同一次更新里完成，而不是「结束再启动」两拍。
- **重启之后的提示要回到第一步**。会话是新的，这条由构造保证；但用例要钉住它——回到第二步
  的提示会让用户以为上一条还没画完。
