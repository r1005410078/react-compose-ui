# 变更：时间线关键帧框选与批量移动、删除

## 原因

时间线上的关键帧选择今天是**单选**：`ComposeAnimationPanelValue.selectedKeyframeId` 只装一个
id，拖动与删除也各自只作用于一个关键帧。把一段动画整体往后挪 100 ms、或者清掉某个时间段里
散在几条轨道上的十几个关键帧，用户只能一个一个点、一个一个拖——而这两件事恰恰是调动画节奏时
最常做的。

关键帧车道的空白处今天没有任何手势（只有 Ctrl + 滚轮缩放与滚轮平移），因此框选不与任何既有
交互争抢入口。

## 变更内容

- **BREAKING** `ComposeAnimationPanelValue.selectedKeyframeId: string | null` 换成
  `selectedKeyframeIds: readonly string[]`；`select` 动作的 `keyframeId` 同步换成
  `keyframeIds`。会话选择是一个集合，单选是集合恰好一个成员的退化情形，不再另存一份。
- **框选**：在关键帧车道的空白处按下并拖动，画出一个矩形；松手时矩形**碰到**的关键帧
  （菱形的命中区与矩形相交，可跨多条属性轨道与多个对象轨道）成为选区。判定只有「碰到就选」
  一种，不区分拖拽方向——关键帧是点不是面，「完全框住」与「碰到」对点没有区别。
- **点击语义与画布一致**：点关键帧替换选区，`Shift` + 点切换它在选区里的去留；
  `Shift` + 框选把矩形碰到的加进选区。按在已选中的关键帧上没有移动就松手才收敛成单选，
  按下那一刻不收敛——否则从多选中拖任何一个都会先把其余的丢掉。
- **批量移动**：拖动选区里任意一个关键帧，整个选区同加一个时间位移；焦点落在选区成员上按
  ArrowLeft/ArrowRight 同样作用于整个选区。位移被钳制到「没有任何成员越出 0～duration、
  也没有任何成员落到同轨道未选中关键帧的时间上」的最后一个合法值。面板发出**一个**
  `move-keyframes` 动作，编辑器翻译成 N 条 `moveKeyframe` 命令共享 `mergeKey`，
  撤销一步整体回去。
- **批量删除**：焦点在时间线内且选区非空时 `Delete` / `Backspace` 删除整个选区；已选中的
  关键帧上的右键菜单把「删除此关键帧」换成「删除选中的 N 个关键帧」。面板发出一个
  `remove-keyframes` 动作，编辑器合成一次事务。
- 右侧字段面板只在选区恰好一个成员时显示该帧的时间、值与插值；多选时显示已选数量，不显示
  只能作用于一个帧的字段。

## 非目标

- 批量修改插值与值（留给字段面板对多选的后续变更）。
- 框选动画片段（clip）；片段仍是单选。
- 按时间区间「完全框住」的第二种判定。

## 影响

- 受影响的规范：`animation-panel`
- 受影响的代码：`packages/animation-panel/src/animation-panel`（会话模型、Provider、时间线
  手势与字段面板）、`packages/editor/src/animation-mode`（会话状态形状、动作到命令的翻译）
- 唯一的第一方消费者是 `editor`，BREAKING 不波及别的包
