## 上下文

`TRIM` 已经落地，它带来了三样这次直接复用的东西：`pick` 输入种类、世界坐标下的曲线求交
（`intersectComposeSegments` / `SegmentArc` / `Arcs`），以及「盒局部几何 → 世界空间线段与弧」
的换算（`curve-trim.ts` 里的 `boxCurve` 与 `worldShapes`）。`TRIM` 在一维上排序取邻居，
`HATCH` 在二维上绕一圈——**是同一份数学的另一种用法，不是第二套**。

协议侧同样已经就位：`ComposePathCurve` 有 `subpaths` 与 `fillRule`，`isPointInsideComposeCurve`
已经按 `fillRule` 分派，`getComposeCurveFill` 是填充的唯一读取入口。

## 目标 / 非目标

- 目标：一条 `HATCH` 命令，点一下把光标底下围出来的那块面填上色；能跨对象取边界；岛自动挖空；
  不封闭时可诊断；产物是普通 Entity，既有的 Inspector / 绑定 / 动画轨道全部白拿。
- 非目标（v1）：图案填充（斜线、砖纹）；间隙容差；自动跟随边界的关联；拖过多块；一次多点落成
  一个 Entity；布尔运算；像素漫填；`path`（贝塞尔）作为边界。

## 决策

### 决策 1：产物是普通 Entity，不是 face、不是渲染规则

- **决策**：求出的面落成一个带 `Curve` 的普通曲线 Entity，填充写在 `Appearance.backgroundPaint`。
- **理由**：Illustrator 的 Live Paint 把颜色挂在 face 上，账单是公开的——face 不能单独有透明度、
  效果、外观堆栈，也用不了 Pathfinder、轮廓化描边、剪切蒙版、混合与符号，因为那个颜色**没有对象
  可以挂**。产出真 Entity 之后这张账单一分钱不用付：选中、改色、数据绑定、外观动画轨道、场景树、
  撤销全部是既有路径。
- **考虑过**：Figma 式的「region 挂在一个 VectorNode 上」。它的关联最稳（`loops` 存的是段下标），
  但**跨不了对象**——要跨两个图层得先 Flatten，而那是破坏性的。本产品的边界天生跨对象。

### 决策 2：边界恰好是一个对象的完整几何时，改它，不新建

- **决策**：面求出来之后先问一句——这块面的边界是不是**某一个 Entity 的完整几何**（它自己闭合，
  且没有被任何交点切开）。是就写它的 `backgroundPaint` 并到此为止；否则落成新 Entity。
- **理由**：没有这条，拿桶点一个没有任何东西穿过的矩形，会得到一个与它逐像素重合的新对象压在
  下面——屏幕上看着对了，场景树里多出一个一模一样的东西，而用户显然是想把这个矩形填上色。
  每一个有油漆桶的产品在这一档都是「改这个形状」。
- **判据必须是「完整」而不是「同一个 Entity」**：自交的折线（8 字形）两个环都出自它自己，
  而写它的 `backgroundPaint` 会把**两个**环一起填上，不是用户点的那一个。
- **这不是模式歧义**：决定走哪一支的是图上看得见的东西，不是藏在别处的状态；`TRIM` 早就是同样的
  形态（同一下点击可能缩短、可能断成两条、也可能整条删掉）。约束照抄那一条——**悬停预览与落地
  读同一份解算**，且命令行把这一下会发生什么写出来。
- **锁定时拒绝并说明，MUST NOT 退回去新建**：「你锁了它」和「我给你造了个新的」是两件事，
  后者会让锁形同虚设。

### 决策 3：`Hatch` 只存一个 `seed`，且关联是手动的

- **决策**：`Hatch: { seed: { x, y } }`，Entity 局部坐标（与 `Ports.position`、`Curve` 几何同一个
  空间）。缺席即不是填充。重算走 Inspector 上一个显式的「重新生成」，拿 `seed` 把当初那次求解
  **原样再跑一遍**。
- **理由**：不存边界对象的 id，是因为存了就要回答「这条边是与哪个对象的第几个交点」，而一条直线
  穿过一个圆有两个交点，选哪一个是个启发式。重跑同一个算法没有第二套规则。
- **调研直接支持这条**：AutoCAD 关联图案填充最常被抱怨的失败，**正是那个存下来的落点**——边界挪了
  之后落点掉到界外，填充静默留在原地；老手的对策是干脆不用「拾取内部点」。糟在**静默**：
  没记号、没报错，通常图印出来才发现。
- **因此 v1 不自动跟随**，而 v2 也不能是「把手动重算改成每帧跑一遍」：它得先回答「seed 换了面时
  听谁的」。真正要抄的是 KiCad（跑 DRC 与生成输出前警告区域没重填）与 Altium（重填做成带
  「保持原样」的提示）——**关联可以晚点做，过期状态不能晚点做**。

### 决策 4：v1 没有间隙容差，但要把断口画出来

- **决策**：走不出闭合环就拒绝，并在走不下去的那个节点画一对琥珀记号。
- **理由**：这个仓库里每一个容差都有来源（拾取框抄 `PICKBOX`、捕捉半径是「多近算在这条线上」的
  唯一事实），而「差多少还算封闭」没有这样的来源，它取决于图纸比例。三家的容差各自都有毛病：
  Illustrator Shape Builder 的是**近似匹配不是上限**（设大了反而测不到小缝），Inkscape 的是
  **屏幕像素**（随缩放变），AutoCAD 的 `HPGAPTOL` 是图纸单位。Affinity Designer 看过这些之后
  仍然选择**一点都不做**，要求真闭合——本条与它同款。
- **代价写在明处**：0.5px 的缝也会被拒。补偿是画出断口，把一次挫败变成一次诊断；AutoCAD 在这一档
  只说「找不到有效的图案填充边界」，用户得自己在整张图上找那条缝。
- **琥珀是复用**失效端点那个 token 而不是第七种颜色：缺口就是图上的一处失效。

### 决策 4b：自由端掉头绕过去，失败改由「环没围住落点」判定（落地时推翻了原规则）

- **原规则**：绕行走到一个没有出边的节点就判失败，并在那里画断口。
- **推翻它的是一根线头**：一条画了一半的导线、一根符号的引出线，从边界伸进面里、另一端悬空。
  它**不分割任何东西**，填充本该照常成立；而原规则会在那里失败，并且**断口记号指向的不是缝**
  ——那是一次错误的诊断，比不诊断更糟。这类线头在接线图上到处都是。
- **新规则**：自由端上掉头走回去（留下一条零宽的缝，在产物里裁掉）。这样绕行**总能闭合**，
  于是失败改由「围出来的环没有围住落点」判定——边界真的缺了一段时，绕行会从那个缺口走到外面去。
- **诊断反而更准**：报的是这一圈上遇到的**全部自由端**，而一个真缺口的两侧正好是两个自由端。
  原规则只能报「第一个走不下去的地方」。
- **不是把间隙放过去**：0.5px 的缝仍然被拒，与决策 4 逐字一致。掉头绕过的是线头，不是缝。

### 决策 5：岛复用 `subpaths` + `evenodd`，协议不改

- **决策**：外环走完之后，落在它内部而又走不到的每个连通分量各是一条子路径，整体写 `evenodd`。
- **理由**：AutoCAD 的 Normal 岛屿检测在 DXF 里的组码 75 字面就叫 `odd parity`——「一层层交替
  挖空」与奇偶规则是同一件事。`isPointInsideComposeCurve` 已经按 `fillRule` 分派，因此
  **看得见的洞与点不中的洞自动是同一个洞**。

### 决策 6：当前填充色记在编辑会话，因为它被印出来了

- **决策**：一个宿主 ref，不写文档、不写偏好。两条入口：工具栏 split button 的色板弹出层，
  与命令进行中的 `C` 关键字。色板列的是**这一页已经用过的颜色**。
- **理由**：`CIRCLE` 的 `D`/`R` 不跨命令记忆，理由是**那份状态看不见**；`POLYGON` 的边数可以记，
  因为它印在提示的 `<6>` 里。桶身就是这里的 `<6>`。合法性不在方不方便，在值有没有被印出来。
- **不内置色表**：那是替宿主做一个多半要改的决定，与「不内置电压等级色表」同一条。色板从文档
  算出来，**不引入任何文档字段**。
- **`C` 关键字是第二条入口**，因为货架不得成为任何能力的唯一入口。
- **不挂到光标旁的动态输入框上**：那一档是给每取一个点都在变的量准备的（长度、角度、边数），
  颜色每填几次才动一次。

### 决策 7：默认色是低饱和的深色，理由是角色而不是「没答案」

- **决策**：首次默认取一块压得住的深色。
- **理由**：导线默认红取「最常见的那一档」；区域填充问的是另一个问题——**它垫在符号底下，必须让
  上面的墨读得出来**。同一条判据的两个答案，不是将就。取值待定，要按导线红那套在深色画布与
  白底页面上都量过对比度（场景背景默认透明，填充是会被发布出去的真实像素）。

### 决策 8：图标是第一枚带参数的，桶口留空

- **决策**：`StageToolbarIcon` 加一个可选的漆色参数；桶身轮廓走 `currentColor`，**只有漆面填当前色**。
- **理由**：整桶填色时近白漆在深底、近黑漆在浅底都会与轮廓糊成一块，桶的剪影就没了；留出桶口
  那一截，剪影在任何漆色下都成立。**不用「单色桶 + 底部色带」**：色带是只出现在这一枚图标上的
  新记号，而这套图标的记号词汇表只有五个且写着「accent 只标点」；它还落在 `y=16–18`，
  那一圈版式规则写明只有夹点方块可以进。
- **漆色走 `style` 内联**而不是 presentation attribute：既压得过样式表继承的 `fill: none`，
  也不依赖 `var()` 在属性里被替换（仓库注释里已经记过这条坑）。
- 画幅 MUST 是 20×20：这套图标按 20px 渲染，一个单位就是一个设备像素。

## 风险 / 权衡

- **求面是 O(N²) 的两两求交** → v1 只在一次 `pick` 上跑一遍，不进每帧路径；候选先按世界包围盒
  相交筛过（`TRIM` 已有同样的筛法）。
- **绘图货架加到 17 格，尾部一格（文字）会被收进「更多」** → 代价写在提案里；自定义对话框可以
  拖回来，默认值不假装这件事没发生。
- **弧边转三次贝塞尔是近似** → `path` 的段只有三次一种，这是协议做过的取舍。每 90° 切一段时
  最大径向误差约半径的 `2.7e-4`（半径 500px 上 0.14px）。`svg-import` 已经在做同一件事，
  但它靠第三方库而 `core` 零运行时依赖——这处重复是包边界造成的。
- **圆角多段线的边界 MUST 走 `composePolylineOutline`（圆角后的那一列）而不是尖角顶点**。
  `TRIM` 取尖角顶点并写明了代价（剪口差一个圆角的距离）；填充不能取同样的近似，差一个圆角的
  **面积**是屏幕上看得见的一块色，四个角就是四块。
- **`intersectComposeSegments` 对共线重叠返回空** → 落地时发现它**不是无害的**：射线穿过叠在
  一起的两条边会在**同一个距离上**得到两个交点，而那一档分不出「穿过去了」还是「擦到了」，
  于是每一个射线方向都退化、整块面求不出来——用户看到的是一个明明围好了的矩形填不上色。
  因此建图时把两端节点相同、中点重合的子边**收成一条**：两条画在一起的边界线在图上本来就是
  一条边界。用例钉住了这一条。

## 迁移计划

不需要迁移。`Hatch` 是可选 Component，缺席即不是填充；`Curve` 与 `fillRule` 一个字节不改，
协议版本不变。既有文档逐像素不变。回滚 = 撤掉这一格与这条命令，已经落地的填充仍是普通曲线
Entity，照常渲染与编辑。

## 待解决问题

- 自动关联怎么做，以及 `seed` 换了面时听谁的。
- 过期状态怎么被看见——一个便宜的答案是**只在这块填充被选中时重算一次**（一次 O(N²) 不是每帧），
  但选中一块填充因此变慢多少要量。
- 首次默认色的取值（要量对比度）。
- 宿主要不要能注入一份色板。眼下没有消费者，因此不进协议。
- 场景树里它叫什么名字。
- 文字与符号算不算岛（AutoCAD 会把文字挖空；这里的文字 Entity 没有 `Curve`，天然不是候选）。
