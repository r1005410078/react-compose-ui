# 变更：导线可以有拐点，走直角

## 原因

`WIRE` 今天取两个点、产出一条直线段。两个端子只要不在同一条水平或垂直线上，画出来就是**斜穿**
的——而一次接线图上导线全是横平竖直的（母线引下、盘内接线、汇流柜到 PCS），斜线不只是难看，
它会**压过中间的符号**，而这类图上符号是密排的。PCB 那边同样如此（Manhattan routing）：KiCad、
Altium 画导线默认就是 H/V/45 三段式。

**今天能画出直角的样子，但那是假的。** 得画两条独立的 `WIRE`，接头处两个自由端刚好重合。问题
在于**只有两端绑到了端口**，中间那个接头什么都不是——符号一挪，第一段的绑定端跟着走了，第二段
还停在原处，接头就裂开了。这正是「求解不存储」那条设计的反面：它保证的是**绑定端**跟着走，而
假接头不是绑定。

v1 当初写的理由是「折线导线的价值几乎全部来自自动路由，而路由还没有」。**这条站不住**：PCB
工具全都支持手画拐点，而且它们也都有自动路由——两者不是替代关系。手画的拐点在符号挪走之后
确实会变丑，但用户宁可要一条要修的折线，也不想要一条斜穿整张图的直线。

## 变更内容

- `WIRE` 改为**连续取点**：`Enter` 结束这一条，`U` 放弃上一点，`Escape` 放弃整条。取够两个点
  才能结束。
- 产出的几何在取满两点时是 `line`、三点及以上是 `polyline`，攒成**一个** Entity 在结束时提交
  （与 `PLINE` 同一条路径，不是逐段落地）。
- **只有首尾两个顶点参与绑定**，中间的拐点是纯几何。
- 求解相应放开：`resolveComposeWires` 认 `polyline`，把绑定端写进**首顶点或末顶点**，其余顶点
  一个字不动。
- **不新增任何路由逻辑**：横平竖直由既有的角度约束给（极轴默认开、增量角 45°，正好覆盖
  H/V/45），用户点到哪儿就是哪儿。

## 影响

- 受影响的规范：`compose-document`、`stage-engine`、`stage`
- 受影响的代码：`packages/core/src/wire.ts`、`packages/stage-engine/src/drafting/line-command.ts`、
  `packages/stage-engine/src/hit-testing/feature-points.ts`
- **不改协议字段**：`Curve` 本来就有 `polyline`，`Wire` 一个字段都不加。卡住的是三处——文档
  校验把 `kind !== 'line'` 判为 `wire.unsupported-geometry`、求解写死了同一个条件就返回 null、
  以及 `WIRE` 是两点会话。校验放开到 `line | polyline`，**弧仍然非法**（它没有首尾顶点可言）。
- `ARROW` 与 `WIRE` **不再共用两点会话工厂**：`ARROW` 保持两点（一支箭头只有一个头），`WIRE`
  转成连续取点。
- 几何编辑、命中、捕捉、框选**一行不改**：多段线在这些路径上早已支持，导线因此白拿拖拐点。
- `WIRE` 的 `repeat` 保留，语义变成「`Enter` 结束这一条，接着画下一条」——与 `PLINE` 同形。
