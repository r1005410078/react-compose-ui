# 圆与圆弧

## Why

CAD 至今只有一种图元：两点直线。三类目标场景全都过不去：

| 场景 | 缺什么 |
| --- | --- |
| 一次接线 | 断路器、接地、互感器——符号主体是圆与弧 |
| PCB 原理图 | 元件引脚圆点、可变电阻的斜箭头弧 |
| 网络拓扑 | 节点圆、云形边界 |

「用很多短线段拼一个圆」不是替代品：段数少了看得出棱角，段数多了每个符号几十个 Entity，
而且**捕捉不到圆心也捕捉不到象限点**——那正是接线时唯一想捕的两个点。

它同时挡着步骤 9：DXF 里最常见的两类实体就是 `CIRCLE` 与 `ARC`，模型表达不了就只能在导入时
丢掉或降级成折线，而降级是**不可逆**的。

## What Changes

### 一个 Component 表达圆与弧

`CadArc`：`center` / `radius` / `startAngle` / `sweep`。**整圆是 `sweep = 360` 的弧**，不另立
`CadCircle`——命中、捕捉、渲染、变换四条路径因此各只有一份实现。

`sweep` 而不是 `endAngle`：单给终止角分不出 10° 的弧和 350° 的弧，而这个歧义只在特定角度组合
下现形。角度约定沿用既有的**屏幕顺时针为正**，与 `transformCadBlockPoint`、`parseCadCoordinate`
一致——三处不一致会让「45 度」在不同入口指向不同方向。

### 可见性遍历改为几何联合

`collectCadVisibleSegments` → `collectCadVisibleCurves`，返回 `CadCurve`（线段或圆弧）。

这不是重命名。它是仓库里「命中、框选、捕捉与渲染共用同一条遍历」这条规则第一次面对**非线段
几何**：把圆在遍历里拍扁成线段能让下游一行不改，但渲染同一条遍历就会画出可见的多边形，
而绕开它单独画圆又恰好制造 AGENTS.md 点名的那种分叉——**看得见却点不中**。

### 精确的地方精确，粗糙的地方才近似

- **命中**：点到圆弧的距离有闭式解（`|dist(p,center) − r|`，角度落在扫掠外则取到两端点的
  距离），比线段还便宜。
- **窗口框选**：用圆弧的**紧包围盒**——盒子完全落在框内等价于弧完全落在框内，因此是精确的。
  紧包围盒要判四个轴向极值角是否落在扫掠内，不能拿整圆的盒子凑合。
- **交叉框选**：按弦高误差拍扁成线段再复用既有判定。框选本身就是像素级粗粒度的手势，这里
  的近似不会被用户感知，而精确的弧–矩形求交是一笔与收益不相称的开销。

### 捕捉补两种模式

`center`（圆心）与 `quadrant`（象限点），优先级插在 AutoCAD 的位置：
`port > endpoint > midpoint > center > quadrant > intersection`。弧的端点与中点（半扫掠处）
同样进候选。

### 块内的弧：等比缩放仍是弧，非等比拍扁

块实例的比例是分轴的（镜像用负比例，是常规用法）。**非等比缩放会把圆变成椭圆**，而本步不引入
椭圆图元。因此块展开时：等比（含镜像）→ 仍是精确圆弧；非等比 → 拍扁成线段。

拍扁是**明确的降级而不是错误的几何**：按 `|scale.x|` 硬算成圆会画出一个用户没有画过的形状。

### 两条命令

- `CIRCLE` / `C`：圆心 + 半径点。
- `ARC` / `A`：三点定弧（起点、弧上一点、终点），与 AutoCAD 的默认次序一致。

两点都走既有点求解管线，因此捕捉、正交与网格吸附白拿。

## Impact

- `@compose-ui/cad`：几何、文档协议与校验、遍历、命中、框选、捕捉、平移、块展开、两条命令。
- `@compose-ui/cad-canvas`：圆弧渲染（整圆用 `<circle>`，弧用 `<path>`）、两种捕捉标记。
- 协议：`schemaVersion` **不变**。既有 `.cad.json` 不含 `CadArc`，一律仍然合法。

## 本步刻意不做

- **椭圆与椭圆弧**：它要么来自非等比缩放的块（本步按拍扁处理），要么是独立图元；后者要等到
  有人真的需要，而不是因为「圆的一般化是椭圆」。
- **弧参与交点捕捉**：线–弧与弧–弧求交是实打实的一笔工作，而接线时想捕的是圆心与象限点。
  段–段交点保持现状不变。
- **样条与多段线**：DXF 的 `LWPOLYLINE` bulge 段到步骤 9 再谈，届时它落在本步的圆弧上。
- **弧的夹点编辑**：与直线端点拖拽是同一件被推迟的事，属于另一种交互范式。
