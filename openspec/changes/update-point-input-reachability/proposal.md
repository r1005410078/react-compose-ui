# 变更：让键盘够得着半径，让参考点不再把落点吸回去

## 原因

还原一张储能一次接线图时，取点管线上有两处让人当场卡住（`docs/oneline-diagram-dogfood-
issues.md` 的 O-2 与 O-3）：

- **`CIRCLE` 的「指定半径」不收半径数值**。敲 `C` → 圆心 `500,100` → 提示变成
  `指定半径或 [直径(D)]:` → 敲 `14` → 回车，命令行回 **`需要一个点`**。屏幕上写着的那句话
  是对的行为的反面，而键盘用户在这里没有第二条路。查下来根因不是命令：裸数字要拿**指针
  此刻的位置**当方向，而命令由命令行或工具栏按钮启动、指针从未进过图面时那份位置是空的。
  全图 27 个圆因此全部用「圆周上的一个绝对点」绕过去（圆心 `500,100` 半径 14 → 敲 `514,100`）。
- **圆心落在已有端点上时，小半径的圆画不出来**。命令行说 `这个形状是退化的`，而真正发生的
  是**捕捉把半径点吸回了圆心**。对照实验：同样 r=6，画在空白处成功、圆心压在已有线段端点上
  就失败，改用键入坐标连 r=3 都能落地。用户读到那句话只会去怀疑自己的半径太小。

## 变更内容

- **单字段参数化下，裸数字不需要指针位置**：`radius` / `diameter` 的另一个分量是角度，而
  **角度对结果没有任何影响**——那正是它们被做成单字段的理由（规范里已经写着「一个永远不影响
  结果的只读字段比没有更差」）。因此这一档在指针位置未知时取参考点加任意方向垫底，落地的圆
  一个像素不差。两个字段的那些参数化不变：那里方向是真的由指针给的，没有指针就真的定不出点。
- **命令取点时，会话已经上报的 `reference` 被排除出特征点捕捉**，与几何编辑「拖夹点时排除
  被拖那个顶点的原位置」是同一条判断的第二次应用：落点被吸回参考点，对每一条画几何的命令都
  只能产出退化几何（零长的线段、零半径的圆），而那个结果一定会被当场拒掉。
  排除**按位置**而不按身份：圆心吸在别的对象的端点上时，把落点拽回去的正是**那个端点**，
  按身份排除挡不住它——这恰好就是 O-3 的现场。

## 影响

- 受影响的规范：`stage`（动态输入的裸数字、取点时的捕捉排除）
- 受影响的代码：
  - `packages/stage/src/drafting/use-stage-drafting.ts`：裸数字的垫底落点、`snapExcludedPoint`
