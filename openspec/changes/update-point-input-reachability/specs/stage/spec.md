## ADDED Requirements

### Requirement: 单字段参数化的裸数字不需要指针位置

这一步的参数化是**单字段**（`radius` / `diameter`）时，键入裸数字并确认 MUST 落得了点，
**即使指针从未进入过图面**。

理由是这一档自己的定义：单字段的另一个分量是角度，而**角度对结果没有任何影响**——圆是旋转
对称的，半径点落在哪个方向上画出来都一样，那正是它被做成单字段的理由。因此这里不存在「方向
由鼠标定好」这个前提，落点由参考点与这个数完全确定。

两个数值字段的参数化（`absolute` / `polar` / `cartesian`）MUST NOT 照此办理：那里另一个分量
是真的由指针给的，没有指针就真的定不出点，垫一个默认方向等于替用户猜一个他没说过的角度。

#### Scenario: 命令行启动的 CIRCLE 收得下半径数值

- **WHEN** 用户在命令行敲 `CIRCLE`、键入圆心坐标、再键入 `14` 并回车
- **AND** 指针从未进入过图面
- **THEN** 落地一个半径 14 的圆
- **AND** 命令行 MUST NOT 回「需要一个点」

#### Scenario: 两字段参数化仍然要指针

- **WHEN** `LINE` 取过第一个点、指针从未进入过图面、用户键入 `100` 并回车
- **THEN** 不落点

### Requirement: 参考点被排除出取点时的特征点捕捉

命令正在取点时，会话已经上报的 `reference` MUST 被排除出特征点捕捉，与几何编辑「拖夹点时
排除被拖那个顶点的原位置」是同一条判断。

落点被吸回参考点，对每一条画几何的命令都只能产出**退化**几何——零长的线段、零半径的圆——
而那个结果一定会被当场拒掉。因此这处排除不拿走任何用户够得着的结果。

排除 MUST **按位置**判定而不按 Entity 身份：圆心吸在别的对象的端点上时，把落点拽回去的正是
**那个端点**，按身份排除挡不住它。

#### Scenario: 圆心压在已有端点上仍画得出小圆

- **WHEN** `CIRCLE` 的圆心捕捉到一条已有线段的端点上
- **AND** 半径点离圆心 6 像素，在捕捉容差之内
- **THEN** 落点不被吸回圆心
- **AND** 落地一个半径约 6 的圆

#### Scenario: 连续取点不产出零长段

- **WHEN** `LINE` 取过一点，指针回到刚取过的那个点附近
- **THEN** 落点不被吸回上一点
